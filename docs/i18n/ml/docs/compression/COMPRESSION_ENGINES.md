എഞ്ചിൻ കരാറുകളെ ചുറ്റിപ്പറ്റിയാണ്OmniRoute കംപ്രഷൻ നിർമ്മിച്ചിരിക്കുന്നത്. ഒരു മോഡിന് ഒരു എഞ്ചിൻ നേരിട്ട് പ്രവർത്തിപ്പിക്കാൻ കഴിയും (`caveman` അല്ലെങ്കിൽ `rtk`) അല്ലെങ്കിൽ ഒന്നിലധികം എഞ്ചിനുകൾ ക്രമത്തിൽ എക്സിക്യൂട്ട് ചെയ്യുന്ന ഒരു നിശ്ചിത പൈപ്പ്ലൈൻ.

## മോഡുകൾ

| മോഡ്         | എഞ്ചിൻ പാത                                                                                   | ഉദ്ദേശിച്ച ഇൻപുട്ട്                               |
| ------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `off`        | ഒന്നുമില്ല                                                                                   | കൃത്യമായ വേഗത്തിലുള്ള സംരക്ഷണം                    |
| `lite`       | കേവ്മാൻ ലൈറ്റ് സഹായികൾ                                                                       | കുറഞ്ഞ അപകടസാധ്യതയുള്ള എപ്പോഴും വൃത്തിയാക്കൽ      |
| `standard`   | ഗുഹാമനുഷ്യൻ                                                                                  | സ്വാഭാവിക-ഭാഷാ പ്രോംപ്റ്റ് കണ്ടൻസേഷൻ              |
| `aggressive` | കേവ്മാൻ + history/tool സംഗ്രഹങ്ങൾ                                                            | നീണ്ട ചാറ്റ് സെഷനുകൾ                              |
| `ultra`      | കേവ്മാൻ + അരിവാൾ സഹായികൾ                                                                     | സന്ദർഭ-പരിധി വീണ്ടെടുക്കൽ                         |
| `rtk`        | RTK                                                                                          | ടെർമിനൽ, ഷെൽ, ബിൽഡ്, ടെസ്റ്റ്, ജിറ്റ് ഔട്ട്പുട്ട് |
| `omniglyph`  | OmniGlyph                                                                                    | നേറ്റീവ് പ്രൊവൈഡർ വയറിലെ സന്ദർഭം-ചിത്രം           |
| `stacked`    | പൈപ്പ്ലൈൻ. അഭ്യർത്ഥന ഡിഫോൾട്ട് `session-dedup -> lite` ആണ്. `rtk -> caveman` ഓപ്റ്റ്-ഇൻ ആണ്. | മിക്സഡ് ടൂൾ ലോഗുകളും ഗദ്യവും, പരമാവധി സേവിംഗ്സ്   |

### OmniGlyph കംപ്രഷൻ പ്രൊഫൈലുകൾ

`omniglyph` എഞ്ചിൻ (പാക്കേജ് `omniglyph`, 1.4.0 +) ഒരു പേരുള്ള സെമാൻ്റിക് പ്രൊഫൈൽ സ്വീകരിക്കുന്നു, കംപ്രഷൻ ക്രമീകരണങ്ങളിൽ `omniglyph.profile` വഴി ആഗോളതലത്തിൽ സജ്ജീകരിച്ചിരിക്കുന്നു അല്ലെങ്കിൽ അടുക്കിയിരിക്കുന്ന പൈപ്പ്ലൈനിൻ്റെ സ്റ്റെപ്പ് കോൺഫിഗറിലൂടെ ഓരോ ഘട്ടവും:

| പ്രൊഫൈൽ       | അതിർത്തി                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| `aggressive`  | സ്ഥിരസ്ഥിതി. പ്രസിദ്ധീകരിച്ച രസീതുകളുടെ നയം — ഇമേജ് സിസ്റ്റം, ടൂൾ ഡോക്സ്, ഡെൻസ് ഹിസ്റ്ററി എന്നിവ അളന്നു.     |
| `balanced`    | തത്സമയ സംസ്ഥാന നേറ്റീവ് നിലനിർത്തുന്നു, അവസാന 8 തിരിവുകൾ പരിരക്ഷിക്കുന്നു, പഴയ അടച്ച ചരിത്രത്തെ തകർക്കുന്നു  |
| `coding-safe` | അധികാരം, ടൂൾ സ്കീമകൾ, ലൈവ് ടൂൾ ഔട്ട്പുട്ട് നേറ്റീവ് എന്നിവ നിലനിർത്തുന്നു, അവസാന 12 തിരിവുകൾ സംരക്ഷിക്കുന്നു |
| `passthrough` | രൂപാന്തരപ്പെടാത്ത റൂട്ടുകൾ; എഞ്ചിൻ ഒഴിവാക്കിയിരിക്കുന്നു                                                     |

പ്രൊഫൈൽ എ** സീലിംഗ്, ഒരു തറയല്ല** : പാക്കേജിലെ `mergeCompressionProfileOptions` പ്രൊഫൈൽ അടച്ച ഒരു ലോസി ലെയ്ൻ വീണ്ടും തുറക്കാൻ ഒരു കോളർ അസാധുവാക്കാൻ അനുവദിക്കുന്നില്ല, അതിനാൽ ഒരു ഘട്ടം `preserveSystemPrompt: false` `coding-safe` കീഴിൽ സിസ്റ്റം കംപ്രഷൻ വീണ്ടും പ്രവർത്തനക്ഷമമാക്കാൻ കഴിയില്ല.

ഈ കോഡ്ബേസിൽ അളന്നു: `coding-safe`, `balanced` പരമാവധി `minCompressChars` ഉയർത്തുകയും സിസ്റ്റം, ടൂൾ സ്കീമകൾ, ടൂൾ ഫലങ്ങൾ എന്നിവ നേറ്റീവ് ആയി നിലനിർത്തുകയും ചെയ്യുന്നു, അതിനാൽ ചരിത്രം ശേഖരിക്കാത്ത ഒരു സെഷൻ ഇതുവരെ `below_min_chars` ൽ നിർത്തുകയും എഞ്ചിൻ ഒന്നും രൂപാന്തരപ്പെടുത്തുകയും ചെയ്യുന്നില്ല. അതുകൊണ്ടാണ് ഏറ്റവും സുരക്ഷിതമായ പ്രൊഫൈലിനേക്കാൾ ഡിഫോൾട്ട് `aggressive` ആണ്.

പാക്കേജ് അതിൻ്റെ പരിസ്ഥിതി കോൺഫിഗറേഷനിൽ നിന്ന് സ്വന്തം മോഡൽ സ്കോപ്പും പ്രൊഫൈലും പരിഹരിക്കുന്നു. OmniRoute ഒരിക്കലും തീരുമാനം നിയോഗിക്കുന്നില്ല: പാക്കേജിൻ്റെ ഏറ്റവും നിയന്ത്രിത സ്കോപ്പിലേക്ക് അഡാപ്റ്റർ മോഡൽ ഗേറ്റിനെ പിൻ ചെയ്യുന്നു, അതിനാൽ ഹോസ്റ്റ് എൻവയോൺമെൻ്റ് സജ്ജീകരണങ്ങൾക്ക് അനുവദനീയമായ ലിസ്റ്റ് ചുരുക്കാൻ മാത്രമേ കഴിയൂ, OmniRoute യുടെ അളന്ന രസീതുകൾക്കപ്പുറം ഒരിക്കലും വിശാലമാക്കാൻ കഴിയില്ല.

## എഞ്ചിൻ രജിസ്ട്രി

രജിസ്ട്രി `open-sse/services/compression/engines/registry.ts` യിൽ താമസിക്കുന്നു. എഞ്ചിനുകൾ ഒരു പങ്കിട്ട കരാർ വെളിപ്പെടുത്തുന്നു:

- `id`: `caveman` അല്ലെങ്കിൽ `rtk` പോലുള്ള സ്ഥിരതയുള്ള എഞ്ചിൻ ഐഡി
- `apply(text, config)`: അടുക്കിയിരിക്കുന്ന പൈപ്പ് ലൈനുകൾ ഉപയോഗിക്കുന്ന ലെഗസി എക്സിക്യൂഷൻ പാത
- `compress(input, config)`: പ്രൈമറി എക്സിക്യൂഷൻ പാത്ത് തിരികെ നൽകുന്ന ടെക്സ്റ്റ് + സ്ഥിതിവിവരക്കണക്കുകൾ
- `getConfigSchema()`: സാധുവായ കോൺഫിഗറേഷൻ്റെ JSON-സ്കീമ പോലുള്ള രൂപം നൽകുന്നു
- `validateConfig(config)`: `{ valid, errors[] }` നൽകുന്നു

രജിസ്ട്രേഷൻ `registerCompressionEngine(engine)` (അല്ലെങ്കിൽ വിപുലമായ കേസുകൾക്ക് `registerEngine` ) ഉപയോഗിക്കുന്നു, അത് സ്വീകരിക്കുന്നതിന് മുമ്പ് `assertValidEngine()`, `validateConfig(defaultConfig)` വിളിക്കുന്നു. റൺടൈമിൽ ഒരു എഞ്ചിൻ നീക്കം ചെയ്യാൻ `unregisterCompressionEngine(id)` ഉപയോഗിക്കുക.

കംപ്രഷൻ പ്രവർത്തിപ്പിക്കുന്നതിന് മുമ്പ്`strategySelector.ts` ബിൽറ്റ്-ഇൻ എഞ്ചിനുകൾ രജിസ്റ്റർ ചെയ്യുന്നു. ഇത് പ്രിവ്യൂ, റൺടൈം കംപ്രഷൻ, സ്റ്റാക്ക് ചെയ്ത മോഡ്, ടെസ്റ്റുകൾ, ഭാവി എഞ്ചിനുകൾ എന്നിവ ഒരേ എക്സിക്യൂഷൻ പാത്ത് ഉപയോഗിക്കാൻ അനുവദിക്കുന്നു.

### MCP വിവരണം കംപ്രഷൻ (ബന്ധപ്പെട്ട)

ഒരു പ്രത്യേക രജിസ്ട്രി രജിസ്ട്രി ലെവൽ — ൽ MCP ടൂൾ വിവരണ മെറ്റാഡാറ്റ കംപ്രസ് ചെയ്യുന്നു `open-sse/mcp-server/descriptionCompressor.ts`, [MCP-SERVER.md](../frameworks/MCP-SERVER.md) എന്നിവ കാണുക. ഇത് കേവ്മാൻ നിയമങ്ങൾ വീണ്ടും ഉപയോഗിക്കുന്നു, പക്ഷേ ടൂൾ മെറ്റാഡാറ്റയിൽ പ്രവർത്തിക്കുന്നു, പേലോഡുകൾ അഭ്യർത്ഥിക്കുന്നില്ല.

### അധിക ബിൽറ്റ്-ഇൻ എഞ്ചിനുകൾ

കേവ്മാൻ, RTK, LLMLingua-2 എന്നിവയ്ക്കപ്പുറം, രജിസ്ട്രി നിരവധി സ്പെഷ്യലൈസ്ഡ് ലോസ്ലെസ് / സ്ട്രക്ചറൽ എഞ്ചിനുകൾ അയയ്ക്കുന്നു (അടച്ചുവെച്ച പൈപ്പ് ലൈനുകൾ, കളിസ്ഥലം, ടെസ്റ്റുകൾ എന്നിവ ഉപയോഗിക്കുന്നു):

| എഞ്ചിൻ       | ഐഡി             | അത് എന്ത് ചെയ്യുന്നു                                                                                                                                                                                                               |
| ------------ | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

**CCR വീണ്ടെടുക്കൽ-പ്രോട്ടോക്കോൾ നിർദ്ദേശം (#8033):** ആദ്യമായി CCR ഒരു അഭ്യർത്ഥനയിൽ ≥ 1 ബ്ലോക്ക് മാറ്റിസ്ഥാപിക്കുമ്പോൾ, വിളിക്കുന്നയാളെ → ടൂൾ കോൺട്രാക്റ്റ് മാർക്കർ പഠിപ്പിക്കുന്ന ഒരു ഏകീകൃതമായ `system` സന്ദേശത്തെ ( `[CCR protocol]` സെൻ്റിനലിനൊപ്പം നയിക്കുന്നത്) എഞ്ചിൻ മുൻകൂട്ടി കാണിക്കുന്നു: ഒരു `[CCR retrieve hash=<24hex> chars=N]` മാർക്കർ എന്താണ് അർത്ഥമാക്കുന്നത്, ഹാഷ് പദാനുപദമായി പകർത്തിയിരിക്കണം (എല്ലാം 24 — അക്ഷരങ്ങൾ തെറ്റാണ്. "ബ്ലോക്ക് കണ്ടെത്തിയില്ല" മിസ് ചെയ്യുന്നു), കൂടാതെ ഒരു `[dedup:ref sha=...]` മാർക്കർ എന്നാൽ "ചരിത്രത്തിലേക്ക് തിരിഞ്ഞു നോക്കുക" എന്നാണ് അർത്ഥമാക്കുന്നത്, "ഉപകരണത്തെ വിളിക്കുക" എന്നല്ല. കുറിപ്പ് കുത്തിവച്ചിരിക്കുന്നു** വിളിക്കുന്നയാളുടെ പരസ്യം ചെയ്ത `tools[]` തെളിയിക്കുമ്പോൾ മാത്രമേ അതിന് യഥാർത്ഥത്തിൽ `omniroute_ccr_retrieve` എത്താൻ കഴിയൂ** (`callerSupportsCcrRetrieve()` `open-sse/services/compression/engines/ccr/protocolInstruction.ts` — ആ ടൂൾ ഇല്ലാത്ത ഒരു പ്ലെയിൻ OpenAI-അനുയോജ്യമായ കോളർ ഒരിക്കലും എത്താൻ കഴിയാത്ത എന്തെങ്കിലും വിളിക്കാനുള്ള നിർദ്ദേശം സ്വീകരിക്കില്ല. കുത്തിവയ്ക്കുന്നതിന് മുമ്പ് സെൻ്റിനലിനായി സന്ദേശ ചരിത്രം സ്കാൻ ചെയ്ത് ഐഡംപോട്ടൻസി നടപ്പിലാക്കുന്നു, അതിനാൽ മൾട്ടി-ടേൺ അഭ്യർത്ഥനകൾ (മുൻപ് സന്ദേശങ്ങൾ റീപ്ലേ ചെയ്യുന്നവ) ഓരോ ടേണിലും ഒരു തവണ കുറിപ്പ് അടുക്കുന്നില്ല.

## ഗുഹാമനുഷ്യൻ

കേവ്മാൻ മോഡ് സാധാരണ ഗദ്യത്തിൻ്റെ സെമാൻ്റിക് കണ്ടൻസേഷനിൽ ശ്രദ്ധ കേന്ദ്രീകരിക്കുന്നു:

- കോഡ് ബ്ലോക്കുകൾ, URLs, JSON, പാതകൾ, ഘടനാപരമായ ഡാറ്റ എന്നിവ സംരക്ഷിക്കുന്നു
- ഫില്ലർ, ഹെഡ്ജിംഗ്, ആവർത്തിച്ചുള്ള സന്ദർഭം, വെർബോസ് കണക്റ്റീവ് പദപ്രയോഗം എന്നിവ നീക്കം ചെയ്യുന്നു
- `open-sse/services/compression/rules/` യിലെ ഭാഷാ-അവബോധ ഫയൽ റൂൾ പാക്കുകളെ പിന്തുണയ്ക്കുന്നു
- ലെഗസി `standard`, `aggressive`, `ultra` എന്നീ മോഡുകളിലൂടെ ലഭ്യമാണ്

ഡാഷ്ബോർഡ് ഉപരിതലം `Dashboard -> Context & Cache -> Caveman` ആണ്.

കേവ്മാൻ അപ്സ്ട്രീം `~75%` കുറച്ച് ഔട്ട്പുട്ട് ടോക്കണുകൾ, `22-87%` ശ്രേണിയിലുള്ള ബെഞ്ച്മാർക്കുകളിലെ `65%` ശരാശരി ഔട്ട്പുട്ട് സേവിംഗ്സ്, ഒരു `~46%` ഇൻപുട്ട്-കംപ്രഷൻ ടൂൾ എന്നിവ റിപ്പോർട്ട് ചെയ്യുന്നു. അടുക്കിയിരിക്കുന്ന prompt/context സമ്പാദ്യങ്ങൾ രേഖപ്പെടുത്തുമ്പോൾ OmniRoute കേവ്മാൻ ഇൻപുട്ട്-സൈഡ് നമ്പർ ഉപയോഗിക്കുന്നു; കേവ്മാൻ ഔട്ട്പുട്ട് മോഡ് ഒരു പ്രത്യേക പ്രതികരണ-പെരുമാറ്റ സവിശേഷതയായി തുടരുന്നു.

## RTK

RTK മോഡ് കമാൻഡിലും ടൂൾ ഔട്ട്പുട്ടിലും ശ്രദ്ധ കേന്ദ്രീകരിക്കുന്നു:

- `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, Cargo/Go ടെസ്റ്റുകൾ, TypeScript/Vite/Webpack ബിൽഡുകൾ, ESLint, npm audit/installs, Docker ലോഗുകൾ, ഷെൽ `find`/`grep`, സ്റ്റാക്ക് ട്രെയ്സ്, ജെനറിക് ലോഗുകൾ തുടങ്ങിയ ഔട്ട്പുട്ട് ക്ലാസുകൾ കണ്ടെത്തുന്നു
- `open-sse/services/compression/engines/rtk/filters/` ൽ നിന്ന് 49 JSON ഫിൽട്ടറുകൾ പ്രയോഗിക്കുന്നു
- RTK ശൈലിയിലുള്ള ഡിക്ലറേറ്റീവ് പൈപ്പ്ലൈനിനെ പിന്തുണയ്ക്കുന്നു: ANSI സ്ട്രിപ്പിംഗ്, റീപ്ലേസ്, മാച്ച്-ഔട്ട്പുട്ട് ഷോർട്ട് സർക്യൂട്ട്, strip/keep ലൈനുകൾ, പെർ-ലൈൻ ട്രങ്കേഷൻ, head/tail/max-line ട്രങ്കേഷൻ, ഓൺ-ശൂന്യമായ ഫാൾബാക്ക്
- `.rtk/filters.json` യിലെ ട്രസ്റ്റ്-ഗേറ്റഡ് പ്രോജക്റ്റ് ഫിൽട്ടറുകളും `DATA_DIR/rtk/filters.json` യിലെ ആഗോള ഫിൽട്ടറുകളും പിന്തുണയ്ക്കുന്നു
- സ്ട്രിപ്പുകൾ ANSI സീക്വൻസുകൾ, പ്രോഗ്രസ് നോയ്സ്, ആവർത്തിച്ചുള്ള വരികൾ, സഹായകരമല്ലാത്ത ബോയിലർപ്ലേറ്റ്
- പ്രവർത്തനക്ഷമമായ പരാജയങ്ങൾ, മുന്നറിയിപ്പുകൾ, സംഗ്രഹങ്ങൾ, മാറ്റിയ ഫയലുകൾ, ടെയിൽ സന്ദർഭം എന്നിവ സംരക്ഷിക്കുന്നു
- ആധികാരിക മാനേജ്മെൻ്റ് റൂട്ടുകളിലൂടെ recovery/debugging യ്ക്കായി ഓപ്ഷണലായി പുനർനിർമ്മിച്ച റോ ഔട്ട്പുട്ട് നിലനിർത്താൻ കഴിയും

ഡാഷ്ബോർഡ് ഉപരിതലം `Dashboard -> Context & Cache -> RTK` ആണ്.

ഇഷ്ടാനുസൃത ഫിൽട്ടറുകൾക്കായുള്ള പ്രവർത്തന വിശദാംശങ്ങൾ, വിശ്വസിക്കുക, സ്ഥിരീകരിക്കുക, റോ-ഔട്ട്പുട്ട് വീണ്ടെടുക്കൽ എന്നിവ [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md) ൽ തത്സമയം.

കമാൻഡ്-ഔട്ട്പുട്ട് കംപ്രഷനായിRTK അപ്സ്ട്രീം `60-90%` സേവിംഗ്സ് റിപ്പോർട്ട് ചെയ്യുന്നു. അതിൻ്റെ README ഉദാഹരണം `~118,000` ടോക്കണുകളിൽ നിന്ന് `~23,900` ലേക്ക് പോകുന്ന 30 മിനിറ്റ് Claude കോഡ് സെഷൻ കാണിക്കുന്നു, അല്ലെങ്കിൽ `79.7%` സംരക്ഷിച്ചു.

## LLMLingua-2 (സെമാൻ്റിക് പ്രൂണിംഗ്)

LLMLingua-2 മോഡ് പ്രവർത്തിക്കുന്നു** സെമാൻ്റിക് ടോക്കൺ അരിവാൾ** ഒരു ചെറിയ ONNX ടോക്കൺ ക്ലാസിഫയർ ഉപയോഗിച്ച് ഗദ്യത്തിൽ, റൂൾ അധിഷ്ഠിത കേവ്മാൻ, RTK എഞ്ചിനുകൾ പൂർത്തീകരിക്കുന്നു:

- നോൺ-സിസ്റ്റം സന്ദേശങ്ങളിൽ മാത്രം ഗദ്യം കംപ്രസ് ചെയ്യുന്നു; വേലിയിറക്കിയ കോഡ് ബ്ലോക്കുകളും മറ്റ് സംരക്ഷിത നിർമ്മാണങ്ങളും ഒരിക്കലും മാറ്റില്ല
- ഒരു വർക്കർ ത്രെഡിൽ `@atjsh/llmlingua-2` ബാക്കെൻഡ് (ONNX വഴി `@huggingface/transformers`) പ്രവർത്തിപ്പിക്കുന്നു, അതിനാൽ മോഡൽ അനുമാനം ഒരിക്കലും അഭ്യർത്ഥന ഇവൻ്റ് ലൂപ്പിനെ തടയില്ല
- ആണ്** അടുക്കിവെക്കാവുന്ന** (`stackPriority` 35): അടുക്കിയിരിക്കുന്ന പൈപ്പ്ലൈനിൽ അത് ഘടനാപരമായ എഞ്ചിനുകൾക്ക് (CCR, സെഷൻ-ഡെഡപ്പ്, ഹെഡ്റൂം, കേവ്മാൻ) ശേഷം പ്രവർത്തിക്കുന്നു, എന്നാൽ `ultra` മുമ്പ്, സെമാൻ്റിക് പ്രൂണിംഗ് ഇതിനകം ഘടനാപരമായി കംപ്രസ് ചെയ്തിരിക്കുന്ന ടെക്സ്റ്റ് — ന് ഏറ്റവും ഫലപ്രദമാണ് ഉദാ `rtk -> caveman -> llmlingua`
- **പരാജയം-ഏതെങ്കിലും പിശകിൽ തുറക്കുന്നു** (ഓപ്ഷണൽ ഡെപ്സ്, വർക്കർ സ്പോൺ, മോഡൽ ലോഡ്, അനുമാനം അല്ലെങ്കിൽ കാലഹരണപ്പെടൽ നഷ്ടമായി) → യഥാർത്ഥ വാചകം മാറ്റമില്ലാതെ തിരികെ നൽകും, ഒരിക്കലും ഒരു പിശകില്ല

എഞ്ചിൻ സ്ഥാനം: `open-sse/services/compression/engines/llmlingua/`. ഡാഷ്ബോർഡ് ഉപരിതലം `Dashboard -> Context & Cache -> LLMLingua` ആണ്.

### മോഡലുകൾ

സ്ഥിര മോഡൽ ആണ്**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~ 57 MB, ഫാസ്റ്റ്). ഉയർന്ന കൃത്യത** BERT-ബേസ്** മോഡൽ (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) എഞ്ചിൻ കോൺഫിഗറേഷൻ `model` ഫീൽഡ് വഴി ലഭ്യമാണ്. `@huggingface/transformers` തിരഞ്ഞെടുത്ത മോഡൽ HuggingFace ഹബ്ബിൽ നിന്ന് `${DATA_DIR}/models/llmlingua` ലേക്ക് ആദ്യ കോളിൽ തന്നെ ഡൗൺലോഡ് ചെയ്യുന്നു (`modelStore.ts`); ഒരു `modelPath` കോൺഫിഗറേഷൻ അസാധുവാക്കുന്നത് പകരം ഒരു ലോക്കൽ പകർപ്പിൽ പോയിൻ്റ് ചെയ്യുന്നു (ഓഫ്ലൈൻ / എയർ-ഗാപ്പ്ഡ് ഇൻസ്റ്റാളുകൾ).

### ഓപ്ഷണൽ ഡിപൻഡൻസികളും ഓൺ-ഡിമാൻഡ് ഇൻസ്റ്റാളും

പ്രൂൺ ചെയ്യാവുന്ന LLMLingua റൺടൈം പിയർ സ്റ്റാക്ക് ആണ്** ഓപ്ഷണൽ** . രണ്ട് പാക്കേജുകൾ `package.json` ൽ `optionalDependencies` ആയി പ്രഖ്യാപിക്കുകയും സൂക്ഷിക്കുകയും ചെയ്യുന്നു** ബാഹ്യമായ** പ്രൊഡക്ഷൻ ബിൽഡ് പ്രകാരം (`scripts/build/prepublish.ts` അവയെ ബണ്ടിൽ ചെയ്യുന്നില്ല):

| പാക്കേജ്             | പതിപ്പ് (പിൻ) | കുറിപ്പുകൾ                                                     |
| -------------------- | ------------- | -------------------------------------------------------------- |
| `@atjsh/llmlingua-2` | `2.0.5`       | എൻട്രി പാക്കേജ്; മറ്റുള്ളവരെ സമപ്രായക്കാരായി പ്രഖ്യാപിക്കുന്നു |
| `js-tiktoken`        | `^1.0.20`     | ടോക്കനൈസർ                                                      |

`@huggingface/transformers` `^4.2.0` ൽ പിൻ ചെയ്തിരിക്കുന്നു (പ്രാദേശിക എംബെഡിംഗ്സ് പാതയുമായി പങ്കിടുന്നു, കൂടാതെ ഒറ്റപ്പെട്ട ബണ്ടിൽ കണ്ടെത്തുകയും ചെയ്യുന്നു); `"^3.5.2 || ^4.0.0"` ഉപയോഗിച്ച് `@atjsh/llmlingua-2@2.0.5` പിയർ ചെയ്യുന്നു, അതിനാൽ Transformers.js v3, v4 എന്നിവ പിന്തുണയ്ക്കുന്നു. 2.0.4 മുതൽ, `@atjsh/llmlingua-2` `@tensorflow/tfjs` ആവശ്യമില്ല, ഇത് SLM സ്റ്റാക്കിൽ നിന്ന് ഏറ്റവും വലിയ സിംഗിൾ കോൺട്രിബ്യൂട്ടറെ (TensorFlow.js) നീക്കം ചെയ്തു. മുകളിലുള്ള രണ്ട് പാക്കേജുകൾ മാത്രമാണ് പ്രൂൺ ചെയ്യാവുന്ന SLM പിയേഴ്സ്. ഓപ്ഷണൽ ഡിപൻഡൻസികൾ ഒഴിവാക്കിയില്ലെങ്കിൽ ഒരു സാധാരണ `npm install` (dev) ഓപ്ഷണൽ സ്റ്റാക്ക് ഓട്ടോമാറ്റിക്കായി ഇൻസ്റ്റാൾ ചെയ്യുന്നു.

**എന്തുകൊണ്ട് ആവശ്യാനുസരണം:** npm-പ്രസിദ്ധീകരിച്ച പാക്കേജ്, ഒറ്റപ്പെട്ട ബണ്ടിൽ, Docker ഇമേജ് ഷിപ്പ്** ഇല്ലാതെ** ഈ ഡെപ്സ് മെലിഞ്ഞിരിക്കാൻ. അവർ ഇല്ലാതിരിക്കുമ്പോൾ, തൊഴിലാളിയുടെ ഡിപൻഡൻസി ഗേറ്റ് ( `worker.ts` ലെ ഒരു `@atjsh/llmlingua-2` റിസോൾവ് പ്രോബ്) പരാജയപ്പെടുകയും എഞ്ചിൻ** പരാജയം-നിശബ്ദമായി തുറക്കുന്നു** — തിരഞ്ഞെടുക്കുന്നത് LLMLingua ഒരു നോ-ഓപ് ആയി മാറുന്നു (ടെക്സ്റ്റ് മാറ്റമില്ലാതെ മടങ്ങി, പിശക് ലോഗിൻ ചെയ്തിട്ടില്ല). പ്രൂൺ ചെയ്ത പരിതസ്ഥിതിയിൽ ഇത് സജീവമാക്കുന്നതിന്, ഓപ്ഷണൽ സ്റ്റാക്ക് ഇൻസ്റ്റാൾ ചെയ്യുക:

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` നീക്കംചെയ്യൽ (2.0.4 +) മുമ്പ് ആധിപത്യം പുലർത്തിയിരുന്ന ~ 800 MB കോൺട്രിബ്യൂട്ടർ — ഇല്ലാതാക്കുന്നു, ശേഷിക്കുന്ന കാൽപ്പാട് transformers.js + onnxruntime-node റൺടൈമുകളാണ്, കൂടാതെ TinyBERT മോഡലും (~ 57 MB വഴി ഡൗൺലോഡ് ചെയ്തിട്ടില്ല).

ഓരോ പരിസ്ഥിതിയും:

- **ദേവ് / `npm install`** നിങ്ങൾ `--omit=optional` (അല്ലെങ്കിൽ `--no-optional`) പാസ്സാക്കിയില്ലെങ്കിൽ — സ്വയമേവ ഇൻസ്റ്റാൾ ചെയ്യപ്പെടും. നടപടി ആവശ്യമില്ല.
- **ഗ്ലോബൽ npm (`npm i -g omniroute`) / ഒറ്റയ്ക്ക്** — ഇൻസ്റ്റാൾ ചെയ്ത പാക്കേജ് ഡയറക്ടറിക്കുള്ളിൽ മുകളിലുള്ള ഇൻസ്റ്റോൾ കമാൻഡ് പ്രവർത്തിപ്പിക്കുക, അല്ലെങ്കിൽ ഓപ്ഷണൽ ഡെപ്സ് ഒഴിവാക്കാതെ വീണ്ടും ഇൻസ്റ്റാൾ ചെയ്യുക.
- **Docker** — ഒരു ഡിറൈവ്ഡ് ഇമേജ് ലെയറിൽ ഇൻസ്റ്റോൾ കമാൻഡ് ചേർക്കുക; പ്രസിദ്ധീകരിച്ച ചിത്രം ഡിസൈൻ പ്രകാരം മെലിഞ്ഞതാണ്.
- **VPS (PM2)** ആപ്പിൻ്റെ `node_modules` ലേക്ക് — ഇൻസ്റ്റാൾ ചെയ്യുക, തുടർന്ന് പ്രക്രിയ പുനരാരംഭിക്കുക, അങ്ങനെ തൊഴിലാളി ഗേറ്റ് വീണ്ടും പരിശോധിക്കുന്നു.
- **റോ നെക്സ്റ്റ് ഒറ്റയ്ക്കാണ് (`npm run build` → `.build/next/standalone/server.js`)** — സ്റ്റാൻഡ്എലോൺ ട്രെയ്സ് ഷിപ്പുകൾ തൊഴിലാളിയെയോ ഓപ്ഷണൽ ഡെപ്സിനെയോ NEITHER, അതിനാൽ എഞ്ചിൻ നിശബ്ദമായി പരാജയപ്പെടുന്നു-തുറക്കുന്നു. `scripts/build/colocate-standalone.mjs` രണ്ടും വീണ്ടും പ്രയോഗിക്കുന്നു (തൊഴിലാളികൾ + ഓപ്ഷണൽ-ഡെപ് ക്ലോഷർ സ്റ്റാൻഡ്ലോൺ ട്രീയിലേക്ക് സ്ഥാപിക്കുന്നു); ഓരോ ബിൽഡിനും ശേഷവും ഇത് `postbuild` npm ഹുക്ക് വഴി യാന്ത്രികമായി പ്രവർത്തിക്കുന്നു. ഡിംപോട്ടൻ്റ്, ഡെപ്സ് ഇല്ലാത്തപ്പോൾ പരാജയപ്പെടാത്ത മൃദുവാണ്.

**ഇത് സജീവമാണെന്ന് സ്ഥിരീകരിക്കുക:** തിരഞ്ഞെടുത്ത LLMLingua ഉപയോഗിച്ച്, യഥാർത്ഥ ഗദ്യം യഥാർത്ഥത്തിൽ ചുരുങ്ങുന്നു (എഞ്ചിൻ പരാജയം-തുറക്കുന്നത് നിർത്തുന്നു), കൂടാതെ ആദ്യ അഭ്യർത്ഥന `${DATA_DIR}/models/llmlingua` ലേക്ക് മോഡൽ ഡൗൺലോഡ് ട്രിഗർ ചെയ്യുന്നു. ഗേറ്റ് മനപ്പൂർവ്വം `@atjsh/llmlingua-2` — മാത്രമേ മറ്റ് സമപ്രായക്കാർ ESM-മാത്രം ആണെന്ന് അന്വേഷിക്കുകയും — നിലവിലിരിക്കുമ്പോൾ പോലും `require.resolve` അവരുടെ മേൽ എറിയുകയും ചെയ്യുന്നു, അതിനാൽ `import()` സമയത്ത് ഏതെങ്കിലും പിയർ യഥാർത്ഥത്തിൽ കാണാതായാൽ തൊഴിലാളി ഇപ്പോഴും പരാജയപ്പെടും-തുറക്കുന്നു.

## അടുക്കിവെച്ച പൈപ്പ് ലൈനുകൾ

അടുക്കിയ മോഡ് ക്രമത്തിൽ പൈപ്പ്ലൈൻ ഘട്ടങ്ങൾ പ്രവർത്തിപ്പിക്കുന്നു. സ്ഥിരസ്ഥിതി ഇതാണ്:

```txt
rtk -> caveman
```

ഒരു പ്രോംപ്റ്റ് കമാൻഡ് ഔട്ട്പുട്ടിനെ ഹ്യൂമൻ അല്ലെങ്കിൽ അസിസ്റ്റൻ്റ് ഗദ്യവുമായി സംയോജിപ്പിക്കുന്ന കോഡിംഗ്-ഏജൻ്റ് സെഷനുകൾക്കായി ഇത് ഉപയോഗിക്കുക. RTK ആദ്യം ശബ്ദായമാനമായ ടൂൾ ലോഗുകൾ കുറയ്ക്കുന്നു, തുടർന്ന് കേവ്മാൻ ശേഷിക്കുന്ന സ്വാഭാവിക ഭാഷ കംപ്രസ്സുചെയ്യുന്നു.

കംപ്രഷൻ ക്രമീകരണങ്ങളിലോ കംപ്രഷൻ കോമ്പോസിലോ `stackedPipeline` ഉപയോഗിച്ചാണ് പൈപ്പ്ലൈൻ ഘട്ടങ്ങൾ ക്രമീകരിച്ചിരിക്കുന്നത്.

രണ്ട് എഞ്ചിനുകളും ഒരേ യോഗ്യതയുള്ള പേലോഡ് കുറയ്ക്കുമ്പോൾ, സേവിംഗ്സ് സംയുക്തം:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP പ്രവേശനക്ഷമത ട്രീ ഫിൽട്ടർ

MCP ആക്സസിബിലിറ്റി-ട്രീ സ്മാർട്ട് ഫിൽട്ടർ MCP ൽ പ്രവർത്തിക്കുന്ന ഒരു പോസ്റ്റ് എക്സിക്യൂഷൻ കംപ്രഷൻ ലെയറാണ്.** ഉപകരണ ഫലങ്ങൾ** , നിർദ്ദേശങ്ങളിലോ സന്ദർഭത്തിലോ അല്ല. Playwright, കമ്പ്യൂട്ടർ ഉപയോഗം, ബ്രൗസർ-ഓട്ടോമേഷൻ MCP സെർവറുകൾ എന്നിവ പോലുള്ള ടൂളുകൾ നൽകുന്ന വെർബോസ് ആക്സസ്സിബിലിറ്റി-ട്രീ, ബ്രൗസർ സ്നാപ്പ്ഷോട്ട് പേലോഡുകൾ എന്നിവ ഇത് ലക്ഷ്യമിടുന്നു.

### അത് എന്ത് ചെയ്യുന്നു

1. **നോയ്സ് സ്ട്രിപ്പിംഗ്** — ശൂന്യമായ generic/text എൻട്രികൾ നീക്കം ചെയ്യുന്നു (`- generic:`, `- text: ""`)
2. **സഹോദരങ്ങളുടെ തകർച്ച** — ≥ `collapseThreshold` (സ്ഥിരസ്ഥിതി 30) തുടർച്ചയായ വരികൾ ഘടനാപരമായ ആവർത്തനങ്ങളാകുമ്പോൾ, അവയെ ആദ്യത്തെ `collapseKeepHead` (സ്ഥിരസ്ഥിതി 10) വരികളായി ചുരുക്കുമ്പോൾ + ഒരു എണ്ണത്തിൻ്റെ സംഗ്രഹം + അവസാന `collapseKeepTail` (സ്ഥിരസ്ഥിതി 5) വരികൾ
3. **റഫറൻസ് സംരക്ഷണം** Playwright/computer-use ന് ആവശ്യമായ — `[ref=eXX]` ആങ്കറുകൾ ഒരിക്കലും സ്പർശിക്കില്ല
4. **കഠിനമായ വെട്ടിച്ചുരുക്കൽ** — തകർച്ചയ്ക്കു ശേഷമുള്ള വാചകം `maxTextChars` (സ്ഥിരസ്ഥിതി 50,000) കവിയുന്നുവെങ്കിൽ, ഒരു നാവിഗേഷൻ സൂചനയോടെ വെട്ടിച്ചുരുക്കുന്നു, അങ്ങനെ ഏജൻ്റിന് തുടർന്നും പ്രവർത്തിക്കാനാകും

### എഞ്ചിൻ സ്ഥാനം

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

ആഗോള ക്രമീകരണങ്ങളിൽ `compression.mcpAccessibility` നിയന്ത്രിക്കുന്നത് (മൈഗ്രേഷൻ 056). ഡിഫോൾട്ട് കോൺഫിഗറേഷൻ:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

`type` `"text"` ആയതും നീളം `minLengthToProcess` കവിയുന്നതുമായ ടൂൾ ഫല പേലോഡുകളിൽ മാത്രമേ ഫിൽട്ടർ പ്രയോഗിക്കൂ. ഇത് പ്രോംപ്റ്റ് കംപ്രഷനെയോ അഭ്യർത്ഥന പേലോഡുകളെയോ ബാധിക്കില്ല.

## കംപ്രഷൻ കോമ്പോസ്

കംപ്രഷൻ കോമ്പോസിന് കംപ്രഷൻ പ്രൊഫൈലുകൾ എന്ന് പേരിട്ടിരിക്കുന്നു, അവ റൂട്ടിംഗ് കോമ്പോസിന് നൽകാം:

- `compression_combos`: സ്റ്റോർ മോഡ്, പൈപ്പ്ലൈൻ, RTK കോൺഫിഗറേഷൻ, ഭാഷാ കോൺഫിഗറേഷൻ, ഡിഫോൾട്ട് മാർക്കർ
- `compression_combo_assignments`: ഒരു കംപ്രഷൻ കോംബോ ഒരു റൂട്ടിംഗ് കോംബോയിലേക്ക് മാപ്പ് ചെയ്യുന്നു
- ജനറിക് കോംബോ അസാധുവാക്കുന്നതിന് മുമ്പ് റൺടൈം ഇൻ്റഗ്രേഷൻ ഒരു നിയുക്ത കംപ്രഷൻ കോംബോ പരിഹരിക്കുന്നു
- വിശകലനത്തിൽ `compression_combo_id`, `engine` എന്നിവ ഉൾപ്പെടുന്നു

ഡാഷ്ബോർഡ് ഉപരിതലം: `Dashboard -> Context & Cache -> Compression Combos`.

## മുൻവ്യവസ്ഥകൾ / ഓപ്പറേറ്റർ ഗൈഡ് (CCR & സെഷൻ-ഡെഡപ്പ്)

CCR (`ccr`), `session-dedup` എന്നിവ മാറ്റിസ്ഥാപിക്കുക അല്ലെങ്കിൽ ടെക്സ്റ്റ് എലൈഡ് ചെയ്ത് എ വിടുക** മാർക്കർ** പിന്നിൽ. ഈ വിഭാഗം ഒരു ക്ലയൻ്റിനെ വയറിംഗ് ചെയ്യുന്നതിനും രണ്ട് മാർക്കറുകൾ വായിക്കുന്നതിനും ഒഴിവാക്കിയ ഉള്ളടക്കം വീണ്ടെടുക്കുന്നതിനും കണ്ടെത്തുന്നതിനും ഉള്ള ഓപ്പറേറ്റർ റഫറൻസാണ്. ഓരോ എഞ്ചിൻ്റെയും മെക്കാനിക്സ് മുകളിൽ ഉൾപ്പെടുത്തിയിട്ടുണ്ട്; ഇതാണ് "എങ്ങനെ പ്രവർത്തിപ്പിക്കാം" എന്ന പാളി.

### ഗതാഗതവും അവസാന പോയിൻ്റുകളും

CCR ടൂളുകൾ തുറന്നുകാട്ടുന്ന MCP സെർവറിലേക്ക് മൂന്ന് വഴികളിൽ എത്തിച്ചേരാനാകും. ഡിഫോൾട്ട് ബേസ് URL `http://localhost:20128` (`OMNIROUTE_BASE_URL`):

| ഗതാഗതം                                                  | URL / കമാൻഡ്                            | കുറിപ്പുകൾ                                                                                                                                 |
| ------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| സ്ട്രീം ചെയ്യാവുന്ന HTTP (ക്ലയൻ്റ്, ശുപാർശ ചെയ്യുന്നത്) | `http://localhost:20128/api/mcp/stream` | നിലവിലെ MCP ക്ലയൻ്റുകൾ സംസാരിക്കുന്ന അവസാന പോയിൻ്റ്.                                                                                       |
| ലെഗസി SSE സിംഗിൾടൺ                                      | `http://localhost:20128/api/mcp/sse`    | പഴയ സിംഗിൾടൺ ഗതാഗതം. അത്** അടയ്ക്കുന്നു** സ്ട്രീം ചെയ്യാവുന്ന സെഷനുകൾ; `/api/mcp/stream` `streamable-http` ക്ലയൻ്റുകളെ ഉപയോഗിക്കുക, ഇതല്ല. |
| stdio                                                   | `omniroute --mcp`                       | പ്രക്രിയയ്ക്ക് കാരണമാകുന്ന IDE MCP കോൺഫിഗറിനായി. `--dev` പതാക ഇല്ല; `omniroute --mcp` എന്നത് stdio പ്രവേശന പോയിൻ്റാണ്.                     |

### സംഭരണ ശ്രേണികൾ (പുനരാരംഭിച്ചാൽ നിലനിൽക്കുന്നത്)

CCR a ആണ്** രണ്ട്-ടയർ** സ്റ്റോർ, മെമ്മറിയിൽ മാത്രം അല്ല:

- **ഹോട്ട് ഇൻ-മെമ്മറി ടയർ** — ഓരോ ബ്ലോക്ക് ക്യാപ് 2 MiB, ഓരോ പ്രിൻസിപ്പൽ 16 MiB, ആഗോള 64 MiB. 24 h TTL (പരമാവധി 7 ദിവസം) ലേക്ക് എൻട്രികൾ ഡിഫോൾട്ട്. മെമ്മറിയിൽ നിന്ന് പൂർണ്ണമായ MCP വീണ്ടെടുക്കൽ 256 KiB ആണ്; റേഞ്ച്ഡ് / ഗ്രെപ്പ് മോഡുകളിലൂടെ വലിയ എന്തും ഇപ്പോഴും എത്തിച്ചേരാനാകും.
- **ഡ്യൂറബിൾ SQLite ടയർ** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, ഡിഫോൾട്ടായി ഓൺ) — ഇൻ-മെമ്മറി ടയറിനെ പിന്തുണയ്ക്കുന്നു, അതിനാൽ ഒരു ബ്ലോക്ക് LRU എവിക്ഷൻ, റീസ്റ്റാർട്ട് അല്ലെങ്കിൽ മറ്റൊരു സന്ദർഭത്തിൽ ലാൻഡിംഗ് എന്നിവയെ അതിജീവിക്കുന്നു. വരി ബ്ലോക്കിൻ്റെ TTL നിലനിർത്തുന്നു, അതിനാൽ അതിൻ്റെ TTL കഴിഞ്ഞ ഒരു ബ്ലോക്ക് രണ്ട് നിരകളിൽ നിന്നും പോയി.

മൂന്ന് ഗാർഡുകൾ മോടിയുള്ള ടയർ ബൗണ്ടഡ് — ഒരു ബ്ലോക്ക് മെമ്മറി നിലനിർത്തുന്നു-ഇപ്പോൾ മാത്രം:

1. ബ്ലോക്ക് കഴിഞ്ഞു** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. റൺടൈം ഒരു ക്ലൗഡ് റൺടൈമാണ് (ലോക്കൽ ഡിസ്ക് ഇല്ല);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

അതിനാൽ "ബ്ലോക്ക് അപ്രത്യക്ഷമായി" എന്നത് ഒരു ബ്ലാങ്കറ്റ് റീസ്റ്റാർട്ട് സ്റ്റോറി അല്ല: ഒരു ലോക്കൽ, നോൺ-ക്ലൗഡ് റൺടൈമിലെ ഒരു sub-512 KB ബ്ലോക്ക് അതിൻ്റെ TTL തീരുന്നത് വരെ ഡ്യൂറബിൾ ടയർ വഴി പുനരാരംഭിക്കുമ്പോൾ അതിജീവിക്കുന്നു. വേരിയബിളിനായി [പരിസ്ഥിതി റഫറൻസ്](../reference/ENVIRONMENT.md) കാണുക.

### രണ്ട് അടയാളങ്ങൾ

| മാർക്കർ                               | അർത്ഥം                                                                                                                                        | മോഡൽ എന്തുചെയ്യണം                                                                                                                                                                                                                              |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[CCR retrieve hash=<24hex> chars=N]` | ഒരു വലിയ ബ്ലോക്ക് ഉള്ളടക്കം-വിലാസത്തിൽ സംഭരിച്ചു.                                                                                             | കൂടെ `omniroute_ccr_retrieve` വിളിക്കുക** 24-ഹെക്സ് ഹാഷ് പദാനുപദമായി പകർത്തി** യഥാർത്ഥ വാചകം തിരികെ ലഭിക്കാൻ.                                                                                                                                  |
| `[dedup:ref sha=…]`                   | `session-dedup` എലിഡഡ് ടെക്സ്റ്റ് ഇതേ സെഷൻ്റെ മുമ്പത്തെ ടേണിൽ ഇതിനകം അയച്ചു. ഇത് ഒരു** മനഃപൂർവ്വം തിരിഞ്ഞു നോക്കുക** , ഒരു നഷ്ടമോ പിശകോ അല്ല. | ചെയ്യുക** അല്ല** ഏതെങ്കിലും ഉപകരണം വിളിച്ച് ചെയ്യുക** അല്ല** അത് "പുനർനിർമ്മിക്കാൻ" ശ്രമിക്കുക. വാചകത്തിൻ്റെ ആദ്യ സംഭവം കാനോനിക്കൽ കോപ്പിയാണ്; നിലവിലെ ടേൺ ഒരിക്കലും തിരുത്തിയെഴുതപ്പെടുന്നില്ല, പിന്നീടുള്ള ഒരു ടേണിൽ അത് ഒഴിവാക്കപ്പെടുന്നു. |

`[dedup:ref]` ലുക്ക്-ബാക്ക് ഒരു ബോധപൂർവമായ പ്രോട്ടോക്കോൾ തീരുമാനമാണ് — അയയ്ക്കുന്നതിന് മുമ്പുള്ള പുനർനിർമ്മാണമൊന്നുമില്ല. "ഈ കൃത്യമായ വാചകം ഈ സെഷനിൽ നേരത്തെ തന്നെ വയറിൽ ഉണ്ടായിരുന്നു" എന്ന് പരിഗണിക്കുക.

### ക്ലയൻ്റ് മുൻവ്യവസ്ഥകൾ

- **കീ (stdio):** ഒരു stdio കോളർ ഓരോ അഭ്യർത്ഥന ഐഡൻ്റിറ്റിയും വഹിക്കുന്നില്ല, അതിനാൽ ഇത് `OMNIROUTE_API_KEY` ഉപയോഗിച്ച് പ്രാമാണീകരിക്കുന്നു ( MCP സെർവറിൻ്റെ `env` യിൽ സജ്ജീകരിച്ചിരിക്കുന്നു). അതില്ലാതെ വിളിക്കുന്നയാൾ അജ്ഞാതനാണ്, പ്രിൻസിപ്പൽ ആവശ്യമായ ഉപകരണങ്ങൾ അധഃപതിച്ചേക്കാം.
- **`tools[]` ആണ് കുത്തിവയ്പ്പ് മുൻകൂർ വ്യവസ്ഥ.** CCR വീണ്ടെടുക്കൽ-പ്രോട്ടോക്കോൾ നിർദ്ദേശം (#8033) കുത്തിവച്ചിരിക്കുന്നു** മാത്രം** അഭ്യർത്ഥനയുടെ പരസ്യപ്പെടുത്തിയ `tools[]` ക്ലയൻ്റിന് യഥാർത്ഥത്തിൽ `omniroute_ccr_retrieve` എത്താൻ കഴിയുമെന്ന് തെളിയിക്കുമ്പോൾ. ഈ പൊരുത്തം ഒരു സെപ്പറേറ്റർ (`__`, `.`, `/`, `:`) കൊണ്ട് പരിമിതപ്പെടുത്തിയിരിക്കുന്ന ഒരു ട്രെയിലിംഗ്-സെഗ്മെൻ്റ് പൊരുത്തമാണ്, — ഒരിക്കലും ഒരു വെറും സബ്സ്ട്രിംഗ് — അല്ല, അതിനാൽ `mcp__gateway__omniroute_ccr_retrieve` പോലെയുള്ള നെയിംസ്പെയ്സ് ഉള്ള പേര് ഇപ്പോഴും കണക്കാക്കുന്നു. ഇല്ലാത്തതോ പൊരുത്തപ്പെടാത്തതോ ആയ `tools[]` അർത്ഥമാക്കുന്നത് നിർദ്ദേശങ്ങൾ _നോട്ട്_ ഇൻജക്റ്റ് ചെയ്തതല്ല എന്നാണ്.
- **`codemode:false` (OpenCode ക്ലയൻ്റുകൾ).** OpenCode കോഡ് മോഡിലേക്ക് ഡിഫോൾട്ട് ചെയ്യുന്നു, അത് മോഡലിലേക്കും അതിൻ്റെ നേറ്റീവ് ടൂളുകൾ മാത്രം പരസ്യപ്പെടുത്തുന്നു** ചെയ്യുന്നില്ല** നേറ്റീവ് `tools[]` ലിസ്റ്റിൽ MCP ടൂളുകൾ ഇടുക. MCP സെർവർ എൻട്രിയിൽ `codemode: false` സജ്ജമാക്കുക, അങ്ങനെ `omniroute_ccr_*` ടൂളുകൾ പരസ്യപ്പെടുത്തും. ഇത് എ** ക്ലയൻ്റ്** ക്രമീകരണം, ഒരു OmniRoute അല്ല. ഇതിന് ഇതുവരെ CCR നിർദ്ദേശം നൽകിയിട്ടില്ല: OpenCode ഒരു ടൂൾ `<server>_<tool>` എന്ന് വിളിക്കുന്നു, അതിനാൽ `omniroute` എന്ന് വിളിക്കുന്ന സെർവർ `omniroute_omniroute_ccr_retrieve` വെളിപ്പെടുത്തുന്നു, കൂടാതെ `_` പൊരുത്തപ്പെടുന്ന സെപ്പറേറ്ററുകളിൽ ഒന്നല്ല.
- **പ്രിൻസിപ്പൽമാർ.** സ്റ്റോറേജും വീണ്ടെടുക്കലും ആധികാരിക പ്രിൻസിപ്പലിന് ( API കീയ്ക്ക്) ഒറ്റപ്പെട്ടതാണ്. ഒരു കീ അതിൻ്റെ സ്വന്തം ബ്ലോക്കുകൾ മാത്രം കാണുന്നു.

### ഓരോ ഉപകരണത്തിനും വ്യാപ്തി

ഇടുങ്ങിയ സ്കോപ്പുള്ള HTTP/SSE കോളർമാർക്കായി സ്കോപ്പ് എൻഫോഴ്സ്മെൻ്റ് എല്ലായ്പ്പോഴും ഓണാണ്. `omniroute_` CCR ഉപകരണങ്ങൾക്ക് ഇത് ആവശ്യമാണ്:

| ഉപകരണം                   | വ്യാപ്തി            |
| ------------------------ | ------------------- |
| `omniroute_ccr_store`    | `write:compression` |
| `omniroute_ccr_delete`   | `write:compression` |
| `omniroute_ccr_retrieve` | `read:compression`  |
| `omniroute_ccr_inspect`  | `read:compression`  |
| `omniroute_ccr_list`     | `read:compression`  |
| `omniroute_ccr_stats`    | `read:compression`  |

നഷ്ടമായ സ്കോപ്പ് ഒരു നൽകുന്നു**MCP ടൂൾ പിശക് ഫലം** (`isError: true`, ഒരു HTTP 403 — അല്ല `403 LOCAL_ONLY` എന്നത് പ്രത്യേക ലൂപ്പ്ബാക്ക് റൂട്ട്-ഗാർഡ് ഓത്ത് ആണ്): `Error: Insufficient MCP scopes for <tool>. Missing: <scope>.` ഒരു മിനിമൽ റിമോട്ട് കീ `mcp:connect` ( `/api/mcp/` ലോക്കൽ-ഓൺലി കാർവ്-ഔട്ടിനെ അംഗീകരിക്കുന്നു) കൂടാതെ അതിന് ആവശ്യമായ നിർദ്ദിഷ്ട read/write സ്കോപ്പും ഹോൾഡ് ചെയ്യാൻ കഴിയും.

### വീണ്ടെടുക്കൽ പരിധികളും പേജിനേഷനും

MCP ടൂൾ ടെക്സ്റ്റ് ഫലങ്ങൾ `mcpAccessibility.maxTextChars` ചുറ്റും ക്ലിപ്പ് ചെയ്തിരിക്കുന്നു (സ്ഥിരസ്ഥിതി `50000`). ഒരു ബ്ലോക്കിൻ്റെ ഒരു `full` വീണ്ടെടുക്കൽ 256 KiB — ആണ്.** പരിധിയില്ലാത്ത പൂർണ്ണ വീണ്ടെടുക്കൽ ഇല്ല** . ഒരു ബ്ലോക്കിൻ്റെ `chars=N` വലുതായിരിക്കുമ്പോൾ, മുഴുവൻ വലിക്കുന്നതിനുപകരം അത് പേജ് ചെയ്യുക:

- നിയമാവലി:**`chars > 40000` → ഒരു `mode` ഉപയോഗിക്കുക** , ഒരിക്കലും ഒരു നഗ്നമായ നിറഞ്ഞു.
- `mode:"grep"` — regex `pattern` പൊരുത്തപ്പെടുന്ന 1,000 വരികൾ വരെ (`unique: true` drops repeats), "എനിക്ക് ആവശ്യമുള്ള ഒരു വരി കണ്ടെത്തുക" എന്നതിന് ഏറ്റവും വിലകുറഞ്ഞത്.
- `mode:"lines"` — ഒരു 1-സൂചിക വരി ശ്രേണി; `start` ഉം `end` ഉം ആവശ്യമാണ്.
- `mode:"head"` / `mode:"tail"` — first/last `n` ലൈനുകൾ.
- `mode:"stats"` — ലൈൻ, പ്രതീകം, ബൈറ്റ് എന്നിവ ബോഡി ഇല്ലാതെ എണ്ണുന്നു.

മുഴുവൻ കാര്യങ്ങളും ഒരേസമയം അഭ്യർത്ഥിക്കുന്നതിനുപകരം പേജുകളിൽ ഒരു നീണ്ട ബ്ലോക്ക് നടക്കാൻ `start`/`end` ഉപയോഗിച്ച് `mode:"lines"` ഉപയോഗിക്കുക.

### ടൂൾ നാമകരണം

വീണ്ടെടുക്കൽ ഉപകരണത്തിന് നിലവിൽ `omniroute_ccr_retrieve` എന്നാണ് പേരിട്ടിരിക്കുന്നത് (ക്രോസ്-സെർവർ നെയിം കൂട്ടിയിടികൾക്ക് `omniroute_` പ്രിഫിക്സ് ഒരു കാലഹരണപ്പെട്ട പരിഹാരമാണ്). ഒരു ക്ലീനർ ബൗണ്ടഡ്-സഫിക്സ് ടൂൾ നാമവും MCP JSON ഫലങ്ങൾക്കുള്ള പരിഹാരവും വെട്ടിച്ചുരുക്കിയ മിഡ്-സ്ട്രിംഗ് അപ്സ്ട്രീം ഫോളോ-അപ്പുകളായി ട്രാക്കുചെയ്യുന്നു; ഈ പേജ് നിലവിലെ, ഷിപ്പ് ചെയ്ത പെരുമാറ്റം മാത്രം രേഖപ്പെടുത്തുന്നു.

### സെഷൻ ജീവിതചക്രം

സ്ട്രീമബിൾ-എച്ച്ടിടിപി സെഷനുകൾ നിഷ്ക്രിയമാവുകയും സെർവർ അവ കൊയ്യുകയും ചെയ്യുന്നു; നിഷ്ക്രിയ വിൻഡോ `MCP_SESSION_IDLE_MS` സ്ഥിരാങ്കമാണ് (പേര് സൂചിപ്പിക്കുന്നു, ഹാർഡ്കോഡുചെയ്ത മൂല്യമല്ല, അതിനാൽ ഈ പേജ് മാറുമ്പോൾ അത് ഡ്രിഫ്റ്റ് ചെയ്യില്ല). `Unknown Mcp-Session-Id` — ഉള്ള ഒരു HTTP 404 ആണ് നിഷ്ക്രിയമായ ഒരു സെഷൻ്റെ ലക്ഷണം, സെഷൻ വീണ്ടും കണക്റ്റ് ചെയ്യുകയോ പുനരാരംഭിക്കുകയോ ആണ് പ്രതിവിധി,** അല്ല** ഒരു കീ തിരിക്കുക, ഒരു സ്കോപ്പ് മാറ്റുക അല്ലെങ്കിൽ ഒരു ഉപകരണത്തിൻ്റെ പേരുമാറ്റുക.

| `omniroute_set_compression_engine`  | `write:compression` | മോഡും ഓപ്ഷണൽ പൈപ്പ്ലൈനും സജ്ജമാക്കുക                  |
| `omniroute_list_compression_combos` | `read:compression`  | കംപ്രഷൻ കോമ്പോകൾ ലിസ്റ്റ് ചെയ്യുക                     |
| `omniroute_compression_combo_stats` | `read:compression`  | combo/engine അനലിറ്റിക്സ് വായിക്കുക                   |

## വ്യാപ്തിയും ഒഴിവാക്കലുകളും

**ഉൾച്ചേർക്കലുകൾ ഒരിക്കലും കംപ്രസ് ചെയ്യപ്പെടുന്നില്ല.** `open-sse/handlers/embeddings.ts` ഒരിക്കലും ഒരു കംപ്രഷൻ എഞ്ചിനും — എന്ന് വിളിക്കുന്നില്ല, request/response ബോഡികൾ നേരിട്ട് എക്സിക്യൂട്ടീവിലേക്ക് സ്പർശിക്കാതെ കടന്നുപോകുന്നു. ഇത് ഇന്ന് ഘടനാപരമാണ് (എംബെഡിംഗുകളും ചാറ്റ് പൂർത്തീകരണങ്ങളും ഡിസ്ജോയിൻ്റ് ഹാൻഡ്ലറുകളാണ്), ഒരു റൺടൈം പരിശോധനയല്ല, എന്നാൽ അതിനർത്ഥം #8034 ലെ വെക്റ്റർ-ഡിസ്റ്റോർഷൻ ആശങ്കയ്ക്ക് എംബെഡിംഗ്സ് പാതയിൽ എക്സ്പോഷർ പ്രതലമില്ല എന്നാണ്.

**Per-model/endpoint ഒഴിവാക്കൽ ഫിൽട്ടർ (#8034).** ചാറ്റ് പൂർത്തീകരണങ്ങൾക്കായി, ഒരു ഓപ്പറേറ്റർക്ക് മോഡൽ ഐഡികൾ / `provider/model` ടാർഗെറ്റുകൾക്ക് പേരിടാൻ കഴിയും, അവ ഒരിക്കലും കംപ്രസ് ചെയ്യപ്പെടാൻ പാടില്ലാത്ത — ഒരു ഗാർഡ്റെയിൽ കംപ്രഷൻ പിന്നീട് ഒരു എംബെഡ്ഡിംഗുകൾ-അടുത്തുള്ള പാതയോട് അടുത്ത് വയർ ചെയ്യുകയാണെങ്കിൽ ഉപയോഗപ്രദമാണ്, കൂടാതെ കൃത്യമായ ബൈറ്റ്-ബൈറ്റ് പ്രോംപ്റ്റ് കാര്യങ്ങൾ (നിർണ്ണയിച്ച കാര്യങ്ങൾ, മുൻകൂർ-നിർണ്ണയ-നിർണ്ണയങ്ങൾ, മുതലായവ) ഏത് മോഡലിനും ഉപയോഗപ്രദമാണ്.

- ക്രമീകരണ ഫീൽഡ്: ഗ്ലോബൽ കംപ്രഷൻ കോൺഫിഗറിലുള്ള `exclusions?: string[]` (`GET`/`PUT /api/settings/compression`), നിലവിലുള്ള `key_value` കംപ്രഷൻ നെയിംസ്പേസ് (`src/lib/db/compression.ts`) — വഴി തുടരുന്നു പുതിയ പട്ടികയില്ല.
- ഡാഷ്ബോർഡ് ടാബ്:** ഡാഷ്ബോർഡ് → കംപ്രഷൻ → ഒഴിവാക്കലുകൾ** (`/dashboard/compression/exclusions`).
- പാറ്റേൺ വാക്യഘടന: `*` മാത്രമാണ് വൈൽഡ്കാർഡ്. ഒരു പാറ്റേണിലെ മറ്റെല്ലാ റീജക്സ് മെറ്റാക്യാരാക്ടറും പൊരുത്തപ്പെടുന്നതിന് മുമ്പ് രക്ഷപ്പെടും, അതിനാൽ `gpt-5.6` ലിറ്ററൽ സ്ട്രിംഗുമായി മാത്രം പൊരുത്തപ്പെടുന്നു, ഒരിക്കലും `gpt-5x6` (ReDoS-സേഫ്, ബൗണ്ടഡ്, നെസ്റ്റഡ് ക്വാണ്ടിഫയറുകൾ ഇല്ല). പാറ്റേണുകൾ ബെയർ മോഡൽ ഐഡിക്കും `provider/model` കോമ്പോസിറ്റ് — `gpt-5-6`, `openai/gpt-5-6`, `openai/*` എന്നിവയ്ക്കും എതിരായി കേസ്-ഇൻസെൻസിറ്റീവ് ആയി പൊരുത്തപ്പെടുന്നു, കൂടാതെ `*` മാത്രം എല്ലാ മോഡലുകളും ഒഴിവാക്കുന്നു.
- പൊരുത്തം: `isCompressionExcluded()` / `normalizeCompressionExclusions()` in `open-sse/services/compression/exclusions.ts`. കംപ്രഷൻ ക്രമീകരണങ്ങൾ പരിഹരിച്ചതിന് ശേഷം `chatCore.ts` ഒഴിവാക്കിയ ടാർഗെറ്റ് പരിശോധിക്കുന്നു,** ഏതെങ്കിലും എഞ്ചിൻ പ്രവർത്തിക്കുന്നതിന് മുമ്പ്** , കൂടാതെ കംപ്രഷൻ ആഗോളതലത്തിൽ അപ്രാപ്തമാക്കിയിരിക്കുന്നതുപോലെ ഒരു പൊരുത്തം കൈകാര്യം ചെയ്യുന്നു — അഭ്യർത്ഥന ബോഡി ബൈറ്റിന് സമാനമാണ്. അനലിറ്റിക്സ് ദൃശ്യപരതയ്ക്കായി ഒഴിവാക്കൽ `writeCompressionSkip(..., "excluded")` വഴി രേഖപ്പെടുത്തുന്നു.
- ഡിഫോൾട്ട് (empty/absent ലിസ്റ്റ്): pre-#8034 സ്വഭാവത്തിന് സമാനമായ — ഒന്നും ഒഴിവാക്കിയിട്ടില്ല.

## അറിയപ്പെടുന്ന പരിമിതികൾ

- **LLMLingua-2 (SLM) ന് കോ-ലൊക്കേറ്റഡ് ഓപ്ഷണൽ ഡെപ്സ് ആവശ്യമാണ്.** `@atjsh/llmlingua-2` + പിയേഴ്സ് `dist/node_modules` ലേക്ക് സഹ-ലൊക്കേറ്റ് ചെയ്യുമ്പോൾ മാത്രമേ തൊഴിലാളി ഒരു പ്രൊഡക്ഷൻ ബിൽഡിൽ പ്രവർത്തിക്കൂ ( `scripts/build/colocateOptionals.mjs`, #4286 കാണുക). അവയില്ലാതെ എഞ്ചിൻ പരാജയപ്പെടുന്നു-തുറക്കുന്നു (യഥാർത്ഥ വാചകം നൽകുന്നു). വർക്കർ റെസല്യൂഷൻ ഇനി മുതൽ `import.meta.url` നെ ആശ്രയിക്കുന്നില്ല (അത് ഒറ്റപ്പെട്ട ബണ്ടിലിൽ മരിക്കുന്നു) — അത് റൺടൈമിൽ നങ്കൂരമിടുന്നു cwd / `argv[1]`.
- **കേവ്മാൻ ഭാഷാ പായ്ക്കുകൾ `de` / `fr` / `ja` ഭാഗികമാണ്.** അവർ `context` + `filler` + `structural` നിയമങ്ങൾ ഷിപ്പുചെയ്യുന്നു, എന്നാൽ `dedup` / `ultra` പായ്ക്കുകൾ ഇല്ല, അതിനാൽ `ultra` തീവ്രത ആ ഭാഷകൾക്ക് `full` നേക്കാൾ ശക്തമല്ല (അവർ അവരുടെ സ്വന്തം നിയമങ്ങൾ — മാത്രമേ ഉപയോഗിക്കുന്നുള്ളൂ, അവിടെ ഇംഗ്ലീഷ് `dedup`/`ultra` നിയമങ്ങളിലേക്ക് സൈലൻ്റ് ഫാൾ ബാക്ക് ഇല്ല. `en` / `es` / `id` / `pt-BR` പൂർത്തിയായി. ഭാഗിക പായ്ക്കുകൾക്കായി `dedup.json` + `ultra.json` യുടെ സംഭാവനകൾ സ്വാഗതം ചെയ്യുന്നു.
- **സഞ്ചിത ടെലിമെട്രി കംപ്രസ് ചെയ്ത എഞ്ചിനുകളെ മാത്രമേ ലിസ്റ്റുചെയ്യൂ.** എഞ്ചിൻ പ്രവർത്തിക്കുകയും എന്നാൽ 0 % സേവിംഗ്സ് റിട്ടേൺസ് `stats:null` ഉണ്ടാക്കുകയും ചെയ്യുന്ന ഒരു അടുക്കിയ പൈപ്പ് ലൈൻ സ്റ്റെപ്പ് `engineBreakdown` — ൽ ഒഴിവാക്കിയ ഒരു ഘട്ടത്തിൽ നിന്ന് വേർതിരിച്ചറിയാൻ കഴിയില്ല. "ഓടി, 0 %" എന്നത് "ഒഴിവാക്കി" എന്നതിൽ നിന്ന് വേർതിരിക്കുന്നതിന് ഒരു ബ്രേക്ക്ഡൗൺ മോഡൽ മാറ്റം ആവശ്യമായി വരും, അത് മാറ്റിവയ്ക്കപ്പെടും.
