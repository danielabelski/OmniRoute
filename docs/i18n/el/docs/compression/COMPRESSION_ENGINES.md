Η συμπίεση OmniRoute βασίζεται στις συμβάσεις του κινητήρα. Μια λειτουργία μπορεί να εκτελεί απευθείας έναν κινητήρα (`caveman` ή `rtk`) ή έναν ντετερμινιστικό στοιβαγμένο αγωγό που εκτελεί πολλαπλούς κινητήρες με τη σειρά.

## Λειτουργίες

| Τρόπος       | Διαδρομή κινητήρα                                                                                        | Προβλεπόμενη είσοδος                                              |
| ------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `off`        | κανένας                                                                                                  | Ακριβής άμεση συντήρηση                                           |
| `lite`       | Caveman lite βοηθοί                                                                                      | Πάντα σε λειτουργία καθαρισμού χαμηλού κινδύνου                   |
| `standard`   | Αγριάνθρωπος                                                                                             | Γρήγορη συμπύκνωση φυσικής γλώσσας                                |
| `aggressive` | Caveman + history/tool συνοψιστές                                                                        | Μεγάλες συνεδρίες συνομιλίας                                      |
| `ultra`      | Βοηθοί κλαδέματος Caveman +                                                                              | Ανάκτηση ορίου περιβάλλοντος                                      |
| `rtk`        | RTK                                                                                                      | Έξοδος τερματικού, κελύφους, κατασκευής, δοκιμής και git          |
| `omniglyph`  | OmniGlyph                                                                                                | Context-as-image στο καλώδιο εγγενούς παρόχου                     |
| `stacked`    | Γραμμή σωλήνων. Η προεπιλογή του αιτήματος είναι `session-dedup -> lite`. `rtk -> caveman` είναι opt-in. | Μικτά αρχεία καταγραφής εργαλείων και πρόζα, μέγιστη εξοικονόμηση |

### Προφίλ συμπίεσης OmniGlyph

Ο κινητήρας `omniglyph` (πακέτο `omniglyph`, 1.4.0 +) δέχεται ένα επώνυμο σημασιολογικό προφίλ, που ορίζεται καθολικά μέσω `omniglyph.profile` στις ρυθμίσεις συμπίεσης ή ανά βήμα μέσω της διαμόρφωσης βημάτων της στοιβαγμένης διοχέτευσης:

| Προφίλ        | Σύνορο                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `aggressive`  | Αθέτηση. Η πολιτική των δημοσιευμένων αποδείξεων μέτρησε το σύστημα εικόνων —, τα έγγραφα εργαλείων και το πυκνό ιστορικό |
| `balanced`    | Διατηρεί τη ζωντανή πολιτεία εγγενή, προστατεύει τις τελευταίες 8 στροφές, καταρρέει παλαιότερη κλειστή ιστορία           |
| `coding-safe` | Διατηρεί την εξουσία, τα σχήματα εργαλείων και την έξοδο ζωντανών εργαλείων, προστατεύει τις τελευταίες 12 στροφές        |
| `passthrough` | Διαδρομές χωρίς μετασχηματισμό. ο κινητήρας παραλείπεται                                                                  |

Το προφίλ είναι α** οροφή, όχι πάτωμα** : `mergeCompressionProfileOptions` στο πακέτο αρνείται να αφήσει έναν καλούντα να παρακάμψει, να ανοίξει ξανά μια λωρίδα με απώλειες που το προφίλ έκλεισε, επομένως ένα `preserveSystemPrompt: false` ανά βήμα δεν μπορεί να ενεργοποιήσει ξανά τη συμπίεση συστήματος στο `coding-safe`.

Μετράται σε αυτήν τη βάση κώδικα: `coding-safe` και `balanced` ανεβάζουν `minCompressChars` στο μέγιστο και διατηρούν το σύστημα, τα σχήματα εργαλείων και τα αποτελέσματα των εργαλείων ως εγγενή, έτσι μια περίοδος λειτουργίας που δεν έχει ακόμη συσσωρεύσει ιστορικό σταματά στο `below_min_chars` και ο κινητήρας δεν μετατρέπει τίποτα. Αυτός είναι ο λόγος για τον οποίο η προεπιλογή είναι `aggressive` και όχι το ασφαλέστερο προφίλ.

Το πακέτο επιλύει το δικό του εύρος και προφίλ μοντέλου από τη διαμόρφωση του περιβάλλοντος. OmniRoute δεν αναθέτει ποτέ την απόφαση: ο προσαρμογέας καρφιτσώνει την πύλη μοντέλου στο πιο περιοριστικό εύρος του πακέτου, έτσι οι ρυθμίσεις περιβάλλοντος κεντρικού υπολογιστή μπορούν μόνο να περιορίσουν τη λίστα επιτρεπόμενων, ποτέ να μην τη διευρύνουν πέρα από τις μετρημένες αποδείξεις του OmniRoute.

## Μητρώο κινητήρα

Το μητρώο μένει στο `open-sse/services/compression/engines/registry.ts`. Οι κινητήρες εκθέτουν ένα κοινό συμβόλαιο:

- `id`: σταθερό αναγνωριστικό κινητήρα όπως `caveman` ή `rtk`
- `apply(text, config)`: διαδρομή εκτέλεσης παλαιού τύπου που χρησιμοποιείται από στοιβαγμένους αγωγούς
- `compress(input, config)`: κύρια διαδρομή εκτέλεσης που επιστρέφει στατιστικά + κειμένου
- `getConfigSchema()`: επιστρέφει το σχήμα JSON-Schema της έγκυρης διαμόρφωσης
- `validateConfig(config)`: επιστρέφει `{ valid, errors[] }`

Η εγγραφή χρησιμοποιεί `registerCompressionEngine(engine)` (ή `registerEngine` για προχωρημένες περιπτώσεις), το οποίο καλεί `assertValidEngine()` και `validateConfig(defaultConfig)` πριν αποδεχτεί. Χρησιμοποιήστε `unregisterCompressionEngine(id)` για να αφαιρέσετε έναν κινητήρα κατά το χρόνο λειτουργίας.

`strategySelector.ts` καταγράφει τους ενσωματωμένους κινητήρες πριν από την εκτέλεση της συμπίεσης. Αυτό επιτρέπει την προεπισκόπηση, τη συμπίεση χρόνου εκτέλεσης, τη λειτουργία στοίβαξης, τις δοκιμές και τις μελλοντικές μηχανές να χρησιμοποιούν την ίδια διαδρομή εκτέλεσης.

### συμπίεση περιγραφής MCP (σχετ.)

Ένα ξεχωριστό μητρώο συμπιέζει τα μεταδεδομένα περιγραφής εργαλείου MCP σε επίπεδο μητρώου — δείτε `open-sse/mcp-server/descriptionCompressor.ts` και [MCP-SERVER.md](../frameworks/MCP-SERVER.md). Επαναχρησιμοποιεί τους κανόνες του Caveman, αλλά λειτουργεί σε μεταδεδομένα εργαλείων και όχι σε αιτήματα ωφέλιμων φορτίων.

### Πρόσθετοι ενσωματωμένοι κινητήρες

Πέρα από το Caveman, RTK και LLMLingua-2, το μητρώο αποστέλλει αρκετούς εξειδικευμένους κινητήρες χωρίς απώλειες/δομές (που χρησιμοποιούνται από στοιβαγμένους αγωγούς, την παιδική χαρά και τις δοκιμές):

| Μηχανή            | Ταυτότητα       | Τι κάνει                                                                                                                                                                                              |
| ----------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CCR               | `ccr`           | Content-Compress-Retrieve (H4): αντικαθιστά μεγάλα συνεχόμενα μπλοκ κειμένου με αναφορές με διεύθυνση περιεχομένου, έτσι τα μπλοκ repeated/large αποστέλλονται μία φορά και αναφέρονται στη συνέχεια. |
| κεφαλής           | `headroom`      | SmartCrusher (H3 + N5): πινακοειδής συμπίεση χωρίς απώλειες ομοιογενών ωφέλιμων φορτίων συστοιχίας JSON σε μια στήλη `[N rows]` μορφή.                                                                |
| ιονιστή           | `ionizer`       | Δειγματοληψία σειρών Head/middle/tail για πολύ μεγάλα ομοιογενή μπλοκ, αποθήκευση της διακεκομμένης μέσης ως αναφοράς με διεύθυνση περιεχομένου CCR.                                                  |
| συνεδρία-διαγραφή | `session-dedup` | Απεγγραφή πολλαπλών στροφών με διεύθυνση περιεχομένου (εμπνευσμένο από το TokenMizer): κείμενα που έχουν ήδη εμφανιστεί σε προηγούμενες στροφές της ίδιας συνεδρίας.                                  |

**CCR retrieve-protocol instruction (#8033):** την πρώτη φορά που CCR αντικαθιστά ≥ 1 μπλοκ σε ένα αίτημα, ο κινητήρας επισυνάπτει ένα ενιαίο, αδύναμο μήνυμα `system` (που οδηγεί με τον φρουρό `[CCR protocol]` ) που διδάσκει στον καλούντα τον δείκτη → tool contract: τι σημαίνει ο δείκτης `[CCR retrieve hash=<24hex> chars=N]`, ότι ο κατακερματισμός πρέπει να αντιγραφεί αυτολεξεί (και οι 24 εξαγωνικοί χαρακτήρες — είναι πιθανά λανθασμένα αντίγραφα). Ο δείκτης `[dedup:ref sha=...]` σημαίνει "κοιτάξτε πίσω στην ιστορία", όχι "καλέστε το εργαλείο". Η νότα εγχέεται** μόνο όταν το διαφημιζόμενο `tools[]` του καλούντος αποδείξει ότι μπορεί πραγματικά να φτάσει `omniroute_ccr_retrieve`** (`callerSupportsCcrRetrieve()` σε `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — ένας απλός καλών συμβατός με OpenAI χωρίς αυτό το εργαλείο δεν λαμβάνει ποτέ μια οδηγία να καλέσει κάτι που δεν μπορεί να φτάσει. Η ανικανότητα επιβάλλεται με σάρωση του ιστορικού μηνυμάτων για τον φρουρό πριν από την έγχυση, επομένως τα αιτήματα πολλών στροφών (τα οποία αναπαράγουν προηγούμενα μηνύματα) δεν στοιβάζουν τη σημείωση μία φορά ανά στροφή.

## Αγριάνθρωπος

Η λειτουργία Caveman εστιάζει στη σημασιολογική συμπύκνωση της κανονικής πεζογραφίας:

- διατηρεί μπλοκ κώδικα, URLs, JSON, διαδρομές και δομημένα δεδομένα
- αφαιρεί το υλικό πλήρωσης, αντιστάθμισης κινδύνου, επαναλαμβανόμενου πλαισίου και περίπλοκης συνδετικής φράσεων
- υποστηρίζει πακέτα κανόνων αρχείων με γνώση γλώσσας στο `open-sse/services/compression/rules/`
- παραμένει διαθέσιμο μέσω των λειτουργιών `standard`, `aggressive` και `ultra` παλαιού τύπου

Η επιφάνεια του ταμπλό είναι `Dashboard -> Context & Cache -> Caveman`.

Το Caveman upstream αναφέρει `~75%` λιγότερα διακριτικά εξόδου, `65%` μέση εξοικονόμηση εξόδου σε σημεία αναφοράς με εύρος `22-87%` και εργαλείο συμπίεσης εισόδου `~46%`. OmniRoute χρησιμοποιεί τον αριθμό της πλευράς εισόδου του Caveman κατά την τεκμηρίωση των στοιβαγμένων εξοικονομήσεων prompt/context. Η λειτουργία εξόδου Caveman παραμένει ένα ξεχωριστό χαρακτηριστικό απόκρισης-συμπεριφοράς.

## RTK

Η λειτουργία RTK εστιάζει στην έξοδο εντολών και εργαλείου:

- ανιχνεύει κατηγορίες εξόδου όπως `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, Cargo/Go tests, TypeScript/Vite/Webpack builds, ESLint, npm audit/installs, Docker logs, shell `find`/`grep`, stack traces και γενικά αρχεία καταγραφής
- εφαρμόζει 49 φίλτρα JSON από `open-sse/services/compression/engines/rtk/filters/`
- υποστηρίζει τη γραμμή δηλωτικών τύπων RTK: απογύμνωση ANSI, αντικατάσταση, βραχυκύκλωμα εξόδου αντιστοίχισης, γραμμές strip/keep, περικοπή ανά γραμμή, περικοπή head/tail/max-line και εναλλακτική λύση σε κενό
- υποστηρίζει φίλτρα έργου με πύλη εμπιστοσύνης στο `.rtk/filters.json` και καθολικά φίλτρα στο `DATA_DIR/rtk/filters.json`
- απογυμνώνει ακολουθίες ANSI, θόρυβο προόδου, επαναλαμβανόμενες γραμμές και άχρηστο boilerplate
- Διατηρεί αποτυχίες, προειδοποιήσεις, περιλήψεις, αλλαγμένα αρχεία και ουρά
- μπορεί προαιρετικά να διατηρήσει ανανεωμένη πρωτογενή έξοδο για recovery/debugging μέσω πιστοποιημένων διαδρομών διαχείρισης

Η επιφάνεια του ταμπλό είναι `Dashboard -> Context & Cache -> RTK`.

Λειτουργικές λεπτομέρειες για προσαρμοσμένα φίλτρα, αξιοπιστία, επαλήθευση και ανάκτηση πρωτογενούς παραγωγής ζωντανά στο [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md).

RTK upstream αναφέρει εξοικονόμηση `60-90%` για συμπίεση εντολών-εξόδου. Το παράδειγμά του README δείχνει μια περίοδο λειτουργίας Claude Code 30 λεπτών που μεταβαίνει από `~118,000` tokens σε `~23,900` ή `79.7%` αποθηκεύονται.

## LLMLingua-2 (Σημασιολογικό κλάδεμα)

Η λειτουργία LLMLingua-2 εκτελεί** σημασιολογικό συμβολικό κλάδεμα** στην πρόζα χρησιμοποιώντας έναν μικρό ταξινομητή διακριτικών ONNX, που συμπληρώνει τους κινητήρες Caveman και RTK που βασίζονται σε κανόνες:

- Συμπιέζει την πρόζα μόνο σε μη συστημικά μηνύματα. περιφραγμένα μπλοκ κώδικα και άλλες διατηρημένες κατασκευές δεν αλλοιώνονται ποτέ
- εκτελεί το backend `@atjsh/llmlingua-2` (ONNX μέσω `@huggingface/transformers`) σε ένα νήμα εργαζομένου, επομένως η εξαγωγή συμπερασμάτων μοντέλου δεν αποκλείει ποτέ τον βρόχο συμβάντος αιτήματος
- είναι** στοιβαζόμενο** (`stackPriority` 35): σε μια στοιβαγμένη διοχέτευση τρέχει μετά από τις δομικές μηχανές (CCR, session-dedup, headroom, Caveman) αλλά πριν από `ultra`, αφού το σημασιολογικό κλάδεμα είναι πιο αποτελεσματικό σε ήδη δομικά συμπιεσμένο κείμενο — π.χ. `rtk -> caveman -> llmlingua`
- **fail-ανοίγει σε οποιοδήποτε σφάλμα** (Λείπουν προαιρετικές καταβολές, αναπαραγωγή εργαζομένων, φόρτωση μοντέλου, συμπέρασμα ή χρονικό όριο λήξης) → το αρχικό κείμενο επιστρέφεται αμετάβλητο, ποτέ δεν υπάρχει σφάλμα

Θέση κινητήρα: `open-sse/services/compression/engines/llmlingua/`. Η επιφάνεια του ταμπλό είναι `Dashboard -> Context & Cache -> LLMLingua`.

### Μοντέλα

Το προεπιλεγμένο μοντέλο είναι**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~ 57 MB, γρήγορα). Μεγαλύτερη ακρίβεια** Βάση BERT** Το μοντέλο (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) είναι διαθέσιμο μέσω του πεδίου διαμόρφωσης κινητήρα `model`. `@huggingface/transformers` κατεβάζει αργά το επιλεγμένο μοντέλο από το HuggingFace Hub στο `${DATA_DIR}/models/llmlingua` την πρώτη κλήση (`modelStore.ts`). μια παράκαμψη ρύθμισης παραμέτρων `modelPath` την υποδεικνύει σε ένα τοπικό αντίγραφο (εγκαταστάσεις εκτός σύνδεσης / με κενό αέρα).

### Προαιρετικές εξαρτήσεις και εγκατάσταση κατ' απαίτηση

Η κλαδευόμενη στοίβα χρόνου εκτέλεσης LLMLingua είναι** προαιρετικός** . Δύο πακέτα δηλώνονται ως `optionalDependencies` στο `package.json` και διατηρούνται** εξωτερικός** από την κατασκευή παραγωγής (`scripts/build/prepublish.ts` δεν τα ομαδοποιεί):

| Πακέτο               | Έκδοση (καρφίτσα) | Σημειώσεις                                          |
| -------------------- | ----------------- | --------------------------------------------------- |
| `@atjsh/llmlingua-2` | `2.0.5`           | Πακέτο εισόδου? δηλώνει τους άλλους ως συνομήλικους |

```bash
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

Η αφαίρεση `@tensorflow/tfjs` TinyBERT 2.0.4 +) εξαλείφει transformers.js προηγουμένως κυρίαρχο MB~~MB — +

Ανά περιβάλλον:

- **Dev / `npm install`** — εγκαθίσταται αυτόματα εκτός και αν περάσατε `--omit=optional` (ή `--no-optional`). Δεν χρειάζεται καμία ενέργεια.
- **Παγκόσμιο npm (`npm i -g omniroute`) / αυτόνομο** — εκτελέστε την παραπάνω εντολή εγκατάστασης μέσα στον κατάλογο του εγκατεστημένου πακέτου ή επανεγκαταστήστε χωρίς να παραλείψετε τα προαιρετικά βάθη.
- **Docker** — προσθέστε την εντολή εγκατάστασης σε ένα προκύπτον επίπεδο εικόνας. η δημοσιευμένη εικόνα είναι λεπτή από το σχεδιασμό.
- **VPS (PM2)** — εγκαταστήστε στο `node_modules` της εφαρμογής και, στη συνέχεια, επανεκκινήστε τη διαδικασία, ώστε ο εργαζόμενος να ανιχνεύσει ξανά την πύλη.

Ανίκανος, αστοχία-μαλακός όταν τα βάθη απουσιάζουν.

**Βεβαιωθείτε ότι είναι ενεργό:** Με επιλεγμένο LLMLingua, η πραγματική πρόζα συρρικνώνεται (ο κινητήρας σταματά να ανοίγει με αστοχία) και το πρώτο αίτημα ενεργοποιεί τη λήψη του μοντέλου στο `${DATA_DIR}/models/llmlingua`. Η πύλη ανιχνεύει σκόπιμα μόνο `@atjsh/llmlingua-2` — οι άλλες ομότιμες είναι μόνο για ESM και `require.resolve` ρίχνει πάνω τους ακόμα και όταν υπάρχει — έτσι ώστε ο εργαζόμενος να εξακολουθεί να αποτυγχάνει-ανοίγει εάν κάποιος ομότιμος λείπει πραγματικά τη στιγμή `import()`.

## Στοιβαγμένοι αγωγοί

Η λειτουργία στοίβαξης εκτελεί τα βήματα της διοχέτευσης με τη σειρά. Η προεπιλογή είναι:

```txt
rtk -> caveman
```

Χρησιμοποιήστε το για συνεδρίες παράγοντα κωδικοποίησης όπου μια προτροπή συνδυάζει την έξοδο εντολών με ανθρώπινη ή βοηθητική πεζογραφία. RTK μειώνει πρώτα τα θορυβώδη αρχεία καταγραφής εργαλείων και μετά ο Caveman συμπιέζει την υπόλοιπη φυσική γλώσσα.

Τα βήματα του αγωγού διαμορφώνονται με `stackedPipeline` σε ρυθμίσεις συμπίεσης ή μέσω συνδυασμών συμπίεσης.

Όταν και οι δύο κινητήρες μειώνουν το ίδιο επιλέξιμο ωφέλιμο φορτίο, εξοικονομείται:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## Φίλτρο δέντρου προσβασιμότητας MCP

Το έξυπνο φίλτρο προσβασιμότητας-δέντρου MCP είναι ένα επίπεδο συμπίεσης μετά την εκτέλεση που εκτελείται σε MCP** αποτελέσματα εργαλείου** , όχι σε προτροπές ή περιβάλλον. Στοχεύει στο αναλυτικό δέντρο προσβασιμότητας και στα στιγμιότυπα του προγράμματος περιήγησης που επιστρέφονται από εργαλεία όπως Playwright, χρήση υπολογιστή και διακομιστές MCP αυτοματισμού προγράμματος περιήγησης.

### Τι κάνει

1. **Απογύμνωση θορύβου** — αφαιρεί κενές καταχωρήσεις generic/text (`- generic:`, `- text: ""`)
2. **Κατάρρευση αδελφού** — όταν ≥ `collapseThreshold` (προεπιλογή 30) οι διαδοχικές γραμμές είναι δομικές επαναλήψεις, τις συμπτύσσει στις πρώτες γραμμές `collapseKeepHead` (προεπιλογή 10) + μια σύνοψη καταμέτρησης + τις τελευταίες `collapseKeepTail` (προεπιλογή 5) γραμμές
3. **Συντήρηση αναφ** Οι αγκυρώσεις — `[ref=eXX]` που απαιτούνται από Playwright/computer-use δεν αγγίζονται ποτέ
4. **Σκληρή περικοπή** — εάν το κείμενο μετά τη σύμπτυξη εξακολουθεί να υπερβαίνει `maxTextChars` (προεπιλογή 50.000), περικόπτεται με μια υπόδειξη πλοήγησης, ώστε ο πράκτορας να μπορεί να συνεχίσει να εργάζεται

### Θέση κινητήρα

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### Διαμόρφωση

Ελέγχεται από `compression.mcpAccessibility` σε καθολικές ρυθμίσεις (migration 056). Προεπιλεγμένη διαμόρφωση:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

Το φίλτρο εφαρμόζεται μόνο σε ωφέλιμα φορτία αποτελεσμάτων εργαλείων των οποίων `type` είναι `"text"` και το μήκος τους υπερβαίνει `minLengthToProcess`. Δεν επηρεάζει την άμεση συμπίεση ή την αίτηση ωφέλιμου φορτίου.

### Αναμενόμενη εξοικονόμηση

60–80% στα αποτελέσματα του εργαλείου στιγμιότυπου προγράμματος περιήγησης, ανάλογα με την πολυπλοκότητα της σελίδας. Ο αλγόριθμος σύμπτυξης είναι O(n) στον αριθμό γραμμών και προσθέτει αμελητέο λανθάνοντα χρόνο.

### Αυτό το φίλτρο έναντι των παραπάνω μηχανών συμπίεσης

| Αποψη       | Caveman / RTK / Στοιβαγμένο   | φίλτρο προσβασιμότητας MCP             |
| ----------- | ----------------------------- | -------------------------------------- |
| Στόχος      | Προτροπές αιτήματος / πλαίσιο | Αποτελέσματα εργαλείου MCP             |
| Σκανδάλη    | Ρύθμιση λειτουργίας συμπίεσης | `compression.mcpAccessibility.enabled` |
| Εκταση      | Όλα τα μηνύματα SSE           | Αποτελέσματα εργαλείου μόνο            |
| Σφ. άγκυρες | N/A                           | Διατηρούνται άνευ όρων                 |

## Προαπαιτούμενα / οδηγός χειριστή (CCR & session-dedup)

CCR (`ccr`) και `session-dedup` αντικαθιστούν ή διαγράφουν το κείμενο και αφήνουν a** σημάδι** πίσω. Αυτή η ενότητα είναι η αναφορά χειριστή για την καλωδίωση ενός προγράμματος-πελάτη, την ανάγνωση των δύο δεικτών και την ανάκτηση ή τη διάγνωση του διαγραμμένου περιεχομένου. Η μηχανική κάθε κινητήρα καλύπτεται παραπάνω. αυτό είναι το επίπεδο "πώς το τρέχω".

### Μεταφορές & τερματικά σημεία

Ο διακομιστής MCP που εκθέτει τα εργαλεία CCR μπορεί να προσεγγιστεί με τρεις τρόπους. Η προεπιλεγμένη βάση URL είναι `http://localhost:20128` (`OMNIROUTE_BASE_URL`):

| Μεταφορά                              | URL / εντολή                            | Σημειώσεις                                                                                                                                                            |
| ------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Streamable HTTP (πελάτης, συνιστάται) | `http://localhost:20128/api/mcp/stream` | Στο τελικό σημείο συνομιλούν οι τρέχοντες πελάτες MCP.                                                                                                                |
| Legacy SSE singleton                  | `http://localhost:20128/api/mcp/sse`    | Παλαιότερα μονόκλινα μεταφορά. Το** κλείνει** Συνεδρίες με δυνατότητα ροής· χρησιμοποιήστε προγράμματα-πελάτες `streamable-http` ενάντια `/api/mcp/stream`, όχι αυτό. |
| stdio                                 | `omniroute --mcp`                       | Για τη διαμόρφωση IDE MCP που δημιουργεί τη διαδικασία. Δεν υπάρχει σημαία `--dev`. `omniroute --mcp` είναι το σημείο εισόδου του stdio.                              |

### Επίπεδα αποθήκευσης (τι επιβιώνει από την επανεκκίνηση)

CCR είναι α** δύο επιπέδων** αποθήκευση, όχι μόνο στη μνήμη:

- **Ζεστό επίπεδο μνήμης** — ανά μπλοκ καπάκι 2 MiB, ανά κύριο 16 MiB, παγκόσμιο 64 MiB. Οι καταχωρήσεις από προεπιλογή είναι 24 h TTL (μέγιστο 7 ημέρες). Η πλήρης ανάκτηση MCP από τη μνήμη περιορίζεται στα 256 KiB. οτιδήποτε μεγαλύτερο είναι ακόμα προσβάσιμο μέσω των λειτουργιών εμβέλειας / grep.
- **Ανθεκτική βαθμίδα SQLite** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, ενεργοποιημένο από προεπιλογή) — υποστηρίζει το επίπεδο της μνήμης, έτσι ώστε ένα μπλοκ να επιβιώνει από την εξώθηση LRU, μια επανεκκίνηση ή μια ανάκτηση προσγείωσης σε άλλη παρουσία. Η σειρά διατηρεί το TTL του μπλοκ, επομένως ένα μπλοκ πέρα από TTL του θα εξαφανιστεί και από τα δύο επίπεδα.

Τρεις προφυλακτήρες διατηρούν την ανθεκτική βαθμίδα οριοθετημένη — ένα μπλοκ παραμένει μνήμη-μόνο όταν:

1. το μπλοκ τελείωσε** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. ο χρόνος εκτέλεσης είναι χρόνος εκτέλεσης στο σύννεφο (χωρίς τοπικό δίσκο).
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

Επομένως, το "το μπλοκ εξαφανίστηκε" δεν είναι μια γενική ιστορία επανεκκίνησης: ένα μπλοκ sub-512 KB σε έναν τοπικό χρόνο εκτέλεσης χωρίς σύννεφο επιβιώνει από την επανεκκίνηση μέσω του ανθεκτικού επιπέδου έως ότου εξαντληθεί το TTL του. Δείτε [Περιβαλλοντική αναφορά](../reference/ENVIRONMENT.md) για τη μεταβλητή.

### Οι δύο μαρκαδόροι

| Σημάδι                                | Εννοια                                                                                                                                                           | Τι πρέπει να κάνει το μοντέλο                                                                                                                                                                                                              |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `[CCR retrieve hash=<24hex> chars=N]` | Ένα μεγάλο μπλοκ αποθηκεύτηκε με διεύθυνση περιεχομένου.                                                                                                         | Καλέστε `omniroute_ccr_retrieve` με το** Κατακερματισμός 24 εξαγωνικών αντιγράφων αυτολεξεί** για να πάρετε πίσω το αρχικό κείμενο.                                                                                                        |
| `[dedup:ref sha=…]`                   | `session-dedup` διαλειμμένο κείμενο που έχει ήδη αποσταλεί σε προηγούμενη στροφή της ίδιας συνεδρίας. Αυτό είναι ένα** σκόπιμη αναδρομή** , όχι απώλεια ή λάθος. | Κάνω** δεν** καλέστε οποιοδήποτε εργαλείο και κάντε** δεν** προσπαθήστε να το «ανακατασκευάσετε». Η ανασκόπηση του `[dedup:ref]` είναι μια σκόπιμη απόφαση πρωτοκόλλου — δεν υπάρχει ανακατασκευή πριν από την αποστολή. Αντιμετωπίστε το ως "αυτό ακριβώς το κείμενο ήταν ήδη στο καλώδιο νωρίτερα σε αυτήν τη συνεδρία."

### Προϋποθέσεις πελάτη

- **Κλειδί (stdio):** ένας καλών stdio δεν φέρει ταυτότητα ανά αίτημα, επομένως επαληθεύεται με `OMNIROUTE_API_KEY` (ορίζεται στο `env` του διακομιστή MCP ). Χωρίς αυτό ο καλών είναι ανώνυμος και τα εργαλεία που απαιτούν εντολέα ενδέχεται να υποβαθμιστούν.
- **`tools[]` είναι η προϋπόθεση της ένεσης.** Η οδηγία ανάκτησης πρωτοκόλλου CCR (#8033) εγχέεται** μόνο** όταν το διαφημιζόμενο `tools[]` του αιτήματος αποδεικνύει ότι ο πελάτης μπορεί πραγματικά να φτάσει `omniroute_ccr_retrieve`. Η αντιστοίχιση είναι μια αντιστοίχιση τελικού τμήματος που οριοθετείται από ένα διαχωριστικό (`__`, `.`, `/`, `:`) — ποτέ δεν είναι μια γυμνή υποσυμβολοσειρά — επομένως ένα όνομα με χώρο ονομάτων όπως `mcp__gateway__omniroute_ccr_retrieve` εξακολουθεί να μετράει. Ένα απόν ή μη ταιριαστό `tools[]` σημαίνει ότι η εντολή _δεν_ εγχέεται, από το σχεδιασμό.
- **`codemode:false` ( πελάτες OpenCode ).** OpenCode ορίζει από προεπιλογή τη λειτουργία κώδικα, η οποία διαφημίζει μόνο τα εγγενή εργαλεία του στο μοντέλο και** δεν το κάνει** βάλτε τα εργαλεία MCP στην εγγενή λίστα `tools[]`. Ρυθμίστε `codemode: false` στην καταχώρηση διακομιστή MCP ώστε να διαφημίζονται τα εργαλεία `omniroute_ccr_*`. Αυτό είναι ένα** πελάτης** ρύθμιση, όχι ένα OmniRoute. Δεν λαμβάνει ακόμη την ένεση της εντολής CCR : OpenCode ονομάζει ένα εργαλείο `<server>_<tool>`, έτσι ένας διακομιστής που ονομάζεται `omniroute` εκθέτει `omniroute_omniroute_ccr_retrieve` και `_` δεν είναι ένα από τα αντιστοιχισμένα διαχωριστικά.
- **Διευθυντές.** Η αποθήκευση και η ανάκτηση απομονώνονται ανά επικυρωμένη αρχή (ανά κλειδί API ). Ένα κλειδί βλέπει μόνο τα δικά του μπλοκ.

### Πεδίο εφαρμογής ανά εργαλείο

Η επιβολή εύρους είναι πάντα ενεργοποιημένη για καλούντες HTTP/SSE στενού εύρους. Τα εργαλεία `omniroute_` CCR απαιτούν:

| Εργαλείο                 | Εκταση              |
| ------------------------ | ------------------- |
| `omniroute_ccr_store`    | `write:compression` |
| `omniroute_ccr_delete`   | `write:compression` |
| `omniroute_ccr_retrieve` | `read:compression`  |
| `omniroute_ccr_inspect`  | `read:compression`  |
| `omniroute_ccr_list`     | `read:compression`  |
| `omniroute_ccr_stats`    | `read:compression`  |

Ένα εύρος που λείπει επιστρέφει ένα** Αποτέλεσμα σφάλματος εργαλείου MCP** (`isError: true`, όχι HTTP 403 — το `403 LOCAL_ONLY` είναι το ξεχωριστό loopback route-guard auth): `Error: Insufficient MCP scopes for <tool>. Missing: <scope>.` Ένα ελάχιστο τηλεχειριστήριο μπορεί να κρατήσει `mcp:connect` (εξουσιοδοτεί το `/api/mcp/` μόνο τοπικό carve-out) συν το συγκεκριμένο εύρος read/write που χρειάζεται.

### Όρια ανάκτησης & σελιδοποίηση

Τα αποτελέσματα του κειμένου του εργαλείου MCP περικόπτονται γύρω από `mcpAccessibility.maxTextChars` (προεπιλογή `50000`). Η ανάκτηση `full` ενός μπλοκ περιορίζεται στα 256 KiB —** δεν υπάρχει απεριόριστη πλήρη ανάκτηση** . Όταν το `chars=N` ενός μπλοκ είναι μεγάλο, σελιδοποιήστε το αντί να τραβήξετε ολόκληρο το θέμα:

- Εμπειρικός κανόνας:**`chars > 40000` → χρησιμοποιήστε ένα `mode`** , ποτέ ένα γυμνό γεμάτο.
- `mode:"grep"` — regex `pattern` αντιστοίχιση γραμμή προς γραμμή, έως και 1.000 αντίστοιχες γραμμές (`unique: true` σταγόνες επαναλαμβάνεται), φθηνότερο για "βρες τη μία γραμμή που χρειάζομαι".
- `mode:"lines"` — ένα εύρος γραμμής με 1 ευρετήριο. χρειάζεται και `start` και `end`.
- `mode:"head"` / `mode:"tail"` — first/last `n` γραμμές.
- Η γραμμή `mode:"stats"` —, ο χαρακτήρας και τα byte μετρούν χωρίς το σώμα.

Χρησιμοποιήστε `mode:"lines"` με `start`/`end` για να περπατήσετε ένα μεγάλο τετράγωνο σε σελίδες αντί να ζητήσετε το όλο θέμα ταυτόχρονα.

### Ονομασία εργαλείου

Το εργαλείο ανάκτησης ονομάζεται επί του παρόντος `omniroute_ccr_retrieve` (το πρόθεμα `omniroute_` είναι μια χρονολογημένη λύση για συγκρούσεις ονομάτων μεταξύ διακομιστών). Ένα καθαρότερο όνομα εργαλείου με περιορισμένο επίθημα και μια επιδιόρθωση για MCP JSON αποτελέσματα περικομμένης στη μέση της συμβολοσειράς παρακολουθούνται ως επακόλουθα. αυτή η σελίδα τεκμηριώνει μόνο την τρέχουσα συμπεριφορά αποστολής.

### Κύκλος ζωής συνεδρίας

Οι περίοδοι σύνδεσης Streamable-HTTP αδρανούν και ο διακομιστής τις αποκομίζει. το παράθυρο αδράνειας είναι η σταθερά `MCP_SESSION_IDLE_MS` (αναφέρεται με το όνομα, όχι μια τιμή με σκληρό κώδικα, επομένως αυτή η σελίδα δεν μετατοπίζεται όταν αλλάζει). Το σύμπτωμα μιας συνεδρίας αδράνειας είναι μια HTTP 404 με `Unknown Mcp-Session-Id` — η λύση είναι η επανασύνδεση ή επανεκκίνηση της συνεδρίας,** δεν** για να περιστρέψετε ένα κλειδί, να αλλάξετε ένα εύρος ή να μετονομάσετε ένα εργαλείο.

## Πεδίο εφαρμογής & εξαιρέσεις

**Οι ενσωματώσεις δεν συμπιέζονται ποτέ.** `open-sse/handlers/embeddings.ts` δεν καλεί ποτέ κανέναν κινητήρα συμπίεσης — τα σώματα request/response περνούν κατευθείαν στον εκτελεστή ανέγγιχτα. Αυτό είναι δομικό σήμερα (οι ενσωματώσεις και οι ολοκληρώσεις συνομιλιών είναι ασύνδετοι χειριστές), δεν είναι έλεγχος χρόνου εκτέλεσης, αλλά σημαίνει ότι η ανησυχία διανυσματικής παραμόρφωσης στο #8034 δεν έχει επιφάνεια έκθεσης στη διαδρομή ενσωματώσεων.

**Φίλτρο αποκλεισμού Per-model/endpoint (#8034).** Για ολοκλήρωση συνομιλίας, ένας χειριστής μπορεί να ονομάσει αναγνωριστικά μοντέλων / στόχους `provider/model` που δεν πρέπει ποτέ να συμπιέζονται — προστατευτικό κιγκλίδωμα χρήσιμο εάν η συμπίεση συνδεθεί πιο κοντά σε μια γειτονική διαδρομή ενσωματώσεων αργότερα και γενικά χρήσιμο για οποιοδήποτε μοντέλο του οποίου το ακριβές ερώτημα byte-for-byte έχει σημασία (deterministic evals, prefixessen, κ.λπ.).

- Πεδίο ρυθμίσεων: `exclusions?: string[]` στην καθολική διαμόρφωση συμπίεσης (`GET`/`PUT /api/settings/compression`), συνεχίστηκε μέσω του υπάρχοντος χώρου ονομάτων συμπίεσης `key_value` (`src/lib/db/compression.ts`) — χωρίς νέο πίνακα.
- Καρτέλα πίνακα ελέγχου:** Ταμπλό → Compression → Εξαιρέσεις** (`/dashboard/compression/exclusions`).
- Σύνταξη προτύπου: `*` είναι ο μόνος μπαλαντέρ. Κάθε άλλος μεταχαρακτήρας regex σε ένα μοτίβο έχει διαφύγει πριν από την αντιστοίχιση, επομένως `gpt-5.6` ταιριάζει μόνο με την κυριολεκτική συμβολοσειρά, ποτέ `gpt-5x6` (ReDoS-ασφαλής, περιορισμένος, χωρίς ένθετους ποσοτικούς δείκτες). Τα μοτίβα ταιριάζουν χωρίς διάκριση πεζών-κεφαλαίων τόσο με το γυμνό αναγνωριστικό μοντέλου όσο και με το σύνθετο `provider/model` — `gpt-5-6`, `openai/gpt-5-6` και `openai/*` όλα λειτουργούν και μόνο `*` εξαιρεί κάθε μοντέλο.
- Ταίριασμα: `isCompressionExcluded()` / `normalizeCompressionExclusions()` σε `open-sse/services/compression/exclusions.ts`. `chatCore.ts` ελέγχει τον αποκλεισμένο στόχο αμέσως μετά την επίλυση των ρυθμίσεων συμπίεσης,** πριν λειτουργήσει οποιοσδήποτε κινητήρας** , και αντιμετωπίζει μια αντιστοίχιση ακριβώς όπως η συμπίεση είναι καθολικά απενεργοποιημένη — το σώμα του αιτήματος είναι αποδεδειγμένα ταυτόσημο με byte. Η παράβλεψη καταγράφεται μέσω `writeCompressionSkip(..., "excluded")` για ορατότητα των αναλυτικών στοιχείων.
- Προεπιλογή ( λίστα empty/absent ): ίδια με την #8034 συμπεριφορά — τίποτα δεν αποκλείεται.

## Γνωστοί περιορισμοί

- **LLMLingua-2 (SLM) απαιτεί προαιρετικά βάθη που βρίσκονται μαζί.** Ο εργάτης εκτελείται σε μια έκδοση παραγωγής μόνο όταν οι ομότιμοι `@atjsh/llmlingua-2` + συγκεντρώνονται στο `dist/node_modules` (βλ. `scripts/build/colocateOptionals.mjs`, #4286). Χωρίς αυτά ο κινητήρας αστοχεί-ανοίγει (επιστρέφει το αρχικό κείμενο). Η ανάλυση του εργαζόμενου δεν εξαρτάται πλέον από `import.meta.url` (πεθαίνει στο αυτόνομο πακέτο) — αγκυρώνεται στο χρόνο εκτέλεσης cwd / `argv[1]`.
- **Τα πακέτα γλώσσας Caveman `de` / `fr` / `ja` είναι μερικά.** Αποστέλλουν κανόνες `context` + `filler` + `structural` αλλά όχι πακέτα `dedup` / `ultra`, επομένως η ένταση `ultra` δεν είναι ισχυρότερη από `full` για αυτές τις γλώσσες (χρησιμοποιούν μόνο τους δικούς τους κανόνες — δεν υπάρχει σιωπηλή επιστροφή στους αγγλικούς κανόνες `dedup`/`ultra`, που θα παραβίαζαν το ξένο κείμενο). `en` / `es` / `id` / `pt-BR` έχουν ολοκληρωθεί. Οι συνεισφορές του `dedup.json` + `ultra.json` για τα επιμέρους πακέτα είναι ευπρόσδεκτες.
- **Η στοιβαγμένη τηλεμετρία παραθέτει μόνο τους κινητήρες που συμπιέζονται.** Ένα βήμα στοίβαξης αγωγού του οποίου ο κινητήρας λειτούργησε αλλά παρήγαγε 0 % εξοικονόμηση αποφέρει `stats:null` και έτσι δεν εμφανίζεται στο `engineBreakdown` — και δεν διακρίνεται από ένα βήμα που παραλείφθηκε. Η διάκριση του "τρέξιμο, 0 %" από το "παράβλεψη" θα απαιτούσε αλλαγή του μοντέλου ανάλυσης και αναβάλλεται.
