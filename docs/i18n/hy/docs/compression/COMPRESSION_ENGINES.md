OmniRoute սեղմումը կառուցված է շարժիչի պայմանագրերի շուրջ: Ռեժիմը կարող է ուղղակիորեն գործարկել մեկ շարժիչ (`caveman` կամ `rtk`) կամ դետերմինիստական կուտակված խողովակաշար, որը գործարկում է մի քանի շարժիչներ ըստ հերթականության:

## Ռեժիմներ

| Ռեժիմ        | Շարժիչի ուղին                                                                           | Նախատեսված մուտքագրում                                                 |
| ------------ | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `off`        | ոչ մեկը                                                                                 | Ճշգրիտ արագ պահպանում                                                  |
| `lite`       | Caveman lite օգնականներ                                                                 | Ցածր ռիսկի, մշտապես գործող մաքրում                                     |
| `standard`   | Քարանձավային մարդ                                                                       | Բնական լեզվի արագ խտացում                                              |
| `aggressive` | Caveman + history/tool ամփոփիչներ                                                       | Երկար զրույցի նիստեր                                                   |
| `ultra`      | Caveman + էտման օգնականներ                                                              | Համատեքստի սահմանաչափի վերականգնում                                    |
| `rtk`        | RTK                                                                                     | Տերմինալ, կեղև, կառուցում, փորձարկում և git ելք                        |
| `omniglyph`  | OmniGlyph                                                                               | Համատեքստ՝ որպես պատկեր մայրենի մատակարարի հաղորդալարի վրա             |
| `stacked`    | Խողովակաշար. Հարցման կանխադրվածը `session-dedup -> lite` է: `rtk -> caveman` միացված է: | Խառը գործիքների տեղեկամատյաններ և արձակ, առավելագույն խնայողություններ |

### OmniGlyph սեղմման պրոֆիլներ

`omniglyph` շարժիչը (փաթեթ `omniglyph`, 1.4.0 +) ընդունում է անվանված իմաստային պրոֆիլը, որը սահմանվում է գլոբալ կերպով `omniglyph.profile` միջոցով սեղմման կարգավորումներում կամ յուրաքանչյուր քայլի միջոցով կուտակված խողովակաշարի փուլային կոնֆիգուրացիայի միջոցով.

| Անձնագիր      | Սահման                                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `aggressive`  | Կանխադրված: Հրապարակված անդորրագրերի քաղաքականությունը չափում էր — պատկերների համակարգը, գործիքների փաստաթղթերը և խիտ պատմությունը |
| `balanced`    | Պահում է կենդանի պետական բնիկ, պաշտպանում է վերջին 8 շրջադարձերը, փլուզում է ավելի հին փակ պատմությունը                            |
| `coding-safe` | Պահպանում է հեղինակությունը, գործիքների սխեմաները և կենդանի գործիքի ելքը, պաշտպանում է վերջին 12 շրջադարձերը                       |
| `passthrough` | Երթուղիներ առանց վերափոխման; շարժիչը բաց է թողնվել                                                                                 |

Պրոֆիլը ա** առաստաղ, ոչ հատակ** Փաթեթում `mergeCompressionProfileOptions` հրաժարվում է թույլ տալ զանգահարողին վերաբացել կորցրած գիծը, որի պրոֆիլը փակ է, ուստի յուրաքանչյուր քայլի `preserveSystemPrompt: false` չի կարող նորից միացնել համակարգի սեղմումը `coding-safe` ներքո:

`balanced` այս `coding-safe` `below_min_chars` վրա `minCompressChars` Ահա թե ինչու կանխադրվածը `aggressive` է, քան ամենաանվտանգ պրոֆիլը:

Փաթեթը լուծում է իր մոդելի շրջանակը և պրոֆիլը իր միջավայրի կոնֆիգուրացիայից: OmniRoute երբեք չի պատվիրում որոշումը. ադապտերը ամրացնում է մոդելի դարպասը փաթեթի առավել սահմանափակ շրջանակին, այնպես որ հյուրընկալող միջավայրի կարգավորումները կարող են միայն նեղացնել թույլտվությունների ցանկը և երբեք այն չընդլայնել OmniRoute ի չափված անդորրագրերից:

## Շարժիչի գրանցամատյան

Գրանցամատյանը ապրում է `open-sse/services/compression/engines/registry.ts` ում: Շարժիչները բացահայտում են ընդհանուր պայմանագիրը.

- `id`. կայուն շարժիչի id, ինչպիսիք են `caveman` կամ `rtk`
- `apply(text, config)`. ժառանգության կատարման ուղին, որն օգտագործվում է կուտակված խողովակաշարերի կողմից
- `compress(input, config)`. կատարման առաջնային ուղին վերադարձնում է տեքստը + վիճակագրությունը
- `getConfigSchema()`. վերադարձնում է վավեր կազմաձևի JSON-Schema-ի ձևը
- `validateConfig(config)`: վերադարձնում է `{ valid, errors[] }`

Գրանցումն օգտագործում է `registerCompressionEngine(engine)` (կամ `registerEngine` առաջադեմ դեպքերի համար), որն ընդունելուց առաջ կանչում է `assertValidEngine()` և `validateConfig(defaultConfig)` : Օգտագործեք `unregisterCompressionEngine(id)` շարժիչը գործարկման ժամանակ հեռացնելու համար:

`strategySelector.ts` գրանցում է ներկառուցված շարժիչները մինչև սեղմման գործարկումը: Սա թույլ է տալիս նախադիտումը, գործարկման ժամանակի սեղմումը, կուտակված ռեժիմը, թեստերը և ապագա շարժիչները օգտագործել նույն կատարման ուղին:

### MCP նկարագրության սեղմում (կապված)

Առանձին ռեեստրը սեղմում է MCP գործիքի նկարագրության մետատվյալները ռեեստրի մակարդակի — ում, տես `open-sse/mcp-server/descriptionCompressor.ts` և [MCP-SERVER.md](../frameworks/MCP-SERVER.md) : Այն նորից օգտագործում է Caveman-ի կանոնները, բայց գործում է գործիքի մետատվյալների վրա, այլ ոչ թե վճարովի բեռներ պահանջելու:

### Լրացուցիչ ներկառուցված շարժիչներ

Caveman-ից, RTK և LLMLingua-2 այն կողմ, գրանցամատյանը առաքում է մի քանի մասնագիտացված անկորուստ/կառուցվածքային շարժիչներ (օգտագործվում են կուտակված խողովակաշարերի, խաղահրապարակի և թեստերի կողմից).

| Շարժիչ      | ID              | Ինչ է դա անում                                                                                                                                                                                                |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CCR         | `ccr`           | Content-Compress-Retrieve (H4). փոխարինում է մեծ հարակից տեքստային բլոկները բովանդակությամբ հասցեագրված հղումներով, այնպես որ repeated/large բլոկները ուղարկվում են մեկ անգամ և այնուհետև հղումներ կատարվում: |
| գլխի սենյակ | `headroom`      | SmartCrusher (H3 + N5). համասեռ JSON-զանգվածի օգտակար բեռների առանց կորուստների աղյուսակային խտացում սյունաձև `[N rows]` ձևի:                                                                                 |
| իոնացնող    | `ionizer`       | Head/middle/tail տողերի նմուշառում շատ մեծ միատարր բլոկների համար՝ պահպանելով վերացած միջնամասը՝ որպես CCR բովանդակության հասցեագրված հղում:                                                                  |
| նիստը-հանել | `session-dedup` | Բովանդակության հասցեագրված խաչաձև շրջադարձային կրկնօրինակում (TokenMizer-ի ոգեշնչված). Էլիդների տեքստն արդեն տեսել է նույն նստաշրջանի ավելի վաղ փուլերում:                                                    |

**CCR retrieve-protocol հրահանգ (#8033):** առաջին անգամ, երբ CCR փոխարինում է ≥ 1 բլոկը հարցումով, շարժիչը ներկայացնում է մեկ, անզոր `system` հաղորդագրություն (առաջինը `[CCR protocol]` պահակ) — `[dedup:ref sha=...]` զանգահարողին սովորեցնում է մարկեր → գործիքի պայմանագիրը. `[CCR retrieve hash=<24hex> chars=N]` մարկերը նշանակում է «հետ նայել պատմությանը», այլ ոչ թե «զանգել գործիքը»: Նոտան ներարկված է** միայն այն ժամանակ, երբ զանգահարողի գովազդած `tools[]` ապացուցում է, որ այն իրականում կարող է հասնել `omniroute_ccr_retrieve`** (`callerSupportsCcrRetrieve()` in `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — պարզ OpenAI-ի հետ համատեղելի զանգահարողն առանց այդ գործիքի երբեք հրահանգ չի ստանում զանգահարել մի բան, որին չի կարող հասնել: Idempotency-ն ուժի մեջ է մտնում՝ սկանավորելով հաղորդագրությունների պատմությունը պահակախմբի համար նախքան ներարկումը, այնպես որ մի քանի պտույտների հարցումները (որոնք վերարտադրում են նախորդ հաղորդագրությունները) չեն դնում գրառումը մեկ անգամ:

## Քարանձավային մարդ

Caveman ռեժիմը կենտրոնանում է նորմալ արձակի իմաստային խտացման վրա.

- պահպանում է կոդերի բլոկները, URLs, JSON, ուղիները և կառուցվածքային տվյալները
- հեռացնում է լցոնիչը, հեջավորումը, կրկնվող համատեքստը և բառակապակցություն կապակցող արտահայտությունները
- աջակցում է `open-sse/services/compression/rules/` ում լեզվի իմացությամբ ֆայլերի կանոնների փաթեթները
- հասանելի է մնում ժառանգական `standard`, `aggressive` և `ultra` ռեժիմների միջոցով

Վահանակի մակերեսը `Dashboard -> Context & Cache -> Caveman` է:

Caveman-ը հաղորդում է `~75%` ավելի քիչ ելքային նշաններ, `65%` ելքային միջին խնայողություններ `22-87%` տիրույթով հենանիշերում և `~46%` մուտքագրման սեղմման գործիք: OmniRoute օգտագործում է Caveman-ի մուտքային կողմի համարը, երբ փաստաթղթավորում է կուտակված prompt/context խնայողությունները. Caveman-ի ելքային ռեժիմը մնում է առանձին արձագանք-վարքի հատկանիշ:

## RTK

RTK ռեժիմը կենտրոնանում է հրամանի և գործիքի ելքի վրա.

- հայտնաբերում է ելքային դասեր, ինչպիսիք են `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, Cargo/Go թեստեր, TypeScript/Vite/Webpack builds, ESLint, npm audit/installs, Docker տեղեկամատյաններ, shell `find`/`grep`, stack հետքեր և ընդհանուր տեղեկամատյաններ
- կիրառում է 49 JSON զտիչներ `open-sse/services/compression/engines/rtk/filters/` ից
- աջակցում strip/keep RTK- ANSI ոճի head/tail/max-line խողովակաշարին.
- աջակցում է վստահության տիրույթ ունեցող նախագծի զտիչներ `.rtk/filters.json` ում և գլոբալ զտիչներ `DATA_DIR/rtk/filters.json` ում
- շերտավորում է ANSI հաջորդականությունը, առաջընթացի աղմուկը, կրկնվող տողերը և անօգուտ կաթսայատը
- պահպանում է գործող անհաջողությունները, նախազգուշացումները, ամփոփագրերը, փոխված ֆայլերը և պոչի համատեքստը
- կարող է կամայականորեն պահպանել recovery/debugging ի վերամշակված չմշակված արդյունքը վավերացված կառավարման ուղիների միջոցով

Վահանակի մակերեսը `Dashboard -> Context & Cache -> RTK` է:

Մաքսային ֆիլտրերի, վստահության, հաստատման և չմշակված արդյունքի վերականգնման գործառնական մանրամասները գործում են [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md) ում:

RTK հաղորդում է `60-90%` խնայողությունները հրաման-ելքային սեղմման համար: Դրա README օրինակը ցույց է տալիս 30 րոպե տևողությամբ Claude Code նիստը, որն անցնում է `~118,000` նշաններից դեպի `~23,900` կամ `79.7%` պահված:

## LLMLingua-2 (իմաստային հատում)

LLMLingua-2 ռեժիմը կատարում է** իմաստային նշան էտում** արձակի վրա՝ օգտագործելով ONNX նշանի փոքր դասակարգիչը, որը լրացնում է կանոնների վրա հիմնված Caveman և RTK շարժիչները.

- սեղմում է արձակը միայն ոչ համակարգային հաղորդագրություններում. ցանկապատված ծածկագրի բլոկները և այլ պահպանված կոնստրուկցիաները երբեք չեն փոխվում
- գործարկում է `@atjsh/llmlingua-2` backend-ը (ONNX ՝ `@huggingface/transformers` միջոցով) աշխատանքային շղթայում, այնպես որ մոդելի եզրակացությունը երբեք չի արգելափակում հարցումների իրադարձության հանգույցը
- է** stackable** (`stackPriority` 35). կուտակված խողովակաշարում այն անցնում է կառուցվածքային շարժիչների ետևից (CCR, նիստ-dedup, headroom, Caveman), բայց մինչ `ultra`, քանի որ իմաստային էտումն ամենաարդյունավետն է արդեն կառուցվածքային սեղմված տեքստի — ի վրա, օրինակ՝ `rtk -> caveman -> llmlingua`
- **fail-բացվում է ցանկացած սխալի դեպքում** (բացակայում է ընտրովի խորքերը, աշխատողի ձվադրումը, մոդելի բեռնումը, եզրակացությունը կամ ժամանակի վերջնաժամկետը) → բնօրինակ տեքստը վերադարձվում է անփոփոխ, երբեք սխալ

Շարժիչի գտնվելու վայրը՝ `open-sse/services/compression/engines/llmlingua/`. Վահանակի մակերեսը `Dashboard -> Context & Cache -> LLMLingua` է:

### Մոդելներ

Լռելյայն մոդելն է**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~ 57 MB, արագ)։ Ավելի բարձր ճշգրտություն** BERT- բազա** մոդելը (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) հասանելի է շարժիչի կազմաձևման `model` դաշտի միջոցով: `@huggingface/transformers` ներբեռնում է ընտրված մոդելը HuggingFace Hub-ից `${DATA_DIR}/models/llmlingua` առաջին զանգի ժամանակ (`modelStore.ts`); `modelPath` կոնֆիգուրայի անտեսումը այն ուղղում է տեղական պատճենի փոխարեն (անցանց / օդային բաց տեղադրումներ):

### Ընտրովի կախվածություններ և ըստ պահանջի տեղադրում

The prunable LLMLingua runtime peer stack-ն է** ընտրովի** . Երկու փաթեթ `package.json` ում հայտարարվում են `optionalDependencies` և պահվում** արտաքին** արտադրության կառուցմամբ (`scripts/build/prepublish.ts` դրանք չի միավորում).

| Փաթեթ                | Տարբերակ (փին) | Նշումներ                                                  |
| -------------------- | -------------- | --------------------------------------------------------- |
| `@atjsh/llmlingua-2` | `2.0.5`        | Մուտքի փաթեթ; մյուսներին հայտարարում է որպես հասակակիցներ |
| `js-tiktoken`        | `^1.0.20`      | Տոկենիզատոր                                               |

`@huggingface/transformers` ամրացված է `^4.2.0` ում (համօգտագործվում է տեղական ներկառուցման ուղու հետ և նաև հետագծվում է առանձին փաթեթի մեջ); `@atjsh/llmlingua-2@2.0.5` դրա վրա աշխատում է `"^3.5.2 || ^4.0.0"`, այնպես որ Transformers.js v3 և v4-ն ապահովված են: 2.0.4-ից ի վեր, `@atjsh/llmlingua-2` այլևս չի պահանջում `@tensorflow/tfjs`, որը հանեց ամենամեծ մեկ ներդրողին (TensorFlow.js) SLM կույտից: Միայն վերը նշված երկու փաթեթներն են հատելու SLM հասակակիցներ: Ստանդարտ `npm install` (dev) ինքնաբերաբար տեղադրում է կամընտիր կույտը, եթե ընտրովի կախվածությունները բաց թողնվեն:

**Ինչու ըստ պահանջի.** npm-ի կողմից հրապարակված փաթեթը, ինքնուրույն փաթեթը և Docker պատկերի նավը** առանց** այս խորշերը բարակ մնալու համար: Երբ դրանք բացակայում են, աշխատողի կախվածության դարպասը ( `@atjsh/llmlingua-2` լուծիչ զոնդ `worker.ts` ում) խափանում է, և շարժիչը** fail- բացվում է անձայն** — ընտրելով LLMLingua դառնում է no-op (տեքստը վերադարձվում է անփոփոխ, գրանցված սխալ չկա): Այն էտված միջավայրում ակտիվացնելու համար տեղադրեք կամընտիր դարակը.

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` հեռացումը (2.0.4 +) վերացնում է նախկինում գերիշխող ~ 800 MB ներդրողը — մնացած ոտնահետքը transformers.js + onnxruntime-node-ի գործարկման ժամանակներն են, գումարած TinyBERT մոդելը (~ 57 MB), որը ներբեռնվել է առաջին օգտագործման ժամանակ (ոչ npm-ի միջոցով):

Ըստ միջավայրի՝

- **Dev / `npm install`** — ինքնաբերաբար տեղադրվում է, քանի դեռ չեք անցել `--omit=optional` (կամ `--no-optional`): Գործողության կարիք չկա:
- **Համաշխարհային npm (`npm i -g omniroute`) / ինքնուրույն** — գործարկեք վերևում տեղադրված տեղադրման հրամանը տեղադրված փաթեթի գրացուցակի ներսում կամ նորից տեղադրեք՝ առանց ընտրովի խորշերը բաց թողնելու:
- **Docker** — ավելացնել տեղադրման հրամանը ստացված պատկերի շերտում; Հրապարակված պատկերը դիզայնով բարակ է:
- **VPS (PM2)** — տեղադրեք հավելվածի `node_modules` ում, այնուհետև վերագործարկեք գործընթացը, որպեսզի աշխատողը նորից զննի դարպասը:
- **Raw Հաջորդ ինքնուրույն (`npm run build` → `.build/next/standalone/server.js`)** — անկախ հետք նավերը NEITHER աշխատողը կամ ընտրովի խորքերը, այնպես որ շարժիչը լուռ խափանում է-բացվում է: `scripts/build/colocate-standalone.mjs` նորից կիրառում է երկուսն էլ (աշխատողը esbuild + ընտրովի-խորը փակում է առանձին ծառի մեջ); այն ավտոմատ կերպով աշխատում է `postbuild` npm կեռիկի միջոցով յուրաքանչյուր կառուցումից հետո: Անբավարար, ձախողվող-փափուկ, երբ խորքերը բացակայում են:

**Ստուգեք, որ այն ակտիվ է.** LLMLingua ընտրությամբ իրական արձակը փոքրանում է (շարժիչը դադարում է բացվել), և առաջին հարցումը գործարկում է մոդելի ներբեռնումը `${DATA_DIR}/models/llmlingua`: Դարպասը միտումնավոր զոնդ է անում միայն `@atjsh/llmlingua-2` — մյուս հասակակիցները միայն ESM-ն են, և `require.resolve` նետում է նրանց վրա, նույնիսկ երբ առկա է —, այնպես որ աշխատողը դեռևս ձախողվում է-բացվում է, եթե `import()` ժամանակ իսկապես որևէ մեկը բացակայում է:

## Խցանված խողովակաշարեր

Stacked ռեժիմն իրականացնում է խողովակաշարի քայլերը հերթականությամբ: Լռելյայն է.

```txt
rtk -> caveman
```

Օգտագործեք սա կոդավորման գործակալի նիստերի համար, որտեղ հուշումը համատեղում է հրամանի ելքը մարդկային կամ օգնական արձակի հետ: RTK նախ նվազեցնում է գործիքների աղմկոտ տեղեկամատյանները, այնուհետև Caveman-ը սեղմում է մնացած բնական լեզուն:

Խողովակաշարի քայլերը կազմաձևվում են `stackedPipeline` հետ սեղմման պարամետրերում կամ սեղմման կոմբինացիաների միջոցով:

Երբ երկու շարժիչներն էլ նվազեցնում են նույն թույլատրելի ծանրաբեռնվածությունը, խնայողական բաղադրությունը.

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP Մատչելիության ծառի զտիչ

MCP accessibility-tree խելացի ֆիլտրը հետկատարման սեղմման շերտ է, որն աշխատում է MCP ով** գործիքի արդյունքները** , ոչ թե հուշումների կամ համատեքստի վրա: Այն ուղղված է լայնածավալ մատչելիության ծառին և բրաուզերի ակնթարթային բեռներին, որոնք վերադարձվում են Playwright, համակարգչային օգտագործման և զննարկիչի ավտոմատացման MCP սերվերների միջոցով:

### Ինչ է դա անում

1. **Աղմուկի հեռացում** — հեռացնում է generic/text դատարկ գրառումները (`- generic:`, `- text: ""`)
2. **Եղբայրների փլուզում** — երբ ≥ `collapseThreshold` (կանխադրված 30) հաջորդական տողերը կառուցվածքային կրկնություններ են, դրանք փլուզում է առաջին `collapseKeepHead` (կանխադրված 10) տողերի մեջ + հաշվառման ամփոփում + վերջին `collapseKeepTail` (կանխադրված 5) տողերում
3. **Ref պահպանում** — `[ref=eXX]` խարիսխները, որոնք պահանջվում են Playwright/computer-use կողմից, երբեք չեն դիպչում
4. **Կոշտ կտրվածք** — եթե փլուզումից հետո տեքստը դեռ գերազանցում է `maxTextChars` (կանխադրված 50,000), կտրվում է նավիգացիոն հուշումով, որպեսզի գործակալը կարողանա շարունակել աշխատել:

### Շարժիչի գտնվելու վայրը

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### Կոնֆիգուրացիա

Գլոբալ կարգավորումներում վերահսկվում է `compression.mcpAccessibility` կողմից (միգրացիա 056): Կանխադրված կազմաձևում՝

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

Զտիչը կիրառվում է միայն գործիքի արդյունքի օգտակար բեռների վրա, որոնց `type` `"text"` է, իսկ երկարությունը գերազանցում է `minLengthToProcess`: Այն չի ազդում արագ սեղմման կամ բեռների պահանջների վրա:

### Ակնկալվող խնայողություններ

60–80% զննարկիչի լուսանկարչական գործիքի արդյունքների վրա՝ կախված էջի բարդությունից: Փլուզման ալգորիթմը տողերի քանակում O(n) է և ավելացնում է աննշան ուշացում:

### Այս զտիչն ընդդեմ վերևում գտնվող սեղմման շարժիչների

| Ասպեկտ        | Caveman / RTK / Stacked        | MCP հասանելիության զտիչ                |
| ------------- | ------------------------------ | -------------------------------------- |
| Թիրախ         | Հարցման հուշումներ / համատեքստ | MCP գործիքի արդյունքները               |
| ձգան          | Կոմպրեսիոն ռեժիմի կարգավորում  | `compression.mcpAccessibility.enabled` |
| Շրջանակ       | Բոլոր SSE հաղորդագրությունները | Միայն գործիքի արդյունքները             |
| Ref խարիսխներ | N/A                            | Պահպանվել է անվերապահորեն              |

---

## Կոմպրեսիոն կոմբինացիաներ

Կոմպրեսիոն կոմպոզիցիաները կոչվում են սեղմման պրոֆիլներ, որոնք կարող են վերագրվել երթուղային կոմբինացիաներին.

- `compression_combos`: պահպանում է ռեժիմը, խողովակաշարը, RTK կազմաձևը, լեզվի կազմաձևը և լռելյայն նշիչը
- `compression_combo_assignments`. սեղմում է կոմպոզիցիան դեպի երթուղային կոմբին
- Գործարկման ժամանակի ինտեգրումը լուծում է նշանակված սեղմման կոմպոզիցիան, նախքան ընդհանուր կոմբինատի անտեսումը
- վերլուծությունները ներառում են `compression_combo_id` և `engine`

Վահանակի մակերեսը՝ `Dashboard -> Context & Cache -> Compression Combos`.

## Նախադրյալներ / օպերատորի ուղեցույց (CCR & session-dedup)

CCR (`ccr`) և `session-dedup` փոխարինել կամ հեռացնել տեքստը և թողնել a** մարկեր** հետևում. Այս բաժինը օպերատորի տեղեկանքն է հաճախորդին միացնելու, երկու մարկերները կարդալու և վերացած բովանդակությունը գտնելու կամ ախտորոշելու համար: Յուրաքանչյուր շարժիչի մեխանիկա վերը նշված է. սա «ինչպես աշխատեմ» շերտն է:

### Տրանսպորտ և վերջնակետեր

MCP սերվերին, որը բացահայտում է CCR գործիքները, կարելի է հասնել երեք եղանակով. Նախնական URL հիմքը `http://localhost:20128` է (`OMNIROUTE_BASE_URL`):

| Տրանսպորտ                                     | URL / հրաման                            | Նշումներ                                                                                                                                          |
| --------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Streamable HTTP (հաճախորդ, խորհուրդ է տրվում) | `http://localhost:20128/api/mcp/stream` | Վերջնակետի հետ զրուցում են ընթացիկ MCP հաճախորդները:                                                                                              |
| Ժառանգություն SSE singleton                   | `http://localhost:20128/api/mcp/sse`    | Ավելի հին սինգլտոն տրանսպորտ. Այն** փակվում է** հոսքային նիստեր; օգտագործել `streamable-http` հաճախորդները `/api/mcp/stream` դեմ, ոչ թե այս մեկի: |
| stdio                                         | `omniroute --mcp`                       | IDE MCP կազմաձևի համար, որը ստեղծում է գործընթացը: Չկա `--dev` դրոշ; `omniroute --mcp` stdio մուտքի կետն է:                                       |

### Պահպանման մակարդակներ (ինչը գոյատևում է վերագործարկումից)

CCR է ա** երկաստիճան** խանութ, ոչ միայն հիշողության մեջ.

- **Հիշողության տաք մակարդակ** — մեկ բլոկի գլխարկ 2 MiB, մեկ հիմնական 16 MiB, գլոբալ 64 MiB: Մուտքագրումները կանխադրված են 24 h TTL (առավելագույնը 7 օր): Հիշողությունից MCP ամբողջական որոնումը սահմանվում է 256 KiB ով; ավելի մեծ ցանկացած բան դեռ հասանելի է տիրույթի / grep ռեժիմների միջոցով:
- **Երկարակյաց SQLite մակարդակ** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, լռելյայն միացված) — ապահովում է հիշողության մակարդակը, այնպես որ բլոկը գոյատևում է LRU վտարումից, վերագործարկումից կամ հետբերման վայրէջքից մեկ այլ օրինակում: Շարքը պահպանում է բլոկի TTL, ուստի իր TTL անցած բլոկը վերանում է երկու մակարդակներից:

Երեք պահակները պահպանում են երկարակյաց շերտով սահմանափակված — բլոկը մնում է հիշողություն՝ միայն այն դեպքում, երբ.

1. բլոկն ավարտված է** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. գործարկման ժամանակը ամպային գործարկման ժամանակ է (տեղական սկավառակ չկա);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

Այսպիսով, «բլոկը անհետացավ» վերսկսման վերսկսման պատմություն չէ. sub-512 KB բլոկը լոկալ, ոչ ամպային գործարկման ժամանակի վրա գոյատևում է վերագործարկումից երկարատև մակարդակի միջոցով, մինչև դրա TTL սպառվի: Փոփոխականի համար տե՛ս [Շրջակա միջավայրի տեղեկանք](../reference/ENVIRONMENT.md) :

### Երկու մարկեր

| Մարկեր                                | Իմաստը                                                                                                                                        | Ինչ պետք է անի մոդելը                                                                                                                                                                                      |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[CCR retrieve hash=<24hex> chars=N]` | Մեծ բլոկ պահվել է բովանդակության հասցեով:                                                                                                     | Զանգեք `omniroute_ccr_retrieve` ի հետ** 24 վեցանկյուն հեշ՝ բառացի պատճենված** բնօրինակ տեքստը հետ ստանալու համար:                                                                                          |
| `[dedup:ref sha=…]`                   | `session-dedup` elided տեքստն արդեն ուղարկվել է նույն նիստի ավելի վաղ հերթում: Սա ան** դիտավորյալ հետադարձ հայացք** , ոչ թե կորուստ կամ սխալ: | Արեք** ոչ** զանգահարեք ցանկացած գործիք և արեք** ոչ** փորձեք «վերակառուցել» այն։ Տեքստի առաջին հայտնվելը կանոնական պատճենն է. ընթացիկ շրջադարձը երբեք չի վերագրվում, այն խաբվում է ավելի ուշ շրջադարձի վրա: |

`[dedup:ref]` հետադարձ հայացքը կանխամտածված արձանագրային որոշում է — չկա նախապես ուղարկելու վերակառուցում: Վերաբերվեք դրան, քանի որ «այս ճիշտ տեքստն արդեն հաղորդվում էր այս նստաշրջանի ավելի վաղ»:

### Հաճախորդի նախադրյալները

- **Բանալի (stdio):** stdio զանգահարողը չի կրում յուրաքանչյուր հարցումի նույնականացում, ուստի այն նույնականացվում է `OMNIROUTE_API_KEY` ով (սահմանված է MCP սերվերի `env` ում): Առանց դրա զանգահարողը անանուն է, և այն գործիքները, որոնք պահանջում են տնօրեն, կարող են վատթարանալ:
- **`tools[]` ներարկման նախապայմանն է:** Ներարկվում է CCR retrieve-protocol հրահանգը (#8033):** միայն** երբ հարցումի գովազդված `tools[]` ապացուցում է, որ հաճախորդը իրականում կարող է հասնել `omniroute_ccr_retrieve`: Համընկնումը հետևող հատվածի համընկնում է, որը սահմանափակվում է բաժանարարով (`__`, `.`, `/`, `:`) — երբեք բաց ենթատողով — այնպես որ անունների տարածության անվանումը, ինչպիսին `mcp__gateway__omniroute_ccr_retrieve` է, դեռևս հաշվում է: Բացակայող կամ չհամապատասխանող `tools[]` նշանակում է, որ հրահանգը _չի_ներարկվել՝ ըստ նախագծման:
- **`codemode:false` (OpenCode հաճախորդներ):** OpenCode լռելյայն դնում է Code Mode-ի վրա, որը գովազդում է միայն իր բնիկ գործիքները մոդելին և** չի անում** տեղադրել MCP գործիքներ հայրենի `tools[]` ցուցակում: Սահմանեք `codemode: false` MCP սերվերի մուտքի վրա, որպեսզի `omniroute_ccr_*` գործիքները գովազդվեն: Սա ա** հաճախորդ** ընդլայնված, ոչ թե OmniRoute մեկը. Այն դեռ չի ներարկում CCR հրահանգը. OpenCode անվանում է գործիք `<server>_<tool>`, ուստի `omniroute` կոչվող սերվերը բացահայտում է `omniroute_omniroute_ccr_retrieve`, և `_` համընկնող բաժանարարներից մեկը չէ:
- **Տնօրեններ.** Պահպանումը և առբերումը մեկուսացված են ըստ վավերացված հիմնականի (ըստ API բանալիի): Բանալին տեսնում է միայն իր սեփական բլոկները:

### Առբերման սահմանափակումներ և էջադրում

MCP գործիքի տեքստի արդյունքները կտրված են `mcpAccessibility.maxTextChars` շուրջը (կանխադրված `50000`): Բլոկի `full` առբերումը ծածկված է 256 KiB — ով** չկա անսահմանափակ ամբողջական առբերում** . Երբ բլոկի `chars=N` մեծ է, էջեք այն՝ ամբողջը քաշելու փոխարեն.

- Հիմնական կանոն.**`chars > 40000` → օգտագործել `mode`** , երբեք մերկ լիքը.
- `mode:"grep"` — regex `pattern` համընկնում է տող առ տող, մինչև 1000 համապատասխան տող (`unique: true` կաթիլները կրկնվում են), ամենաէժանը «գտնել ինձ անհրաժեշտ մեկ տողը»:
- `mode:"lines"` — 1-ինդեքսավորված տողերի միջակայք; կարիք ունի և՛ `start`, և՛ `end`:
- `mode:"head"` / `mode:"tail"` — first/last `n` գծեր.
- `mode:"stats"` — տողը, նիշը և բայթը հաշվվում են առանց մարմնի:

Օգտագործեք `mode:"lines"` `start`/`end` ով էջերով երկար բլոկ անցնելու համար, այլ ոչ թե ամբողջը միանգամից պահանջեք:

### Գործիքների անվանումը

Առբերման գործիքը ներկայումս կոչվում է `omniroute_ccr_retrieve` ( `omniroute_` նախածանցը թվագրված լուծում է սերվերների անունների բախումների համար): Ավելի մաքուր սահմանափակված վերջածանցի գործիքի անվանումը և MCP JSON արդյունքների շտկումը՝ կտրված միջին տողի համար, հետևվում են որպես վերին հոսանքով հետևողներ. այս էջը ներկայացնում է միայն ընթացիկ, առաքված վարքագիծը:

### Նիստի կյանքի ցիկլը

Streamable-HTTP նիստերն անգործուն են, և սերվերը դրանք քաղում է. անգործուն պատուհանը `MCP_SESSION_IDLE_MS` հաստատունն է (նշվում է անունով, այլ ոչ թե կոշտ կոդավորված արժեք, այնպես որ այս էջը չի շարժվում, երբ այն փոխվում է): Անգործուն հնձված նստաշրջանի ախտանիշը HTTP 404-ն է `Unknown Mcp-Session-Id` — ով, միջոցը վերամիացումն է կամ վերսկսել նիստը,** ոչ** բանալին պտտելու, շրջանակը փոխելու կամ գործիքը վերանվանելու համար:

## Շրջանակ և բացառումներ

**Ներդրումները երբեք չեն սեղմվում:** `open-sse/handlers/embeddings.ts` երբեք ոչ մի սեղմման շարժիչ չի անվանում — request/response մարմինները ուղղակիորեն անցնում են կատարողին անձեռնմխելի: Սա այսօր կառուցվածքային է (ներկառուցումները և զրույցի ավարտը անհամաչափ մշակողներ են), ոչ թե գործարկման ժամանակի ստուգում, բայց դա նշանակում է, որ #8034 ում վեկտորի աղավաղման մտահոգությունը չունի ներկառուցման ուղու վրա ազդեցության մակերես:

**Per-model/endpoint բացառման զտիչ (#8034):** Զրույցի ավարտի համար օպերատորը կարող է անվանել մոդելի id/ `provider/model` թիրախներ, որոնք երբեք չպետք է սեղմվեն — պաշտպանիչ բազրիք, որն օգտակար է, եթե սեղմումը երբևէ ավելի մոտ է տեղադրվում հարակից ճանապարհին, և, ընդհանուր առմամբ, օգտակար է ցանկացած մոդելի համար, որի բայթ առ բայթ ճշգրիտ հուշում է (դետերմինիստական էվալներ, կանխորոշիչ և այլն):

- Կարգավորումների դաշտ. `exclusions?: string[]` գլոբալ սեղմման կազմաձևում (`GET`/`PUT /api/settings/compression`), պահպանվել է գոյություն ունեցող `key_value` սեղմման անվանատարածքի միջոցով (`src/lib/db/compression.ts`) — նոր աղյուսակ չկա:
- Վահանակի ներդիր.** Վահանակ → Սեղմում → Բացառումներ** (`/dashboard/compression/exclusions`).
- Կաղապարի շարահյուսություն. `*` միակ ցուցանիշն է: Նախշի յուրաքանչյուր այլ ռեգեքս մետանիշը դուրս է գալիս նախքան համապատասխանելը, ուստի `gpt-5.6` համապատասխանում է միայն բառացի տողին, ոչ երբեք `gpt-5x6` (ReDoS-անվտանգ, սահմանափակված, առանց ներդիր քանակականների): Զարդանախշերը մեծատառով համընկնում են ինչպես մերկ մոդելի id-ի, այնպես էլ `provider/model` կոմպոզիտային — `gpt-5-6`, `openai/gpt-5-6` և `openai/*` հետ, և միայն `*` բացառում է յուրաքանչյուր մոդել:
- Համապատասխանեցում՝ `isCompressionExcluded()` / `normalizeCompressionExclusions()` `open-sse/services/compression/exclusions.ts` ում: `chatCore.ts` ստուգում է բացառված թիրախը սեղմման կարգավորումները լուծելուց անմիջապես հետո,** ցանկացած շարժիչի գործարկումից առաջ** , և համընկնումը վերաբերվում է ճիշտ այնպես, ինչպես սեղմումը գլոբալ անջատված լինելու — հարցումի մարմինը ապացուցելիորեն նույնական է բայթին: Բաց թողնելը գրանցվում է `writeCompressionSkip(..., "excluded")` միջոցով՝ վերլուծական տեսանելիության համար:
- Կանխադրված (empty/absent ցուցակ). նույնական է pre-#8034 վարքագծին — ոչինչ չի բացառվում:

## Հայտնի սահմանափակումներ

- **LLMLingua-2 (SLM) պահանջում է համատեղ տեղակայված կամընտիր խորշեր:** Աշխատողը աշխատում է միայն արտադրական կառուցվածքում, երբ `@atjsh/llmlingua-2` + հասակակիցները համատեղ տեղակայվում են `dist/node_modules` ում (տես `scripts/build/colocateOptionals.mjs`, #4286): Առանց դրանց շարժիչը բացվում է (վերադարձնում է բնօրինակ տեքստը): Աշխատողի լուծումն այլևս կախված չէ `import.meta.url` ից (այն մահանում է առանձին փաթեթում) — այն խարսխվում է գործարկման ժամանակի վրա cwd/ `argv[1]`:
- **Caveman լեզվի փաթեթները `de` / `fr` / `ja` մասնակի են:** Նրանք առաքում են `context` + `filler` + `structural` կանոններ, բայց ոչ `dedup` / `ultra` փաթեթներ, այնպես որ `ultra` ինտենսիվությունը ավելի ուժեղ չէ, քան `full` այդ լեզուների համար (նրանք օգտագործում են միայն իրենց սեփական կանոնները — չկան լուռ վերադարձ դեպի անգլերեն `dedup`/`ultra` կանոնները, որոնք կխաթարեն օտար տեքստը): `en` / `es` / `id` / `pt-BR` ավարտված են: Ողջունելի են `dedup.json` + `ultra.json` ի ներդրումները մասնակի փաթեթների համար:
- **Խցանված հեռաչափությունը ցույց է տալիս միայն սեղմված շարժիչները:** Խողովակաշարերի կուտակված աստիճանը, որի շարժիչն աշխատել է, բայց 0% խնայողություն է առաջացրել, վերադարձնում է `stats:null` և, հետևաբար, չի երևում `engineBreakdown` — ում, որը չի տարբերվում բաց թողնված քայլից: «վազել, 0 %»-ը «բաց թողնված»-ից տարբերելը կպահանջի անսարքության մոդելի փոփոխություն և հետաձգվում է:
