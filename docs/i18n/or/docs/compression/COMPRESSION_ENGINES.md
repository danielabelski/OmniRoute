OmniRoute ସଙ୍କୋଚନ ଇଞ୍ଜିନ୍ ଚୁକ୍ତିନାମା ଉପରେ ନିର୍ମିତ। ଏକ ମୋଡ୍ ସିଧାସଳଖ ଗୋଟିଏ ଇଞ୍ଜିନ୍ (`caveman` କିମ୍ବା `rtk`) କିମ୍ବା ଏକ ସ୍ଥିରିକୃତ ଷ୍ଟାକ୍ ପାଇପଲାଇନ ଚଲାଇପାରେ ଯାହା କ୍ରମରେ ଏକାଧିକ ଇଞ୍ଜିନ୍ ଏକଜେକ୍ୟୁଟ୍ କରେ।

| ------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------- |

### OmniGlyph ସଙ୍କୋଚନ ପ୍ରୋଫାଇଲ୍।

`omniglyph` ଇଞ୍ଜିନ୍ (ପ୍ୟାକେଜ୍ `omniglyph`, 1.4.0 +) ଏକ ନାମିତ ଅର୍ଥଗତ ପ୍ରୋଫାଇଲ୍ ଗ୍ରହଣ କରେ, ସଙ୍କୋଚନ ସେଟିଙ୍ଗରେ `omniglyph.profile` ମାଧ୍ୟମରେ ସର୍ବଭାରତୀୟ ସ୍ତରରେ ସେଟ୍ ହୋଇଯାଏ କିମ୍ବା ଷ୍ଟାକ୍ ହୋଇଥିବା ପାଇପଲାଇନର ଷ୍ଟେପ୍ ବିନ୍ୟାସ ମାଧ୍ୟମରେ ପ୍ରତି ପାଦରେ:

| ପ୍ରୋଫାଇଲ୍     | ସୀମା                                                                                |
| ------------- | ----------------------------------------------------------------------------------- |
| `aggressive`  | ଡିଫଲ୍ଟ। ପ୍ରକାଶିତ ରସିଦ ନୀତି — ପ୍ରତିଛବି ପ୍ରଣାଳୀ, ଟୁଲ୍ ଡକସ୍ ଏବଂ ଘନ ଇତିହାସ ମାପ କଲା।     |
| `balanced`    | ଜୀବନ୍ତ ରାଜ୍ୟ ଦେଶୀ ରଖେ, ଶେଷ turns ଟର୍ନକୁ ସୁରକ୍ଷା କରେ, ପୁରୁଣା ବନ୍ଦ ଇତିହାସକୁ ନଷ୍ଟ କରେ। |
| `coding-safe` | ପ୍ରାଧିକରଣ, ଟୁଲ୍ ସ୍କିମା ଏବଂ ଲାଇଭ୍ ଟୁଲ୍ ଆଉଟପୁଟ୍ ଦେଶୀ ରଖେ, ଶେଷ 12 ଟର୍ନକୁ ସୁରକ୍ଷା ଦିଏ।  |
| `passthrough` | ପରିବର୍ତ୍ତନ ନକରି ମାର୍ଗଗୁଡିକ; ଇଞ୍ଜିନ୍ ଏଡ଼ାଇ ଦିଆଯାଇଛି।                                 |

ପ୍ରୋଫାଇଲ୍ ହେଉଛି** ଛାତ, ଚଟାଣ ନୁହେଁ।** : ପ୍ୟାକେଜରେ `mergeCompressionProfileOptions` ପ୍ରୋଫାଇଲ୍ ବନ୍ଦ ହୋଇଥିବା ଏକ କ୍ଷତିଗ୍ରସ୍ତ ଗାଡ଼ି ଖୋଲିବାକୁ ଏକ କଲର୍ ଓଭରବ୍ରିଡ୍ କରିବାକୁ ମନା କରେ, ତେଣୁ `coding-safe` ଅଧୀନରେ ପ୍ରତି ଷ୍ଟେପ୍ `preserveSystemPrompt: false` ପୁନ re ସକ୍ଷମ କରିପାରିବ ନାହିଁ।

ଏହି କୋଡବେସରେ ମାପ କରାଯାଇଛି: `coding-safe` ଏବଂ `balanced` `minCompressChars` ସର୍ବାଧିକ ବ raise ାଇଥାଏ ଏବଂ ସିଷ୍ଟମ, ଟୁଲ ସ୍କିମା ଏବଂ ଟୁଲ ଫଳାଫଳକୁ ସ୍ଥାନୀୟ ରଖେ, ତେଣୁ ଏକ ଅଧିବେଶନ ଯାହା ଇତିହାସ ସଂଗ୍ରହ କରିନାହିଁ ତଥାପି `below_min_chars` ରେ ଅଟକିଯାଏ ଏବଂ ଇଞ୍ଜିନ କିଛି ପରିବର୍ତ୍ତନ କରେ ନାହିଁ। ସେଥିପାଇଁ ସୁରକ୍ଷିତ ପ୍ରୋଫାଇଲ୍ ପରିବର୍ତ୍ତେ ଡିଫଲ୍ଟ `aggressive` ଅଟେ।

ପ୍ୟାକେଜ୍ ଏହାର ପରିବେଶ ବିନ୍ୟାସରୁ ଏହାର ନିଜସ୍ୱ ମଡେଲ୍ ପରିସର ଏବଂ ପ୍ରୋଫାଇଲ୍ ସମାଧାନ କରେ। OmniRoute କଦାପି ନିଷ୍ପତ୍ତିକୁ ପ୍ରତିନିଧିତ୍। କରେ ନାହିଁ: ଆଡାପ୍ଟର ମଡେଲ ଗେଟକୁ ପ୍ୟାକେଜର ସର୍ବାଧିକ ପ୍ରତିବନ୍ଧକ ପରିସରକୁ ପିନ୍ କରେ, ତେଣୁ ହୋଷ୍ଟ ପରିବେଶ ସେଟିଂସମୂହ କେବଳ ଅନୁମତି ତାଲିକାକୁ ସଂକୀର୍ଣ୍ଣ କରିପାରେ, OmniRoute ର ମାପାଯାଇଥିବା ରସିଦକୁ କେବେବି ବିସ୍ତାର କରିପାରିବ ନାହିଁ।

## ଇଞ୍ଜିନ ରେଜିଷ୍ଟ୍ରି।

ରେଜିଷ୍ଟ୍ରି `open-sse/services/compression/engines/registry.ts` ରେ ରୁହେ। ଇ Eng ୍ଜିନଗୁଡିକ ଏକ ଅଂଶୀଦାର ଚୁକ୍ତି ପ୍ରକାଶ କରେ:

- `id`: ସ୍ଥିର ଇଞ୍ଜିନ୍ id ଯେପରିକି `caveman` କିମ୍ବା `rtk`
- `apply(text, config)`: ଷ୍ଟାକ୍ ପାଇପଲାଇନ ଦ୍ୱାରା ବ୍ୟବହୃତ ପୁରୁଣା ନିଷ୍ପାଦନ ପଥ।
- `compress(input, config)`: ପ୍ରାଥମିକ ନିଷ୍ପାଦନ ପଥ ଫେରସ୍ତ ପାଠ୍ୟ + ପରିସଂଖ୍ୟାନ।
- `getConfigSchema()`: ବ valid ଧ ବିନ୍ୟାସ ର JSON- ସ୍କିମା ପରି ଆକୃତି ଫେରସ୍ତ କରେ।
- `validateConfig(config)`: `{ valid, errors[] }` ଫେରସ୍ତ କରେ।

ପଞ୍ଜୀକରଣ `registerCompressionEngine(engine)` (କିମ୍ବା ଉନ୍ନତ ମାମଲା ପାଇଁ `registerEngine` ) ବ୍ୟବହାର କରେ, ଯାହା ଗ୍ରହଣ କରିବା ପୂର୍ବରୁ `assertValidEngine()` ଏବଂ `validateConfig(defaultConfig)` କୁ ଡାକେ। ଚାଲିବା ସମୟରେ ଏକ ଇଞ୍ଜିନ୍ ଅପସାରଣ କରିବାକୁ `unregisterCompressionEngine(id)` ବ୍ୟବହାର କରନ୍ତୁ।

`strategySelector.ts` ସଙ୍କୋଚନ ଚାଲିବା ପୂର୍ବରୁ ବିଲ୍ଟ-ଇନ୍ ଇଞ୍ଜିନଗୁଡ଼ିକୁ ପଞ୍ଜିକରଣ କରେ। ଏହା ପୂର୍ବାବଲୋକନ, ଚାଲିବା ସମୟ ସଙ୍କୋଚନ, ଷ୍ଟାକ୍ଡ୍ ମୋଡ୍, ପରୀକ୍ଷଣ, ଏବଂ ଭବିଷ୍ୟତର ଇଞ୍ଜିନଗୁଡ଼ିକ ସମାନ ନିଷ୍ପାଦନ ପଥ ବ୍ୟବହାର କରିବାକୁ ଦିଏ।

### MCP ବର୍ଣ୍ଣନା ସଙ୍କୋଚନ (ସମ୍ବନ୍ଧୀୟ)

ଏକ ପୃଥକ ରେଜିଷ୍ଟ୍ରି MCP ଉପକରଣ ବର୍ଣ୍ଣନା ମେଟାଡାଟାକୁ ରେଜିଷ୍ଟ୍ରି ସ୍ତରୀୟ — ରେ ସଙ୍କୋଚନ କରେ `open-sse/mcp-server/descriptionCompressor.ts` ଏବଂ [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ଦେଖନ୍ତୁ। ଏହା କେଭମ୍ୟାନ୍ ନିୟମକୁ ପୁନ uses ବ୍ୟବହାର କରେ କିନ୍ତୁ ଟୁଲ୍ ମେଟାଡାଟା ଉପରେ କାର୍ଯ୍ୟ କରେ, ପେଲୋଡ୍ ଅନୁରୋଧ କରେ ନାହିଁ।

### ଅତିରିକ୍ତ ବିଲ୍ଟ-ଇଞ୍ଜିନ୍।

## ଗୁମ୍ଫା

କେଭମ୍ୟାନ୍ ମୋଡ୍ ସାଧାରଣ ଗଦ୍ୟର ଅର୍ଥଗତ ଘନତ୍ୱ ଉପରେ ଧ୍ୟାନ ଦେଇଥାଏ:

- ଫିଲର୍, ହେଡିଂ, ବାରମ୍ବାର ପ୍ରସଙ୍ଗ, ଏବଂ କ୍ରିୟା ସଂଯୋଜକ ଫ୍ରେସିଂ ଅପସାରଣ କରେ।
- `open-sse/services/compression/rules/` ରେ ଭାଷା-ସଚେତନ ଫାଇଲ୍ ନିୟମ ପ୍ୟାକ୍ କୁ ସମର୍ଥନ କରେ।

କେଭମ୍ୟାନ୍ ଅପଷ୍ଟ୍ରିମ୍ `~75%` କମ୍ ଆଉଟପୁଟ୍ ଟୋକେନ୍, `22-87%` ପରିସର ସହିତ ବେଞ୍ଚମାର୍କରେ `65%` ହାରାହାରି ଆଉଟପୁଟ୍ ସଞ୍ଚୟ ଏବଂ ଏକ `~46%` ଇନପୁଟ୍-ସଙ୍କୋଚନ ଉପକରଣ ରିପୋର୍ଟ କରେ। ଷ୍ଟାକ୍ ହୋଇଥିବା prompt/context ସଞ୍ଚୟକୁ ଡକ୍ୟୁମେଣ୍ଟ୍ କରିବା ସମୟରେ OmniRoute କ୍ୟାଭମ୍ୟାନ୍ ଇନପୁଟ୍-ସାଇଡ୍ ନମ୍ବର ବ୍ୟବହାର କରେ। ଗୁମ୍ଫା ଆଉଟପୁଟ୍ ମୋଡ୍ ଏକ ପୃଥକ ପ୍ରତିକ୍ରିୟା-ଆଚରଣ ବ feature ଶିଷ୍ଟ୍ୟ ହୋଇ ରହିଥାଏ।

## LLMLingua-2 (ଅର୍ଥଗତ ଛେଦନ)

LLMLingua-2 ମୋଡ୍ କାର୍ଯ୍ୟ କରେ।** ଅର୍ଥଗତ ଟୋକେନ୍ ଛେଦନ।** ଏକ ଛୋଟ ONNX ଟୋକେନ୍ କ୍ଲାସିଫାୟର୍ ବ୍ୟବହାର କରି ଗଦ୍ୟ ଉପରେ, ନିୟମ-ଆଧାରିତ କ୍ୟାଭମ୍ୟାନ୍ ଏବଂ RTK ଇଞ୍ଜିନ୍ଗୁଡ଼ିକୁ ପରିପୂର୍ଣ୍ଣ କରେ:

- ଏକ ଶ୍ରମିକ ସୂତ୍ରରେ `@atjsh/llmlingua-2` ବ୍ୟାକେଣ୍ଡ (ONNX ମାଧ୍ୟମରେ `@huggingface/transformers`) ଚଲାଇଥାଏ, ତେଣୁ ମଡେଲ ଇନଫେରେନ୍ସ ଅନୁରୋଧ ଇଭେଣ୍ଟ ଲୁପ୍ କୁ କେବେବି ଅବରୋଧ କରେ ନାହିଁ।

**କାହିଁକି ଚାହିଦା:** npm- ପ୍ରକାଶିତ ପ୍ୟାକେଜ୍, ସ୍ୱତନ୍ତ୍ର ବଣ୍ଡଲ୍, ଏବଂ Docker ପ୍ରତିଛବି ଜାହାଜ।** ବିନା** ପତଳା ରହିବାକୁ ଏହି ଡିପ୍ସ। ଯେତେବେଳେ ସେମାନେ ଅନୁପସ୍ଥିତ ରହନ୍ତି, ଶ୍ରମିକଙ୍କ ନିର୍ଭରଶୀଳତା ଗେଟ୍ ( `worker.ts` ରେ `@atjsh/llmlingua-2` ସମାଧାନ ଯାଞ୍ଚ) ବିଫଳ ହୁଏ ଏବଂ ଇଞ୍ଜିନ।** ବିଫଳ-ଚୁପଚାପ୍ ଖୋଲିବ।** — ଚୟନ କରିବା LLMLingua ଏକ ନୋ-ଅପ୍ ହୋଇଯାଏ (ପାଠ୍ୟ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ଫେରିଗଲା, କ error ଣସି ତ୍ରୁଟି ଲଗ୍ ହୋଇନାହିଁ)। ଏହାକୁ ଏକ ଛେଦନ ପରିବେଶରେ ସକ୍ରିୟ କରିବାକୁ, ଇଚ୍ଛାଧୀନ ଷ୍ଟାକ ସଂସ୍ଥାପନ କରନ୍ତୁ:

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` ଅପସାରଣ (2.0.4 +) ପୂର୍ବରୁ ପ୍ରାଧାନ୍ୟ ପ୍ରାପ୍ତ ~ 800 MB ସହଯୋଗୀ — ଦୂର କରିଥାଏ ଅବଶିଷ୍ଟ ପାଦଚିହ୍ନ ହେଉଛି transformers.js + onnxruntime-node ଚାଲିବା ସମୟ, ଏବଂ TinyBERT ମଡେଲ୍ (~ 57 MB) ପ୍ରଥମ ବ୍ୟବହାରରେ ଡାଉନଲୋଡ୍ ହୋଇଛି (npm ମାଧ୍ୟମରେ ନୁହେଁ)।

ପ୍ରତି ପରିବେଶ:

- **ଦେବ / `npm install`** — ସ୍ୱୟଂଚାଳିତ ଭାବରେ ସଂସ୍ଥାପିତ ହୋଇଛି ଯେପର୍ଯ୍ୟନ୍ତ ଆପଣ `--omit=optional` (କିମ୍ବା `--no-optional`) ପାସ୍ କରିନାହାଁନ୍ତି। କ action ଣସି କାର୍ଯ୍ୟ ଆବଶ୍ୟକ ନାହିଁ।
- **ଗ୍ଲୋବାଲ୍ npm (`npm i -g omniroute`) / ଷ୍ଟାଣ୍ଡାଲୋନ।** — ସଂସ୍ଥାପିତ ପ୍ୟାକେଜ୍ ଡିରେକ୍ଟୋରୀ ଭିତରେ ଇନଷ୍ଟଲ୍ କମାଣ୍ଡ୍ ଚଲାନ୍ତୁ, କିମ୍ବା ଇଚ୍ଛାଧୀନ ଡିପ୍ସ ଛାଡି ପୁନ rein ସଂସ୍ଥାପନ କରନ୍ତୁ।
- **Docker** — ଏକ ନିର୍ମିତ ପ୍ରତିଛବି ସ୍ତରରେ ସ୍ଥାପନ ନିର୍ଦ୍ଦେଶକୁ ଯୋଗକର; ପ୍ରକାଶିତ ପ୍ରତିଛବି ଡିଜାଇନ୍ ଦ୍ୱାରା ପତଳା।
- **VPS (PM2)** — ଆପର `node_modules` ରେ ଇନଷ୍ଟଲ୍ କରନ୍ତୁ, ତାପରେ ପ୍ରକ୍ରିୟା ପୁନ rest ଆରମ୍ଭ କରନ୍ତୁ ଯାହା ଦ୍ the ାରା ଶ୍ରମିକ ଗେଟ୍ ପୁନ-ଯାଞ୍ଚ କରିବେ।
- **କଞ୍ଚା ପରବର୍ତ୍ତୀ ସ୍ୱତନ୍ତ୍ର (`npm run build` → `.build/next/standalone/server.js`)** — ଷ୍ଟାଣ୍ଡାଲୋନ୍ ଟ୍ରେସ୍ ଜାହାଜ NEITHER ଶ୍ରମିକ କିମ୍ବା ଇଚ୍ଛାଧୀନ ଡିପ୍ସ, ତେଣୁ ଇଞ୍ଜିନ୍ ଚୁପଚାପ୍ ବିଫଳ ହୁଏ। `scripts/build/colocate-standalone.mjs` ଉଭୟ ପୁନ-ପ୍ରୟୋଗ କରେ (କର୍ମକର୍ତ୍ତା ଏସବିଲ୍ଡ + ଇଚ୍ଛାଧୀନ-ଡିପ୍ ବନ୍ଦ ଗଛରେ ବନ୍ଦ); ପ୍ରତ୍ୟେକ ନିର୍ମାଣ ପରେ ଏହା `postbuild` npm ହୁକ୍ ମାଧ୍ୟମରେ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଚାଲିଥାଏ। ଡିପ୍ସ ଅନୁପସ୍ଥିତ ଥିବାବେଳେ ଅଜ୍ଞାତ, ବିଫଳ-ନରମ।

**ଏହା ସକ୍ରିୟ ଅଛି ଯାଞ୍ଚ କରନ୍ତୁ:** LLMLingua ମନୋନୀତ ସହିତ, ପ୍ରକୃତ ଗଦ୍ୟ ପ୍ରକୃତରେ ସଙ୍କୋଚନ ହୁଏ (ଇଞ୍ଜିନ୍ ବିଫଳ ଖୋଲିବା ବନ୍ଦ କରେ), ଏବଂ ପ୍ରଥମ ଅନୁରୋଧ ମଡେଲ ଡାଉନଲୋଡ୍ କୁ `${DATA_DIR}/models/llmlingua` ରେ ଟ୍ରିଗର କରିଥାଏ। ଗେଟ୍ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବରେ କେବଳ `@atjsh/llmlingua-2` — ଅନୁସନ୍ଧାନ କରେ ଅନ୍ୟ ସାଥୀମାନେ କେବଳ ESM ଅଟନ୍ତି ଏବଂ — ଉପସ୍ଥିତ ଥିବାବେଳେ ମଧ୍ୟ `require.resolve` ସେମାନଙ୍କ ଉପରେ ପକାଇଥାଏ ତେଣୁ ଯଦି କ er ଣସି ସାଥି `import()` ସମୟରେ ପ୍ରକୃତରେ ହଜିଯାଏ ତେବେ ଶ୍ରମିକ ତଥାପି ବିଫଳ ହୁଏ।

## ଷ୍ଟାକ୍ ପାଇପ୍ ଲାଇନ୍।

ଷ୍ଟାକ୍ଡ୍ ମୋଡ୍ କ୍ରମରେ ପାଇପଲାଇନ ଷ୍ଟେପ୍ ଚଲାଇଥାଏ। ଡିଫଲ୍ଟ ହେଉଛି:

```txt
rtk -> caveman
```

କୋଡିଂ-ଏଜେଣ୍ଟ ଅଧିବେଶନ ପାଇଁ ଏହାକୁ ବ୍ୟବହାର କରନ୍ତୁ ଯେଉଁଠାରେ ଏକ ପ୍ରମ୍ପ୍ଟ କମାଣ୍ଡ ଆଉଟପୁଟ୍ ମାନବ କିମ୍ବା ସହାୟକ ଗଦ୍ୟ ସହିତ ମିଶ୍ରଣ କରେ। RTK ପ୍ରଥମେ କୋଳାହଳକାରୀ ଉପକରଣ ଲଗ୍ ହ୍ରାସ କରେ, ତା’ପରେ କେଭମ୍ୟାନ୍ ଅବଶିଷ୍ଟ ପ୍ରାକୃତିକ ଭାଷାକୁ ସଙ୍କୋଚନ କରେ।

ପାଇପଲାଇନ ଷ୍ଟେପଗୁଡିକ `stackedPipeline` ସହିତ ସଙ୍କୋଚନ ସେଟିଙ୍ଗରେ କିମ୍ବା ସଙ୍କୋଚନ କମ୍ବୋ ମାଧ୍ୟମରେ ବିନ୍ୟାସିତ।

ଯେତେବେଳେ ଉଭୟ ଇଞ୍ଜିନ୍ ସମାନ ଯୋଗ୍ୟ ପେଲୋଡ୍ ହ୍ରାସ କରନ୍ତି, ସଞ୍ଚୟ ଯ ound ଗିକ:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP ଅଭିଗମ୍ୟତା ବୃକ୍ଷ ଫିଲ୍ଟର୍।

MCP ଆକ୍ସେସିବିଲିଟି-ଟ୍ରି ସ୍ମାର୍ଟ ଫିଲ୍ଟର୍ ହେଉଛି ଏକ ଏକଜେକ୍ୟୁଶନ୍ ସଙ୍କୋଚନ ସ୍ତର ଯାହା MCP ରେ ଚାଲିଥାଏ।** ଉପକରଣ ଫଳାଫଳ** , ପ୍ରମ୍ପ୍ଟ କିମ୍ବା ପ୍ରସଙ୍ଗରେ ନୁହେଁ। ଏହା Playwright, କମ୍ପ୍ୟୁଟର ବ୍ୟବହାର, ଏବଂ ବ୍ରାଉଜର-ସ୍ୱୟଂଚାଳିତ MCP ସର୍ଭର ପରି ଉପକରଣ ଦ୍ୱାରା ଫେରସ୍ତ ହୋଇଥିବା ଭର୍ବୋଜ୍ ଆକ୍ସେସିବିଲିଟି-ଟ୍ରି ଏବଂ ବ୍ରାଉଜର୍ ସ୍ନାପସଟ୍ ପେଲୋଡ୍ କୁ ଟାର୍ଗେଟ୍ କରେ।

### ଏହା କଣ କରେ।

1. **କୋଳାହଳ** — ଖାଲି generic/text ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ (`- generic:`, `- text: ""`) ଅପସାରଣ କରେ।
2. **ଭାଇଭଉଣୀ ଭୁଶୁଡ଼ିବା।** — ≥ `collapseThreshold` `collapseKeepHead` + + `collapseKeepTail`
3. **ସଂରକ୍ଷଣ** Playwright/computer-use ଦ୍ୱାରା ଆବଶ୍ୟକ — `[ref=eXX]` ଆଙ୍କର୍ କଦାପି ସ୍ପର୍ଶ ହୁଏ ନାହିଁ।
4. **କଠିନ କାଟିବା।** — ଯଦି ପତନ ପରେ ପାଠ୍ୟ `maxTextChars` (ଡିଫଲ୍ଟ 50,000) ଅତିକ୍ରମ କରେ, ଏକ ନାଭିଗେସନ୍ ଇଙ୍ଗିତ ସହିତ ଛୋଟ ହୋଇଯାଏ ତେଣୁ ଏଜେଣ୍ଟ କାର୍ଯ୍ୟ ଜାରି ରଖିପାରେ।


### ବିନ୍ୟାସ

ଗ୍ଲୋବାଲ୍ ସେଟିଙ୍ଗରେ `compression.mcpAccessibility` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ (ସ୍ଥାନାନ୍ତରଣ 056)। ଡିଫଲ୍ଟ ବିନ୍ୟାସ:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

ଫିଲ୍ଟର୍ କେବଳ ଟୁଲ୍-ଫଳାଫଳ ପେଲୋଡ୍ ପାଇଁ ପ୍ରୟୋଗ କରାଯାଏ ଯାହାର `type` `"text"` ଏବଂ ଯାହାର ଲମ୍ବ `minLengthToProcess` ଅତିକ୍ରମ କରେ। ଏହା ତୁରନ୍ତ ସଙ୍କୋଚନ କିମ୍ବା ପେଲୋଡ୍ ଅନୁରୋଧକୁ ପ୍ରଭାବିତ କରେ ନାହିଁ।

### ଆଶାକରାଯାଇଥିବା ସଞ୍ଚୟ।

ପୃଷ୍ଠା ଜଟିଳତା ଉପରେ ନିର୍ଭର କରି ବ୍ରାଉଜର୍ ସ୍ନାପସଟ୍ ଟୁଲ୍ ଫଳାଫଳ ଉପରେ 60-80%। କ୍ଲାସ୍ ଆଲଗୋରିଦମ ହେଉଛି O (n) ରେଖା ଗଣନାରେ ଏବଂ ଅବହେଳିତ ବିଳମ୍ବତା ଯୋଗ କରେ।

## ସଙ୍କୋଚନ କମ୍ବୋସ୍।

ସଙ୍କୋଚନ କମ୍ବୋକୁ ସଙ୍କୋଚନ ପ୍ରୋଫାଇଲ୍ ନାମିତ କରାଯାଇଛି ଯାହାକି ରାଉଟିଙ୍ଗ୍ କମ୍ବୋକୁ ନ୍ୟସ୍ତ କରାଯାଇପାରିବ:

- `compression_combos`: ମୋଡ୍, ପାଇପଲାଇନ, RTK ବିନ୍ୟାସ, ଭାଷା ବିନ୍ୟାସ, ଏବଂ ଡିଫଲ୍ଟ ମାର୍କର ଗଚ୍ଛିତ କରେ।
- `compression_combo_assignments`: ଏକ ସଙ୍କୋଚନ କମ୍ବୋକୁ ଏକ ରାଉଟିଙ୍ଗ୍ କମ୍ବୋକୁ ମାନଚିତ୍ର କରେ।
- ଚାଲିବା ସମୟ ଏକୀକରଣ ଜେନେରିକ୍ କମ୍ବୋ ଓଭରବ୍ରିଡ୍ ପୂର୍ବରୁ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ସଙ୍କୋଚନ କମ୍ବୋ ସମାଧାନ କରେ।
- ଆନାଲିଟିକ୍ସରେ `compression_combo_id` ଏବଂ `engine` ଅନ୍ତର୍ଭୁକ୍ତ।

## ପ୍ରାଥମିକତା / ଅପରେଟର୍ ଗାଇଡ୍ (CCR & session-dedup)

CCR (`ccr`) ଏବଂ `session-dedup` ଟେକ୍ସଟ୍ ବଦଳାନ୍ତୁ କିମ୍ବା ଏଲିଡ୍ କରନ୍ତୁ ଏବଂ a ଛାଡିଦିଅନ୍ତୁ।** ମାର୍କର** ପଛରେ ଏହି ବିଭାଗ ହେଉଛି ଏକ କ୍ଲାଏଣ୍ଟକୁ ତାର କରିବା, ଦୁଇଟି ମାର୍କର୍ ପ reading ିବା, ଏବଂ ଏଲିଡ୍ ବିଷୟବସ୍ତୁ ପୁନରୁଦ୍ଧାର କିମ୍ବା ନିରାକରଣ ପାଇଁ ଅପରେଟର୍ ରେଫରେନ୍ସ। ପ୍ରତ୍ୟେକ ଇଞ୍ଜିନ୍ ର ଯାନ୍ତ୍ରିକତା ଉପରେ ଆଚ୍ଛାଦିତ; ଏହା ହେଉଛି "ମୁଁ ଏହାକୁ କିପରି ଚଲାଇବି" ସ୍ତର।

### ପରିବହନ ଏବଂ ଶେଷ ପଏଣ୍ଟଗୁଡିକ।

MCP ସର୍ଭର ଯାହା CCR ଉପକରଣଗୁଡ଼ିକୁ ଉନ୍ମୋଚନ କରେ ତିନୋଟି ଉପାୟରେ ପହଞ୍ଚିପାରିବ। ଡିଫଲ୍ଟ ଆଧାର URL ହେଉଛି `http://localhost:20128` (`OMNIROUTE_BASE_URL`):

| ପରିବହନ                               | URL / ନିର୍ଦ୍ଦେଶ।                        | ଟିପ୍ପଣୀ।                                                                                                                                          |
| ------------------------------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| ଷ୍ଟ୍ରିମେବଲ୍ HTTP (କ୍ଲାଏଣ୍ଟ, ସୁପାରିଶ) | `http://localhost:20128/api/mcp/stream` | ଶେଷ ପଏଣ୍ଟ ସାମ୍ପ୍ରତିକ MCP କ୍ଲାଏଣ୍ଟମାନଙ୍କ ସହିତ କଥାବାର୍ତ୍ତା ହୁଏ।                                                                                     |
| ପୁରୁଣା SSE ସିଙ୍ଗଲେଟନ୍।               | `http://localhost:20128/api/mcp/sse`    | ପୁରୁଣା ସିଙ୍ଗଲେଟନ୍ ପରିବହନ। ଏହା** ବନ୍ଦ** ଷ୍ଟ୍ରିମେବଲ୍ ଅଧିବେଶନଗୁଡିକ; `/api/mcp/stream` ବିପକ୍ଷରେ `streamable-http` କ୍ଲାଏଣ୍ଟ ବ୍ୟବହାର କରନ୍ତୁ, ଏହା ନୁହେଁ। |
| stdio                                | `omniroute --mcp`                       | IDE MCP ବିନ୍ୟାସ ପାଇଁ ଯାହା ପ୍ରକ୍ରିୟା ସୃଷ୍ଟି କରେ। କ z ଣସି `--dev` ପତାକା ନାହିଁ; `omniroute --mcp` ହେଉଛି stdio ପ୍ରବେଶ ବିନ୍ଦୁ।                         |

### ଷ୍ଟୋରେଜ୍ ସ୍ତରଗୁଡିକ (ଯାହା ପୁନ rest ଆରମ୍ଭରୁ ବଞ୍ଚିଥାଏ)

CCR ହେଉଛି a** ଦୁଇ-ସ୍ତର** ଷ୍ଟୋର୍ କରନ୍ତୁ, କେବଳ ମେମୋରୀ ନୁହେଁ:

- **ହଟ ଇନ-ମେମୋରୀ ସ୍ତର।** — ପ୍ରତି ବ୍ଲକ୍ କ୍ୟାପ୍ 2 MiB, ପ୍ରତି-ପ୍ରିନ୍ସିପାଲ୍ 16 MiB, ଗ୍ଲୋବାଲ୍ 64 MiB। ଏଣ୍ଟ୍ରିଗୁଡିକ ଏକ 24 h TTL (ସର୍ବାଧିକ 7 ଦିନ) କୁ ଡିଫଲ୍ଟ। ସ୍ମୃତିରୁ ସମ୍ପୂର୍ଣ୍ଣ MCP ପୁନରୁଦ୍ଧାର 256 KiB ରେ କ୍ୟାପ୍ ହୋଇଛି; ରେଞ୍ଜ / grep ମୋଡ୍ ମାଧ୍ୟମରେ ବଡ଼ କିଛି ତଥାପି ଉପଲବ୍ଧ।
- **ସ୍ଥାୟୀ SQLite ସ୍ତର।** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, ଡିଫଲ୍ଟ ଭାବରେ) — ଇନ-ମେମୋରୀ ସ୍ତରକୁ ସମର୍ଥନ କରେ ତେଣୁ ଏକ ବ୍ଲକ LRU ଉଚ୍ଛେଦ, ପୁନ rest ଆରମ୍ଭ କିମ୍ବା ଅନ୍ୟ ଏକ ଅବସ୍ଥାରେ ଅବତରଣରୁ ବଞ୍ଚିଥାଏ। ଧାଡିଟି ବ୍ଲକର TTL ରଖେ, ତେଣୁ ଏହାର TTL ଅତୀତର ଏକ ବ୍ଲକ ଉଭୟ ସ୍ତରରୁ ଚାଲିଗଲା।

ତିନୋଟି ରାକ୍ଷୀ ସ୍ଥାୟୀ ସ୍ତରର ସୀମାବଦ୍ଧ — ରଖନ୍ତି ଯେତେବେଳେ ଏକ ବ୍ଲକ କେବଳ ସ୍ମୃତି ରହିଥାଏ:

1. ବ୍ଲକ୍ ସମାପ୍ତ ହୋଇଛି।** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. ଚାଲିବା ସମୟ ହେଉଛି ଏକ କ୍ଲାଉଡ୍ ଚାଲିବା ସମୟ (କ local ଣସି ସ୍ଥାନୀୟ ଡିସ୍କ ନାହିଁ);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

ତେଣୁ "ବ୍ଲକ୍ ଅଦୃଶ୍ୟ ହେଲା" ଏକ କମ୍ବଳ ପୁନ art ଆରମ୍ଭ କାହାଣୀ ନୁହେଁ: ଏକ ସ୍ଥାନୀୟ, କ୍ଲାଉଡ୍ ନଥିବା ଚାଲିବା ସମୟରେ ଏକ sub-512 KB ବ୍ଲକ୍, ଏହାର TTL ଶେଷ ନହେବା ପର୍ଯ୍ୟନ୍ତ ସ୍ଥାୟୀ ସ୍ତର ଦେଇ ପୁନ rest ଆରମ୍ଭରୁ ବଞ୍ଚିଥାଏ। ଭେରିଏବଲ୍ ପାଇଁ [ପରିବେଶ ରେଫରେନ୍ସ](../reference/ENVIRONMENT.md) ଦେଖନ୍ତୁ।

### ଗ୍ରାହକଙ୍କ ପୂର୍ବ ସର୍ତ୍ତ।

- **ଚାବି (stdio):** ଏକ stdio କଲର୍ କ per ଣସି ଅନୁରୋଧ ଅନୁରୋଧ ବହନ କରେ ନାହିଁ, ତେଣୁ ଏହା `OMNIROUTE_API_KEY` ସହିତ ପ୍ରାମାଣିକରଣ କରେ ( MCP ସର୍ଭରର `env` ରେ ସେଟ୍)। ଏହା ବିନା କଲର୍ ଅଜ୍ onymous ାତ ଏବଂ ସାଧନ ଯାହା ଏକ ମୁଖ୍ୟ ଆବଶ୍ୟକ କରେ ତାହା ଖରାପ ହୋଇପାରେ।
- **`tools[]` ହେଉଛି ଇଞ୍ଜେକ୍ସନ୍ ପୂର୍ବ ସର୍ତ୍ତ।** CCR ପୁନରୁଦ୍ଧାର-ପ୍ରୋଟୋକଲ୍ ନିର୍ଦ୍ଦେଶ (#8033) ଇଞ୍ଜେକ୍ସନ ଦିଆଯାଇଛି।** କେବଳ** ଯେତେବେଳେ ଅନୁରୋଧର ବିଜ୍ଞାପନିତ `tools[]` ପ୍ରମାଣ କରେ ଯେ ଗ୍ରାହକ ପ୍ରକୃତରେ `omniroute_ccr_retrieve` ପହଞ୍ଚି ପାରିବେ। ମ୍ୟାଚ୍ ହେଉଛି ଏକ ଟ୍ରେଲିଙ୍ଗ୍-ସେଗମେଣ୍ଟ୍ ମ୍ୟାଚ୍ ଯାହାକି ଏକ ବିଚ୍ଛିନ୍ନକର୍ତ୍ତା (`__`, `.`, `/`, `:`) — ଦ୍ୱାରା କେବେହେଲେ ଖାଲି ସବଷ୍ଟ୍ରିଙ୍ଗ୍ — ନୁହେଁ ତେଣୁ `mcp__gateway__omniroute_ccr_retrieve` ପରି ଏକ ନାମ ସ୍ଥାନ ନାମ ଗଣନା କରେ। ଏକ ଅନୁପସ୍ଥିତ କିମ୍ବା ମେଳ ଖାଉଥିବା `tools[]` ର ଅର୍ଥ ହେଉଛି ଡିଜାଇନ୍ ଦ୍ୱାରା ନିର୍ଦ୍ଦେଶଟି _not_ ଇଞ୍ଜେକ୍ସନ ନୁହେଁ।
- **`codemode:false` (OpenCode ଗ୍ରାହକ)।** OpenCode କୋଡ୍ ମୋଡ୍ କୁ ଡିଫଲ୍ଟ କରେ, ଯାହା କେବଳ ଏହାର ମୂଳ ଉପକରଣଗୁଡ଼ିକୁ ମଡେଲକୁ ବିଜ୍ଞାପନ କରେ ଏବଂ।** କରେ ନାହିଁ** ସ୍ଥାନୀୟ `tools[]` ତାଲିକାରେ MCP ସାଧନ ରଖନ୍ତୁ। MCP ସର୍ଭର ଏଣ୍ଟ୍ରିରେ `codemode: false` ସେଟ୍ କରନ୍ତୁ ତେଣୁ `omniroute_ccr_*` ଉପକରଣଗୁଡ଼ିକ ବିଜ୍ଞାପନିତ ହେବ। ଏହା ହେଉଛି** କ୍ଲାଏଣ୍ଟ** ସେଟିଂ, ଏକ OmniRoute ନୁହେଁ। ଏହା ଏପର୍ଯ୍ୟନ୍ତ CCR ନିର୍ଦ୍ଦେଶକୁ ଇଞ୍ଜେକ୍ସନ ଦେଇନାହିଁ: OpenCode ଏକ ଉପକରଣ `<server>_<tool>` ନାମ କରେ, ତେଣୁ `omniroute` ନାମକ ଏକ ସର୍ଭର `omniroute_omniroute_ccr_retrieve` ଏକ୍ସପୋଜର୍ କରେ, ଏବଂ `_` ମେଳ ହୋଇଥିବା ବିଚ୍ଛିନ୍ନକାରୀମାନଙ୍କ ମଧ୍ୟରୁ ଗୋଟିଏ ନୁହେଁ।
- **ପ୍ରିନ୍ସିପାଲ୍** ପ୍ରାମାଣିକ ପ୍ରିନ୍ସିପାଲ୍ ( API କି ପ୍ରତି) ପ୍ରତି ସଂରକ୍ଷଣ ଏବଂ ପୁନରୁଦ୍ଧାର ପୃଥକ ଅଟେ। ଏକ ଚାବି କେବଳ ନିଜର ବ୍ଲକଗୁଡିକ ଦେଖେ।

### ପୁନରୁଦ୍ଧାର ସୀମା ଏବଂ ପୃଷ୍ଠା

MCP ଟୁଲ୍ ପାଠ୍ୟ ଫଳାଫଳଗୁଡିକ `mcpAccessibility.maxTextChars` (ଡିଫଲ୍ଟ `50000`) ଉପରେ କ୍ଲିପ୍ ହୋଇଛି। ଏକ ବ୍ଲକର `full` ପୁନରୁଦ୍ଧାର 256 KiB — ରେ କ୍ୟାପ୍ ହୋଇଛି।** କ un ଣସି ସୀମାହୀନ ପୂର୍ଣ୍ଣ ପୁନରୁଦ୍ଧାର ନାହିଁ।** । ଯେତେବେଳେ ଏକ ବ୍ଲକର `chars=N` ବଡ଼, ସମଗ୍ର ଜିନିଷ ଟାଣିବା ପରିବର୍ତ୍ତେ ଏହାକୁ ପୃଷ୍ଠା କର:

- ଆଙ୍ଗୁଠିର ନିୟମ:**`chars > 40000` → ଏକ `mode` ବ୍ୟବହାର କରନ୍ତୁ।** , କଦାପି ଖାଲି ପୂର୍ଣ୍ଣ ନୁହେଁ।
- `mode:"grep"` — regex `pattern` ଧାଡ଼ିରେ ମେଳକ ରେଖା, 1000 ମେଳକ ରେଖା (`unique: true` ଡ୍ରପ୍ ପୁନରାବୃତ୍ତି), "ମୁଁ ଆବଶ୍ୟକ କରୁଥିବା ଗୋଟିଏ ଲାଇନ ଖୋଜିବା" ପାଇଁ ଶସ୍ତା ଅଟେ।
- `mode:"lines"` — ଏକ 1-ସୂଚୀବଦ୍ଧ ରେଖା ପରିସର; ଉଭୟ `start` ଏବଂ `end` ଆବଶ୍ୟକ କରେ।
- `mode:"head"` / `mode:"tail"` — first/last `n` ରେଖା।
- `mode:"stats"` — ରେଖା, ବର୍ଣ୍ଣ, ଏବଂ ବାଇଟ୍ ଶରୀର ବିନା ଗଣନା କରେ।

ସମଗ୍ର ଜିନିଷକୁ ଥରେ ଅନୁରୋଧ କରିବା ପରିବର୍ତ୍ତେ ପୃଷ୍ଠାଗୁଡ଼ିକରେ ଏକ ଲମ୍ବା ବ୍ଲକ ଚାଲିବା ପାଇଁ `start`/`end` ସହିତ `mode:"lines"` ବ୍ୟବହାର କରନ୍ତୁ।

### ସାଧନ ନାମକରଣ।

ପୁନରୁଦ୍ଧାର ଉପକରଣଟି ବର୍ତ୍ତମାନ `omniroute_ccr_retrieve` ନାମିତ ହୋଇଛି ( `omniroute_` ଉପସର୍ଗ କ୍ରସ୍-ସର୍ଭର ନାମ ଧକ୍କା ପାଇଁ ଏକ ତାରିଫ୍ ୱାର୍କଆଉଟ୍)। ଏକ କ୍ଲିନର୍ ସୀମାବଦ୍ଧ-ସଫିକ୍ସ ଟୁଲ୍ ନାମ ଏବଂ MCP JSON ଫଳାଫଳ ପାଇଁ ଏକ ଫିକ୍ସ ଅପ-ଷ୍ଟ୍ରିମ୍ ଅନୁସରଣ ଭାବରେ ଟ୍ରାକ୍ କରାଯାଏ। ଏହି ପୃଷ୍ଠା କେବଳ ସାମ୍ପ୍ରତିକ, ପଠାଯାଇଥିବା ଆଚରଣକୁ ଡକ୍ୟୁମେଣ୍ଟ୍ କରେ।

### ଅଧିବେଶନ ଜୀବନଚକ୍ର।

ଷ୍ଟ୍ରିମେବଲ୍- HTTP ଅଧିବେଶନଗୁଡ଼ିକ ନିଷ୍କ୍ରିୟ ହୋଇଯାଏ ଏବଂ ସର୍ଭର ସେମାନଙ୍କୁ ଅମଳ କରେ। ନିଷ୍କ୍ରିୟ ୱିଣ୍ଡୋ ହେଉଛି `MCP_SESSION_IDLE_MS` ସ୍ଥିର (ନାମ ଦ୍ୱାରା ସୂଚିତ, ହାର୍ଡକୋଡେଡ୍ ମୂଲ୍ୟ ନୁହେଁ, ତେଣୁ ଯେତେବେଳେ ଏହା ପରିବର୍ତ୍ତନ ହୁଏ ଏହି ପୃଷ୍ଠାଟି ଖସିଯାଏ ନାହିଁ)। ଏକ ନିଷ୍କ୍ରିୟ ଅମଳ ଅଧିବେଶନର ଲକ୍ଷଣ ହେଉଛି HTTP 404 ସହିତ `Unknown Mcp-Session-Id` — ଏହାର ପ୍ରତିକାର ହେଉଛି ଅଧିବେଶନକୁ ପୁନ nect ସଂଯୋଗ କିମ୍ବା ପୁନ art ଆରମ୍ଭ କରିବା,** ନୁହେଁ** ଏକ ଚାବି ଘୂର୍ଣ୍ଣନ କରିବା, ଏକ ପରିସର ପରିବର୍ତ୍ତନ କରିବା, କିମ୍ବା ଏକ ଉପକରଣର ନାମ ପରିବର୍ତ୍ତନ କରିବା।

## ପରିସର ଏବଂ ବହିଷ୍କାର

**ଏମ୍ବେଡିଙ୍ଗ୍ କଦାପି ସଙ୍କୋଚିତ ହୁଏ ନାହିଁ।** `open-sse/handlers/embeddings.ts` କ any ଣସି ସଙ୍କୋଚନ ଇଞ୍ଜିନ୍ — କୁ ଡାକେ ନାହିଁ request/response ସଂସ୍ଥାଗୁଡ଼ିକ ସିଧା ସଳଖ ନିର୍ବାହକାରୀଙ୍କ ନିକଟକୁ ଯାଇଥାଏ। ଆଜି ଏହା ଗଠନମୂଳକ ଅଟେ (ଏମ୍ବେଡିଂ ଏବଂ ଚାଟ୍ ସଂପୂର୍ଣ୍ଣତା ହେଉଛି ଡିଜେଣ୍ଟ୍ ହ୍ୟାଣ୍ଡେଲର୍), ଚାଲିବା ସମୟ ଯାଞ୍ଚ ନୁହେଁ, କିନ୍ତୁ ଏହାର ଅର୍ଥ ହେଉଛି #8034 ରେ ଭେକ୍ଟର-ବିକୃତି ଚିନ୍ତାର ଏମ୍ବେଡିଂ ପଥରେ କ exp ଣସି ଏକ୍ସପୋଜର ପୃଷ୍ଠ ନାହିଁ।

**Per-model/endpoint ବହିଷ୍କାର ଫିଲ୍ଟର୍ (#8034)।** ଚାଟ୍ ସମାପ୍ତି ପାଇଁ, ଜଣେ ଅପରେଟର୍ ମଡେଲ୍ ids / `provider/model` ଟାର୍ଗେଟଗୁଡିକର ନାମ ଦେଇପାରେ ଯାହାକି — ଏକ ଗାର୍ଡେୟାର୍ ଉପଯୋଗୀ ନୁହେଁ ଯଦି ସଙ୍କୋଚନ କେବେହେଲେ ଏକ ଏମ୍ବେଡିଂ-ସଂଲଗ୍ନ ପଥ ନିକଟରେ ତାର ହୋଇଯାଏ, ଏବଂ ସାଧାରଣତ any ଯେକ model ଣସି ମଡେଲ୍ ପାଇଁ ଉପଯୋଗୀ, ଯାହାର ସଠିକ୍ ବାଇଟ୍-ବାଇ-ପ୍ରମ୍ପ୍ଟ ପ୍ରମୂଖ ବିଷୟ (ନିର୍ଣ୍ଣୟକାରୀ ଇଭାଲ୍, କ୍ୟାଚ୍-ସମ୍ବେଦନଶୀଳ ଉପସର୍ଗ ଇତ୍ୟାଦି)।

- ସେଟିଙ୍ଗ୍ ଫିଲ୍ଡ: ଗ୍ଲୋବାଲ୍ ସଙ୍କୋଚନ ବିନ୍ୟାସ (`GET`/`PUT /api/settings/compression`) ଉପରେ `exclusions?: string[]`, ବିଦ୍ୟମାନ `key_value` ସଙ୍କୋଚନ ନାମ ସ୍ଥାନ (`src/lib/db/compression.ts`) — ଦ୍ୱାରା କ table ଣସି ନୂତନ ସାରଣୀ ନାହିଁ।
- ଡ୍ୟାସବୋର୍ଡ ଟ୍ୟାବ୍:** ଡ୍ୟାସବୋର୍ଡ → ସଙ୍କୋଚନ → ବହିଷ୍କାର।** (`/dashboard/compression/exclusions`)
- ପାଟର୍ନ ବାକ୍ୟବିନ୍ୟାସ: `*` ହେଉଛି ଏକମାତ୍ର ୱାଇଲ୍ଡକାର୍ଡ। ଏକ pattern ାଞ୍ଚାରେ ଥିବା ଅନ୍ୟ ସମସ୍ତ ରେଜେକ୍ସ ମେଟାକାରକ୍ଟର୍ ମେଳ ହେବା ପୂର୍ବରୁ ପଳାଇ ଯାଇଥାଏ, ତେଣୁ `gpt-5.6` କେବଳ ଆକ୍ଷରିକ ଷ୍ଟ୍ରିଙ୍ଗ ସହିତ ମେଳ ହୁଏ, କେବେବି `gpt-5x6` (ReDoS- ନିରାପଦ, ସୀମାବଦ୍ଧ, କ ested ଣସି ନାଷ୍ଟେଡ୍ କ୍ୱାଣ୍ଟିଫାୟର୍)। ପ୍ୟାଟର୍ନଗୁଡିକ ଉଭୟ ଖାଲି ମଡେଲ୍ id ଏବଂ `provider/model` କମ୍ପୋଜିଟ୍ — `gpt-5-6`, `openai/gpt-5-6`, ଏବଂ `openai/*` ବିରୁଦ୍ଧରେ କେସ୍-ସମ୍ବେଦନଶୀଳ ଭାବରେ ମେଳ ହୁଏ, ଏବଂ `*` କେବଳ ପ୍ରତ୍ୟେକ ମଡେଲକୁ ବାଦ ଦେଇଥାଏ।
- ମେଳ: `open-sse/services/compression/exclusions.ts` ରେ `isCompressionExcluded()` / `normalizeCompressionExclusions()`। ସଙ୍କୋଚନ ସେଟିଂସମୂହ ସମାଧାନ କରିବା ପରେ `chatCore.ts` ବାଦ ଦିଆଯାଇଥିବା ଲକ୍ଷ୍ୟକୁ ଯାଞ୍ଚ କରେ,** ଯେକ any ଣସି ଇଞ୍ଜିନ୍ ଚାଲିବା ପୂର୍ବରୁ।** , ଏବଂ ଏକ ମେଳକକୁ ଠିକ୍ ଭାବରେ ସଙ୍କୋଚନ ପରି ସର୍ବଭାରତୀୟ ସ୍ତରରେ ଅକ୍ଷମ ହୋଇଥିବା — ଅନୁରୋଧ ସଂସ୍ଥା ବାଇଟ୍-ସମାନ ଅଟେ। ଆନାଲିଟିକ୍ସ ଭିଜିବିଲିଟି ପାଇଁ `writeCompressionSkip(..., "excluded")` ମାଧ୍ୟମରେ ସ୍କିପ୍ ରେକର୍ଡ କରାଯାଇଛି।
- ଡିଫଲ୍ଟ (empty/absent ତାଲିକା): pre-#8034 ଆଚରଣ ସହିତ ସମାନ — କିଛି ବାଦ ଦିଆଯାଇ ନାହିଁ।

## ଜଣାଶୁଣା ସୀମା।

- **LLMLingua-2 (SLM) ସହ-ଅବସ୍ଥାନ ଇଚ୍ଛାଧୀନ ଡିପ୍ସ ଆବଶ୍ୟକ କରେ।** `@atjsh/llmlingua-2` + ସାଥୀମାନେ `dist/node_modules` ରେ ମିଳିତ ହେଲେ ଶ୍ରମିକ କେବଳ ଏକ ଉତ୍ପାଦନ ନିର୍ମାଣରେ ଚାଲିଥାଏ ( `scripts/build/colocateOptionals.mjs`, #4286 ଦେଖନ୍ତୁ)। ସେଗୁଡିକ ବିନା ଇଞ୍ଜିନ୍ ଫେଲ-ଖୋଲିବ (ମୂଳ ପାଠ୍ୟ ଫେରସ୍ତ କରେ)। ୱାର୍କର୍ ରିଜୋଲ୍ୟୁସନ୍ ଆଉ `import.meta.url` ଉପରେ ନିର୍ଭର କରେ ନାହିଁ (ଏହା ଷ୍ଟାଣ୍ଡାଲୋନ୍ ବଣ୍ଡଲରେ ମରିଯାଏ) — ଏହା ଚାଲୁଥିବା ସମୟ cwd / `argv[1]` ଉପରେ ଆଙ୍କର୍ କରେ।
- **ଗୁମ୍ଫା ଭାଷା ପ୍ୟାକ୍ `de` / `fr` / `ja` ଆଂଶିକ।** ସେମାନେ `context` + `filler` + `structural` ନିୟମ ପଠାନ୍ତି କିନ୍ତୁ `dedup` / `ultra` ପ୍ୟାକ୍ ନାହିଁ, ତେଣୁ `ultra` ତୀବ୍ରତା ସେହି ଭାଷାଗୁଡ଼ିକ ପାଇଁ `full` ଠାରୁ ଅଧିକ ଶକ୍ତିଶାଳୀ ନୁହେଁ (ସେମାନେ କେବଳ ନିଜ ନିୟମ ବ୍ୟବହାର କରନ୍ତି — ଇଂରାଜୀ `dedup`/`ultra` ନିୟମକୁ କ silent ଣସି ନୀରବ ପତନ ନୁହେଁ, ଯାହା ବିଦେଶୀ ପାଠ୍ୟକୁ ଖଣ୍ଡନ କରିବ)। `en` / `es` / `id` / `pt-BR` ସଂପୂର୍ଣ୍ଣ ଅଟେ। ଆଂଶିକ ପ୍ୟାକ୍ ପାଇଁ `dedup.json` + `ultra.json` ର ଅବଦାନ ସ୍ୱାଗତଯୋଗ୍ୟ।
- **ଷ୍ଟାକ୍ ହୋଇଥିବା ଟେଲିମେଟ୍ରି କେବଳ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରେ ଯାହା ସଙ୍କୋଚିତ ହୁଏ।** ଏକ ଷ୍ଟାକ୍-ପାଇପଲାଇନ ଷ୍ଟେପ୍ ଯାହାର ଇଞ୍ଜିନ୍ ଚାଲିଥିଲା କିନ୍ତୁ 0% ସଞ୍ଚୟ ଉତ୍ପାଦନ `stats:null` ରିଟର୍ନ କରେ ଏବଂ `engineBreakdown` — ରେ ଦେଖାଯାଏ ନାହିଁ ଯାହା ଏକ ଷ୍ଟେପ୍ ଠାରୁ ଅଲଗା ଅଟେ। "ରନ୍, 0%" କୁ "ସ୍କିପ୍" ରୁ ପୃଥକ କରିବା ଏକ ବ୍ରେକଡାଉନ୍-ମଡେଲ୍ ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ କରେ ଏବଂ ଏହାକୁ ସ୍ଥଗିତ ରଖାଯାଏ।
