OmniRoute සම්පීඩනය එන්ජින් කොන්ත්‍රාත්තු වටා ගොඩනගා ඇත. මාදිලියකට එක් එන්ජිමක් සෘජුවම ධාවනය කළ හැක (`caveman` හෝ `rtk`) හෝ බහුවිධ එන්ජින් ක්‍රියාත්මක කරන අධිෂ්ඨානාත්මක ගොඩගැසූ නල මාර්ගයක්.

### OmniGlyph සම්පීඩන පැතිකඩ

`omniglyph` එන්ජිම (පැකේජය `omniglyph`, 1.4.0 +) සංකෝචන සැකසුම් තුළ `omniglyph.profile` හරහා ගෝලීය වශයෙන් සකසන ලද හෝ ගොඩගැසූ නල මාර්ගයේ පියවර වින්‍යාසය හරහා ගෝලීය වශයෙන් සකසන ලද අර්ථකථන පැතිකඩක් පිළිගනී:

| පැතිකඩ        | මායිම                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| `aggressive`  | පෙරනිමිය. ප්‍රකාශිත ලදුපත්වල ප්‍රතිපත්තිය — රූප පද්ධතිය, මෙවලම් ලේඛන සහ ඝන ඉතිහාසය මනින ලදී            |
| `balanced`    | සජීවී රාජ්‍ය ස්වදේශිකව තබා ගනී, අවසාන හැරීම් 8 ආරක්ෂා කරයි, පැරණි සංවෘත ඉතිහාසය බිඳ දමයි               |
| `coding-safe` | අධිකාරිය, මෙවලම් යෝජනා ක්‍රම සහ සජීවී මෙවලම් ප්‍රතිදානය ස්වදේශිකව තබා ගනී, අවසාන හැරීම් 12 ආරක්ෂා කරයි |
| `passthrough` | පරිවර්තනයකින් තොරව මාර්ග; එන්ජිම මඟ හැර ඇත                                                             |

පැතිකඩ යනු a** සිවිලිම, බිමක් නොවේ** : පැකේජයේ ඇති `mergeCompressionProfileOptions` පැතිකඩ වසා ඇති පාඩු සහිත මංතීරුවක් නැවත විවෘත කිරීමට ඇමතුම්කරුවෙකුට ඉඩ දීම ප්‍රතික්ෂේප කරයි, එබැවින් එක් පියවරක් `preserveSystemPrompt: false` `coding-safe` යටතේ පද්ධති සම්පීඩනය නැවත සක්‍රිය කළ නොහැක.

මෙම කේත පදනම මත මනිනු ලැබේ: `coding-safe` සහ `balanced` එහි උපරිමයට `minCompressChars` ඉහළ නංවා පද්ධතිය, මෙවලම් ක්‍රම සහ මෙවලම් ප්‍රතිඵල ස්වදේශිකව තබා ගන්න, එබැවින් ඉතිහාසය රැස් කර නොමැති සැසියක් තවමත් `below_min_chars` හි නතර වන අතර එන්ජිම කිසිවක් පරිවර්තනය නොකරයි. ආරක්ෂිතම පැතිකඩට වඩා පෙරනිමිය `aggressive` වන්නේ එබැවිනි.

පැකේජය එහි පරිසර වින්‍යාසයෙන් තමන්ගේම ආදර්ශ විෂය පථය සහ පැතිකඩ විසඳයි. OmniRoute කිසිවිටක තීරණය පවරන්නේ නැත: ඇඩැප්ටරය පැකේජයේ වඩාත්ම සීමා සහිත විෂය පථයට ආදර්ශ ද්වාරය සවි කරයි, එබැවින් ධාරක පරිසර සැකසුම් වලට අවසර ලැයිස්තුව පටු කළ හැකිය, කිසි විටෙකත් OmniRoute හි මනින ලද කුවිතාන්සියෙන් එය පුළුල් කළ නොහැක.

## එන්ජින් රෙජිස්ට්රි

රෙජිස්ට්රි `open-sse/services/compression/engines/registry.ts` හි ජීවත් වේ. එන්ජින් හවුල් ගිවිසුමක් හෙළි කරයි:

- `id`: `caveman` හෝ `rtk` වැනි ස්ථායී එන්ජින් id
- `apply(text, config)`: ගොඩගැසූ නල මාර්ග භාවිතා කරන උරුම ක්‍රියාත්මක කිරීමේ මාර්ගය
- `compress(input, config)`: ප්‍රාථමික ක්‍රියාත්මක කිරීමේ මාර්ගය + සංඛ්‍යාලේඛන පෙළ ආපසු ලබා දෙයි
- `getConfigSchema()`: වලංගු වින්‍යාසයේ JSON-Schema වැනි හැඩය ලබා දෙයි
- `validateConfig(config)`: ආපසු `{ valid, errors[] }`

ලියාපදිංචිය `registerCompressionEngine(engine)` (හෝ උසස් අවස්ථා සඳහා `registerEngine` ) භාවිතා කරයි, එය පිළිගැනීමට පෙර `assertValidEngine()` සහ `validateConfig(defaultConfig)` අමතයි. ධාවන වේලාවේදී එන්ජිමක් ඉවත් කිරීමට `unregisterCompressionEngine(id)` භාවිතා කරන්න.

`strategySelector.ts` සම්පීඩනය ක්‍රියාත්මක වීමට පෙර ගොඩනඟන ලද එන්ජින් ලියාපදිංචි කරයි. මෙය පෙරදසුන, ධාවන කාල සම්පීඩනය, ගොඩගැසූ මාදිලිය, පරීක්ෂණ සහ අනාගත එන්ජින් එකම ක්‍රියාත්මක කිරීමේ මාර්ගය භාවිතා කිරීමට ඉඩ දෙයි.

### MCP විස්තර සම්පීඩනය (අදාළ)

වෙනම රෙජිස්ට්‍රියක් රෙජිස්ට්‍රි මට්ටමේ — හි MCP මෙවලම් විස්තර පාරදත්ත සම්පීඩනය කරයි `open-sse/mcp-server/descriptionCompressor.ts` සහ [MCP-SERVER.md](../frameworks/MCP-SERVER.md) බලන්න. එය Caveman නීති නැවත භාවිතා කරන නමුත් මෙවලම් පාරදත්ත මත ක්‍රියා කරයි, ගෙවීම් ඉල්ලීම් නොකරයි.

## ගුහා මිනිසා

Caveman මාදිලිය සාමාන්‍ය ගද්‍යයේ අර්ථකථන ඝනීභවනය කෙරෙහි අවධානය යොමු කරයි:

- කේත කුට්ටි, URLs, JSON, මාර්ග සහ ව්‍යුහගත දත්ත සංරක්ෂණය කරයි
- ෆිලර්, හෙජින්, පුනරාවර්තන සන්දර්භය සහ වාචික සම්බන්ධක වාක්‍ය ඛණ්ඩය ඉවත් කරයි
- `open-sse/services/compression/rules/` හි භාෂා දැනුවත් ගොනු රීති ඇසුරුම් සඳහා සහය දක්වයි
- උරුමය `standard`, `aggressive`, සහ `ultra` මාතයන් හරහා පවතී

උපකරණ පුවරුව මතුපිට `Dashboard -> Context & Cache -> Caveman` වේ.

Caveman upstream `~75%` අඩු ප්‍රතිදාන ටෝකන, `22-87%` පරාසයක් සහිත මිණුම් සලකුණු වල `65%` සාමාන්‍ය ප්‍රතිදාන ඉතුරුම් සහ `~46%` ආදාන-සම්පීඩන මෙවලමක් වාර්තා කරයි. OmniRoute ගොඩගැසූ prompt/context ඉතුරුම් ලේඛනගත කිරීමේදී Caveman ආදාන පැත්තේ අංකය භාවිතා කරයි; Caveman ප්‍රතිදාන මාදිලිය වෙනම ප්‍රතිචාර-හැසිරීමේ අංගයක් ලෙස පවතී.

- **දේව් / `npm install`** ඔබ `--omit=optional` (හෝ `--no-optional`) සමත් වුවහොත් මිස — ස්වයංක්‍රීයව ස්ථාපනය වේ. ක්‍රියාමාර්ග අවශ්‍ය නැත.
- **ගෝලීය npm (`npm i -g omniroute`) / ස්වාධීන** — ස්ථාපනය කරන ලද පැකේජ නාමාවලිය තුළ ඉහත ස්ථාපන විධානය ක්‍රියාත්මක කරන්න, නැතහොත් විකල්ප deps ඉවත් නොකර නැවත ස්ථාපනය කරන්න.
- **Docker** — ව්‍යුත්පන්න රූප ස්තරයක් තුළ ස්ථාපන විධානය එක් කරන්න; ප්‍රකාශිත රූපය මෝස්තරයෙන් සිහින් ය.
- **VPS (PM2)** — යෙදුමේ `node_modules` වෙත ස්ථාපනය කරන්න, ඉන්පසු ක්‍රියාවලිය නැවත ආරම්භ කරන්න එවිට සේවකයා ගේට්ටුව නැවත පරීක්ෂා කරයි.
- **Raw Next ස්වාධීන (`npm run build` → `.build/next/standalone/server.js`)** — ස්වාධීන හෝඩුවාවක් නැව් NEITHER සේවකයා හෝ විකල්ප ඩෙප්ස්, එම නිසා එන්ජිම නිහඬව අසාර්ථක-විවෘත වේ. `scripts/build/colocate-standalone.mjs` දෙකම නැවත අදාළ වේ (සේවකයා ස්වාධීන ගසට + විකල්ප-ගැඹුරු වසා දැමීම esbuild); එය සෑම ගොඩනැගීමකටම පසු `postbuild` npm කොක්ක හරහා ස්වයංක්‍රීයව ක්‍රියාත්මක වේ. Deps නොමැති විට Idempotent, fail-soft.

**එය සක්‍රිය බව තහවුරු කරන්න:** තෝරා ගත් LLMLingua සමඟ, සැබෑ ගද්‍යය සැබවින්ම හැකිලෙනු ඇත (එන්ජිම අසාර්ථක-විවෘත වීම නවත්වයි), සහ පළමු ඉල්ලීම මඟින් මාදිලිය `${DATA_DIR}/models/llmlingua` වෙත බාගත කිරීම අවුලුවයි. ගේට්ටුව හිතාමතාම අනෙක් සම වයසේ මිතුරන් ESM-පමණක් `@atjsh/llmlingua-2` — පමණක් පරීක්ෂා කරන අතර — පවතින විට පවා `require.resolve` ඔවුන් මතට විසි කරයි, එබැවින් `import()` වේලාවේදී කිසියම් සම වයසේ මිතුරෙකු සැබෑ ලෙසම අතුරුදහන් වී ඇත්නම් සේවකයා තවමත් අසාර්ථක වේ.

## ගොඩගැසූ නල මාර්ග

ගොඩගැසූ මාදිලිය නල මාර්ග පියවර අනුපිළිවෙලින් ධාවනය කරයි. පෙරනිමිය වන්නේ:

```txt
rtk -> caveman
```

ප්‍රේරකයක් විධාන ප්‍රතිදානය මානව හෝ සහකාර ගද්‍ය සමඟ ඒකාබද්ධ කරන කේත-නියෝජිත සැසි සඳහා මෙය භාවිතා කරන්න. RTK පළමුව ඝෝෂාකාරී මෙවලම් ලොග් අඩු කරයි, පසුව Caveman ඉතිරි ස්වභාවික භාෂාව සම්පීඩනය කරයි.

නල මාර්ග පියවර සම්පීඩන සැකසුම් තුළ හෝ සම්පීඩන සංයෝජන හරහා `stackedPipeline` සමඟ වින්‍යාස කර ඇත.

එන්ජින් දෙකම එකම යෝග්‍ය බර පැටවීම අඩු කරන විට, ඉතුරුම් සංයෝගය:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP ප්‍රවේශ්‍යතා ගස පෙරහන

MCP ප්‍රවේශ්‍යතා-tree ස්මාර්ට් ෆිල්ටරය යනු MCP මත ක්‍රියාත්මක වන පශ්චාත්-ක්‍රියාත්මක සම්පීඩන ස්ථරයකි.** මෙවලම් ප්රතිඵල** , විමසීම් හෝ සන්දර්භය මත නොවේ. එය Playwright, පරිගණක භාවිතය සහ බ්‍රවුසර-ස්වයංක්‍රීය MCP සේවාදායකයන් වැනි මෙවලම් මගින් ආපසු ලබා දෙන වාචික ප්‍රවේශ්‍යතා-ගස සහ බ්‍රවුසර ස්නැප්ෂොට් ගෙවීම් ඉලක්ක කරයි.

### එය කරන්නේ කුමක්ද

1. **ශබ්දය ඉවත් කිරීම** — හිස් generic/text ඇතුළත් කිරීම් ඉවත් කරයි (`- generic:`, `- text: ""`)
2. **සහෝදරයන් බිඳ වැටීම** — විට ≥ `collapseThreshold` (පෙරනිමි 30) අනුක්‍රමික රේඛා ව්‍යුහාත්මක පුනරාවර්තන වූ +, ඒවා පළමු `collapseKeepHead` ( `collapseKeepTail` 10) පේළිවලට +
3. **Ref සංරක්ෂණය** Playwright/computer-use ට අවශ්‍ය — `[ref=eXX]` නැංගුරම් කිසිවිටෙක ස්පර්ශ නොවේ
4. **දැඩි කප්පාදුව** — බිඳවැටීමෙන් පසු පෙළ තවමත් `maxTextChars` (පෙරනිමි 50,000) ඉක්මවන්නේ නම්, සංචාලන ඉඟියක් සමඟ කප්පාදු වන නිසා නියෝජිතයාට දිගටම වැඩ කළ හැක

### එන්ජිම පිහිටීම

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### මානකරනය

ගෝලීය සැකසුම් තුළ `compression.mcpAccessibility` මගින් පාලනය වේ (සංක්‍රමණය 056). පෙරනිමි වින්‍යාසය:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

පෙරහන යොදනු ලබන්නේ `type` `"text"` සහ දිග `minLengthToProcess` ඉක්මවන මෙවලම්-ප්‍රතිඵල ගෙවීම සඳහා පමණි. එය ඉක්මන් සම්පීඩනයට හෝ ගෙවීමේ ඉල්ලීමට බලපාන්නේ නැත.

### අපේක්ෂිත ඉතිරිකිරීම්

සම්පීඩන සංයෝජන මාර්ගගත සංයෝජන සඳහා පැවරිය හැකි සම්පීඩන පැතිකඩ ලෙස හැඳින්වේ:

- `compression_combos`: ගබඩා මාදිලිය, නල මාර්ගය, RTK වින්‍යාසය, භාෂා වින්‍යාසය සහ පෙරනිමි මාකර්
- `compression_combo_assignments`: සම්පීඩන සංයෝජනයක් මාර්ගගත සංයෝජනයකට සිතියම්ගත කරයි
- ධාවන කාල අනුකලනය සාමාන්‍ය සංයෝජනය අභිබවා යාමට පෙර පවරා ඇති සම්පීඩන සංයෝජනයක් විසඳයි
- විශ්ලේෂණවලට `compression_combo_id` සහ `engine` ඇතුළත් වේ

උපකරණ පුවරුව මතුපිට: `Dashboard -> Context & Cache -> Compression Combos`.

## පූර්ව අවශ්‍යතා / ක්‍රියාකරු මාර්ගෝපදේශය (CCR සහ සැසිය-ඩෙඩප්)

CCR (`ccr`) සහ `session-dedup` අකුරු ප්‍රතිස්ථාපනය හෝ elide කර අ** සලකුණ** පිටුපසින්. මෙම කොටස සේවාලාභියෙකු රැහැන්ගත කිරීම, සලකුණු දෙක කියවීම සහ ඉවත් කළ අන්තර්ගතය ලබා ගැනීම හෝ රෝග විනිශ්චය කිරීම සඳහා ක්‍රියාකරු යොමු වේ. එක් එක් එන්ජිමෙහි යාන්ත්රික ඉහත ආවරණය කර ඇත; මෙය "මම එය ධාවනය කරන්නේ කෙසේද" ස්ථරයයි.

### ගබඩා ස්ථර (නැවත ආරම්භ කිරීමේදී ඉතිරිව ඇති දේ)

CCR යනු a** ද්වි-ස්ථර** ගබඩාව, මතකයේ පමණක් නොවේ:

- **මතකයේ උණුසුම් ස්ථරය** — per-block cap 2 MiB, per-principal 16 MiB, global 64 MiB. 24 h TTL (උපරිම දින 7) වෙත පෙරනිමි ඇතුළත් කිරීම්. මතකයෙන් සම්පූර්ණ MCP ලබා ගැනීම 256 KiB දක්වා සීමා කර ඇත; විශාල ඕනෑම දෙයක් තවමත් පරාසයක / grep මාතයන් හරහා ළඟා විය හැක.
- **කල් පවතින SQLite ස්ථරය** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, පෙරනිමියෙන් සක්‍රියයි) — මතකයේ ඇති ස්ථරයට පිටුබලය දෙයි, එබැවින් බ්ලොක් එකක් LRU ඉවත් කිරීම, නැවත ආරම්භ කිරීම හෝ වෙනත් අවස්ථාවක ගොඩබෑමකින් බේරෙයි. පේළිය බ්ලොක් එකේ TTL තබා ගනී, එබැවින් එහි TTL පසු කර ඇති බ්ලොක් එකක් ස්ථර දෙකෙන් ඉවත් වේ.

ආරක්ෂකයින් තිදෙනෙක් කල් පවතින ස්ථරයට සීමා වූ — රඳවා තබා ගනී.

1. අවහිරය අවසන්** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. ධාවන කාලය වලාකුළු ධාවන කාලයකි (දේශීය තැටියක් නොමැත);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

එබැවින් "බ්ලොක් අතුරුදහන්" යනු බ්ලැන්කට් නැවත ආරම්භ කිරීමේ කතාවක් නොවේ: දේශීය, වලාකුළු නොවන ධාවන කාලයක sub-512 KB බ්ලොක් එකක් එහි TTL අවසන් වන තෙක් කල් පවතින ස්ථරය හරහා නැවත ආරම්භ කිරීමකින් බේරී ඇත. විචල්‍යය සඳහා [පරිසර යොමුව](../reference/ENVIRONMENT.md) බලන්න.

### සේවාලාභී පූර්වාවශ්යතාවයන්

- **යතුර (stdio):** stdio ඇමතුම්කරුට ඉල්ලීම් සඳහා අනන්‍යතාවයක් නොමැත, එබැවින් එය `OMNIROUTE_API_KEY` සමඟ සත්‍යාපනය කරයි ( MCP සේවාදායකයේ `env`). එය නොමැතිව අමතන්නා නිර්නාමික වන අතර විදුහල්පතිවරයෙකු අවශ්‍ය මෙවලම් පිරිහීමට ලක් විය හැක.
- **`tools[]` is the injection precondition.** The CCR retrieve-protocol instruction (#8033) is injected **only** when the request's advertised `tools[]` proves the client can actually reach `omniroute_ccr_retrieve`. The match is a trailing-segment match bounded by a separator (`__`, `.`, `/`, `:`) — never a bare substring — so a namespaced name such as `mcp__gateway__omniroute_ccr_retrieve` still counts. An absent or non-matching `tools[]` means the instruction is _not_ injected, by design.
- **`codemode:false` (OpenCode සේවාදායකයින්).** OpenCode කේත ප්‍රකාරයට පෙරනිමි වේ, එය එහි ස්වදේශීය මෙවලම් පමණක් ආකෘතියට ප්‍රචාරණය කරයි** කරන්නේ නැහැ** දේශීය `tools[]` ලැයිස්තුවට MCP මෙවලම් දමන්න. MCP සේවාදායක ප්‍රවේශය මත `codemode: false` සකසන්න එවිට `omniroute_ccr_*` මෙවලම් ප්‍රචාරණය වේ. මෙය අ** සේවාදායකයා** සැකසීම, OmniRoute එකක් නොවේ. එය තවමත් CCR උපදෙස් එන්නත් කර නැත: OpenCode `<server>_<tool>` මෙවලමක් නම් කරයි, එබැවින් `omniroute` නම් සේවාදායකයක් `omniroute_omniroute_ccr_retrieve` නිරාවරණය කරයි, සහ `_` ගැලපෙන බෙදුම්කරුවන්ගෙන් එකක් නොවේ.
- **විදුහල්පතිවරු.** ගබඩා කිරීම සහ ලබා ගැනීම සත්‍යාපිත ප්‍රධානයකට ( API යතුරකට) හුදකලා වේ. යතුරක් දකින්නේ තමන්ගේම කුට්ටි පමණි.

### එක් මෙවලමක් සඳහා විෂය පථය

පටු පරාසයක HTTP/SSE අමතන්නන් සඳහා විෂය පථය බලාත්මක කිරීම සැමවිටම ක්‍රියාත්මක වේ. `omniroute_` CCR මෙවලම් සඳහා අවශ්‍ය වන්නේ:

| මෙවලම                    | විෂය පථය            |
| ------------------------ | ------------------- |
| `omniroute_ccr_store`    | `write:compression` |
| `omniroute_ccr_delete`   | `write:compression` |
| `omniroute_ccr_retrieve` | `read:compression`  |
| `omniroute_ccr_inspect`  | `read:compression`  |
| `omniroute_ccr_list`     | `read:compression`  |
| `omniroute_ccr_stats`    | `read:compression`  |

නැතිවූ විෂය පථයක් නැවත ලබා දෙයි**MCP මෙවලම් දෝෂ ප්රතිඵලය** (`isError: true`, HTTP 403 — නොවේ `403 LOCAL_ONLY` යනු වෙනම loopback route-guard auth වේ): `Error: Insufficient MCP scopes for <tool>. Missing: <scope>.` අවම දුරස්ථ යතුරක් `mcp:connect` ( `/api/mcp/` දේශීය-පමණක් කැටයම් කිරීමට අවසර දෙයි) සහ එයට අවශ්‍ය නිශ්චිත read/write විෂය පථය රඳවා ගත හැක.

### ලබා ගැනීමේ සීමාවන් සහ පිටුකරණය

MCP මෙවලම් පෙළ ප්‍රතිඵල `mcpAccessibility.maxTextChars` වටා කපා ඇත (පෙරනිමි `50000`). බ්ලොක් එකක `full` ලබා ගැනීමක් 256 KiB — ට සීමා කර ඇත** අසීමිත සම්පූර්ණ ලබා ගැනීමක් නොමැත** . බ්ලොක් එකක `chars=N` විශාල වන විට, සම්පූර්ණ දේ අදින්නේ වෙනුවට එය පිටුව කරන්න:

- මාපටැඟිල්ලේ රීතිය:**`chars > 40000` → `mode` භාවිතා කරයි** , කිසිවිටෙක හිස් පිරී නැත.
- `mode:"grep"` — regex `pattern` ගැලපෙන පේළි 1,000ක් දක්වා (`unique: true` drops repeats), ලාභම "මට අවශ්‍ය එක් පේළියක් සොයා ගන්න"
- `mode:"lines"` — 1-සුචිගත රේඛා පරාසයක්; `start` සහ `end` දෙකම අවශ්‍යයි.
- `mode:"head"` / `mode:"tail"` — first/last `n` රේඛා.
- `mode:"stats"` — රේඛාව, චරිතය සහ බයිට් ශරීරය නොමැතිව ගණන් කරයි.

මුළු දේම එකවර ඉල්ලනවාට වඩා පිටු තුළ දිගු අවහිරයක් ඇවිදීමට `start`/`end` සමඟ `mode:"lines"` භාවිතා කරන්න.

### මෙවලම් නම් කිරීම

ලබා ගැනීමේ මෙවලම දැනට `omniroute_ccr_retrieve` ලෙස නම් කර ඇත ( `omniroute_` උපසර්ගය යනු හරස්-සේවාදායක නාම ගැටීම් සඳහා දින නියම කරන ලද විසඳුමකි). පිරිසිදු සීමා සහිත-ප්‍රත්‍ය මෙවලම් නාමයක් සහ MCP JSON ප්‍රතිඵල සඳහා විසඳුමක් කප්පාදු කරන ලද මැද-තැටියේ උඩුගත කිරීම් පසු විපරම් ලෙස නිරීක්ෂණය කරනු ලැබේ; මෙම පිටුව වත්මන්, නැව්ගත කළ හැසිරීම පමණක් ලේඛනගත කරයි.

### සැසියේ ජීවන චක්රය

ප්‍රවාහ කළ හැකි-HTTP සැසි අක්‍රිය වන අතර සේවාදායකය ඒවා ලබා ගනී; නිෂ්ක්‍රීය කවුළුව `MCP_SESSION_IDLE_MS` නියතයයි (නම මගින් සඳහන් කර ඇත, දෘඪ කේත අගයක් නොවේ, එබැවින් මෙම පිටුව වෙනස් වන විට ප්ලාවිත නොවේ). idle-reaped සැසියක රෝග ලක්ෂණය වන්නේ `Unknown Mcp-Session-Id` — සමඟ HTTP 404 වේ, පිළියම වන්නේ සැසිය නැවත සම්බන්ධ කිරීම හෝ නැවත ආරම්භ කිරීමයි,** නැත** යතුරක් කරකවීමට, විෂය පථය වෙනස් කිරීමට හෝ මෙවලමක් නැවත නම් කිරීමට.

## විෂය පථය සහ බැහැර කිරීම්

**කාවැද්දීම කිසි විටෙක සම්පීඩිත නොවේ.** `open-sse/handlers/embeddings.ts` කිසිවිටෙකත් කිසිදු සම්පීඩන එන්ජිමක් — request/response හඳුන්වන්නේ නැත. මෙය අද දින ව්‍යුහාත්මක වේ (Embeddings සහ chat completions is disjoint handlers), ධාවන කාල පරික්ෂාවක් නොවේ, නමුත් එයින් අදහස් වන්නේ #8034 හි දෛශික-විකෘති සැලකිල්ලට embeddings මාර්ගයෙහි නිරාවරණ මතුපිටක් නොමැති බවයි.

**Per-model/endpoint බැහැර කිරීමේ පෙරහන (#8034).** කතාබස් සම්පූර්ණ කිරීම සඳහා, ක්‍රියාකරුවෙකුට කිසි විටෙක සම්පීඩනය නොකළ යුතු ආදර්ශ ids / `provider/model` ඉලක්ක නම් කළ හැක — සම්පීඩනය කවදා හෝ පසුව කාවැද්දීම යාබද මාර්ගයකට සමීපව වයර් කර ඇත්නම් ප්‍රයෝජනවත් වන අතර, සාමාන්‍යයෙන් බයිට් සඳහා-බයිට් සඳහා ප්‍රමාද වන කරුණු (නිශ්චය කිරීම, පූර්ව නිර්ණය, ආදිය) ඕනෑම ආකෘතියක් සඳහා ප්‍රයෝජනවත් වේ.

- සැකසුම් ක්ෂේත්‍රය: ගෝලීය සම්පීඩන වින්‍යාසය (`GET`/`PUT /api/settings/compression`) මත `exclusions?: string[]`, පවතින `key_value` සම්පීඩන නාම අවකාශය (`src/lib/db/compression.ts`) — හරහා නව වගුවක් නොමැත.
- උපකරණ පුවරු ටැබය:** උපකරණ පුවරුව → සම්පීඩන → බැහැර කිරීම්** (`/dashboard/compression/exclusions`)
- රටා වාක්‍ය ඛණ්ඩය: `*` යනු එකම Wildcard වේ. රටාවක ඇති අනෙක් සෑම regex metacharacter එකක් ගැලපීමට පෙර ගැලවී යයි, එබැවින් `gpt-5.6` ගැලපෙන්නේ වචනාර්ථ තන්තුවට පමණි, කිසි විටෙකත් `gpt-5x6` නොවේ (ReDoS-safe, bounded, nested quantifiers නැත). නිරුවත් මාදිලි හැඳුනුම්පත සහ `provider/model` සංයුක්ත — `gpt-5-6`, `openai/gpt-5-6`, සහ `openai/*` යන දෙකටම එරෙහිව රටා අසංවේදී ලෙස ගැලපේ, සහ `*` පමණක් සෑම ආකෘතියක්ම බැහැර කරයි.
- ගැලපීම: `isCompressionExcluded()` / `normalizeCompressionExclusions()` in `open-sse/services/compression/exclusions.ts`. `chatCore.ts` සම්පීඩන සැකසුම් නිරාකරණය කිරීමෙන් පසු ඉවත් කළ ඉලක්කය පරීක්ෂා කරයි,** ඕනෑම එන්ජිමක් ධාවනය වීමට පෙර** , සහ සංකෝචනය ගෝලීය වශයෙන් අක්‍රිය — ලෙස ගැළපීමක් සලකයි, ඉල්ලීම් අන්තර්ගතය ඔප්පු කළ හැකි පරිදි බයිට සමාන වේ. විශ්ලේෂණ දෘශ්‍යතාව සඳහා මඟහැරීම `writeCompressionSkip(..., "excluded")` හරහා සටහන් වේ.
- පෙරනිමිය (empty/absent ලැයිස්තුව): පෙර-#8034 හැසිරීම් — ට සමාන කිසිවක් බැහැර නොකෙරේ.

## දන්නා සීමාවන්

- **LLMLingua-2 (SLM) සඳහා සම-ස්ථානගත විකල්ප ඩෙප්ස් අවශ්‍ය වේ.** `@atjsh/llmlingua-2` + සම වයසේ මිතුරන් `dist/node_modules` වෙත සම-ස්ථානගත වූ විට පමණක් සේවකයා නිෂ්පාදන ගොඩනැගීමක ධාවනය කරයි ( `scripts/build/colocateOptionals.mjs`, #4286 බලන්න). ඒවා නොමැතිව එන්ජිම අසමත් වීම විවෘත වේ (මුල් පිටපත ආපසු ලබා දෙයි). සේවක විභේදනය තවදුරටත් `import.meta.url` මත රඳා නොපවතී (එය ස්වාධීන බණ්ඩලය තුළ මිය යයි) — එය ධාවන කාලය මත නැංගුරම් දමයි cwd / `argv[1]`.
- **Caveman භාෂා ඇසුරුම් `de` / `fr` / `ja` අර්ධ වේ.** ඔවුන් `context` + `filler` + `structural` නීති නැව්ගත කරන නමුත් `dedup` / `ultra` ඇසුරුම් නොමැත, එබැවින් එම භාෂා සඳහා `ultra` තීව්‍රතාවය `full` වලට වඩා ප්‍රබල නොවේ (ඔවුන් භාවිතා කරන්නේ ඔවුන්ගේම නීති — පමණි, ඉංග්‍රීසි `dedup`/`ultra` නීති වලට නිහඬ වැටීමක් නොමැත, එය මැංගල් වනු ඇත). `en` / `es` / `id` / `pt-BR` සම්පූර්ණයි. අර්ධ ඇසුරුම් සඳහා `dedup.json` + `ultra.json` හි දායකත්වය සාදරයෙන් පිළිගනිමු.
- **Stacked telemetry ලැයිස්තුගත කරන්නේ සම්පීඩිත එන්ජින් පමණි.** එන්ජිම ක්‍රියාත්මක වූ නමුත් 0 % ඉතුරුම් ප්‍රතිලාභ `stats:null` නිපදවන ලද ගොඩගැසී ඇති නල මාර්ග පියවරක් `engineBreakdown` — හි මඟ හැරුණු පියවරකින් වෙන්කර හඳුනාගත නොහැකි ලෙස දිස් නොවේ. "පැන, 0 %" "මඟ හැරිය" වෙතින් වෙන්කර හඳුනා ගැනීම සඳහා බිඳවැටීම්-ආකෘති වෙනසක් අවශ්‍ය වන අතර එය කල් දමනු ලැබේ.
