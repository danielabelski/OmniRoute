Сжатие OmniRoute построено на контрактах движка. Режим может запускать один механизм напрямую (`caveman` или `rtk`) или детерминированный составной конвейер, который выполняет несколько механизмов по порядку.

## Режимы

| Режим        | Путь двигателя                                                                                      | Предполагаемый ввод                                           |
| ------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `off`        | никто                                                                                               | Точная оперативная сохранность                                |
| `lite`       | Облегченные помощники Caveman                                                                       | Постоянная очистка с низким уровнем риска                     |
| `standard`   | Пещерный человек                                                                                    | Быстрое сжатие речи на естественном языке                     |
| `aggressive` | Caveman + history/tool сумматоры                                                                    | Длинные сеансы чата                                           |
| `ultra`      | Помощники по обрезке Caveman +                                                                      | Восстановление ограничения контекста                          |
| `rtk`        | RTK                                                                                                 | Терминал, оболочка, сборка, тестирование и вывод git          |
| `omniglyph`  | OmniGlyph                                                                                           | Контекст как изображение на собственном проводе провайдера    |
| `stacked`    | Трубопровод. По умолчанию запрос — `session-dedup -> lite`. `rtk -> caveman` является добровольным. | Смешанные журналы инструментов и проза, максимальная экономия |

### профили сжатия OmniGlyph

Механизм `omniglyph` (пакет `omniglyph`, 1.4.0 +) принимает именованный семантический профиль, устанавливаемый глобально через `omniglyph.profile` в настройках сжатия или для каждого шага через конфигурацию шага составного конвейера:

| Профиль       | Граница                                                                                                                                |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `aggressive`  | По умолчанию. Политика опубликованных квитанций измеряла систему изображений —, документацию по инструментам и плотную историю.        |
| `balanced`    | Сохраняет живое состояние, защищает последние 8 ходов, сворачивает старую закрытую историю                                             |
| `coding-safe` | Сохраняет авторитетность, схемы инструментов и выходные данные работающих инструментов в исходном виде, защищает последние 12 оборотов |
| `passthrough` | Маршруты без трансформации; двигатель пропущен                                                                                         |

Профиль представляет собой** потолок, а не пол** : `mergeCompressionProfileOptions` в пакете отказывается позволить вызывающему абоненту переопределить повторное открытие полосы с потерями, профиль закрыт, поэтому пошаговый `preserveSystemPrompt: false` не может повторно включить сжатие системы под `coding-safe`.

Измерено на этой базе кода: `coding-safe` и `balanced` поднимают `minCompressChars` до максимума и сохраняют систему, схемы инструментов и результаты инструментов «родными», поэтому сеанс, который еще не накопил историю, останавливается на `below_min_chars`, и движок ничего не преобразует. Вот почему по умолчанию используется `aggressive`, а не самый безопасный профиль.

Пакет определяет свою собственную область и профиль модели из конфигурации своей среды. OmniRoute никогда не делегирует принятие решения: адаптер закрепляет ворота модели в самой строгой области действия пакета, поэтому настройки среды хоста могут только сузить список разрешенных, но никогда не расширять его сверх измеренных поступлений OmniRoute.

## Реестр двигателя

Реестр находится в `open-sse/services/compression/engines/registry.ts`. Движки предоставляют общий контракт:

- `id`: стабильный идентификатор движка, например `caveman` или `rtk`
- `apply(text, config)`: устаревший путь выполнения, используемый составными конвейерами.
- `compress(input, config)`: основной путь выполнения, возвращающий текстовую статистику +
- `getConfigSchema()`: возвращает форму допустимой конфигурации, подобную JSON-схеме.
- `validateConfig(config)`: возвращает `{ valid, errors[] }`

При регистрации используется `registerCompressionEngine(engine)` (или `registerEngine` для сложных случаев), который перед принятием вызывает `assertValidEngine()` и `validateConfig(defaultConfig)`. Используйте `unregisterCompressionEngine(id)` для удаления механизма во время выполнения.

`strategySelector.ts` регистрирует встроенные механизмы перед запуском сжатия. Это позволяет предварительному просмотру, сжатию времени выполнения, многоуровневому режиму, тестам и будущим механизмам использовать один и тот же путь выполнения.

### Сжатие описания MCP (связанное)

Отдельный реестр сжимает метаданные описания инструмента MCP на уровне реестра — см. `open-sse/mcp-server/descriptionCompressor.ts` и [MCP-SERVER.md](../frameworks/MCP-SERVER.md). Он повторно использует правила Caveman, но работает с метаданными инструмента, а не с запросами полезных данных.

### Дополнительные встроенные двигатели

Помимо Caveman, RTK и LLMLingua-2, в реестр входит несколько специализированных структурных движков без потерь (используемых многоуровневыми конвейерами, игровой площадкой и тестами):

| Двигатель           | Идентификатор   | Что он делает                                                                                                                                                                                      |
| ------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CCR                 | `ccr`           | Content-Compress-Retrieve (H4): заменяет большие непрерывные текстовые блоки ссылками, адресованными по содержимому, поэтому блоки repeated/large отправляются один раз, а затем на них ссылаются. |
| запас по высоте     | `headroom`      | SmartCrusher (H3 + N5): табличное сжатие без потерь однородных полезных данных массива JSON в столбчатую форму `[N rows]`.                                                                         |
| ионизатор           | `ionizer`       | Выборка строк Head/middle/tail для очень больших однородных блоков с сохранением пропущенной середины как ссылки с адресом содержимого CCR.                                                        |
| дедупликация сеанса | `session-dedup` | Межповоротная дедупликация с адресацией содержимого (на основе TokenMizer): удаляет текст, уже замеченный на предыдущих этапах того же сеанса.                                                     |

**Инструкция протокола получения CCR (#8033):** когда CCR в первый раз заменяет блок ≥ 1 в запросе, движок добавляет одно идемпотентное сообщение `system` (начинающееся с дозорного `[CCR protocol]` ), обучающее вызывающую сторону маркеру контракт инструмента → : что означает маркер `[CCR retrieve hash=<24hex> chars=N]`, что хэш должен быть скопирован дословно (все 24 шестнадцатеричных символа, неправильно скопированные хэши — являются вероятной причиной промахов «блок не найден») и что маркер `[dedup:ref sha=...]` означает «оглянуться назад в историю», а не «вызвать инструмент». Примечание вводится** только тогда, когда объявленный `tools[]` вызывающего абонента доказывает, что он действительно может достичь `omniroute_ccr_retrieve`** (`callerSupportsCcrRetrieve()` в `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — простой OpenAI-совместимый вызывающий объект без этого инструмента никогда не получает инструкции на вызов чего-то, чего он не может достичь. Идемпотентность обеспечивается путем сканирования истории сообщений дозорного перед внедрением, поэтому многоходовые запросы (которые воспроизводят предыдущие сообщения) не складывают заметку один раз за ход.

## Пещерный человек

Режим «Пещерный человек» фокусируется на семантической конденсации обычной прозы:

- сохраняет блоки кода, URLs, JSON, пути и структурированные данные
- удаляет наполнители, избежания, повторяющийся контекст и многословные соединительные фразы.
- поддерживает языковые пакеты правил для файлов в `open-sse/services/compression/rules/`
- остается доступным в устаревших режимах `standard`, `aggressive` и `ultra`

Поверхность приборной панели — `Dashboard -> Context & Cache -> Caveman`.

Caveman upstream сообщает о меньшем количестве выходных токенов `~75%`, средней экономии выходных данных `65%` в тестах с диапазоном `22-87%` и об инструменте сжатия входных данных `~46%`. OmniRoute использует входной номер Caveman при документировании накопленной экономии prompt/context ; Режим вывода «Пещерный человек» остается отдельной функцией реагирования.

## RTK

Режим RTK фокусируется на выводе команд и инструментов:

- обнаруживает классы вывода, такие как `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, тесты Cargo/Go, сборки TypeScript/Vite/Webpack, ESLint, npm audit/installs, журналы Docker, оболочка `find`/`grep`, трассировки стека и общие журналы
- применяет 49 фильтров JSON из `open-sse/services/compression/engines/rtk/filters/`
- поддерживает декларативный конвейер в стиле RTK: удаление ANSI, замена, короткое замыкание при совпадении вывода, строки strip/keep, построчное усечение, усечение head/tail/max-line и возврат к пустому состоянию.
- поддерживает фильтры проектов с контролем доверия в `.rtk/filters.json` и глобальные фильтры в `DATA_DIR/rtk/filters.json`
- удаляет последовательности ANSI, шум прогресса, повторяющиеся строки и бесполезный шаблон
- сохраняет сбои, предупреждения, сводки, измененные файлы и хвостовой контекст, требующие принятия мер.
- при желании можно сохранить отредактированные необработанные выходные данные для recovery/debugging через аутентифицированные маршруты управления.

Поверхность приборной панели — `Dashboard -> Context & Cache -> RTK`.

Подробные сведения о пользовательских фильтрах, доверии, проверке и восстановлении необработанных данных хранятся в [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md).

RTK upstream сообщает об экономии `60-90%` при сжатии вывода команд. В примере с README показан 30-минутный сеанс кода Claude, который переходит от токенов `~118,000` к `~23,900` или сохраненному `79.7%`.

## LLMLingua-2 (семантическая обрезка)

режим LLMLingua-2 выполняет** семантическая обрезка токенов** на прозе с использованием небольшого классификатора токенов ONNX, дополняющего основанные на правилах механизмы Caveman и RTK :

- сжимает прозу только в несистемных сообщениях; изолированные блоки кода и другие сохраненные конструкции никогда не изменяются.
- запускает серверную часть `@atjsh/llmlingua-2` (ONNX через `@huggingface/transformers`) в рабочем потоке, поэтому вывод модели никогда не блокирует цикл событий запроса
- является** штабелируемый** (`stackPriority` 35): в составном конвейере он выполняется после структурных механизмов (CCR, session-dedup, headroom, Caveman), но перед `ultra`, поскольку семантическая обрезка наиболее эффективна для уже структурно сжатого текста — например `rtk -> caveman -> llmlingua`
- **отказоустойчиво открывается при любой ошибке** (отсутствуют необязательные deps, появление рабочих, загрузка модели, вывод или тайм-аут) → исходный текст возвращается без изменений, никогда не возникает ошибок

Расположение двигателя: `open-sse/services/compression/engines/llmlingua/`. Поверхность приборной панели — `Dashboard -> Context & Cache -> LLMLingua`.

### Модели

Модель по умолчанию**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~ 57 MB, быстро). Более высокая точность** BERT-база** Модель (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) доступна через поле конфигурации двигателя `model`. `@huggingface/transformers` лениво загружает выбранную модель из HuggingFace Hub в `${DATA_DIR}/models/llmlingua` при первом вызове (`modelStore.ts`); переопределение конфигурации `modelPath` вместо этого указывает на локальную копию (автономная установка/установка с воздушным зазором).

### Дополнительные зависимости и установка по требованию

Обрезаемый одноранговый стек среды выполнения LLMLingua :** необязательный** . Два пакета объявлены как `optionalDependencies` в `package.json` и сохранены.** внешний** по производственной сборке (`scripts/build/prepublish.ts` не включает их в комплект):

| Упаковка             | Версия (контакт) | Примечания                                 |
| -------------------- | ---------------- | ------------------------------------------ |
| `@atjsh/llmlingua-2` | `2.0.5`          | Входной пакет; объявляет остальных равными |
| `js-tiktoken`        | `^1.0.20`        | токенизатор                                |

`@huggingface/transformers` закреплен на `^4.2.0` (совместно с локальным путем внедрения, а также отслеживается в автономном пакете); `@atjsh/llmlingua-2@2.0.5` подключается к нему через `"^3.5.2 || ^4.0.0"`, поэтому поддерживаются как Transformers.js v3, так и v4. Начиная с версии 2.0.4, `@atjsh/llmlingua-2` больше не требует `@tensorflow/tfjs`, что привело к удалению крупнейшего участника (TensorFlow.js) из стека SLM. Только два вышеперечисленных пакета являются удаляемыми узлами SLM. Стандартный `npm install` (dev) автоматически устанавливает дополнительный стек, если не опущены необязательные зависимости.

**Почему по требованию:** пакет, опубликованный npm, автономный пакет и поставка образа Docker** без** эти глубины, чтобы оставаться стройными. Когда они отсутствуют, шлюз зависимости работника (зонд разрешения `@atjsh/llmlingua-2` в `worker.ts`) выходит из строя, и механизм** отказ-открывается бесшумно** — выбрав LLMLingua становится неактивным (текст возвращается без изменений, ошибки не регистрируются). Чтобы активировать его в сокращенной среде, установите дополнительный стек:

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

Удаление `@tensorflow/tfjs` (2.0.4 +) устраняет ранее доминирующего участника ~ 800 MB — оставшийся след — это среда выполнения transformers.js + onnxruntime-node, а также модель TinyBERT (~ 57 MB), загружаемая при первом использовании (не через npm).

Для каждой среды:

- **Дев / `npm install`** — устанавливается автоматически, если вы не передали `--omit=optional` (или `--no-optional`). Никаких действий не требуется.
- **Глобальный npm (`npm i -g omniroute`)/автономный** — запустите приведенную выше команду установки внутри каталога установленного пакета или переустановите, не пропуская необязательные deps.
- **Docker** — добавить команду установки в слой производного образа; опубликованное изображение имеет тонкий дизайн.
- **VPS (PM2)** — установите в `node_modules` приложения, затем перезапустите процесс, чтобы рабочий повторно проверил ворота.
- **Автономный формат Raw Next (`npm run build` → `.build/next/standalone/server.js`)** — автономная трассировка, NEITHER ни рабочий, ни дополнительные deps, поэтому движок автоматически открывается при сбое. `scripts/build/colocate-standalone.mjs` повторно применяет оба (закрытие worker esbuild + option-dep в автономном дереве); он запускается автоматически через перехватчик `postbuild` npm после каждой сборки. Идемпотентный, отказоустойчивый при отсутствии deps.

**Убедитесь, что он активен:** при выборе LLMLingua реальная проза фактически сжимается (движок перестает открываться при сбое), и первый запрос запускает загрузку модели в `${DATA_DIR}/models/llmlingua`. Шлюз намеренно проверяет только `@atjsh/llmlingua-2` — остальные одноранговые узлы доступны только для ESM, и `require.resolve` выдает им ошибку, даже если присутствует — поэтому рабочий объект все равно открывается при сбое, если какой-либо одноранговый узел действительно отсутствует во время `import()`.

## Многоуровневые трубопроводы

В стековом режиме этапы конвейера выполняются по порядку. По умолчанию:

```txt
rtk -> caveman
```

Используйте это для сеансов агента кодирования, где подсказка сочетает вывод команды с текстом человека или помощника. RTK сначала уменьшает шум в журналах инструментов, затем Caveman сжимает оставшийся естественный язык.

Шаги конвейера настраиваются с помощью `stackedPipeline` в настройках сжатия или с помощью комбинаций сжатия.

Когда оба двигателя уменьшают одинаковую допустимую полезную нагрузку, экономия увеличивается:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## Фильтр дерева доступности MCP

Интеллектуальный фильтр дерева доступности MCP — это уровень сжатия после выполнения, который работает на MCP** результаты инструмента** , а не в подсказках или контексте. Он нацелен на подробные полезные данные дерева доступности и снимков браузера, возвращаемые такими инструментами, как Playwright, серверы MCP для использования на компьютере и автоматизации браузера.

### Что он делает

1. **Удаление шума** — удаляет пустые записи generic/text (`- generic:`, `- text: ""`)
2. **Братский коллапс** — когда ≥ `collapseThreshold` (по умолчанию 30) последовательные строки являются структурными повторами, сжимает их в первые строки `collapseKeepHead` (по умолчанию 10) + сводку подсчета + последние строки `collapseKeepTail` (по умолчанию 5)
3. **Сохранение ссылки** — Якоря `[ref=eXX]`, необходимые для Playwright/computer-use никогда не затрагиваются
4. **Жесткое усечение** — если текст после свертывания по-прежнему превышает `maxTextChars` (по умолчанию 50 000), усекается с помощью навигационной подсказки, чтобы агент мог продолжить работу

### Расположение двигателя

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### Конфигурация

Управляется `compression.mcpAccessibility` в глобальных настройках (миграция 056). Конфигурация по умолчанию:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

Фильтр применяется только к полезным данным результатов инструмента, `type` которых равен `"text"` и длина которых превышает `minLengthToProcess`. Это не влияет на оперативное сжатие или полезные данные запроса.

### Ожидаемая экономия

60–80 % на результаты инструмента создания снимков браузера, в зависимости от сложности страницы. Алгоритм коллапса имеет количество строк O(n) и добавляет незначительную задержку.

### Этот фильтр против двигателей сжатия выше

| Аспект          | Пещерный человек / RTK / Сложенный | фильтр доступности MCP                 |
| --------------- | ---------------------------------- | -------------------------------------- |
| Цель            | Запросить подсказки/контекст       | результаты инструмента MCP             |
| Курок           | Настройка режима сжатия            | `compression.mcpAccessibility.enabled` |
| Объем           | Все сообщения SSE                  | Только результаты инструмента          |
| Ссылочные якоря | N/A                                | Сохраняется безоговорочно              |

## Комбинации сжатия

Комбинации сжатия — это именованные профили сжатия, которые можно назначать комбинациям маршрутизации:

- `compression_combos`: сохраняет режим, конвейер, конфигурацию RTK, языковую конфигурацию и маркер по умолчанию.
- `compression_combo_assignments`: сопоставляет комбинацию сжатия с комбинацией маршрутизации.
- интеграция во время выполнения разрешает назначенную комбинацию сжатия перед переопределением универсальной комбинации.
- аналитика включает `compression_combo_id` и `engine`

Поверхность приборной панели: `Dashboard -> Context & Cache -> Compression Combos`.

## Предварительные требования/руководство оператора (CCR и дедупликация сеансов)

CCR (`ccr`) и `session-dedup` заменяют или удаляют текст и оставляют** маркер** позади. Этот раздел представляет собой справочную информацию для оператора по подключению клиента, чтению двух маркеров и извлечению или диагностике пропущенного содержимого. Механика каждого двигателя описана выше; это слой «как это запустить».

| --------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Streamable HTTP (клиент, рекомендуется) | `http://localhost:20128/api/mcp/stream` | Конечная точка, с которой общаются текущие клиенты MCP.                                                                                        |
| Устаревший синглтон SSE                 | `http://localhost:20128/api/mcp/sse`    | Старый синглтонный транспорт. Это** закрывается** потоковые сеансы; используйте клиенты `streamable-http` против `/api/mcp/stream`, а не этот. |
| студия                                  | `omniroute --mcp`                       | Для конфигурации IDE MCP, запускающей процесс. Флага `--dev` нет; `omniroute --mcp` — это точка входа в stdio.                                 |

### Уровни хранилища (то, что сохраняется после перезапуска)

CCR - это** двухъярусный** хранить, а не только в памяти:

- **Горячий уровень в памяти** — ограничение на блок 2 MiB, на принципала 16 MiB, глобально 64 MiB. По умолчанию для записей указывается 24-часовой TTL (максимум 7 дней). Полное извлечение MCP из памяти ограничено 256 KiB; все большее по-прежнему доступно через режимы range/grep.
- **Прочный уровень SQLite** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, on по умолчанию) — поддерживает уровень в памяти, поэтому блок выдерживает вытеснение LRU, перезапуск или получение приземления на другой экземпляр. В строке сохраняется TTL блока, поэтому блок после TTL удаляется с обоих уровней.

Три охранника поддерживают прочный уровень, ограниченный — блок остается только в памяти, когда:

1. блок закончился** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. среда выполнения — облачная среда выполнения (без локального диска);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

Таким образом, «блок исчез» — это не история полного перезапуска: блок sub-512 KB в локальной, необлачной среде выполнения выдерживает перезапуск через устойчивый уровень до тех пор, пока не закончится его TTL. См. [ссылку на среду](../reference/ENVIRONMENT.md) для переменной.

### Два маркера

| Маркер                                | Значение                                                                                                                                       | Что должна делать модель                                                                                                                                                                                                          |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[CCR retrieve hash=<24hex> chars=N]` | Большой блок хранился с адресацией по содержимому.                                                                                             | Позвоните в `omniroute_ccr_retrieve` с помощью** 24-шестнадцатеричный хэш скопирован дословно** чтобы вернуть исходный текст.                                                                                                     |
| `[dedup:ref sha=…]`                   | `session-dedup` исключил текст, уже отправленный на предыдущем этапе того же сеанса. Это** намеренный взгляд назад** , а не потеря или ошибка. | Делать** нет** вызови любой инструмент и сделай** нет** попытайтесь «реконструировать» его. Первое появление текста является канонической копией; текущий ход никогда не перезаписывается, он дедупируется на более позднем ходу. |

Обратный просмотр `[dedup:ref]` — это преднамеренное решение протокола. — не требует реконструкции перед отправкой. Относитесь к этому так, как будто «этот точный текст уже был передан ранее в этом сеансе».

### Предварительные требования клиента

- **Ключ (стдио):** вызывающая сторона stdio не имеет идентификатора для каждого запроса, поэтому она аутентифицируется с помощью `OMNIROUTE_API_KEY` (установленного в `env` сервера MCP ). Без этого вызывающая сторона анонимна, а инструменты, требующие принципала, могут ухудшиться.
- **`tools[]` — предварительное условие инъекции.** Вводится инструкция протокола извлечения CCR (#8033).** только** когда объявленный запрос `tools[]` доказывает, что клиент действительно может достичь `omniroute_ccr_retrieve`. Соответствие представляет собой совпадение конечного сегмента, ограниченное разделителем (`__`, `.`, `/`, `:`). — никогда не является пустой подстрокой — поэтому имя в пространстве имен, такое как `mcp__gateway__omniroute_ccr_retrieve` по-прежнему учитывается. Отсутствие или несовпадение значения `tools[]` означает, что инструкция _не_ введена намеренно.
- **`codemode:false` (клиенты OpenCode ).** OpenCode по умолчанию использует режим кода, который объявляет модели только свои собственные инструменты и** не делает** поместите инструменты MCP в собственный список `tools[]`. Установите `codemode: false` в записи сервера MCP, чтобы объявлялись инструменты `omniroute_ccr_*`. Это** клиент** настройка, а не OmniRoute. В него еще не введена инструкция CCR : OpenCode называет инструмент `<server>_<tool>`, поэтому сервер с именем `omniroute` предоставляет `omniroute_omniroute_ccr_retrieve`, а `_` не является одним из совпадающих разделителей.
- **Руководители.** Хранение и извлечение изолированы для каждого аутентифицированного участника (для каждого ключа API ). Ключ видит только свои блоки.

### Ограничения поиска и нумерация страниц

Текстовые результаты инструмента MCP обрезаются вокруг `mcpAccessibility.maxTextChars` ( `50000` по умолчанию). Извлечение блока `full` ограничено 256 KiB —** не существует неограниченного полного извлечения** . Если `chars=N` блока велик, выведите его на страницу вместо того, чтобы вытаскивать весь блок целиком:

- Эмпирическое правило:**`chars > 40000` → использовать `mode`** , никогда не голый полный.
- `mode:"grep"` — regex `pattern` сопоставляется построчно, до 1000 совпадающих строк (`unique: true` удаляет повторы), самый дешевый вариант «найти одну строку, которая мне нужна».
- `mode:"lines"` — — диапазон строк с 1 индексом; нужны как `start` так и `end`.
- `mode:"head"` / `mode:"tail"` — first/last `n` линии.
- `mode:"stats"` — подсчитывает строки, символы и байты без тела.

Используйте `mode:"lines"` с `start`/`end`, чтобы пройти длинный блок страниц, а не запрашивать все сразу.

### Именование инструмента

Инструмент извлечения в настоящее время называется `omniroute_ccr_retrieve` (префикс `omniroute_` — устаревшее решение проблемы конфликтов имен между серверами). Более чистое имя инструмента с ограниченным суффиксом и исправление усечения средней строки результатов MCP JSON отслеживаются как последующие действия; на этой странице документируется только текущее поведение при поставке.

### Жизненный цикл сеанса

Сеансы Streamable-HTTP простаивают, и сервер их обрабатывает; окно ожидания — это константа `MCP_SESSION_IDLE_MS` (на которую ссылается имя, а не жестко запрограммированное значение, поэтому эта страница не перемещается при ее изменении). Симптомом незанятого сеанса является ошибка HTTP 404 с `Unknown Mcp-Session-Id` — Решением является повторное подключение или перезапуск сеанса,** нет** чтобы повернуть ключ, изменить область действия или переименовать инструмент.

## Область применения и исключения

**Вложения никогда не сжимаются.** `open-sse/handlers/embeddings.ts` никогда не вызывает какой-либо механизм сжатия. — тела request/response передаются непосредственно исполнителю без изменений. Сегодня это структурно (вложения и дополнения в чате являются непересекающимися обработчиками), а не проверка во время выполнения, но это означает, что проблема векторного искажения в #8034 не имеет поверхности воздействия на пути встраивания.

**фильтр исключения Per-model/endpoint (#8034).** Для завершения чата оператор может назвать идентификаторы моделей / цели `provider/model`, которые никогда не должны сжиматься. — является ограждением, полезным, если сжатие когда-либо будет когда-либо подключено ближе к пути, соседнему с встраиванием, позже, и обычно полезно для любой модели, чья точная побайтовая подсказка имеет значение (детерминированные оценки, чувствительные к кешу префиксы и т. д.).

- Поле настроек: `exclusions?: string[]` в глобальной конфигурации сжатия (`GET`/`PUT /api/settings/compression`), сохраняется через существующее пространство имен сжатия `key_value` (`src/lib/db/compression.ts`). — нет новой таблицы.
- Вкладка «Панель управления»:** Панель мониторинга → Сжатие → Исключения** (`/dashboard/compression/exclusions`).
- Синтаксис шаблона: `*` — единственный подстановочный знак. Каждый другой метасимвол регулярного выражения в шаблоне экранируется перед сопоставлением, поэтому `gpt-5.6` соответствует только буквальной строке, а не `gpt-5x6` (ReDoS-безопасно, ограничено, без вложенных кванторов). Шаблоны сопоставляются без учета регистра как по простому идентификатору модели, так и по составному `provider/model` — `gpt-5-6`, `openai/gpt-5-6` и `openai/*`, все работает, и только `*` исключает каждую модель.
- Соответствие: `isCompressionExcluded()` / `normalizeCompressionExclusions()` в `open-sse/services/compression/exclusions.ts`. `chatCore.ts` проверяет исключенную цель сразу после разрешения настроек сжатия,** прежде чем запустится двигатель** и обрабатывает совпадение точно так же, как если бы сжатие было глобально отключено — тело запроса доказуемо идентично по байтам. Пропуск записывается через `writeCompressionSkip(..., "excluded")` для наглядности аналитики.
- По умолчанию (список empty/absent ): идентично поведению до #8034 — ничего не исключено.

## Известные ограничения

- **LLMLingua-2 (SLM) требует совместного размещения дополнительных deps.** Рабочий процесс запускается только в производственной сборке, когда узлы `@atjsh/llmlingua-2` + расположены в `dist/node_modules` (см. `scripts/build/colocateOptionals.mjs`, #4286). Без них движок открывается (возвращает исходный текст). Разрешение рабочего процесса больше не зависит от `import.meta.url` (оно умирает в автономном пакете) — оно привязывается к среде выполнения cwd/ `argv[1]`.
- **Языковые пакеты Caveman `de` / `fr` / `ja` являются частичными.** Они поставляют правила `context` + `filler` + `structural`, но не содержат пакетов `dedup` / `ultra`, поэтому интенсивность `ultra` не сильнее, чем `full` для этих языков (они используют только свои собственные правила — нет молчаливого возврата к английским правилам `dedup`/`ultra`, которые искажали бы иностранный текст). `en` / `es` / `id` / `pt-BR` завершены. Приветствуются взносы в размере `dedup.json` + `ultra.json` за частичные пакеты.
- **В составной телеметрии перечислены только механизмы сжатия.** Шаг составного конвейера, механизм которого работал, но дал экономию 0 %, возвращает `stats:null` и поэтому не отображается в `engineBreakdown` — неотличимо от шага, который был пропущен. Отличие «выполнено, 0 %» от «пропущено» потребует изменения модели разбивки и будет отложено.
