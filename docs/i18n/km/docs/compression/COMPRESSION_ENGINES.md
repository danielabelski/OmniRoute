### ទម្រង់បង្ហាប់OmniGlyph

ម៉ាស៊ីន `omniglyph` (កញ្ចប់ `omniglyph`, 1.4.0 +) ទទួលយកទម្រង់ semantic ដែលមានឈ្មោះថា កំណត់ជាសកលតាមរយៈ `omniglyph.profile` នៅក្នុងការកំណត់ការបង្ហាប់ ឬក្នុងមួយជំហានតាមរយៈការកំណត់រចនាសម្ព័ន្ធជំហាននៃបំពង់ជង់៖

| ប្រវត្តិរូប   | ព្រំដែន                                                                                        |
| ------------- | ---------------------------------------------------------------------------------------------- |
| `aggressive`  | លំនាំដើម។ គោលការណ៍ដែលបង្កាន់ដៃបោះផ្សាយបានវាស់វែងប្រព័ន្ធរូបភាព — ឯកសារឧបករណ៍ និងប្រវត្តិក្រាស់ |
| `balanced`    | រក្សាស្ថានភាពរស់នៅដើម ការពារ 8 វេនចុងក្រោយ បង្រួមប្រវត្តិបិទចាស់                               |
| `coding-safe` | រក្សាសិទ្ធិអំណាច គ្រោងការណ៍ឧបករណ៍ និងលទ្ធផលឧបករណ៍បន្តផ្ទាល់ ការពារវេន 12 ចុងក្រោយ              |
| `passthrough` | ផ្លូវដោយគ្មានការផ្លាស់ប្តូរ; ម៉ាស៊ីនត្រូវបានរំលង                                               |

ប្រវត្តិរូបគឺ ក** ពិដានមិនមែនជាជាន់** : `mergeCompressionProfileOptions` ក្នុងកញ្ចប់បដិសេធមិនឱ្យអ្នកហៅចូលបដិសេធ បើកផ្លូវដែលបាត់បង់ដែលទម្រង់បានបិទឡើងវិញ ដូច្នេះ `preserveSystemPrompt: false` ក្នុងមួយជំហានមិនអាចបើកការបង្ហាប់ប្រព័ន្ធឡើងវិញក្រោម `coding-safe` បានទេ។

បានវាស់វែងនៅលើមូលដ្ឋានកូដនេះ៖ `coding-safe` និង `balanced` បង្កើន `minCompressChars` ដល់អតិបរមារបស់វា ហើយរក្សាប្រព័ន្ធ គ្រោងការណ៍ឧបករណ៍ និងលទ្ធផលឧបករណ៍ដើម ដូច្នេះវគ្គដែលមិនទាន់ប្រមូលប្រវត្តិនៅតែឈប់នៅ `below_min_chars` ហើយម៉ាស៊ីនមិនផ្លាស់ប្តូរអ្វីទាំងអស់។ នោះហើយជាមូលហេតុដែលលំនាំដើមគឺ `aggressive` ជាជាងទម្រង់សុវត្ថិភាពបំផុត។

កញ្ចប់ដោះស្រាយវិសាលភាពគំរូ និងទម្រង់ផ្ទាល់ខ្លួនរបស់វាពីការកំណត់រចនាសម្ព័ន្ធបរិស្ថានរបស់វា។ OmniRoute មិនដែលធ្វើប្រតិភូកម្មការសម្រេចចិត្តទេ៖ អាដាប់ទ័រតោងច្រកគំរូទៅនឹងវិសាលភាពរឹតត្បិតបំផុតរបស់កញ្ចប់ ដូច្នេះការកំណត់បរិស្ថានម៉ាស៊ីនអាចបង្រួមបញ្ជីអនុញ្ញាតតែប៉ុណ្ណោះ មិនត្រូវពង្រីកវាឱ្យលើសពីបង្កាន់ដៃដែលវាស់វែងរបស់ OmniRoute ឡើយ។

## ការចុះបញ្ជីម៉ាស៊ីន

បញ្ជីឈ្មោះរស់នៅក្នុង `open-sse/services/compression/engines/registry.ts`។ ម៉ាស៊ីនបង្ហាញកិច្ចសន្យារួម៖

- `id`: លេខសម្គាល់ម៉ាស៊ីនមានស្ថេរភាពដូចជា `caveman` ឬ `rtk`
- `apply(text, config)`: ផ្លូវប្រតិបត្តិចាស់ដែលប្រើដោយបំពង់បង្ហូរជង់
- `compress(input, config)`: ផ្លូវប្រតិបត្តិចម្បងដែលត្រឡប់អត្ថបទ + ស្ថិតិ
- `getConfigSchema()`: ត្រឡប់រូបរាងដូច JSON-Schema នៃការកំណត់ត្រឹមត្រូវ។
- `validateConfig(config)`: ត្រឡប់ `{ valid, errors[] }`

ការចុះឈ្មោះប្រើ `registerCompressionEngine(engine)` (ឬ `registerEngine` សម្រាប់ករណីកម្រិតខ្ពស់) ដែលហៅ `assertValidEngine()` និង `validateConfig(defaultConfig)` មុនពេលទទួលយក។ ប្រើ `unregisterCompressionEngine(id)` ដើម្បីលុបម៉ាស៊ីននៅពេលដំណើរការ។

`strategySelector.ts` ចុះឈ្មោះម៉ាស៊ីនដែលភ្ជាប់មកជាមួយ មុនពេលការបង្ហាប់ដំណើរការ។ វាអនុញ្ញាតឱ្យការមើលជាមុន ការបង្ហាប់ពេលដំណើរការ របៀបជង់ ការធ្វើតេស្ត និងម៉ាស៊ីននាពេលអនាគតប្រើផ្លូវប្រតិបត្តិដូចគ្នា។

### ការបង្ហាប់ការពិពណ៌នាMCP (ពាក់ព័ន្ធ)

បញ្ជីឈ្មោះដាច់ដោយឡែកមួយបង្ហាប់ទិន្នន័យមេតាការពិពណ៌នាឧបករណ៍ MCP នៅកម្រិតចុះឈ្មោះ — សូមមើល `open-sse/mcp-server/descriptionCompressor.ts` និង [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ។ វាប្រើច្បាប់ Caveman ឡើងវិញ ប៉ុន្តែដំណើរការលើទិន្នន័យមេតារបស់ឧបករណ៍ មិនមែនស្នើសុំការផ្ទុកបន្ទុកទេ។

**CCR ទាញយកពិធីការសេចក្តីណែនាំ (#8033):** ជាលើកដំបូង CCR ជំនួស ≥ 1 ប្លុកនៅក្នុងសំណើមួយ ម៉ាស៊ីននឹងដាក់សារ `system` តែមួយដែលមានសក្តានុពល (នាំមុខជាមួយ `[CCR protocol]` sentinel) បង្រៀនអ្នកហៅទូរស័ព្ទអំពីកិច្ចសន្យាឧបករណ៍ → : អ្វីដែលសញ្ញាសម្គាល់ `[CCR retrieve hash=<24hex> chars=N]` មានន័យថា hash ត្រូវតែត្រូវបានចម្លងពាក្យសំដី (ទាំង 24 តួអក្សរ hex — miss-copied) ហើយទំនងជាមិនបានរកឃើញថា hashe `[dedup:ref sha=...]` marker មានន័យថា "មើលទៅក្នុងប្រវត្តិសាស្ត្រ" មិនមែន "ហៅឧបករណ៍" ទេ។ ចំណាំត្រូវបានចាក់** លុះត្រាតែ `tools[]` ផ្សាយពាណិជ្ជកម្មរបស់អ្នកហៅចូល បង្ហាញថាវាពិតជាអាចទៅដល់ `omniroute_ccr_retrieve`** (`callerSupportsCcrRetrieve()` in `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — អ្នកហៅទូរសព្ទដែលឆបគ្នាជាមួយ OpenAI ធម្មតាដោយគ្មានឧបករណ៍នោះមិនដែលទទួលបានការណែនាំដើម្បីហៅអ្វីមួយដែលវាមិនអាចទៅដល់បានទេ។ Idempotency ត្រូវបានអនុវត្តដោយការស្កេនប្រវត្តិសារសម្រាប់ sentinel មុនពេលចាក់បញ្ចូល ដូច្នេះសំណើច្រើនវេន (ដែលចាក់សារពីមុនឡើងវិញ) មិនជង់កំណត់ត្រាម្តងក្នុងមួយវេនទេ។

## មនុស្សល្អាង

របៀប Caveman ផ្តោតលើការ condensation semantic នៃ prose ធម្មតា:

- រក្សាប្លុកកូដ URLsJSON ផ្លូវ និងទិន្នន័យដែលមានរចនាសម្ព័ន្ធ
- ដកការបំពេញ ការការពារ បរិបទដដែលៗ និងឃ្លាភ្ជាប់ពាក្យសំដី
- គាំទ្រកញ្ចប់ច្បាប់ឯកសារដែលស្គាល់ភាសានៅក្នុង `open-sse/services/compression/rules/`
- នៅតែមានតាមរយៈមុខងារ `standard`, `aggressive`, និង `ultra` កេរ្តិ៍ដំណែល

ផ្ទៃតាប្លូគឺ `Dashboard -> Context & Cache -> Caveman`។

Caveman upstream reports `~75%` fewer output tokens, `65%` average output savings in benchmarks with a `22-87%` range, and a `~46%` input-compression tool. OmniRoute uses the Caveman input-side number when documenting stacked prompt/context savings; Caveman output mode remains a separate response-behavior feature.

**ហេតុអ្វីបានជាតាមតម្រូវការ៖** កញ្ចប់ដែលបានបោះពុម្ព npm កញ្ចប់ឯកតា និងនាវារូបភាព Docker** ដោយគ្មាន** deps ទាំងនេះដើម្បីរក្សារាងស្លីម។ នៅពេលដែលពួកគេអវត្តមាន ច្រកអាស្រ័យរបស់កម្មករ (ការស៊ើបអង្កេត `@atjsh/llmlingua-2` ក្នុង `worker.ts`) បរាជ័យ ហើយម៉ាស៊ីន** បរាជ័យ - បើកដោយស្ងៀមស្ងាត់** — ជ្រើសរើស LLMLingua ក្លាយជា no-op (អត្ថបទត្រឡប់មិនផ្លាស់ប្តូរ គ្មានកំហុសត្រូវបានកត់ត្រា)។ ដើម្បីដំណើរការវានៅក្នុងបរិយាកាសដែលបានកាត់ចេញ សូមដំឡើងជង់ស្រេចចិត្ត៖

```bash
# pin to the versions declared in package.json optionalDependencies
```

ក្នុងមួយបរិស្ថាន៖

- **Dev / `npm install`** — បានដំឡើងដោយស្វ័យប្រវត្តិ លុះត្រាតែអ្នកឆ្លងកាត់ `--omit=optional` (ឬ `--no-optional`) ។ មិនត្រូវការសកម្មភាពទេ។
- **npm សកល (`npm i -g omniroute`) / ឯករាជ្យ** — ដំណើរការពាក្យបញ្ជាដំឡើងខាងលើនៅខាងក្នុងថតកញ្ចប់ដែលបានដំឡើង ឬដំឡើងឡើងវិញដោយមិនលុបចោល deps ស្រេចចិត្ត។
- **Docker** — បន្ថែមពាក្យបញ្ជាដំឡើងនៅក្នុងស្រទាប់រូបភាពដែលបានមកពី; រូបភាពដែលបានបោះពុម្ពផ្សាយគឺស្ដើងតាមការរចនា។
- **VPS (PM2)** — ដំឡើងទៅក្នុង `node_modules` របស់កម្មវិធី បន្ទាប់មកចាប់ផ្តើមដំណើរការឡើងវិញ ដូច្នេះកម្មករធ្វើការស៊ើបអង្កេតច្រកទ្វារឡើងវិញ។
- **ឆៅបន្ទាប់ដាច់ដោយឡែក (`npm run build` → `.build/next/standalone/server.js`)** — នាវាតាមដានតែម្នាក់ឯង NEITHER កម្មករឬ deps ស្រេចចិត្ត ដូច្នេះម៉ាស៊ីនមិនដំណើរការដោយស្ងៀមស្ងាត់។ `scripts/build/colocate-standalone.mjs` អនុវត្តទាំងពីរឡើងវិញ (កម្មករ esbuild + optional-dep បិទចូលទៅក្នុងដើមឈើឯករាជ្យ); វាដំណើរការដោយស្វ័យប្រវត្តិតាមរយៈទំពក់ `postbuild` npm បន្ទាប់ពីរាល់ការស្ថាបនា។ Ideempotent, បរាជ័យ - ទន់នៅពេលដែល deps គឺអវត្តមាន។

**ផ្ទៀងផ្ទាត់ថាវាសកម្ម៖** ជាមួយនឹងការជ្រើសរើស LLMLingua ការនិយាយពិតពិតជារួញ (ម៉ាស៊ីនឈប់ដំណើរការមិនដំណើរការ) ហើយសំណើដំបូងធ្វើឱ្យការទាញយកគំរូចូលទៅក្នុង `${DATA_DIR}/models/llmlingua`។ ច្រកទ្វារដោយចេតនាស៊ើបអង្កេតតែ `@atjsh/llmlingua-2` — មិត្តភក្ដិផ្សេងទៀតគឺសម្រាប់តែ ESM ហើយ `require.resolve` បោះទៅលើពួកគេសូម្បីតែនៅពេល — មានវត្តមានដូច្នេះកម្មករនៅតែបរាជ័យ - បើកប្រសិនបើមិត្តភក្ដិណាមួយត្រូវបានបាត់ពិតប្រាកដនៅម៉ោង `import()` ។

## បំពង់ជង់

របៀបជង់ដំណើរការជំហានបំពង់តាមលំដាប់លំដោយ។ លំនាំដើមគឺ៖

```txt
rtk -> caveman
```

ប្រើវាសម្រាប់វគ្គ coding-agent ដែលប្រអប់បញ្ចូលបញ្ចូលលទ្ធផលពាក្យបញ្ជាជាមួយ prose មនុស្ស ឬជំនួយការ។ RTK កាត់បន្ថយកំណត់ហេតុឧបករណ៍ដែលមានសំលេងរំខានជាមុនសិន បន្ទាប់មក Caveman បង្រួមភាសាធម្មជាតិដែលនៅសល់។

ជំហាននៃបំពង់ត្រូវបានកំណត់រចនាសម្ព័ន្ធជាមួយ `stackedPipeline` ក្នុងការកំណត់បង្ហាប់ ឬតាមរយៈការបង្ហាប់បន្សំ។

នៅពេលដែលម៉ាស៊ីនទាំងពីរកាត់បន្ថយបន្ទុកដែលមានសិទ្ធិដូចគ្នា សមាសធាតុសន្សំ៖

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP តម្រងមែកធាងភាពងាយស្រួល

MCP accessibility-tree smart filter គឺជាស្រទាប់បង្ហាប់ក្រោយការប្រតិបត្តិដែលដំណើរការលើ MCP** លទ្ធផលឧបករណ៍** មិនមែននៅលើប្រអប់បញ្ចូល ឬបរិបទទេ។ វាកំណត់គោលដៅលើការចូលប្រើប្រាស់ verbose-tree និង browser snapshot payloads ត្រឡប់ដោយឧបករណ៍ដូចជា Playwright, computer-use, and browser-automation MCP servers ។

### អ្វីដែលវាធ្វើ

1. **ការដកសំលេងរំខាន** — លុបធាតុ generic/text ទទេ (`- generic:`, `- text: ""`)
2. **បងប្អូនបង្កើតដួលរលំ** — ពេល ≥ `collapseThreshold` (លំនាំដើម 30) បន្ទាត់ជាប់គ្នាគឺជាការធ្វើឡើងវិញតាមលំដាប់ បង្រួមពួកវាទៅក្នុងបន្ទាត់ `collapseKeepHead` ដំបូង (លំនាំដើម 10) + a រាប់សង្ខេប + ចុងក្រោយ `collapseKeepTail` (លំនាំដើម 5) បន្ទាត់
3. **ការរក្សាទុកឯកសារយោង** — `[ref=eXX]` យុថ្កាដែលតម្រូវដោយ Playwright/computer-use មិនត្រូវបានប៉ះឡើយ។
4. **ការកាត់ចេញរឹង** — ប្រសិនបើអត្ថបទបន្ទាប់ពីការដួលរលំនៅតែលើសពី `maxTextChars` (លំនាំដើម 50,000) កាត់ឱ្យខ្លីជាមួយនឹងព័ត៌មានជំនួយរុករក ដូច្នេះភ្នាក់ងារអាចបន្តធ្វើការ

### ទីតាំងម៉ាស៊ីន

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### ការកំណត់រចនាសម្ព័ន្ធ

គ្រប់គ្រងដោយ `compression.mcpAccessibility` នៅក្នុងការកំណត់សកល (ការធ្វើចំណាកស្រុក 056) ។ ការកំណត់លំនាំដើម៖

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

តម្រងនេះត្រូវបានអនុវត្តតែចំពោះបន្ទុកលទ្ធផលឧបករណ៍ដែល `type` គឺ `"text"` និងប្រវែងរបស់វាលើស `minLengthToProcess`។ វាមិនប៉ះពាល់ដល់ការបង្ហាប់ភ្លាមៗ ឬស្នើសុំការផ្ទុកបន្ទុកទេ។

### ការសន្សំដែលរំពឹងទុក

60-80% លើលទ្ធផលឧបករណ៍ចាប់យកកម្មវិធីរុករក អាស្រ័យលើភាពស្មុគស្មាញនៃទំព័រ។ ក្បួនដោះស្រាយការដួលរលំគឺ O(n) នៅក្នុងការរាប់បន្ទាត់ ហើយបន្ថែមភាពយឺតយ៉ាវដែលធ្វេសប្រហែស។

### តម្រងនេះធៀបនឹងម៉ាស៊ីនបង្ហាប់ខាងលើ

## ការបង្ហាប់ Combo

Combos Combos ត្រូវបានគេដាក់ឈ្មោះថា ទម្រង់បង្ហាប់ ដែលអាចត្រូវបានកំណត់ទៅ routing combos៖

- `compression_combos`៖ របៀបរក្សាទុក បំពង់បង្ហូរ ការកំណត់ RTK ការកំណត់ភាសា និងសញ្ញាសម្គាល់លំនាំដើម
- `compression_combo_assignments`: គូសផែនទីបន្សំការបង្ហាប់ទៅបន្សំកំណត់ផ្លូវ
- ការរួមបញ្ចូលពេលដំណើរការដោះស្រាយបន្សំការបង្ហាប់ដែលបានកំណត់ មុនពេលការបដិសេធបន្សំទូទៅ
- ការវិភាគរួមមាន `compression_combo_id` និង `engine`

ផ្ទៃគ្រប់គ្រង៖ `Dashboard -> Context & Cache -> Compression Combos`។

## តម្រូវការជាមុន / មគ្គុទ្ទេសក៍ប្រតិបត្តិករ (CCR & session-dedup)

CCR (`ccr`) និង `session-dedup` ជំនួស ឬ elide អត្ថបទ ហើយទុក a** សញ្ញាសម្គាល់** នៅខាងក្រោយ។ ផ្នែកនេះគឺជាឯកសារយោងប្រតិបត្តិករសម្រាប់ភ្ជាប់ម៉ាស៊ីនភ្ញៀវ អានសញ្ញាសម្គាល់ទាំងពីរ និងការទាញយក ឬវិភាគមាតិកាដែលបានលុបចេញ។ យន្តការនៃម៉ាស៊ីននីមួយៗត្រូវបានគ្របដណ្តប់ខាងលើ; នេះគឺជាស្រទាប់ "តើខ្ញុំដំណើរការវាដោយរបៀបណា" ។

### ការដឹកជញ្ជូន និងចំណុចបញ្ចប់

ម៉ាស៊ីនមេ MCP ដែលបង្ហាញឧបករណ៍ CCR អាចទៅដល់បីវិធី។ URL មូលដ្ឋានលំនាំដើមគឺ `http://localhost:20128` (`OMNIROUTE_BASE_URL`):

| ការដឹកជញ្ជូន                            | URL / ពាក្យបញ្ជា                        | កំណត់ចំណាំ                                                                                                                              |
| --------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP ដែលអាចស្ទ្រីមបាន (អតិថិជនបានណែនាំ) | `http://localhost:20128/api/mcp/stream` | ចំណុចបញ្ចប់ដែលអតិថិជន MCP បច្ចុប្បន្ននិយាយជាមួយ។                                                                                        |
| កេរ្តិ៍ដំណែល SSE singleton              | `http://localhost:20128/api/mcp/sse`    | ការដឹកជញ្ជូន Singleton ចាស់។ វា។** បិទ** វគ្គដែលអាចផ្សាយបាន; ប្រើអតិថិជន `streamable-http` ប្រឆាំងនឹង `/api/mcp/stream` មិនមែនមួយនេះទេ។ |

### កម្រិតផ្ទុក (អ្វីដែលនៅរស់រានពីការចាប់ផ្ដើមឡើងវិញ)

CCR គឺជាមួយ** ពីរជាន់** រក្សាទុក មិនមែនក្នុងអង្គចងចាំប៉ុណ្ណោះ៖

- **កម្រិតក្តៅក្នុងការចងចាំ** — per-block cap 2 MiB, per-principal 16 MiB, global 64 MiB។ ធាតុលំនាំដើមទៅ 24 ម៉ោង TTL (អតិបរមា 7 ថ្ងៃ) ។ ការទាញយក MCP ពេញលេញពីអង្គចងចាំត្រូវបានបិទនៅ 256 KiB; អ្វីដែលធំជាងនេះគឺនៅតែអាចឈានដល់បានតាមរយៈរបៀបជួរ / grep ។
- **ថ្នាក់ SQLite ជាប់លាប់** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, បើកតាមលំនាំដើម) — គាំទ្រថ្នាក់ក្នុងអង្គចងចាំ ដូច្នេះប្លុកមួយនៅរស់រានមានជីវិតពីការបណ្តេញចេញ LRU ការចាប់ផ្តើមឡើងវិញ ឬទាញយកការចុះចតនៅលើឧទាហរណ៍ផ្សេងទៀត។ ជួរដេករក្សា TTL របស់ប្លុក ដូច្នេះប្លុកដែលឆ្លងកាត់ TTL របស់វាបាត់ពីកម្រិតទាំងពីរ។

ឆ្មាំបីនាក់រក្សាកម្រិតជាប់បានយូរ — ប្លុកមួយរក្សាការចងចាំបានតែនៅពេលដែល៖

1. ប្លុកបានបញ្ចប់** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. ពេលវេលាដំណើរការគឺជាពេលវេលាដំណើរការលើពពក (មិនមានថាសមូលដ្ឋាន);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

ដូច្នេះ "ប្លុកបានបាត់" មិនមែនជារឿងចាប់ផ្ដើមឡើងវិញទេ៖ ប្លុក sub-512 KB នៅលើពេលវេលាដំណើរការដែលមិនមែនជាពពកក្នុងតំបន់អាចរស់រានមានជីវិតពីការចាប់ផ្ដើមឡើងវិញតាមរយៈកម្រិតប្រើប្រាស់បានយូររហូតដល់ TTL របស់វាអស់។ សូមមើល [ឯកសារយោងបរិស្ថាន](../reference/ENVIRONMENT.md) សម្រាប់អថេរ។

### តម្រូវការជាមុនរបស់អតិថិជន

- **គ្រាប់ចុច (stdio)៖** អ្នកហៅទូរសព្ទ stdio មិនមានអត្តសញ្ញាណតាមសំណើ ដូច្នេះវាផ្ទៀងផ្ទាត់ជាមួយ `OMNIROUTE_API_KEY` (កំណត់នៅក្នុង `env` របស់ម៉ាស៊ីនមេ MCP )។ បើគ្មានវាទេ អ្នកហៅចូលគឺអនាមិក ហើយឧបករណ៍ដែលទាមទារប្រាក់ដើមអាចបន្ទាបបន្ថោក។
- **`tools[]` គឺជាលក្ខខណ្ឌចាក់ថ្នាំជាមុន។** CCR retrieve-protocol instruction (#8033) ត្រូវបានចាក់** តែប៉ុណ្ណោះ** នៅពេលដែល `tools[]` ផ្សាយពាណិជ្ជកម្មរបស់សំណើបង្ហាញថាអតិថិជនពិតជាអាចឈានដល់ `omniroute_ccr_retrieve`។ ការផ្គូផ្គងគឺជាការផ្គូផ្គងផ្នែកបន្ទាប់ដែលត្រូវបានកំណត់ដោយសញ្ញាបំបែក (`__`, `.`, `/`, `:`) — មិនដែលជាអក្សរក្រោមទទេ — ដូច្នេះឈ្មោះដកឃ្លាដូចជា `mcp__gateway__omniroute_ccr_retrieve` នៅតែរាប់។ អវត្តមាន ឬមិនផ្គូផ្គង `tools[]` មានន័យថាការណែនាំគឺ _not_ ចាក់តាមការរចនា។
- **`codemode:false` (អតិថិជន OpenCode ) ។** OpenCode កំណត់លំនាំដើមទៅជារបៀបកូដ ដែលផ្សាយតែឧបករណ៍ដើមរបស់វាចំពោះគំរូ និង** មិន** ដាក់ឧបករណ៍ MCP នៅលើបញ្ជី `tools[]` ដើម។ កំណត់ `codemode: false` នៅលើធាតុម៉ាស៊ីនមេ MCP ដូច្នេះឧបករណ៍ `omniroute_ccr_*` ត្រូវបានផ្សព្វផ្សាយ។ នេះគឺជា ក** អតិថិជន** ការកំណត់មិនមែនជា OmniRoute ទេ។ វាមិនទាន់ទទួលបានការណែនាំ CCR នៅឡើយទេ៖ OpenCode ដាក់ឈ្មោះឧបករណ៍ `<server>_<tool>` ដូច្នេះម៉ាស៊ីនមេដែលហៅថា `omniroute` បង្ហាញ `omniroute_omniroute_ccr_retrieve` ហើយ `_` មិនមែនជាឧបករណ៍បំបែកដែលត្រូវគ្នានោះទេ។
- **នាយកសាលា។** ការផ្ទុក និងការទាញយកគឺដាច់ដោយឡែកពីគ្នាសម្រាប់ប្រាក់ដើមដែលបានផ្ទៀងផ្ទាត់ (ក្នុងមួយ API key)។ គ្រាប់ចុចមើលឃើញតែប្លុករបស់វាប៉ុណ្ណោះ។

### ដែនកំណត់នៃការទាញយក និងទំព័រ

លទ្ធផលអត្ថបទរបស់ឧបករណ៍MCP ត្រូវបានកាត់ជុំវិញ `mcpAccessibility.maxTextChars` ( `50000` លំនាំដើម )។ ការទាញយក `full` នៃប្លុកមួយត្រូវបានបិទនៅ 256 KiB —** មិនមានការទាញយកពេញលេញដោយគ្មានដែនកំណត់ទេ។** . នៅពេលដែល `chars=N` របស់ប្លុកមានទំហំធំ ទំព័រវាជំនួសឱ្យការទាញរឿងទាំងមូល៖

- ក្បួនមេដៃ៖**`chars > 40000` → ប្រើ `mode`** , មិនដែលពេញ។
- `mode:"grep"` — regex `pattern` ត្រូវគ្នាតាមបន្ទាត់ រហូតដល់ទៅ 1,000 បន្ទាត់ដែលត្រូវគ្នា (`unique: true` drops repeats) ដែលថោកបំផុតសម្រាប់ "រកបន្ទាត់ដែលខ្ញុំត្រូវការ"។
- `mode:"lines"` — a 1-indexed line range; ត្រូវការទាំង `start` និង `end`។
- `mode:"head"` / `mode:"tail"` — first/last `n` បន្ទាត់។
- `mode:"stats"` — បន្ទាត់ តួអក្សរ និងបៃរាប់ដោយគ្មានតួ។

ប្រើ `mode:"lines"` ជាមួយ `start`/`end` ដើម្បីដើរប្លុកវែងៗក្នុងទំព័រ ជាជាងការស្នើសុំរឿងទាំងមូលក្នុងពេលតែមួយ។

### ការដាក់ឈ្មោះឧបករណ៍

ឧបករណ៍ទាញយកបច្ចុប្បន្នត្រូវបានដាក់ឈ្មោះថា `omniroute_ccr_retrieve` (បុព្វបទ `omniroute_` គឺជាដំណោះស្រាយចុះកាលបរិច្ឆេទសម្រាប់ការប៉ះទង្គិចគ្នានៃឈ្មោះម៉ាស៊ីនមេ)។ ឈ្មោះឧបករណ៍ដែលជាប់ព្រំដែនដែលត្រូវបានសម្អាត និងការជួសជុលសម្រាប់លទ្ធផល MCP JSON ដែលបានកាត់ឱ្យខ្លីពាក់កណ្តាលខ្សែអក្សរត្រូវបានតាមដានជាការតាមដានបន្តបន្ទាប់។ ទំព័រនេះចងក្រងនូវឥរិយាបទបច្ចុប្បន្ន និងដឹកជញ្ជូនតែប៉ុណ្ណោះ។

### វដ្តជីវិតសម័យ

វគ្គ Streamable-HTTP ទុកចោល ហើយម៉ាស៊ីនមេច្រូតពួកវា។ បង្អួចទំនេរគឺ `MCP_SESSION_IDLE_MS` ថេរ (យោងតាមឈ្មោះ មិនមែនជាតម្លៃដែលសរសេរកូដរឹងទេ ដូច្នេះទំព័រនេះមិនរសាត់នៅពេលវាផ្លាស់ប្តូរ) ។ រោគសញ្ញានៃវគ្គដែលទុកចោលគឺ HTTP 404 ជាមួយ `Unknown Mcp-Session-Id` — ដំណោះស្រាយគឺត្រូវភ្ជាប់ឡើងវិញ ឬចាប់ផ្តើមវគ្គឡើងវិញ។** ទេ។** ដើម្បីបង្វិលសោ ផ្លាស់ប្តូរវិសាលភាព ឬប្តូរឈ្មោះឧបករណ៍។

## វិសាលភាព និងការលើកលែង

**ការបង្កប់មិនដែលត្រូវបានបង្ហាប់ទេ។** `open-sse/handlers/embeddings.ts` មិនដែលហៅម៉ាស៊ីនបង្ហាប់ណាមួយ — សាកសព request/response ឆ្លងកាត់ត្រង់ទៅប្រតិបត្តិករដោយមិនប៉ះ។ ថ្ងៃនេះជារចនាសម្ព័ន្ធ (ការបង្កប់ និងការបញ្ចប់ការជជែកគឺជាឧបករណ៍ដោះស្រាយមិនជាប់គ្នា) មិនមែនជាការត្រួតពិនិត្យពេលដំណើរការទេ ប៉ុន្តែវាមានន័យថាការព្រួយបារម្ភពីការបង្ខូចទ្រង់ទ្រាយវ៉ិចទ័រនៅក្នុង #8034 មិនមានផ្ទៃខាងក្រៅនៅក្នុងផ្លូវបង្កប់នោះទេ។

**តម្រងមិនរាប់បញ្ចូល Per-model/endpoint (#8034) ។** សម្រាប់ការបញ្ចប់ការជជែក ប្រតិបត្តិករអាចដាក់ឈ្មោះ model ids/ `provider/model` targets ដែលមិនត្រូវបង្ហាប់ — a guardrail មានប្រយោជន៍ទេ ប្រសិនបើការបង្ហាប់ត្រូវបានភ្ជាប់ទៅជិតផ្លូវបង្កប់ដែលនៅជាប់គ្នានៅពេលក្រោយ ហើយជាទូទៅមានប្រយោជន៍សម្រាប់ម៉ូដែលណាមួយដែលមានបញ្ហាភ្លាមៗនៃ byte-for-byte prompt matter (deterministic evals, cache-sensitive prefixes) ។ល។

- វាលការកំណត់៖ `exclusions?: string[]` នៅលើការកំណត់រចនាសម្ព័ន្ធការបង្ហាប់សកល (`GET`/`PUT /api/settings/compression`) បានបន្តតាមរយៈ ចន្លោះឈ្មោះបង្ហាប់ `key_value` ដែលមានស្រាប់ (`src/lib/db/compression.ts`) — មិនមានតារាងថ្មីទេ។
- ផ្ទាំងគ្រប់គ្រង៖** ផ្ទាំងគ្រប់គ្រង → ការបង្ហាប់ → ការបដិសេធ** (`/dashboard/compression/exclusions`) ។
- វាក្យសម្ព័ន្ធលំនាំ៖ `*` គឺជាតួអក្សរជំនួសតែមួយគត់។ រាល់តួអក្សរមេតា regex ផ្សេងទៀតនៅក្នុងលំនាំមួយត្រូវបានគេចចេញមុនពេលផ្គូផ្គង ដូច្នេះ `gpt-5.6` ត្រូវគ្នានឹងខ្សែអក្សរព្យញ្ជនៈតែប៉ុណ្ណោះ មិនដែល `gpt-5x6` (ReDoS-safe, bounded, no nested quantifiers)។ លំនាំផ្គូផ្គង case-insensitive ប្រឆាំងនឹងទាំង id model ទទេ និង `provider/model` composite — `gpt-5-6`, `openai/gpt-5-6`, និង `openai/*` ការងារទាំងអស់ ហើយ `*` តែម្នាក់ឯងមិនរាប់បញ្ចូលគ្រប់ម៉ូដែលទាំងអស់។
- ការផ្គូផ្គង៖ `isCompressionExcluded()` / `normalizeCompressionExclusions()` ក្នុង `open-sse/services/compression/exclusions.ts`។ `chatCore.ts` ពិនិត្យមើលគោលដៅដែលបានដកចេញភ្លាមៗបន្ទាប់ពីដោះស្រាយការកំណត់ការបង្ហាប់។** មុនពេលម៉ាស៊ីនណាមួយដំណើរការ** ហើយចាត់ទុកការផ្គូផ្គងដូចជាការបង្ហាប់ដែលត្រូវបានបិទជាសកល — តួសំណើគឺដូចគ្នាបេះបិទ។ ការរំលងត្រូវបានកត់ត្រាតាមរយៈ `writeCompressionSkip(..., "excluded")` សម្រាប់ភាពមើលឃើញនៃការវិភាគ។
- លំនាំដើម (empty/absent list )៖ ដូចគ្នាបេះបិទទៅនឹងឥរិយាបថមុន #8034 — គ្មានអ្វីត្រូវបានដកចេញទេ។
