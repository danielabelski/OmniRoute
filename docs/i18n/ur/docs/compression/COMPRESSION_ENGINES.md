OmniRoute کمپریشن انجن کے معاہدوں کے ارد گرد بنایا گیا ہے۔ ایک موڈ ایک انجن کو براہ راست چلا سکتا ہے (`caveman` یا `rtk`) یا ایک ڈیٹرمنسٹک اسٹیک پائپ لائن جو ایک سے زیادہ انجنوں کو ترتیب سے چلاتی ہے۔

## موڈز

| موڈ          | انجن کا راستہ                                                                     | مطلوبہ ان پٹ                                          |
| ------------ | --------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `off`        | کوئی نہیں                                                                         | عین مطابق فوری تحفظ                                   |
| `lite`       | کیو مین لائٹ مددگار                                                               | کم خطرہ ہمیشہ صفائی پر                                |
| `standard`   | غار والا                                                                          | قدرتی زبان کا فوری سنکشیپن                            |
| `aggressive` | Caveman + history/tool خلاصہ کرنے والے                                            | طویل چیٹ سیشن                                         |
| `ultra`      | Caveman + کٹائی کے مددگار                                                         | سیاق و سباق کی حد کی بازیابی۔                         |
| `rtk`        | RTK                                                                               | ٹرمینل، شیل، بلڈ، ٹیسٹ، اور گٹ آؤٹ پٹ                 |
| `omniglyph`  | OmniGlyph                                                                         | مقامی فراہم کنندہ کے تار پر سیاق و سباق کے بطور تصویر |
| `stacked`    | پائپ لائن۔ درخواست ڈیفالٹ `session-dedup -> lite` ہے۔ `rtk -> caveman` آپٹ ان ہے۔ | مخلوط ٹول لاگ اور نثر، زیادہ سے زیادہ بچت             |

### OmniGlyph کمپریشن پروفائلز

`omniglyph` انجن (پیکیج `omniglyph`, 1.4.0 +) ایک نامی سیمنٹک پروفائل کو قبول کرتا ہے، جو عالمی سطح پر `omniglyph.profile` کے ذریعے کمپریشن سیٹنگز میں یا اسٹیک شدہ پائپ لائن کی سٹیپ کنفیگریشن کے ذریعے فی قدم پر سیٹ کیا جاتا ہے:

| پروفائل       | باؤنڈری                                                                                      |
| ------------- | -------------------------------------------------------------------------------------------- |
| `aggressive`  | طے شدہ پالیسی میں شائع شدہ رسیدیں — امیجز سسٹم، ٹول ڈاکس اور گھنی تاریخ کی پیمائش کرتی ہیں۔  |
| `balanced`    | زندہ ریاست کو مقامی رکھتا ہے، آخری 8 موڑ کی حفاظت کرتا ہے، پرانی بند تاریخ کو منہدم کرتا ہے۔ |
| `coding-safe` | اتھارٹی، ٹول اسکیموں اور لائیو ٹول آؤٹ پٹ کو مقامی رکھتا ہے، آخری 12 موڑ کی حفاظت کرتا ہے۔   |
| `passthrough` | تبدیلی کے بغیر راستے؛ انجن چھوڑ دیا گیا ہے                                                   |

پروفائل ایک ہے۔** چھت، فرش نہیں** : پیکج میں `mergeCompressionProfileOptions` کسی کالر کو اوور رائڈ کرنے سے انکار کرتا ہے پروفائل بند ہونے والی نقصان دہ لین کو دوبارہ کھولنے کی اجازت دیتا ہے، لہذا فی قدم `preserveSystemPrompt: false` `coding-safe` کے تحت سسٹم کمپریشن کو دوبارہ فعال نہیں کر سکتا۔

اس کوڈ بیس پر ماپا گیا: `coding-safe` اور `balanced` `minCompressChars` زیادہ سے زیادہ بڑھاتے ہیں اور سسٹم، ٹول اسکیموں اور ٹول کے نتائج کو مقامی رکھتے ہیں، لہذا ایک سیشن جس نے ابھی تک تاریخ جمع نہیں کی ہے وہ `below_min_chars` پر رک جاتا ہے اور انجن کچھ بھی تبدیل نہیں کرتا ہے۔ یہی وجہ ہے کہ ڈیفالٹ محفوظ ترین پروفائل کے بجائے `aggressive` ہے۔

پیکج اپنے ماڈل کے دائرہ کار اور پروفائل کو اپنے ماحول کی ترتیب سے حل کرتا ہے۔ OmniRoute کبھی بھی فیصلہ نہیں دیتا: اڈاپٹر ماڈل گیٹ کو پیکج کے سب سے زیادہ پابندی والے دائرہ کار میں پن کرتا ہے، لہذا میزبان ماحول کی ترتیبات صرف اجازت کی فہرست کو محدود کر سکتی ہیں، اسے OmniRoute کی پیمائش شدہ رسیدوں سے پہلے کبھی بھی وسیع نہیں کر سکتی ہیں۔

## انجن رجسٹری

رجسٹری `open-sse/services/compression/engines/registry.ts` میں رہتی ہے۔ انجن ایک مشترکہ معاہدے کو ظاہر کرتے ہیں:

- `id`: مستحکم انجن آئی ڈی جیسے `caveman` یا `rtk`
- `apply(text, config)`: اسٹیک شدہ پائپ لائنوں کے ذریعہ استعمال ہونے والا میراثی عمل درآمد کا راستہ
- `compress(input, config)`: بنیادی عمل درآمد کا راستہ واپس کرنے والا متن + اعدادوشمار
- `getConfigSchema()`: درست ترتیب کی JSON-Schema جیسی شکل لوٹاتا ہے۔
- `validateConfig(config)`: `{ valid, errors[] }` لوٹاتا ہے۔

رجسٹریشن میں `registerCompressionEngine(engine)` (یا ایڈوانس کیسز کے لیے `registerEngine` ) استعمال ہوتا ہے، جو قبول کرنے سے پہلے `assertValidEngine()` اور `validateConfig(defaultConfig)` کو کال کرتا ہے۔ رن ٹائم پر انجن کو ہٹانے کے لیے `unregisterCompressionEngine(id)` استعمال کریں۔

`strategySelector.ts` کمپریشن چلنے سے پہلے بلٹ ان انجنوں کو رجسٹر کرتا ہے۔ یہ پیش نظارہ، رن ٹائم کمپریشن، اسٹیکڈ موڈ، ٹیسٹ، اور مستقبل کے انجنوں کو ایک ہی عملدرآمد کا راستہ استعمال کرنے دیتا ہے۔

### MCP تفصیل کمپریشن (متعلقہ)

ایک علیحدہ رجسٹری MCP ٹول ڈسکرپشن میٹا ڈیٹا کو رجسٹری لیول — پر کمپریس کرتی ہے `open-sse/mcp-server/descriptionCompressor.ts` اور [MCP-SERVER.md](../frameworks/MCP-SERVER.md) دیکھیں۔ یہ Caveman قواعد کو دوبارہ استعمال کرتا ہے لیکن ٹول میٹا ڈیٹا پر کام کرتا ہے، پے لوڈز کی درخواست پر نہیں۔

### اضافی بلٹ ان انجن

Caveman، RTK، اور LLMLingua-2 سے آگے، رجسٹری کئی مخصوص نقصان کے بغیر / ساختی انجن بھیجتی ہے (اسٹیک شدہ پائپ لائنوں، کھیل کے میدان، اور ٹیسٹوں کے ذریعے استعمال کیا جاتا ہے):

| انجن        | آئی ڈی          | یہ کیا کرتا ہے                                                                                                                                                                      |
| ----------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CCR         | `ccr`           | Content-Compress-Retrieve (H4): بڑے متناسب ٹیکسٹ بلاکس کو مواد سے متعلق حوالہ جات سے بدل دیتا ہے، لہذا repeated/large بلاکس ایک بار بھیجے جاتے ہیں اور اس کے بعد حوالہ دیا جاتا ہے۔ |
| ہیڈ روم     | `headroom`      | SmartCrusher (H3 + N5): ایک کالم `[N rows]` شکل میں یکساں JSON-array پے لوڈز کا بے نقصان ٹیبلر کمپیکشن۔                                                                             |
| آئنائزر     | `ionizer`       | بہت بڑے یکساں بلاکس کے لیے Head/middle/tail قطار کا نمونہ لینا، ایلیڈڈ مڈل کو CCR مواد سے خطاب شدہ حوالہ کے طور پر محفوظ کرنا۔                                                      |
| سیشن ڈیڈ اپ | `session-dedup` | مواد سے خطاب شدہ کراس ٹرن ڈیڈپلیکیشن (TokenMizer-Inspired): ایک ہی سیشن کے پہلے موڑ میں پہلے سے نظر آنے والا ایلائیڈ ٹیکسٹ۔                                                         |

**CCR بازیافت پروٹوکول ہدایات (#8033):** پہلی بار جب CCR درخواست میں ≥ 1 بلاک کی جگہ لے لیتا ہے، انجن ایک واحد، idempotent `system` پیغام ( `[CCR protocol]` سینٹینل کے ساتھ معروف) کال کرنے والے کو مارکر → ٹول معاہدہ سکھاتا ہے: `[CCR retrieve hash=<24hex> chars=N]` مارکر کا کیا مطلب ہے، کہ ہیش کو لفظی طور پر کاپی کیا جانا چاہیے (تمام 24 — کی غلطی کی وجہ سے ہے "بلاک نہیں ملا" یاد کرتا ہے) اور یہ کہ `[dedup:ref sha=...]` مارکر کا مطلب ہے "تاریخ میں پیچھے دیکھو"، "ٹول کو کال کریں" نہیں۔ نوٹ انجکشن ہے** صرف اس وقت جب کال کرنے والے کا اشتہار دیا گیا `tools[]` ثابت کرتا ہے کہ یہ حقیقت میں `omniroute_ccr_retrieve` تک پہنچ سکتا ہے۔** (`callerSupportsCcrRetrieve()` in `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — اس ٹول کے بغیر ایک سادہ OpenAI- ہم آہنگ کالر کو کبھی بھی ایسی چیز کو کال کرنے کی ہدایت موصول نہیں ہوتی جس تک وہ پہنچ نہیں سکتا۔ انجیکشن لگانے سے پہلے سینٹینل کے لیے میسج ہسٹری کو اسکین کرکے Idempotency نافذ کی جاتی ہے، اس لیے ملٹی ٹرن کی درخواستیں (جو پہلے کے پیغامات کو دوبارہ چلاتی ہیں) ہر باری پر ایک بار نوٹ کو اسٹیک نہیں کرتی ہیں۔

## غار والا

کیو مین موڈ عام نثر کی معنوی سنکشیشن پر مرکوز ہے:

- کوڈ بلاکس، URLs، JSON، راستے، اور سٹرکچرڈ ڈیٹا کو محفوظ رکھتا ہے۔
- فلر، ہیجنگ، بار بار سیاق و سباق، اور وربوز کنیکٹیو فقرے کو ہٹاتا ہے۔
- `open-sse/services/compression/rules/` میں زبان سے آگاہ فائل رول پیک کو سپورٹ کرتا ہے۔
- لیگیسی `standard`، `aggressive`، اور `ultra` طریقوں کے ذریعے دستیاب رہتا ہے۔

ڈیش بورڈ کی سطح `Dashboard -> Context & Cache -> Caveman` ہے۔

Caveman upstream `~75%` کم آؤٹ پٹ ٹوکنز، `22-87%` رینج کے ساتھ بینچ مارکس میں `65%` اوسط آؤٹ پٹ بچت، اور `~46%` ان پٹ-کمپریشن ٹول کی رپورٹ کرتا ہے۔ OmniRoute اسٹیکڈ prompt/context بچت کی دستاویز کرتے وقت Caveman ان پٹ سائیڈ نمبر کا استعمال کرتا ہے۔ کیو مین آؤٹ پٹ موڈ ایک علیحدہ ردعمل کے رویے کی خصوصیت بنی ہوئی ہے۔

## RTK

RTK موڈ کمانڈ اور ٹول آؤٹ پٹ پر فوکس کرتا ہے:

- آؤٹ پٹ کلاسز کا پتہ لگاتا ہے جیسے کہ `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, Cargo/Go ٹیسٹس , TypeScript/Vite/Webpack builds , ESLint, npm audit/installs, Docker logs , shell `find`/`grep`, اسٹیک ٹریسز اور عام لاگز
- `open-sse/services/compression/engines/rtk/filters/` سے 49 JSON فلٹرز کا اطلاق ہوتا ہے۔
- RTK طرز کی اعلانیہ پائپ لائن کو سپورٹ کرتا ہے: ANSI سٹرپنگ، ریپلیس، میچ آؤٹ پٹ شارٹ سرکٹ، strip/keep لائنز، فی لائن ٹرنکیشن، head/tail/max-line ٹرنکیشن، اور آن خالی فال بیک
- `.rtk/filters.json` میں ٹرسٹ گیٹڈ پروجیکٹ فلٹرز اور `DATA_DIR/rtk/filters.json` میں عالمی فلٹرز کو سپورٹ کرتا ہے۔
- سٹرپس ANSI تسلسل، ترقی کا شور، بار بار لائنیں، اور غیر مددگار بوائلر پلیٹ
- قابل عمل ناکامیوں، انتباہات، خلاصے، تبدیل شدہ فائلوں اور ٹیل سیاق و سباق کو محفوظ رکھتا ہے۔
- اختیاری طور پر تصدیق شدہ انتظامی راستوں کے ذریعے recovery/debugging کے لیے redacted خام آؤٹ پٹ کو برقرار رکھ سکتا ہے۔

ڈیش بورڈ کی سطح `Dashboard -> Context & Cache -> RTK` ہے۔

اپنی مرضی کے مطابق فلٹرز، اعتماد، تصدیق، اور خام آؤٹ پٹ ریکوری کے لیے آپریشنل تفصیلات [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md) میں رہتی ہیں۔

RTK upstream کمانڈ آؤٹ پٹ کمپریشن کے لیے `60-90%` بچت کی اطلاع دیتا ہے۔ اس کی README مثال ایک 30 منٹ کا Claude کوڈ سیشن دکھاتی ہے جو `~118,000` ٹوکن سے `~23,900` تک جاتا ہے، یا `79.7%` محفوظ کیا جاتا ہے۔

## LLMLingua-2 (Semantic pruning)

LLMLingua-2 موڈ انجام دیتا ہے۔** سیمنٹک ٹوکن کی کٹائی** اصول پر مبنی Caveman اور RTK انجنوں کی تکمیل کرتے ہوئے، ایک چھوٹا ONNX ٹوکن درجہ بندی کا استعمال کرتے ہوئے نثر پر:

- صرف نان سسٹم پیغامات میں نثر کو کمپریس کرتا ہے۔ باڑ والے کوڈ بلاکس اور دیگر محفوظ تعمیرات کو کبھی تبدیل نہیں کیا جاتا ہے۔
- ورکر تھریڈ میں `@atjsh/llmlingua-2` بیک اینڈ (ONNX بذریعہ `@huggingface/transformers`) چلاتا ہے، لہذا ماڈل کا اندازہ کبھی بھی درخواست کے ایونٹ لوپ کو بلاک نہیں کرتا
- ہے** اسٹیک ایبل** (`stackPriority` 35): اسٹیک شدہ پائپ لائن میں یہ ساختی انجنوں کے بعد چلتی ہے (CCR، session-dedup، headroom، Caveman) لیکن `ultra` سے پہلے، کیونکہ سیمنٹک پرننگ پہلے سے ساختی طور پر کمپریسڈ ٹیکسٹ — مثلاً `rtk -> caveman -> llmlingua` پر سب سے زیادہ مؤثر ہے۔
- **کسی بھی غلطی پر فیل کھلتا ہے۔** (اختیاری ڈیپس، ورکر سپون، ماڈل لوڈ، انفرنس، یا ٹائم آؤٹ غائب) → اصل متن کو بغیر تبدیلی کے واپس کر دیا جاتا ہے، کبھی غلطی نہیں ہوتی

انجن کا مقام: `open-sse/services/compression/engines/llmlingua/` ڈیش بورڈ کی سطح `Dashboard -> Context & Cache -> LLMLingua` ہے۔

### ماڈلز

پہلے سے طے شدہ ماڈل ہے۔**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`، ~ 57 MB، تیز)۔ ایک اعلیٰ درستگی** BERT بیس** ماڈل (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) انجن کنفگ `model` فیلڈ کے ذریعے دستیاب ہے۔ `@huggingface/transformers` منتخب ماڈل کو HuggingFace Hub سے `${DATA_DIR}/models/llmlingua` میں پہلی کال پر سستی سے ڈاؤن لوڈ کرتا ہے (`modelStore.ts`); ایک `modelPath` config اوور رائڈ اس کی بجائے اسے مقامی کاپی پر پوائنٹ کرتا ہے (آف لائن / ایئر گیپڈ انسٹالز)۔

### اختیاری انحصار اور آن ڈیمانڈ انسٹال

prunable LLMLingua رن ٹائم پیئر اسٹیک ہے۔** اختیاری** . دو پیکجز کو `package.json` میں `optionalDependencies` قرار دیا جاتا ہے اور رکھا جاتا ہے۔** بیرونی** پروڈکشن بلڈ کے ذریعہ (`scripts/build/prepublish.ts` انہیں بنڈل نہیں کرتا ہے):

| پیکج                 | ورژن (پن) | نوٹس                                         |
| -------------------- | --------- | -------------------------------------------- |
| `@atjsh/llmlingua-2` | `2.0.5`   | داخلہ پیکج؛ دوسروں کو ہم مرتبہ قرار دیتا ہے۔ |
| `js-tiktoken`        | `^1.0.20` | ٹوکنائزر                                     |

`@huggingface/transformers` کو `^4.2.0` پر پن کیا جاتا ہے (مقامی ایمبیڈنگس پاتھ کے ساتھ شیئر کیا جاتا ہے اور اسٹینڈ اسٹون بنڈل میں بھی ٹریس کیا جاتا ہے)؛ `@atjsh/llmlingua-2@2.0.5` اس پر `"^3.5.2 || ^4.0.0"` کے ساتھ پیئر کرتا ہے، لہذا Transformers.js v3 اور v4 دونوں معاون ہیں۔ 2.0.4 کے بعد سے، `@atjsh/llmlingua-2` اب `@tensorflow/tfjs` کی ضرورت نہیں ہے، جس نے SLM اسٹیک سے سب سے بڑا واحد تعاون کنندہ (TensorFlow.js) ہٹا دیا۔ اوپر صرف دو پیکجز قابل کٹائی SLM ساتھی ہیں۔ ایک معیاری `npm install` (dev) اختیاری اسٹیک کو خود بخود انسٹال کرتا ہے جب تک کہ اختیاری انحصار کو چھوڑ دیا جائے۔

**کیوں آن ڈیمانڈ:** npm-شائع کردہ پیکیج، اسٹینڈ اسٹون بنڈل، اور Docker امیج شپ** بغیر** ان ڈیپس پتلا رہنے کے لئے. جب وہ غیر حاضر ہوتے ہیں، تو کارکن کا انحصار گیٹ ( `worker.ts` میں `@atjsh/llmlingua-2` ریزولوشن پروب) ناکام ہوجاتا ہے اور انجن** فیل - خاموشی سے کھلتا ہے۔** — کو منتخب کرنے سے LLMLingua ایک no-op بن جاتا ہے (متن میں کوئی تبدیلی نہیں ہوئی، کوئی غلطی لاگ ان نہیں ہوئی)۔ اسے کٹے ہوئے ماحول میں چالو کرنے کے لیے، اختیاری اسٹیک انسٹال کریں:

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` ہٹانا (2.0.4 +) پہلے سے غالب ~ 800 MB کنٹریبیوٹر — ختم کر دیتا ہے باقی فوٹ پرنٹ transformers.js + onnxruntime-node رن ٹائمز ہے، نیز TinyBERT ماڈل (~ 57 MB پر پہلے ڈاؤن لوڈ کریں)۔

ماحول کے مطابق:

- **دیو/ `npm install`** — خود بخود انسٹال ہوجاتا ہے جب تک کہ آپ `--omit=optional` (یا `--no-optional`) کو پاس نہ کریں۔ کسی کارروائی کی ضرورت نہیں۔
- **عالمی این پی ایم (`npm i -g omniroute`) / اسٹینڈ لون** — انسٹال کردہ پیکیج ڈائرکٹری کے اندر اوپر انسٹال کمانڈ چلائیں، یا اختیاری ڈیپس کو چھوڑے بغیر دوبارہ انسٹال کریں۔
- **Docker** — ایک اخذ کردہ امیج لیئر میں انسٹال کمانڈ شامل کریں۔ شائع شدہ تصویر بحری جہاز ڈیزائن کے لحاظ سے پتلی ہے۔
- **VPS (PM2)** — ایپ کے `node_modules` میں انسٹال کریں، پھر اس عمل کو دوبارہ شروع کریں تاکہ کارکن گیٹ کی دوبارہ تحقیقات کرے۔
- **را نیکسٹ اسٹینڈ ایلون (`npm run build` → `.build/next/standalone/server.js`)** — اسٹینڈ اسٹون ٹریس بحری جہاز ورکر کو NEITHER اور نہ ہی اختیاری ڈیپس، لہذا انجن خاموشی سے فیل ہو جاتا ہے۔ `scripts/build/colocate-standalone.mjs` دونوں کو دوبارہ لاگو کرتا ہے (کارکن esbuild + اختیاری-dep بندش کو اسٹینڈ اسٹون ٹری میں) یہ ہر تعمیر کے بعد `postbuild` npm ہک کے ذریعے خود بخود چلتا ہے۔ جب ڈیپس غیر حاضر ہوں تو بے حس، ناکام نرم۔

**تصدیق کریں کہ یہ فعال ہے:** LLMLingua منتخب ہونے کے ساتھ، حقیقی نثر دراصل سکڑ جاتا ہے (انجن فیل ہونے سے رک جاتا ہے)، اور پہلی درخواست ماڈل ڈاؤن لوڈ کو `${DATA_DIR}/models/llmlingua` میں متحرک کرتی ہے۔ گیٹ جان بوجھ کر صرف `@atjsh/llmlingua-2` — تحقیقات کرتا ہے دوسرے ساتھی صرف ESM ہیں اور `require.resolve` ان پر پھینک دیتا ہے یہاں تک کہ جب — موجود ہو تو کارکن پھر بھی فیل ہو جاتا ہے اگر کوئی ساتھی `import()` وقت پر حقیقی طور پر غائب ہو تو۔

## اسٹیک شدہ پائپ لائنز

اسٹیکڈ موڈ پائپ لائن کے مراحل کو ترتیب سے چلاتا ہے۔ پہلے سے طے شدہ ہے:

```txt
rtk -> caveman
```

اسے کوڈنگ ایجنٹ سیشنز کے لیے استعمال کریں جہاں ایک پرامپٹ کمانڈ آؤٹ پٹ کو انسانی یا معاون نثر کے ساتھ جوڑتا ہے۔ RTK پہلے شور والے ٹول لاگ کو کم کرتا ہے، پھر Caveman باقی قدرتی زبان کو کمپریس کرتا ہے۔

پائپ لائن کے مراحل کو `stackedPipeline` کے ساتھ کمپریشن سیٹنگ میں یا کمپریشن کمبوس کے ذریعے ترتیب دیا جاتا ہے۔

جب دونوں انجن ایک ہی اہل پے لوڈ کو کم کرتے ہیں تو بچت کا مرکب:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP ایکسیسبیلٹی ٹری فلٹر

MCP ایکسیسبیلٹی-ٹری اسمارٹ فلٹر ایک پوسٹ ایگزیکیوشن کمپریشن لیئر ہے جو MCP پر چلتا ہے۔** آلے کے نتائج** ، اشارے یا سیاق و سباق پر نہیں۔ یہ Playwright، کمپیوٹر کے استعمال، اور براؤزر آٹومیشن MCP سرورز جیسے ٹولز کے ذریعے واپس کیے گئے وربوز ایکسیسبیلٹی-ٹری اور براؤزر اسنیپ شاٹ پے لوڈز کو نشانہ بناتا ہے۔

### یہ کیا کرتا ہے

1. **شور اتارنا** — خالی generic/text اندراجات کو ہٹاتا ہے (`- generic:`, `- text: ""`)
2. **بہن بھائی کا خاتمہ** — جب ≥ `collapseThreshold` (پہلے سے طے شدہ 30) مسلسل لائنیں ساختی دہرائی جاتی ہیں، انہیں پہلی `collapseKeepHead` (پہلے سے طے `collapseKeepTail` 10) لائنوں میں + دیتی +
3. **حوالہ تحفظ** — `[ref=eXX]` Playwright/computer-use کو درکار اینکرز کو کبھی ہاتھ نہیں لگایا جاتا
4. **سخت تراشنا** — اگر منہدم ہونے کے بعد بھی متن `maxTextChars` (پہلے سے طے شدہ 50,000) سے زیادہ ہے تو، نیویگیشن اشارے کے ساتھ چھوٹا ہوجاتا ہے تاکہ ایجنٹ کام جاری رکھ سکے۔

### انجن کا مقام

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### کنفیگریشن

عالمی ترتیبات میں `compression.mcpAccessibility` کے ذریعے کنٹرول کیا جاتا ہے (ہجرت 056)۔ پہلے سے طے شدہ ترتیب:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

فلٹر کا اطلاق صرف ٹول رزلٹ پے لوڈز پر ہوتا ہے جن کا `type` `"text"` ہے اور جن کی لمبائی `minLengthToProcess` سے زیادہ ہے۔ یہ فوری کمپریشن یا درخواست پے لوڈز کو متاثر نہیں کرتا ہے۔

### متوقع بچت

صفحہ کی پیچیدگی کے لحاظ سے براؤزر اسنیپ شاٹ ٹول کے نتائج پر 60–80%۔ کولپس الگورتھم لائن کی گنتی میں O(n) ہے اور نہ ہونے کے برابر تاخیر کا اضافہ کرتا ہے۔

### یہ فلٹر بمقابلہ اوپر والے کمپریشن انجن

| پہلو         | غار کا آدمی / RTK / سجا ہوا          | MCP ایکسیسبیلٹی فلٹر                   |
| ------------ | ------------------------------------ | -------------------------------------- |
| ہدف          | اشارے / سیاق و سباق کی درخواست کریں۔ | MCP ٹول کے نتائج                       |

## کمپریشن کومبوس

کمپریشن کمبوس کو کمپریشن پروفائلز کا نام دیا گیا ہے جو روٹنگ کومبوز کو تفویض کیا جا سکتا ہے:

- `compression_combos`: اسٹورز موڈ، پائپ لائن، RTK کنفیگریشن، لینگویج کنفگ، اور ڈیفالٹ مارکر
- `compression_combo_assignments`: ایک کمپریشن کومبو کو روٹنگ کومبو سے نقشہ بناتا ہے۔
- رن ٹائم انٹیگریشن عام کومبو کو اوور رائیڈ کرنے سے پہلے تفویض کردہ کمپریشن کومبو کو حل کرتا ہے۔
- تجزیات میں `compression_combo_id` اور `engine` شامل ہیں۔

ڈیش بورڈ کی سطح: `Dashboard -> Context & Cache -> Compression Combos`

## پیشگی شرائط / آپریٹر گائیڈ (CCR اور سیشن ڈیڈ اپ)

CCR (`ccr`) اور `session-dedup` متن کو تبدیل کریں یا ایلائیڈ کریں اور a چھوڑ دیں۔** مارکر** پیچھے یہ سیکشن کلائنٹ کو وائرنگ کرنے، دو مارکروں کو پڑھنے، اور ایلیڈڈ مواد کی بازیافت یا تشخیص کرنے کے لیے آپریٹر کا حوالہ ہے۔ ہر انجن کی میکانکس اوپر دی گئی ہیں۔ یہ "میں اسے کیسے چلا سکتا ہوں" پرت ہے۔

### ٹرانسپورٹ اور اختتامی مقامات

MCP سرور جو CCR ٹولز کو بے نقاب کرتا ہے تین طریقوں سے پہنچا جا سکتا ہے۔ پہلے سے طے شدہ بنیاد URL ہے `http://localhost:20128` (`OMNIROUTE_BASE_URL`):

| ٹرانسپورٹ                            | URL /حکم                                | نوٹس                                                                                                                                       |
| ------------------------------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| سٹریم ایبل HTTP (کلائنٹ، تجویز کردہ) | `http://localhost:20128/api/mcp/stream` | اختتامی نقطہ موجودہ MCP کلائنٹس سے بات کرتے ہیں۔                                                                                           |
| لیگیسی SSE سنگلٹن                    | `http://localhost:20128/api/mcp/sse`    | پرانی سنگلٹن ٹرانسپورٹ۔ یہ** بند کرتا ہے** سٹریم ایبل سیشنز؛ `streamable-http` کلائنٹس کو `/api/mcp/stream` کے خلاف استعمال کریں، یہ نہیں۔ |
| stdio                                | `omniroute --mcp`                       | IDE MCP config کے لیے جو عمل کو جنم دیتا ہے۔ کوئی `--dev` پرچم نہیں ہے؛ `omniroute --mcp` stdio انٹری پوائنٹ ہے۔                           |

### سٹوریج کے درجات (دوبارہ شروع کرنے سے کیا بچتا ہے)

CCR ہے a** دو درجے** اسٹور، صرف میموری میں نہیں:

- **ہاٹ ان میموری ٹائر** — فی بلاک کیپ 2 MiB، فی پرنسپل 16 MiB، عالمی 64 MiB۔ اندراجات پہلے سے طے شدہ 24 گھنٹے TTL (زیادہ سے زیادہ 7 دن)۔ میموری سے مکمل MCP بازیافت 256 KiB پر محدود ہے۔ کوئی بھی بڑی چیز رینجڈ/گریپ موڈز کے ذریعے قابل رسائی ہے۔
- **پائیدار SQLite ٹائر** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, آن بذریعہ ڈیفالٹ) — ان میموری ٹائر کی پشت پناہی کرتا ہے لہذا ایک بلاک LRU بے دخلی، دوبارہ شروع، یا کسی اور موقع پر لینڈنگ کی بازیافت سے بچ جاتا ہے۔ قطار بلاک کے TTL برقرار رکھتی ہے، لہذا اس کے TTL سے آگے کا بلاک دونوں درجوں سے چلا گیا ہے۔

تین گارڈز پائیدار ٹائر باؤنڈڈ — رکھتے ہیں ایک بلاک یادداشت میں صرف اس وقت رہتا ہے جب:

1. بلاک ختم ہو گیا ہے** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`)
2. رن ٹائم کلاؤڈ رن ٹائم ہے (کوئی مقامی ڈسک نہیں)؛
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

لہذا "بلاک غائب ہو گیا" ایک کمبل دوبارہ شروع کرنے کی کہانی نہیں ہے: ایک مقامی، غیر کلاؤڈ رن ٹائم پر ایک sub-512 KB بلاک پائیدار ٹائر کے ذریعے دوبارہ شروع ہونے تک زندہ رہتا ہے جب تک کہ اس کا TTL ختم نہ ہو جائے۔ متغیر کے لیے [ماحولیات کا حوالہ](../reference/ENVIRONMENT.md) دیکھیں۔

| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[CCR retrieve hash=<24hex> chars=N]` | ایک بڑا بلاک مواد کو ایڈریس کے ذریعے محفوظ کیا گیا تھا۔                                                                                          | کے ساتھ `omniroute_ccr_retrieve` کال کریں۔** 24-ہیکس ہیش لفظی طور پر نقل کی گئی۔** اصل متن واپس حاصل کرنے کے لیے۔                                                                                                         |
| `[dedup:ref sha=…]`                   | `session-dedup` elided متن پہلے ہی اسی سیشن کے پہلے موڑ میں بھیجا گیا ہے۔ یہ ایک ہے** جان بوجھ کر پیچھے کی طرف دیکھنا** ، نقصان یا غلطی نہیں ہے۔ | کرو** نہیں** کسی بھی آلے کو کال کریں اور کریں۔** نہیں** اسے "دوبارہ تشکیل" کرنے کی کوشش کریں۔ متن کا پہلا واقعہ کینونیکل کاپی ہے۔ موجودہ موڑ کو کبھی بھی دوبارہ نہیں لکھا جاتا، یہ بعد میں آنے والے موڑ پر نکالا جاتا ہے۔ |

`[dedup:ref]` نظر واپس ایک جان بوجھ کر پروٹوکول کا فیصلہ ہے — پہلے سے بھیجنے کی تعمیر نو نہیں ہے۔ اسے اس طرح سمجھیں کہ "یہ قطعی متن اس سیشن میں پہلے ہی تار پر موجود تھا۔"

### کلائنٹ کی شرائط

- **کلید (stdio):** ایک stdio کالر فی درخواست کی کوئی شناخت نہیں رکھتا ہے، لہذا یہ `OMNIROUTE_API_KEY` ( MCP سرور کے `env` میں سیٹ) کے ساتھ تصدیق کرتا ہے۔ اس کے بغیر کال کرنے والا گمنام ہوتا ہے اور ایسے ٹولز جن کے لیے پرنسپل کی ضرورت ہوتی ہے ان کی کمی ہو سکتی ہے۔
- **`tools[]` is the injection precondition.** The CCR retrieve-protocol instruction (#8033) is injected **only** when the request's advertised `tools[]` proves the client can actually reach `omniroute_ccr_retrieve`. The match is a trailing-segment match bounded by a separator (`__`, `.`, `/`, `:`) — never a bare substring — so a namespaced name such as `mcp__gateway__omniroute_ccr_retrieve` still counts. An absent or non-matching `tools[]` means the instruction is _not_ injected, by design.
- **`codemode:false` (OpenCode کلائنٹس)۔** OpenCode کوڈ موڈ پر ڈیفالٹ کرتا ہے، جو ماڈل میں صرف اپنے مقامی ٹولز کی تشہیر کرتا ہے اور** نہیں کرتا** مقامی `tools[]` فہرست میں MCP ٹولز ڈالیں۔ MCP سرور کے اندراج پر `codemode: false` سیٹ کریں تاکہ `omniroute_ccr_*` ٹولز کی تشہیر کی جائے۔ یہ ایک ہے** کلائنٹ** ترتیب، ایک OmniRoute نہیں. اس میں ابھی تک CCR انسٹرکشن نہیں لگایا گیا ہے: OpenCode ایک ٹول کو `<server>_<tool>` کا نام دیتا ہے، لہذا `omniroute` نامی سرور `omniroute_omniroute_ccr_retrieve` ظاہر کرتا ہے، اور `_` مماثل جداکاروں میں سے ایک نہیں ہے۔
- **پرنسپلز۔** ذخیرہ اور بازیافت فی توثیق شدہ پرنسپل (فی API کلید) الگ تھلگ ہے۔ ایک کلید صرف اپنے بلاکس کو دیکھتی ہے۔

### دائرہ کار فی ٹول

محدود دائرہ کار والے HTTP/SSE کال کرنے والوں کے لیے دائرہ کار کا نفاذ ہمیشہ جاری رہتا ہے۔ `omniroute_` CCR ٹولز کی ضرورت ہے:

| ٹول                      | دائرہ کار           |
| ------------------------ | ------------------- |
| `omniroute_ccr_store`    | `write:compression` |
| `omniroute_ccr_delete`   | `write:compression` |
| `omniroute_ccr_retrieve` | `read:compression`  |
| `omniroute_ccr_inspect`  | `read:compression`  |
| `omniroute_ccr_list`     | `read:compression`  |
| `omniroute_ccr_stats`    | `read:compression`  |

ایک گمشدہ دائرہ کار ایک لوٹاتا ہے۔**MCP ٹول کی خرابی کا نتیجہ** (`isError: true`، HTTP 403 — نہیں `403 LOCAL_ONLY` الگ لوپ بیک روٹ گارڈ auth ہے): `Error: Insufficient MCP scopes for <tool>. Missing: <scope>.` ایک کم سے کم ریموٹ کلید `mcp:connect` پکڑ سکتی ہے ( `/api/mcp/` مقامی طور پر صرف تراشنے کی اجازت دیتا ہے) اور اس کے علاوہ مخصوص read/write دائرہ کار کو اس کی ضرورت ہے۔

### بازیافت کی حدود اور صفحہ بندی

MCP ٹول ٹیکسٹ کے نتائج `mcpAccessibility.maxTextChars` (پہلے سے طے شدہ `50000`) کے ارد گرد تراشے جاتے ہیں۔ ایک بلاک کی ایک `full` بازیافت 256 KiB — پر محدود ہے۔** کوئی لامحدود مکمل بازیافت نہیں ہے۔** . جب کسی بلاک کا `chars=N` بڑا ہو تو پوری چیز کو کھینچنے کے بجائے اس کا صفحہ بنائیں:

- انگوٹھے کا اصول:**`chars > 40000` → ایک `mode` استعمال کریں۔** , ایک ننگی مکمل کبھی نہیں.
- `mode:"grep"` — regex `pattern` مماثل لائن بذریعہ لائن، 1,000 تک مماثل لائنیں (`unique: true` ڈراپس دہراتی ہیں)، "مجھے مطلوبہ ایک لائن تلاش کریں" کے لیے سب سے سستا۔
- `mode:"lines"` — ایک 1-انڈیکسڈ لائن رینج؛ `start` اور `end` دونوں کی ضرورت ہے۔
- `mode:"head"` / `mode:"tail"` — first/last `n` لائنیں.
- `mode:"stats"` — لائن، کردار، اور بائٹ شمار جسم کے بغیر۔

`mode:"lines"` استعمال `start`/`end` کے ساتھ کریں تاکہ ایک ہی وقت میں پوری چیز کی درخواست کرنے کے بجائے صفحات میں ایک لمبا بلاک چل سکے۔

### ٹول کا نام دینا

بازیافت ٹول کو فی الحال `omniroute_ccr_retrieve` کا نام دیا گیا ہے ( `omniroute_` کا سابقہ کراس سرور نام کے تصادم کے لئے ایک تاریخ والا کام ہے)۔ ایک کلینر باؤنڈڈ لاحقہ ٹول کا نام اور MCP JSON نتائج کے لیے ایک فکس تراشے ہوئے وسط سٹرنگ کو اپ اسٹریم فالو اپ کے طور پر ٹریک کیا جاتا ہے۔ یہ صفحہ صرف موجودہ، بھیجے گئے سلوک کو دستاویز کرتا ہے۔

### سیشن لائف سائیکل

سٹریم ایبل-HTTP سیشنز بیکار ہو جاتے ہیں اور سرور انہیں کاٹتا ہے۔ غیر فعال ونڈو `MCP_SESSION_IDLE_MS` مستقل ہے (نام سے حوالہ دیا گیا ہے، ہارڈ کوڈ شدہ قدر نہیں، لہذا یہ صفحہ تبدیل ہونے پر نہیں بڑھتا ہے)۔ بیکار کاٹے جانے والے سیشن کی علامت `Unknown Mcp-Session-Id` — کے ساتھ HTTP 404 ہے اس کا علاج سیشن کو دوبارہ جوڑنا یا دوبارہ شروع کرنا ہے،** نہیں** کسی کلید کو گھمانے، دائرہ کار کو تبدیل کرنے، یا کسی ٹول کا نام تبدیل کرنے کے لیے۔

## دائرہ کار اور اخراج

**ایمبیڈنگز کبھی کمپریس نہیں ہوتے ہیں۔** `open-sse/handlers/embeddings.ts` کبھی بھی کسی کمپریشن انجن کو — نہیں کہتا ہے request/response باڈیز سیدھے ایگزیکیوٹر کے پاس جاتی ہیں اچھوت۔ یہ آج ڈھانچہ ہے (ایمبیڈنگز اور چیٹ کی تکمیلات ڈس جوائنٹ ہینڈلرز ہیں)، رن ٹائم چیک نہیں، لیکن اس کا مطلب ہے کہ #8034 میں ویکٹر ڈسٹورشن کی تشویش ایمبیڈنگز کے راستے میں کوئی نمائشی سطح نہیں ہے۔

**Per-model/endpoint اخراج فلٹر (#8034)** چیٹ کی تکمیل کے لیے، ایک آپریٹر ماڈل ids/ `provider/model` اہداف کا نام دے سکتا ہے جنہیں کبھی بھی کمپریسڈ نہیں ہونا چاہیے — ایک گارڈریل مفید ہے اگر کمپریشن کو بعد میں ایمبیڈنگز سے ملحقہ راستے کے قریب وائر کیا گیا ہو، اور عام طور پر کسی بھی ایسے ماڈل کے لیے مفید ہو جس کے عین مطابق بائٹ کے لیے بائٹ پرامپٹ معاملات (ڈیٹرمنسٹک، پریفکس وغیرہ)۔

- ترتیبات کا میدان: `exclusions?: string[]` عالمی کمپریشن کنفیگریشن پر (`GET`/`PUT /api/settings/compression`)، موجودہ `key_value` کمپریشن نیم اسپیس (`src/lib/db/compression.ts`) — کوئی نیا ٹیبل نہیں ہے۔
- ڈیش بورڈ ٹیب:** ڈیش بورڈ → کمپریشن → اخراج** (`/dashboard/compression/exclusions`)
- پیٹرن نحو: `*` واحد وائلڈ کارڈ ہے۔ پیٹرن میں ہر دوسرا ریجیکس میٹا کیریکٹر ملاپ سے پہلے بچ جاتا ہے، لہذا `gpt-5.6` صرف لفظی سٹرنگ سے میل کھاتا ہے، کبھی `gpt-5x6` (ReDoS-safe، bounded، no nested quantifiers)۔ پیٹرنز کیس کی غیر حساسیت سے مماثل ہیں دونوں ننگے ماڈل id اور `provider/model` کمپوزٹ — `gpt-5-6`، `openai/gpt-5-6` اور `openai/*` تمام کام کرتے ہیں، اور `*` ہی ہر ماڈل کو خارج کرتا ہے۔
- مماثلت: `isCompressionExcluded()` / `normalizeCompressionExclusions()` `open-sse/services/compression/exclusions.ts` میں۔ `chatCore.ts` کمپریشن کی ترتیبات کو حل کرنے کے بعد خارج شدہ ہدف کو چیک کرتا ہے،** کوئی انجن چلنے سے پہلے** ، اور میچ کے ساتھ بالکل ایسے ہی برتاؤ کرتا ہے جیسے عالمی سطح پر کمپریشن کو غیر فعال کیا جا رہا ہے — درخواست کا باڈی ثابت طور پر بائٹ جیسی ہے۔ اسکیپ کو `writeCompressionSkip(..., "excluded")` کے ذریعے تجزیاتی مرئیت کے لیے ریکارڈ کیا جاتا ہے۔
- پہلے سے طے شدہ (empty/absent فہرست): پری #8034 رویے — سے مماثل کچھ بھی خارج نہیں کیا گیا ہے۔

## معلوم حدود

- **LLMLingua-2 (SLM) کو شریک جگہ اختیاری ڈیپس کی ضرورت ہے۔** کارکن صرف پروڈکشن کی تعمیر میں چلتا ہے جب `@atjsh/llmlingua-2` + ساتھی `dist/node_modules` میں شریک ہوتے ہیں (دیکھیں `scripts/build/colocateOptionals.mjs`، #4286)۔ ان کے بغیر انجن فیل ہو جاتا ہے (اصل متن واپس کرتا ہے)۔ ورکر ریزولوشن اب `import.meta.url` پر منحصر نہیں ہے (یہ اسٹینڈ لون بنڈل میں مر جاتا ہے) — یہ رن ٹائم cwd / `argv[1]` پر اینکر کرتا ہے۔
- **کیو مین لینگویج پیکز `de` / `fr` / `ja` جزوی ہیں۔** وہ `context` + `filler` + `structural` قواعد بھیجتے ہیں لیکن کوئی `dedup` / `ultra` پیک نہیں ہے، لہذا `ultra` شدت ان زبانوں کے لیے `full` سے زیادہ مضبوط نہیں ہے (وہ صرف اپنے اصول — استعمال کرتے ہیں، انگریزی `dedup`/`ultra` قواعد کی طرف کوئی خاموشی نہیں ہے، جو غیر ملکی متن کو گھیرے گی)۔ `en` / `es` / `id` / `pt-BR` مکمل ہیں۔ جزوی پیک کے لیے `dedup.json` + `ultra.json` کی شراکتیں خوش آئند ہیں۔
- **اسٹیکڈ ٹیلی میٹری صرف ان انجنوں کی فہرست دیتی ہے جو کمپریسڈ ہوتے ہیں۔** ایک اسٹیک شدہ پائپ لائن کا مرحلہ جس کا انجن چلتا ہے لیکن 0% بچت `stats:null` دیتا ہے اور اس طرح `engineBreakdown` — میں نظر نہیں آتا ہے اس قدم سے الگ نہیں کیا جا سکتا جسے چھوڑ دیا گیا تھا۔ "اسکیپڈ" سے "رن، 0%" کو الگ کرنے کے لیے بریک ڈاؤن ماڈل کی تبدیلی کی ضرورت ہوگی اور اسے موخر کر دیا گیا ہے۔
