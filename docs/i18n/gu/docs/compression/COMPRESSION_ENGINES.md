OmniRoute કમ્પ્રેશન એન્જિન કોન્ટ્રાક્ટની આસપાસ બનેલ છે. મોડ એક એન્જિનને સીધું ચલાવી શકે છે (`caveman` અથવા `rtk`) અથવા એક નિર્ધારિત સ્ટેક્ડ પાઇપલાઇન કે જે બહુવિધ એન્જિનોને ક્રમમાં ચલાવે છે.

## મોડ્સ

| મોડ          | એન્જિન પાથ                                                                          | ઇચ્છિત ઇનપુટ                              |
| ------------ | ----------------------------------------------------------------------------------- | ----------------------------------------- |
| `off`        | કોઈ નહીં                                                                            | ચોક્કસ પ્રોમ્પ્ટ સાચવણી                   |
| `lite`       | કેવમેન લાઇટ સહાયકો                                                                  | ઓછું જોખમ હંમેશા સફાઈ પર                  |
| `standard`   | કેવમેન                                                                              | નેચરલ-ભાષા પ્રોમ્પ્ટ કન્ડેન્સેશન          |
| `aggressive` | કેવમેન + history/tool સારાંશકારો                                                    | લાંબા ચેટ સત્રો                           |
| `ultra`      | કેવમેન + કાપણી મદદગારો                                                              | સંદર્ભ-મર્યાદા પુનઃપ્રાપ્તિ               |
| `rtk`        | RTK                                                                                 | ટર્મિનલ, શેલ, બિલ્ડ, ટેસ્ટ અને ગિટ આઉટપુટ |
| `omniglyph`  | OmniGlyph                                                                           | મૂળ પ્રદાતા વાયર પર છબી તરીકે સંદર્ભ      |
| `stacked`    | પાઇપલાઇન. વિનંતી ડિફોલ્ટ `session-dedup -> lite` છે. `rtk -> caveman` પસંદ કરેલ છે. | મિશ્ર સાધન લોગ અને ગદ્ય, મહત્તમ બચત       |

### OmniGlyph કમ્પ્રેશન પ્રોફાઇલ્સ

`omniglyph` એન્જિન (પેકેજ `omniglyph`, 1.4.0 +) નામવાળી સિમેન્ટીક પ્રોફાઇલ સ્વીકારે છે, જે વૈશ્વિક સ્તરે `omniglyph.profile` દ્વારા કમ્પ્રેશન સેટિંગ્સમાં અથવા સ્ટેક્ડ પાઇપલાઇનની સ્ટેપ રૂપરેખા દ્વારા સ્ટેપ દીઠ સેટ કરવામાં આવે છે:

| પ્રોફાઇલ      | સીમા                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| `aggressive`  | ડિફૉલ્ટ. નીતિ પ્રકાશિત રસીદો માપવામાં — છબીઓ સિસ્ટમ, સાધન દસ્તાવેજો અને ગાઢ ઇતિહાસ          |
| `balanced`    | લાઇવ સ્ટેટ નેટીવ રાખે છે, છેલ્લા 8 વળાંકોનું રક્ષણ કરે છે, જૂના બંધ ઇતિહાસને સંકુચિત કરે છે |
| `coding-safe` | ઓથોરિટી, ટૂલ સ્કીમા અને લાઇવ ટૂલ આઉટપુટ નેટીવ રાખે છે, છેલ્લા 12 વળાંકોનું રક્ષણ કરે છે     |
| `passthrough` | રૂપાંતર કર્યા વિના માર્ગો; એન્જિન છોડવામાં આવ્યું છે                                        |

પ્રોફાઇલ એ છે** છત, ફ્લોર નહીં** : પેકેજમાં `mergeCompressionProfileOptions` એ કોલરને ઓવરરાઇડ કરેલી પ્રોફાઇલ બંધ થયેલ નુકસાની લેન ફરીથી ખોલવા દેવાનો ઇનકાર કરે છે, તેથી પ્રતિ-પગલાં `preserveSystemPrompt: false` `coding-safe` હેઠળ સિસ્ટમ કમ્પ્રેશનને ફરીથી સક્ષમ કરી શકતું નથી.

આ કોડબેઝ પર માપવામાં આવે છે: `coding-safe` અને `balanced` `minCompressChars` તેની મહત્તમ સુધી વધારી દે છે અને સિસ્ટમ, ટૂલ સ્કીમા અને ટૂલ પરિણામો નેટીવ રાખે છે, તેથી એક સત્ર કે જેણે હજી સુધી ઇતિહાસ એકત્રિત કર્યો નથી તે `below_min_chars` પર અટકે છે અને એન્જિન કંઈપણ રૂપાંતરિત કરતું નથી. તેથી જ સૌથી સુરક્ષિત પ્રોફાઇલને બદલે ડિફોલ્ટ `aggressive` છે.

પેકેજ તેના પર્યાવરણ રૂપરેખાંકનમાંથી તેના પોતાના મોડલ અવકાશ અને પ્રોફાઇલને ઉકેલે છે. OmniRoute ક્યારેય નિર્ણય સોંપતું નથી: એડેપ્ટર મોડેલ ગેટને પેકેજના સૌથી પ્રતિબંધિત અવકાશમાં પિન કરે છે, તેથી યજમાન પર્યાવરણ સેટિંગ્સ ફક્ત અનુમતિ સૂચિને સાંકડી શકે છે, તેને OmniRoute ની માપેલી રસીદોથી આગળ કદી પહોળી કરી શકતી નથી.

## એન્જિન રજિસ્ટ્રી

રજિસ્ટ્રી `open-sse/services/compression/engines/registry.ts` માં રહે છે. એંજીન એક વહેંચાયેલ કરારનો પર્દાફાશ કરે છે:

- `id`: સ્થિર એન્જિન આઈડી જેમ કે `caveman` અથવા `rtk`
- `apply(text, config)`: સ્ટેક્ડ પાઇપલાઇન્સ દ્વારા ઉપયોગમાં લેવાતો લેગસી એક્ઝેક્યુશન પાથ
- `compress(input, config)`: પ્રાથમિક એક્ઝેક્યુશન પાથ રીટર્નિંગ ટેક્સ્ટ + આંકડા
- `getConfigSchema()`: માન્ય રૂપરેખાનો JSON-Schema-જેવો આકાર પરત કરે છે
- `validateConfig(config)`: `{ valid, errors[] }` પરત કરે છે

નોંધણી `registerCompressionEngine(engine)` (અથવા અદ્યતન કેસ માટે `registerEngine` ) નો ઉપયોગ કરે છે, જે સ્વીકારતા પહેલા `assertValidEngine()` અને `validateConfig(defaultConfig)` ને કૉલ કરે છે. રનટાઇમ પર એન્જિનને દૂર કરવા માટે `unregisterCompressionEngine(id)` ઉપયોગ કરો.

`strategySelector.ts` કમ્પ્રેશન ચાલે તે પહેલાં બિલ્ટ-ઇન એન્જિનની નોંધણી કરે છે. આ પૂર્વાવલોકન, રનટાઇમ કમ્પ્રેશન, સ્ટેક્ડ મોડ, પરીક્ષણો અને ભાવિ એન્જિનોને સમાન અમલ પાથનો ઉપયોગ કરવા દે છે.

### MCP વર્ણન સંકોચન (સંબંધિત)

એક અલગ રજિસ્ટ્રી રજિસ્ટ્રી-લેવલ — પર MCP ટૂલ વર્ણન મેટાડેટાને સંકુચિત કરે છે `open-sse/mcp-server/descriptionCompressor.ts` અને [MCP-SERVER.md](../frameworks/MCP-SERVER.md) જુઓ. તે કેવમેન નિયમોનો પુનઃઉપયોગ કરે છે પરંતુ ટૂલ મેટાડેટા પર કાર્ય કરે છે, પેલોડ્સની વિનંતી પર નહીં.

### વધારાના બિલ્ટ-ઇન એન્જિન

કેવમેન, RTK અને LLMLingua-2 થી આગળ, રજિસ્ટ્રી ઘણા વિશિષ્ટ લોસલેસ/સ્ટ્રક્ચરલ એન્જિનો મોકલે છે (સ્ટૅક્ડ પાઇપલાઇન્સ, રમતનું મેદાન અને પરીક્ષણો દ્વારા ઉપયોગમાં લેવાય છે):

| એન્જીન     | આઈડી            | તે શું કરે છે                                                                                                                                                                                 |
| ---------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CCR        | `ccr`           | સામગ્રી-કોમ્પ્રેસ-પુનઃપ્રાપ્તિ (H4): સામગ્રી-સંબોધિત સંદર્ભો સાથે મોટા સંલગ્ન ટેક્સ્ટ બ્લોક્સને બદલે છે, તેથી repeated/large બ્લોક્સ એકવાર મોકલવામાં આવે છે અને તે પછી સંદર્ભ આપવામાં આવે છે. |
| હેડરૂમ     | `headroom`      | SmartCrusher (H3 + N5): સ્તંભાકાર `[N rows]` સ્વરૂપમાં સજાતીય JSON-એરે પેલોડ્સનું લોસલેસ ટેબ્યુલર કોમ્પેક્શન.                                                                                 |
| ionizer    | `ionizer`       | ખૂબ મોટા સજાતીય બ્લોક્સ માટેHead/middle/tail પંક્તિ નમૂના, એલિડેડ મધ્યને CCR સામગ્રી-સંબોધિત સંદર્ભ તરીકે સંગ્રહિત કરે છે.                                                                    |
| સત્ર-ડિડઅપ | `session-dedup` | સામગ્રી-સંબોધિત ક્રોસ-ટર્ન ડિડુપ્લિકેશન (ટોકનમિઝર-પ્રેરિત): એલિડ્સ ટેક્સ્ટ પહેલેથી જ સમાન સત્રના અગાઉના વળાંકમાં જોવા મળે છે.                                                                 |

**CCR પુનઃપ્રાપ્તિ-પ્રોટોકોલ સૂચના (#8033):** પ્રથમ વખત CCR વિનંતીમાં ≥ 1 બ્લોકને બદલે છે, ત્યારે એન્જિન એક સિંગલ, ઇમ્પોટેન્ટ `system` સંદેશ ( `[CCR protocol]` સેન્ટિનલ સાથે અગ્રણી) આગળ મોકલે છે જે કૉલરને માર્કર → ટૂલ કરાર શીખવે છે: `[CCR retrieve hash=<24hex> chars=N]` માર્કરનો અર્થ શું છે, કે હેશની શબ્દશઃ નકલ કરવી આવશ્યક છે (બધા 24 — હેક્સના સંભવતઃ અક્ષરો છે. "બ્લોક મળ્યો નથી" ચૂકી જાય છે), અને તે `[dedup:ref sha=...]` માર્કરનો અર્થ થાય છે "ઇતિહાસમાં પાછા જુઓ", "ટૂલને કૉલ કરો" નહીં. નોંધ ઇન્જેક્ટ કરવામાં આવે છે** માત્ર ત્યારે જ જ્યારે કોલરની જાહેરાત `tools[]` સાબિત કરે છે કે તે ખરેખર `omniroute_ccr_retrieve` સુધી પહોંચી શકે છે** (`callerSupportsCcrRetrieve()` માં `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — એક સાદો ઓપનએઆઈ-સુસંગત કોલર તે ટૂલ વિના ક્યારેય કોઈ એવી વસ્તુને કૉલ કરવાની સૂચના પ્રાપ્ત કરતું નથી જ્યાં તે પહોંચી ન શકે. ઇન્જેક્શન આપતા પહેલા સેન્ટિનલ માટે સંદેશ ઇતિહાસને સ્કેન કરીને આઇડમ્પોટેન્સી લાગુ કરવામાં આવે છે, તેથી મલ્ટિ-ટર્ન વિનંતીઓ (જે અગાઉના સંદેશાઓને ફરીથી ચલાવે છે) દરેક વારે એકવાર નોંધને સ્ટેક કરતી નથી.

## કેવમેન

કેવમેન મોડ સામાન્ય ગદ્યના સિમેન્ટીક કન્ડેન્સેશન પર ધ્યાન કેન્દ્રિત કરે છે:

- કોડ બ્લોક્સ, URLs, JSON, પાથ અને સ્ટ્રક્ચર્ડ ડેટા સાચવે છે
- ફિલર, હેજિંગ, પુનરાવર્તિત સંદર્ભ અને વર્બોઝ કનેક્ટિવ શબ્દસમૂહને દૂર કરે છે
- `open-sse/services/compression/rules/` માં ભાષા-જાગૃત ફાઇલ નિયમ પેકને સપોર્ટ કરે છે
- લેગસી `standard`, `aggressive`, અને `ultra` મોડ્સ દ્વારા ઉપલબ્ધ રહે છે

ડેશબોર્ડ સપાટી `Dashboard -> Context & Cache -> Caveman` છે.

કેવમેન અપસ્ટ્રીમ `~75%` ઓછા આઉટપુટ ટોકન્સ, `22-87%` રેન્જ સાથે બેન્ચમાર્કમાં `65%` સરેરાશ આઉટપુટ બચત અને `~46%` ઇનપુટ-કમ્પ્રેશન ટૂલનો અહેવાલ આપે છે. સ્ટેક્ડ prompt/context બચતનું દસ્તાવેજીકરણ કરતી વખતે OmniRoute કેવમેન ઇનપુટ-સાઇડ નંબરનો ઉપયોગ કરે છે; કેવમેન આઉટપુટ મોડ એક અલગ પ્રતિભાવ-વર્તણૂક લક્ષણ રહે છે.

## RTK

RTK મોડ આદેશ અને સાધન આઉટપુટ પર ધ્યાન કેન્દ્રિત કરે છે:

- આઉટપુટ વર્ગો જેમ કે `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, Cargo/Go પરીક્ષણો, TypeScript/Vite/Webpack બિલ્ડ્સ, ESLint, npm audit/installs, Docker લોગ્સ, શેલ `find`/`grep`, સ્ટેક ટ્રેસ અને સામાન્ય લૉગ્સ શોધે છે
- `open-sse/services/compression/engines/rtk/filters/` માંથી 49 JSON ફિલ્ટર્સ લાગુ કરે છે
- RTK-શૈલીની ઘોષણાત્મક પાઇપલાઇનને સપોર્ટ કરે છે: ANSI સ્ટ્રિપિંગ, રિપ્લેસ, મેચ-આઉટપુટ શોર્ટ-સર્કિટ, strip/keep લાઇન્સ, પ્રતિ-લાઇન ટ્રંકેશન, head/tail/max-line ટ્રંકેશન અને ઑન-એમ્પ્ટી ફૉલબૅક
- `.rtk/filters.json` માં ટ્રસ્ટ-ગેટેડ પ્રોજેક્ટ ફિલ્ટર્સ અને `DATA_DIR/rtk/filters.json` માં વૈશ્વિક ફિલ્ટર્સને સપોર્ટ કરે છે
- સ્ટ્રિપ્સ ANSI સિક્વન્સ, પ્રોગ્રેસ નોઈઝ, પુનરાવર્તિત રેખાઓ અને બિનસહાયક બોઈલરપ્લેટ
- એક્શનેબલ નિષ્ફળતાઓ, ચેતવણીઓ, સારાંશ, બદલાયેલી ફાઇલો અને પૂંછડી સંદર્ભને સાચવે છે
- વૈકલ્પિક રીતે અધિકૃત સંચાલન માર્ગો દ્વારા recovery/debugging માટે સુધારેલ કાચા આઉટપુટને જાળવી શકે છે

ડેશબોર્ડ સપાટી `Dashboard -> Context & Cache -> RTK` છે.

કસ્ટમ ફિલ્ટર્સ, ટ્રસ્ટ, વેરિફિકેશન અને રો-આઉટપુટ પુનઃપ્રાપ્તિ માટેની ઓપરેશનલ વિગતો [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md) માં રહે છે.

RTK અપસ્ટ્રીમ આદેશ-આઉટપુટ કમ્પ્રેશન માટે `60-90%` બચતનો અહેવાલ આપે છે. તેનું README ઉદાહરણ `~118,000` ટોકન્સથી `~23,900` સુધી જતું 30-મિનિટનું Claude કોડ સત્ર દર્શાવે છે, અથવા `79.7%` સાચવવામાં આવ્યું છે.

## LLMLingua-2 (અર્થાત્મક કાપણી)

LLMLingua-2 મોડ કરે છે** સિમેન્ટીક ટોકન કાપણી** નિયમ-આધારિત કેવમેન અને RTK એન્જિનોને પૂરક બનાવતા, નાના ONNX ટોકન વર્ગીકૃતનો ઉપયોગ કરીને ગદ્ય પર:

- માત્ર બિન-સિસ્ટમ સંદેશાઓમાં ગદ્યને સંકુચિત કરે છે; ફેન્સ્ડ કોડ બ્લોક્સ અને અન્ય સાચવેલ બાંધકામો ક્યારેય બદલાતા નથી
- વર્કર થ્રેડમાં `@atjsh/llmlingua-2` બેકએન્ડ (ONNX via `@huggingface/transformers`) ચલાવે છે, તેથી મોડેલ અનુમાન ક્યારેય વિનંતી ઇવેન્ટ લૂપને અવરોધિત કરતું નથી
- છે** સ્ટેકેબલ** (`stackPriority` 35): સ્ટેક્ડ પાઇપલાઇનમાં તે સ્ટ્રક્ચરલ એન્જિનો (CCR, સેશન-ડેડઅપ, હેડરૂમ, કેવમેન) પછી ચાલે છે પરંતુ `ultra` પહેલાં, કારણ કે સિમેન્ટીક કાપણી પહેલેથી જ માળખાકીય રીતે-સંકુચિત ટેક્સ્ટ — ઉદાહરણ તરીકે `rtk -> caveman -> llmlingua` પર સૌથી વધુ અસરકારક છે.
- **કોઈપણ ભૂલ પર નિષ્ફળ-ઓપન થાય છે** (વૈકલ્પિક ડેપ્સ, વર્કર સ્પૉન, મોડલ લોડ, અનુમાન, અથવા સમયસમાપ્તિ ખૂટે છે) → મૂળ ટેક્સ્ટ યથાવત પરત કરવામાં આવે છે, ક્યારેય ભૂલ નથી

એન્જિન સ્થાન: `open-sse/services/compression/engines/llmlingua/`. ડેશબોર્ડ સપાટી `Dashboard -> Context & Cache -> LLMLingua` છે.

### મોડલ્સ

ડિફૉલ્ટ મોડલ છે**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~ 57 MB, ઝડપી). ઉચ્ચ ચોકસાઈ** BERT-આધાર** મોડેલ (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) એન્જિન રૂપરેખા `model` ફીલ્ડ દ્વારા ઉપલબ્ધ છે. `@huggingface/transformers` પસંદ કરેલ મોડલને HuggingFace હબમાંથી `${DATA_DIR}/models/llmlingua` માં પ્રથમ કોલ પર આળસથી ડાઉનલોડ કરે છે (`modelStore.ts`); `modelPath` રૂપરેખા ઓવરરાઇડ તેને બદલે સ્થાનિક નકલ પર નિર્દેશ કરે છે (ઓફલાઇન / એર-ગેપ્ડ ઇન્સ્ટોલ).

### વૈકલ્પિક નિર્ભરતા અને માંગ પર ઇન્સ્ટોલ

પ્રુનેબલ LLMLingua રનટાઇમ પીઅર સ્ટેક છે** વૈકલ્પિક** . બે પેકેજો `package.json` માં `optionalDependencies` તરીકે જાહેર કરવામાં આવે છે અને રાખવામાં આવે છે** બાહ્ય** પ્રોડક્શન બિલ્ડ દ્વારા (`scripts/build/prepublish.ts` તેમને બંડલ કરતું નથી):

| પેકેજ                | સંસ્કરણ (પિન) | નોંધો                                            |
| -------------------- | ------------- | ------------------------------------------------ |
| `@atjsh/llmlingua-2` | `2.0.5`       | પ્રવેશ પેકેજ; અન્યને સાથીદારો તરીકે જાહેર કરે છે |
| `js-tiktoken`        | `^1.0.20`     | ટોકનાઇઝર                                         |

`@huggingface/transformers` એ `^4.2.0` પર પિન કરેલ છે (સ્થાનિક એમ્બેડિંગ્સ પાથ સાથે શેર કરેલ છે અને સ્ટેન્ડઅલોન બંડલમાં પણ શોધાયેલ છે); `@atjsh/llmlingua-2@2.0.5` તેના પર `"^3.5.2 || ^4.0.0"` સાથે પીઅર કરે છે, તેથી Transformers.js v3 અને v4 બંને સપોર્ટેડ છે. 2.0.4 થી, `@atjsh/llmlingua-2` હવે `@tensorflow/tfjs` ની જરૂર નથી, જેણે SLM સ્ટેકમાંથી સૌથી મોટા સિંગલ યોગદાનકર્તા (TensorFlow.js) ને દૂર કર્યા છે. ફક્ત ઉપરના બે પેકેજો જ કાપવા યોગ્ય SLM પીઅર છે. પ્રમાણભૂત `npm install` (dev) વૈકલ્પિક સ્ટેકને આપમેળે ઇન્સ્ટોલ કરે છે સિવાય કે વૈકલ્પિક અવલંબન અવગણવામાં આવે.

**શા માટે માંગ પર:** npm-પ્રકાશિત પેકેજ, એકલ બંડલ અને Docker ઇમેજ શિપ** વગર** આ ડીપ્સ સ્લિમ રહેવા માટે. જ્યારે તેઓ ગેરહાજર હોય છે, ત્યારે કામદારનો નિર્ભરતા દરવાજો ( `worker.ts` માં `@atjsh/llmlingua-2` રિઝોલ્યુશન પ્રોબ) નિષ્ફળ જાય છે અને એન્જિન** નિષ્ફળ-ચૂપચાપ ખુલે છે** — પસંદ કરવાનું LLMLingua નો-ઓપ બની જાય છે (ટેક્સ્ટ અપરિવર્તિત પરત આવે છે, કોઈ ભૂલ લોગ થયેલ નથી). તેને કાપેલા વાતાવરણમાં સક્રિય કરવા માટે, વૈકલ્પિક સ્ટેક ઇન્સ્ટોલ કરો:

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` રિમૂવલ (2.0.4 +) અગાઉના પ્રભાવશાળી ~ 800 MB યોગદાનકર્તા — ને દૂર કરે છે બાકીની ફૂટપ્રિન્ટ એ transformers.js + onnxruntime-નોડ રનટાઈમ્સ છે, ઉપરાંત TinyBERT મોડલ (~ 57 MB પર ડાઉનલોડ કરો)

પર્યાવરણ દીઠ:

- **દેવ / `npm install`** જ્યાં સુધી તમે `--omit=optional` (અથવા `--no-optional`) પાસ ન કરો ત્યાં સુધી — આપોઆપ ઇન્સ્ટોલ થઈ જાય છે. કોઈ પગલાંની જરૂર નથી.
- **વૈશ્વિક npm (`npm i -g omniroute`) / એકલ** — ઇન્સ્ટોલ કરેલ પેકેજ ડાયરેક્ટરી અંદર ઉપરના install આદેશને ચલાવો, અથવા વૈકલ્પિક ડેપ્સને અવગણ્યા વિના પુનઃસ્થાપિત કરો.
- **Docker** — વ્યુત્પન્ન ઇમેજ સ્તરમાં install આદેશ ઉમેરો; પ્રકાશિત ઇમેજ ડિઝાઇન દ્વારા પાતળી છે.
- **VPS (PM2)** — એપ્લિકેશનના `node_modules` માં ઇન્સ્ટોલ કરો, પછી પ્રક્રિયાને ફરીથી શરૂ કરો જેથી કાર્યકર ગેટની ફરીથી તપાસ કરે.
- **રો નેક્સ્ટ સ્ટેન્ડઅલોન (`npm run build` → `.build/next/standalone/server.js`)** — સ્ટેન્ડઅલોન ટ્રેસ જહાજો કાર્યકર અથવા વૈકલ્પિક ડેપ્સને NEITHER, તેથી એન્જિન ચુપચાપ નિષ્ફળ જાય છે. `scripts/build/colocate-standalone.mjs` બંનેને ફરીથી લાગુ કરે છે (વર્કર esbuild + વૈકલ્પિક-ડેપ બંધ એકલ વૃક્ષમાં); તે દરેક બિલ્ડ પછી `postbuild` npm હૂક દ્વારા આપમેળે ચાલે છે. જ્યારે ડેપ્સ ગેરહાજર હોય ત્યારે આઇડમ્પોટન્ટ, નિષ્ફળ-નરમ.

**ચકાસો કે તે સક્રિય છે:** LLMLingua પસંદ કર્યા પછી, વાસ્તવિક ગદ્ય વાસ્તવમાં સંકોચાય છે (એન્જિન નિષ્ફળ થવાનું બંધ કરે છે), અને પ્રથમ વિનંતી `${DATA_DIR}/models/llmlingua` માં મોડેલ ડાઉનલોડને ટ્રિગર કરે છે. ગેટ ઈરાદાપૂર્વક માત્ર `@atjsh/llmlingua-2` — તપાસ કરે છે અન્ય સાથીદારો ફક્ત ESM-જ હોય છે અને `require.resolve` તેમના પર ફેંકે છે જ્યારે — હાજર હોય ત્યારે પણ કાર્યકર નિષ્ફળ જાય છે-જો કોઈ પીઅર `import()` સમયે ખરેખર ખૂટે છે.

## સ્ટેક્ડ પાઇપલાઇન્સ

સ્ટેક્ડ મોડ પાઇપલાઇન સ્ટેપ્સને ક્રમમાં ચલાવે છે. ડિફૉલ્ટ છે:

```txt
rtk -> caveman
```

કોડિંગ-એજન્ટ સત્રો માટે આનો ઉપયોગ કરો જ્યાં પ્રોમ્પ્ટ કમાન્ડ આઉટપુટને માનવ અથવા સહાયક ગદ્ય સાથે જોડે છે. RTK પહેલા ઘોંઘાટીયા ટૂલ લોગને ઘટાડે છે, પછી કેવમેન બાકીની કુદરતી ભાષાને સંકુચિત કરે છે.

કમ્પ્રેશન સેટિંગ્સમાં અથવા કમ્પ્રેશન કોમ્બોઝ દ્વારા પાઇપલાઇન સ્ટેપ્સ `stackedPipeline` સાથે ગોઠવવામાં આવે છે.

જ્યારે બંને એન્જિન સમાન પાત્ર પેલોડ ઘટાડે છે, ત્યારે બચત સંયોજન:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP ઍક્સેસિબિલિટી ટ્રી ફિલ્ટર

MCP ઍક્સેસિબિલિટી-ટ્રી સ્માર્ટ ફિલ્ટર એ એક્ઝેક્યુશન પછીનું કમ્પ્રેશન લેયર છે જે MCP પર ચાલે છે** સાધન પરિણામો** , પ્રોમ્પ્ટ અથવા સંદર્ભ પર નહીં. તે Playwright, કોમ્પ્યુટર-ઉપયોગ અને બ્રાઉઝર-ઓટોમેશન MCP સર્વર્સ જેવા સાધનો દ્વારા પરત કરવામાં આવેલા વર્બોઝ એક્સેસિબિલિટી-ટ્રી અને બ્રાઉઝર સ્નેપશોટ પેલોડ્સને લક્ષ્ય બનાવે છે.

### તે શું કરે છે

1. **ઘોંઘાટ છીનવી** — ખાલી generic/text એન્ટ્રીઓ દૂર કરે છે (`- generic:`, `- text: ""`)
2. **ભાઈ-બહેનનું પતન** — જ્યારે ≥ `collapseThreshold` (ડિફૉલ્ટ 30) સળંગ રેખાઓ માળખાકીય પુનરાવર્તિત થાય છે, તેમને પ્રથમ `collapseKeepHead` (ડિફૉલ્ટ 10) રેખાઓમાં સંકુચિત કરે છે અને છેલ્લી `collapseKeepTail` (ડિફૉલ્ટ 5) રેખાઓ + એ ગણતરી સારાંશ +
3. **સંદર્ભ જાળવણી** — `[ref=eXX]` Playwright/computer-use દ્વારા જરૂરી એન્કરને ક્યારેય સ્પર્શ કરવામાં આવતો નથી
4. **હાર્ડ ટ્રંકેશન** — જો સંકુચિત થયા પછીનું લખાણ હજુ પણ `maxTextChars` (ડિફૉલ્ટ 50,000) કરતાં વધી જાય, તો નેવિગેશન સંકેત સાથે કાપવામાં આવે છે જેથી એજન્ટ કામ કરવાનું ચાલુ રાખી શકે

### એન્જિન સ્થાન

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### રૂપરેખાંકન

વૈશ્વિક સેટિંગ્સમાં `compression.mcpAccessibility` દ્વારા નિયંત્રિત (માઇગ્રેશન 056). ડિફૉલ્ટ રૂપરેખા:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

ફિલ્ટર ફક્ત ટૂલ-પરિણામ પેલોડ્સ પર જ લાગુ થાય છે કે જેની `type` `"text"` છે અને જેની લંબાઈ `minLengthToProcess` કરતાં વધી ગઈ છે. તે પ્રોમ્પ્ટ કમ્પ્રેશન અથવા વિનંતી પેલોડ્સને અસર કરતું નથી.

### અપેક્ષિત બચત

પૃષ્ઠ જટિલતાને આધારે, બ્રાઉઝર સ્નેપશોટ ટૂલ પરિણામો પર 60-80%. સંકુચિત અલ્ગોરિધમ લાઇનની ગણતરીમાં O(n) છે અને નજીવી વિલંબતા ઉમેરે છે.

## કમ્પ્રેશન કોમ્બોઝ

કમ્પ્રેશન કોમ્બોઝનું નામ કમ્પ્રેશન પ્રોફાઇલ્સ છે જે રૂટીંગ કોમ્બોઝને સોંપી શકાય છે:

- `compression_combos`: સ્ટોર્સ મોડ, પાઇપલાઇન, RTK રૂપરેખા, ભાષા રૂપરેખા, અને ડિફોલ્ટ માર્કર
- `compression_combo_assignments`: કમ્પ્રેશન કોમ્બોને રૂટીંગ કોમ્બોમાં મેપ કરે છે
- રનટાઇમ એકીકરણ સામાન્ય કોમ્બો ઓવરરાઇડ થાય તે પહેલાં સોંપેલ કમ્પ્રેશન કોમ્બોને ઉકેલે છે
- વિશ્લેષણમાં `compression_combo_id` અને `engine` સમાવેશ થાય છે

ડેશબોર્ડ સપાટી: `Dashboard -> Context & Cache -> Compression Combos`.

## પૂર્વજરૂરીયાતો / ઓપરેટર માર્ગદર્શિકા (CCR અને સત્ર-ડેડઅપ)

CCR (`ccr`) અને `session-dedup` ટેક્સ્ટને બદલો અથવા એલાઇડ કરો અને a છોડી દો** માર્કર** પાછળ આ વિભાગ ક્લાયન્ટને વાયરિંગ અપ કરવા, બે માર્કર્સ વાંચવા અને એલિડેડ સામગ્રીને પુનઃપ્રાપ્ત કરવા અથવા નિદાન કરવા માટે ઓપરેટર સંદર્ભ છે. દરેક એન્જિનના મિકેનિક્સ ઉપર આવરી લેવામાં આવ્યા છે; આ "હું તેને કેવી રીતે ચલાવીશ" સ્તર છે.

### પરિવહન અને અંતિમ બિંદુઓ

MCP સર્વર જે CCR સાધનોને ઉજાગર કરે છે તે ત્રણ રીતે પહોંચી શકાય છે. મૂળભૂત આધાર URL એ `http://localhost:20128` છે (`OMNIROUTE_BASE_URL`):

| પરિવહન                                 | URL / આદેશ                              | નોંધો                                                                                                                               |
| -------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| સ્ટ્રીમેબલ HTTP (ક્લાયન્ટ, ભલામણ કરેલ) | `http://localhost:20128/api/mcp/stream` | એન્ડપોઇન્ટ વર્તમાન MCP ગ્રાહકો સાથે વાત કરે છે.                                                                                     |
| લેગસી SSE સિંગલટન                      | `http://localhost:20128/api/mcp/sse`    | જૂનું સિંગલટન પરિવહન. તે** બંધ કરે છે** સ્ટ્રીમેબલ સત્રો; `streamable-http` ક્લાયન્ટનો ઉપયોગ `/api/mcp/stream` સામે કરો, આ એક નહીં. |
| stdio                                  | `omniroute --mcp`                       | IDE MCP રૂપરેખા માટે જે પ્રક્રિયાને જન્મ આપે છે. ત્યાં કોઈ `--dev` ધ્વજ નથી; `omniroute --mcp` એ stdio એન્ટ્રી પોઈન્ટ છે.           |

### સ્ટોરેજ ટિયર્સ (પુનઃપ્રારંભ કરવાથી શું બચે છે)

CCR એ છે** બે સ્તર** સ્ટોર, ફક્ત મેમરીમાં નહીં:

- **હોટ ઇન-મેમરી ટાયર** — પ્રતિ-બ્લોક કેપ 2 MiB, પ્રતિ-પ્રિન્સિપલ 16 MiB, વૈશ્વિક 64 MiB. એન્ટ્રી ડિફૉલ્ટ 24 કલાક TTL (મહત્તમ 7 દિવસ) પર હોય છે. મેમરીમાંથી સંપૂર્ણ MCP પુનઃપ્રાપ્તિ 256 KiB પર મર્યાદિત છે; રેન્જ્ડ/ગ્રેપ મોડ્સ દ્વારા હજુ પણ મોટી કોઈપણ વસ્તુ પહોંચી શકાય છે.
- **ટકાઉ SQLite ટાયર** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, ઑન બાય ડિફૉલ્ટ) — ઇન-મેમરી ટાયરને સમર્થન આપે છે જેથી બ્લોક LRU ઇવિક્શન, પુનઃપ્રારંભ અથવા અન્ય ઉદાહરણ પર પુનઃપ્રાપ્ત લેન્ડિંગથી બચી જાય. પંક્તિ બ્લોકના TTL રાખે છે, તેથી તેના TTL થી આગળનો બ્લોક બંને સ્તરોમાંથી જતો રહે છે.

ત્રણ રક્ષકો ટકાઉ ટાયર બાઉન્ડેડ — એક બ્લોક મેમરીમાં રહે છે ત્યારે જ:

1. બ્લોક સમાપ્ત થઈ ગયો છે** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. રનટાઇમ એ ક્લાઉડ રનટાઇમ છે (કોઈ સ્થાનિક ડિસ્ક નથી);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

તેથી "ધ બ્લોક અદ્રશ્ય થઈ ગયો" એ બ્લેન્કેટ રીસ્ટાર્ટ સ્ટોરી નથી: સ્થાનિક, નોન-ક્લાઉડ રનટાઇમ પરનો sub-512 KB બ્લોક જ્યાં સુધી તેનું TTL સમાપ્ત ન થાય ત્યાં સુધી ટકાઉ સ્તર દ્વારા પુનઃપ્રારંભમાં ટકી રહે છે. ચલ માટે [પર્યાવરણ સંદર્ભ](../reference/ENVIRONMENT.md) જુઓ.

### બે માર્કર

| માર્કર                                | અર્થ                                                                                                                    | મોડેલે શું કરવું જોઈએ                                                                                                                                                                                         |

### ગ્રાહક પૂર્વજરૂરીયાતો

- **કી (stdio):** stdio કૉલર પ્રતિ-વિનંતી ઓળખ ધરાવતું નથી, તેથી તે `OMNIROUTE_API_KEY` ( MCP સર્વરના `env` માં સેટ કરેલ) વડે પ્રમાણિત કરે છે. તેના વિના કૉલર અનામી છે અને એવા સાધનો કે જેને પ્રિન્સિપાલની જરૂર છે તે બગડી શકે છે.
- **`tools[]` is the injection precondition.** The CCR retrieve-protocol instruction (#8033) is injected **only** when the request's advertised `tools[]` proves the client can actually reach `omniroute_ccr_retrieve`. The match is a trailing-segment match bounded by a separator (`__`, `.`, `/`, `:`) — never a bare substring — so a namespaced name such as `mcp__gateway__omniroute_ccr_retrieve` still counts. An absent or non-matching `tools[]` means the instruction is _not_ injected, by design.
- **`codemode:false` (OpenCode ગ્રાહકો).** OpenCode કોડ મોડમાં ડિફોલ્ટ થાય છે, જે ફક્ત તેના મૂળ ટૂલ્સની જાહેરાત કરે છે અને** કરતું નથી** મૂળ `tools[]` સૂચિમાં MCP સાધનો મૂકો. MCP સર્વર એન્ટ્રી પર `codemode: false` સેટ કરો જેથી `omniroute_ccr_*` ટૂલ્સની જાહેરાત કરવામાં આવે. આ એ** ગ્રાહક** સેટિંગ, એક OmniRoute નથી. તે હજુ સુધી CCR સૂચનાને ઇન્જેક્ટ કરતું નથી: OpenCode એક સાધનને `<server>_<tool>` નામ આપે છે, તેથી `omniroute` નામનું સર્વર `omniroute_omniroute_ccr_retrieve` એક્સપોઝ કરે છે, અને `_` મેળ ખાતા વિભાજકોમાંથી એક નથી.
- **આચાર્યો.** સંગ્રહ અને પુનઃપ્રાપ્તિ પ્રમાણિત પ્રિન્સિપલ ( API કી દીઠ) દીઠ અલગ છે. કી ફક્ત તેના પોતાના બ્લોક્સ જુએ છે.

### પુનઃપ્રાપ્તિ મર્યાદા અને પૃષ્ઠ ક્રમાંકન

MCP ટૂલ ટેક્સ્ટ પરિણામો `mcpAccessibility.maxTextChars` (ડિફૉલ્ટ `50000`) ની આસપાસ ક્લિપ કરવામાં આવે છે. બ્લોકની `full` પુનઃપ્રાપ્તિ 256 KiB — પર મર્યાદિત છે** ત્યાં કોઈ અમર્યાદિત સંપૂર્ણ પુનઃપ્રાપ્તિ નથી** . જ્યારે બ્લોકનું `chars=N` મોટું હોય, ત્યારે આખી વસ્તુ ખેંચવાને બદલે તેને પેજ કરો:

- અંગૂઠાનો નિયમ:**`chars > 40000` → એ `mode` ઉપયોગ કરો** , એકદમ સંપૂર્ણ ક્યારેય.
- `mode:"grep"` — regex `pattern` મેળ ખાતી લાઇન બાય લાઇન, 1,000 મેચિંગ લાઇન સુધી (`unique: true` ડ્રોપ્સ રિપીટ), "મને જોઈતી એક લાઇન શોધો" માટે સૌથી સસ્તું.
- `mode:"lines"` — એ 1-અનુક્રમિત રેખા શ્રેણી; `start` અને `end` બંનેની જરૂર છે.
- `mode:"head"` / `mode:"tail"` — first/last `n` રેખાઓ.
- `mode:"stats"` — લાઈન, કેરેક્ટર અને બાઈટ કાઉન્ટ્સ બોડી વગર.

એકસાથે સમગ્ર બાબતની વિનંતી કરવાને બદલે પૃષ્ઠોમાં લાંબા બ્લોક ચાલવા માટે `start`/`end` સાથે `mode:"lines"` ઉપયોગ કરો.

### સાધન નામકરણ

પુનઃપ્રાપ્ત સાધનને હાલમાં `omniroute_ccr_retrieve` નામ આપવામાં આવ્યું છે ( `omniroute_` ઉપસર્ગ ક્રોસ-સર્વર નામની અથડામણ માટે ડેટેડ વર્કઅરાઉન્ડ છે). ક્લીનર બાઉન્ડેડ-સફિક્સ ટૂલનું નામ અને MCP JSON પરિણામો માટેનું ફિક્સ ટ્રંકેટેડ મિડ-સ્ટ્રિંગ અપસ્ટ્રીમ ફોલો-અપ્સ તરીકે ટ્રૅક કરવામાં આવે છે; આ પૃષ્ઠ માત્ર વર્તમાન, મોકલેલ વર્તનને દસ્તાવેજ કરે છે.

### સત્ર જીવનચક્ર

સ્ટ્રીમેબલ-HTTP સત્રો નિષ્ક્રિય થઈ જાય છે અને સર્વર તેમને કાપે છે; નિષ્ક્રિય વિન્ડો એ `MCP_SESSION_IDLE_MS` સ્થિરાંક છે (નામ દ્વારા સંદર્ભિત, હાર્ડકોડ મૂલ્ય નથી, તેથી જ્યારે તે બદલાય છે ત્યારે આ પૃષ્ઠ વહેતું નથી). નિષ્ક્રિય-પાણી કરેલ સત્રનું લક્ષણ એ `Unknown Mcp-Session-Id` — સાથે HTTP 404 છે, ઉપાય એ સત્રને ફરીથી કનેક્ટ કરવું અથવા પુનઃશરૂ કરવું છે,** નથી** કી ફેરવવા, અવકાશ બદલવા અથવા ટૂલનું નામ બદલવા માટે.

## અવકાશ અને બાકાત

**એમ્બેડિંગ્સ ક્યારેય સંકુચિત થતા નથી.** `open-sse/handlers/embeddings.ts` ક્યારેય કોઈ કમ્પ્રેશન એન્જિનને — કહેતું નથી, request/response બોડી સીધા જ એક્ઝિક્યુટર સુધી પહોંચે છે. આ આજે માળખાકીય છે (એમ્બેડિંગ્સ અને ચેટ કમ્પ્લીશન ડિસજોઇન્ટ હેન્ડલર્સ છે), રનટાઇમ ચેક નથી, પરંતુ તેનો અર્થ એ છે કે #8034 માં વેક્ટર-ડિસ્ટોર્શન ચિંતા એમ્બેડિંગ્સ પાથમાં કોઈ એક્સપોઝર સપાટી નથી.

**Per-model/endpoint બાકાત ફિલ્ટર (#8034).** ચેટ પૂર્ણ કરવા માટે, ઓપરેટર મોડલ ids/ `provider/model` લક્ષ્યોને નામ આપી શકે છે જે ક્યારેય સંકુચિત ન હોવા જોઈએ — એક ગાર્ડરેલ ઉપયોગી છે જો કમ્પ્રેશન ક્યારેય એમ્બેડિંગ્સ-સંલગ્ન પાથની નજીક વાયર કરવામાં આવ્યું હોય, અને સામાન્ય રીતે કોઈપણ મોડેલ માટે ઉપયોગી જેની ચોક્કસ બાઈટ-ફોર-બાઈટ પ્રોમ્પ્ટ બાબતો (નિર્ધારિત, પૂર્વસૂચક, વગેરે).

- સેટિંગ્સ ફીલ્ડ: વૈશ્વિક કમ્પ્રેશન રૂપરેખા પર `exclusions?: string[]` (`GET`/`PUT /api/settings/compression`), હાલની `key_value` કમ્પ્રેશન નેમસ્પેસ (`src/lib/db/compression.ts`) — કોઈ નવું ટેબલ દ્વારા ચાલુ રહે છે.
- ડેશબોર્ડ ટેબ:** ડેશબોર્ડ → કમ્પ્રેશન → બાકાત** (`/dashboard/compression/exclusions`)
- પેટર્ન સિન્ટેક્સ: `*` એકમાત્ર વાઇલ્ડકાર્ડ છે. પેટર્નમાં દરેક અન્ય રેજેક્સ મેટાકેરેક્ટર મેચિંગ કરતા પહેલા છટકી જાય છે, તેથી `gpt-5.6` માત્ર શાબ્દિક સ્ટ્રિંગ સાથે મેળ ખાય છે, ક્યારેય `gpt-5x6` (ReDoS-સેફ, બાઉન્ડેડ, કોઈ નેસ્ટેડ ક્વોન્ટિફાયર નથી). પેટર્ન બેર મોડલ id અને `provider/model` સંયુક્ત — `gpt-5-6`, `openai/gpt-5-6`, અને `openai/*` બંને સાથે કેસ-સંવેદનશીલ રીતે મેળ ખાય છે, અને `*` દરેક મોડેલને બાકાત રાખે છે.
- મેચિંગ: `isCompressionExcluded()` / `normalizeCompressionExclusions()` માં `open-sse/services/compression/exclusions.ts`. `chatCore.ts` કમ્પ્રેશન સેટિંગ્સને ઉકેલ્યા પછી જ બાકાત લક્ષ્યને તપાસે છે,** કોઈપણ એન્જિન ચાલે તે પહેલા** , અને સંકોચનને વૈશ્વિક સ્તરે અક્ષમ કરવામાં આવે — જ રીતે મેચને વર્તે છે. વિશ્લેષણની દૃશ્યતા માટે `writeCompressionSkip(..., "excluded")` દ્વારા સ્કીપ રેકોર્ડ કરવામાં આવે છે.
- ડિફૉલ્ટ (empty/absent સૂચિ): પૂર્વ-#8034 વર્તન — જેવું જ કંઈ બાકાત નથી.

## જાણીતી મર્યાદાઓ

- **LLMLingua-2 (SLM) ને સહ-સ્થિત વૈકલ્પિક ડેપ્સની જરૂર છે.** કાર્યકર માત્ર ત્યારે જ પ્રોડક્શન બિલ્ડમાં ચાલે છે જ્યારે `@atjsh/llmlingua-2` + સાથીદારો `dist/node_modules` (જુઓ `scripts/build/colocateOptionals.mjs`, #4286) માં સહ-સ્થિત હોય છે. તેમના વિના એન્જિન ફેલ-ઓપન થાય છે (મૂળ લખાણ પરત કરે છે). વર્કર રિઝોલ્યુશન હવે `import.meta.url` પર નિર્ભર નથી (તે સ્ટેન્ડઅલોન બંડલમાં મૃત્યુ પામે છે) — તે રનટાઇમ cwd/ `argv[1]` પર એન્કર કરે છે.
- **કેવમેન ભાષા પેક `de` / `fr` / `ja` આંશિક છે.** તેઓ `context` + `filler` + `structural` નિયમો મોકલે છે પરંતુ કોઈ `dedup` / `ultra` પૅક્સ નથી, તેથી તે ભાષાઓ માટે `ultra` તીવ્રતા `full` કરતાં વધુ મજબૂત નથી (તેઓ ફક્ત તેમના પોતાના નિયમો — ઉપયોગ કરે છે, અંગ્રેજી `dedup`/`ultra` નિયમોમાં કોઈ સાયલન્ટ ફૉલ-બેક નથી, જે વિદેશી ટેક્સ્ટને મૅન્ગલ કરશે). `en` / `es` / `id` / `pt-BR` પૂર્ણ છે. આંશિક પેક માટે `dedup.json` + `ultra.json` ના યોગદાન આવકાર્ય છે.
- **સ્ટૅક્ડ ટેલિમેટ્રી ફક્ત સંકુચિત એન્જિનોની સૂચિ આપે છે.** સ્ટૅક્ડ-પાઈપલાઈન સ્ટેપ કે જેનું એન્જિન ચાલતું હતું પરંતુ 0% બચતનું ઉત્પાદન કરે છે તે `stats:null` અને તેથી તે `engineBreakdown` — માં દેખાતું નથી જે અવગણવામાં આવેલ સ્ટેપથી અસ્પષ્ટ છે. "છોડી" થી "રન, 0 %" ને અલગ કરવા માટે બ્રેકડાઉન-મોડલ ફેરફારની જરૂર પડશે અને તેને સ્થગિત કરવામાં આવશે.
