OmniRoute መጭመቅ የተገነባው በሞተር ኮንትራቶች ዙሪያ ነው። አንድ ሞድ አንድ ሞተር በቀጥታ (`caveman` ወይም `rtk`) ወይም በርካታ ሞተሮችን በቅደም ተከተል የሚያከናውን የተወሰነ የተቆለለ የቧንቧ መስመር ሊያሄድ ይችላል።

## ሁነታዎች

| ሁነታ          | የሞተር መንገድ                                                                   | የታሰበ ግቤት                                       |
| ------------ | --------------------------------------------------------------------------- | ---------------------------------------------- |
| `off`        | ምንም                                                                         | ትክክለኛ ፈጣን ጥበቃ                                  |
| `lite`       | Caveman Lite ረዳቶች                                                           | ዝቅተኛ-አደጋ ሁል ጊዜ ማጽዳት                            |
| `standard`   | ዋሻማን                                                                        | የተፈጥሮ-ቋንቋ ፈጣን ጤዛ                               |
| `aggressive` | Caveman + history/tool ማጠቃለያዎች                                              | ረጅም የውይይት ክፍለ ጊዜዎች                             |
| `ultra`      | Caveman + መግረዝ ረዳቶች                                                         | አውድ-ገደብ ማግኛ                                    |
| `rtk`        | RTK                                                                         | ተርሚናል፣ሼል፣ግንባታ፣ሙከራ እና የጂት ውፅዓት                  |
| `omniglyph`  | OmniGlyph                                                                   | በአገሬው አቅራቢ ሽቦ ላይ እንደ አውድ-ምስል                   |
| `stacked`    | የቧንቧ መስመር. የጥያቄው ነባሪ `session-dedup -> lite` ነው። `rtk -> caveman` መርጦ ገብቷል። | የተቀላቀሉ የመሳሪያ ምዝግብ ማስታወሻዎች እና ፕሮሴዎች፣ ከፍተኛ ቁጠባዎች |

### OmniGlyph መጭመቂያ መገለጫዎች

የ `omniglyph` ሞተር (ጥቅል `omniglyph`፣ 1.4.0 +) በዓለም አቀፍ ደረጃ በ `omniglyph.profile` በማመቂያ ቅንጅቶች ወይም በተቆለለ የቧንቧ መስመር ውቅረት ውስጥ የተቀመጠ የትርጓሜ መገለጫን ይቀበላል።

| መገለጫ          | ድንበር                                                                      |
| ------------- | ------------------------------------------------------------------------- |
| `aggressive`  | ነባሪ መመሪያው የታተሙት ደረሰኞች — ምስሎች ስርዓትን፣ የመሳሪያ ሰነዶችን እና ጥቅጥቅ ያለ ታሪክን ይለካሉ      |
| `balanced`    | የቀጥታ ግዛትን ቤተኛ ያቆያል፣ የመጨረሻዎቹን 8 ዙር ይጠብቃል፣ የቆየ የተዘጋ ታሪክን ያፈርሳል              |
| `coding-safe` | ስልጣንን፣ የመሳሪያ ንድፎችን እና የቀጥታ መሳሪያ ውፅዓትን ቤተኛ ያቆያል፣ የመጨረሻዎቹን 12 መዞሪያዎች ይጠብቃል። |
| `passthrough` | መንገዶች ሳይቀይሩ; ሞተሩ ተዘሏል                                                     |

መገለጫው ሀ** ጣሪያ, ወለል አይደለም** : በጥቅሉ ውስጥ ያለው `mergeCompressionProfileOptions` ጠሪው የጠፋውን መስመር እንደገና እንዲከፍት አይፈቅድም መገለጫው ተዘግቷል፣ ስለዚህ በየደረጃው `preserveSystemPrompt: false` በ `coding-safe` ስር የስርዓት መጭመቂያውን እንደገና ማንቃት አይችልም።

በዚህ ኮድ ቤዝ ላይ የሚለካው `coding-safe` እና `balanced` `minCompressChars` ወደ ከፍተኛው ከፍ ያደርጋሉ እና ስርዓትን፣ የመሳሪያ ንድፎችን እና የመሳሪያ ውጤቶችን ቤተኛ ያቆዩታል፣ ስለዚህ ታሪክን ያልሰበሰበ ክፍለ ጊዜ በ `below_min_chars` ላይ ይቆማል እና ሞተሩ ምንም ነገር አይለውጥም። ለዚህም ነው ነባሪው ከደህንነቱ የተጠበቀው መገለጫ ይልቅ `aggressive` የሆነው።

ጥቅሉ የራሱን የሞዴል ስፋት እና መገለጫ ከአካባቢው ውቅር ይፈታል። OmniRoute ውሳኔውን በፍፁም አይሰጥም፡ አስማሚው የአምሳያው በርን ወደ ጥቅሉ በጣም ገዳቢው ወሰን ይሰኩት፣ ስለዚህ አስተናጋጅ አካባቢ ቅንጅቶች የተፈቀደ ዝርዝሩን ብቻ ማጥበብ ይችላሉ፣ ከ OmniRoute የተለኩ ደረሰኞች አልፈው አያሰፉም።

## የሞተር መዝገብ ቤት

መዝገቡ በ `open-sse/services/compression/engines/registry.ts` ይኖራል። ሞተሮች የጋራ ውልን ያጋልጣሉ፡-

- `id`: የተረጋጋ የሞተር መታወቂያ እንደ `caveman` ወይም `rtk`
- `apply(text, config)`: በተደራረቡ የቧንቧ መስመሮች ጥቅም ላይ የሚውል የቆየ የማስፈጸሚያ መንገድ
- `compress(input, config)`: የመጀመሪያ ደረጃ የማስፈጸሚያ መንገድ የጽሑፍ + ስታቲስቲክስ መመለሻ
- `getConfigSchema()`: JSON-Schema-የሚመስለውን ትክክለኛ ውቅር ይመልሳል
- `validateConfig(config)`: `{ valid, errors[] }` ይመልሳል

ምዝገባ `registerCompressionEngine(engine)` (ወይም `registerEngine` ለላቁ ጉዳዮች) ይጠቀማል፣ ከመቀበሉ በፊት `assertValidEngine()` እና `validateConfig(defaultConfig)` ይጠራል። በሂደት ጊዜ ሞተርን ለማስወገድ `unregisterCompressionEngine(id)` ይጠቀሙ።

`strategySelector.ts` መጨናነቅ ከመጀመሩ በፊት አብሮገነብ ሞተሮችን ይመዘግባል። ይህ ቅድመ እይታን፣ የሩጫ ጊዜ መጭመቅን፣ የተቆለለ ሁነታን፣ ሙከራዎችን እና የወደፊት ሞተሮች ተመሳሳይ የማስፈጸሚያ መንገድን እንዲጠቀሙ ያስችላቸዋል።

### MCP መግለጫ መጭመቅ (የተዛመደ)

የተለየ መዝገብ MCP መሣሪያ መግለጫ ሜታዳታ በመዝገቡ ደረጃ — ይጨመቃል `open-sse/mcp-server/descriptionCompressor.ts` እና [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ይመልከቱ። የ Caveman ደንቦችን እንደገና ይጠቀማል ነገር ግን በመሳሪያ ሜታዳታ ነው የሚሰራው እንጂ ክፍያ አይጠይቅም።

### ተጨማሪ አብሮገነብ ሞተሮች

ከካቬማን፣ RTK እና LLMLingua-2 ባሻገር፣ መዝገቡ ብዙ ልዩ ኪሳራ የሌላቸው / መዋቅራዊ ሞተሮችን (በተደራራቢ የቧንቧ መስመሮች፣ የመጫወቻ ስፍራው እና ሙከራዎች) ይልካል።

| ሞተር         | መታወቂያ           | ምን ያደርጋል                                                                                                                              |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| CCR         | `ccr`           | Content-Compress-Retrieve (H4): ትላልቅ ተከታታይ የጽሑፍ ብሎኮችን በይዘት-አድራሻ ማጣቀሻዎች ይተካቸዋል፣ ስለዚህ repeated/large ብሎኮች አንድ ጊዜ ይላካሉ እና ከዚያ በኋላ ይጠቀሳሉ። |
| የጭንቅላት ክፍል  | `headroom`      | SmartCrusher (H3 + N5)፡- ኪሳራ የሌለው የሠንጠረዥ መጠቆሚያ ተመሳሳይ የJSON-array ጭነት ጭነቶች ወደ አምድ `[N rows]` ቅጽ።                                       |
| ionizer     | `ionizer`       | Head/middle/tail ረድፍ ናሙና በጣም ትልቅ ተመሳሳይ ብሎኮች, የተሸፈኑ መካከለኛ እንደ CCR ይዘት አድራሻ ማጣቀሻ በማስቀመጥ.                                                |
| ክፍለ-ጊዜ ማጥፋት | `session-dedup` | የይዘት አድራሻ ተሻጋሪ ማባዛት (TokenMizer-inspired)፡ ቀደም ባሉት ተመሳሳይ ክፍለ ጊዜዎች ላይ የታየውን ጽሑፍ ይሸልማል።                                                 |

**CCR ሰርስሮ-ፕሮቶኮል መመሪያ (#8033):** ለመጀመሪያ ጊዜ CCR በጥያቄ ውስጥ ≥ 1 ብሎክ ይተካዋል፣ ሞተሩ አንድ ነጠላ ያዘጋጃል፣ idempotent `system` መልእክት (ከ `[CCR protocol]` መልእክተኛ ጋር እየመራ) ጠሪው የ → መሣሪያ ውልን ያስተምራል `[CCR retrieve hash=<24hex> chars=N]` ማርከር ማለት ምን ማለት ነው፣ ሃሽ በቃላት መገለበጥ አለበት (ሁሉም 24 ሄክስ ቁምፊዎች — ያልተገለበጡ ሀሽሶች) `[dedup:ref sha=...]` ማለት "ወደ ታሪክ መለስ ብለህ ተመልከት" እንጂ "መሳሪያውን ጥራ" ማለት አይደለም። ማስታወሻው በመርፌ የተወጋ ነው** የደዋዩ ያስተዋወቀው `tools[]` በትክክል `omniroute_ccr_retrieve` ሊደርስ እንደሚችል ሲያረጋግጥ ብቻ ነው።** (`callerSupportsCcrRetrieve()` in `open-sse/services/compression/engines/ccr/protocolInstruction.ts`) — ከOpenAI ጋር ተኳሃኝ የሆነ ደዋይ ያለዚያ መሳሪያ በጭራሽ ሊደርስበት የማይችል ነገር ለመጥራት መመሪያ አይደርሰውም። አለመቻል የሚተገበረው መርፌ ከመውሰዱ በፊት የመልእክቱን ታሪክ በመቃኘት ለተላላኪው ሰው ነው፣ ስለዚህ የባለብዙ ዙር ጥያቄዎች (ቀደምት መልዕክቶችን የሚደግሙ) ማስታወሻውን በየተራ አንድ ጊዜ አይቆለሉም።

## LLMLingua-2 (የፍቺ መከርከም)

LLMLingua-2 ሁነታ ይሰራል** የትርጉም ቶከን መቁረጥ** ደንብን መሰረት ያደረጉ Caveman እና RTK ሞተሮችን በማሟላት ትንሽ ONNX ማስመሰያ ክላሲፋየር በመጠቀም በስድ ፕሮዝ

- የሥርዓት ባልሆኑ መልእክቶች ውስጥ ፕሮሴስን ይጨመቃል ፤ የታጠሩ የኮድ ብሎኮች እና ሌሎች የተጠበቁ ግንባታዎች በጭራሽ አይለወጡም።
- የ `@atjsh/llmlingua-2` ጀርባን (ONNX via `@huggingface/transformers`) በሠራተኛ ክር ውስጥ ያስኬዳል፣ ስለዚህ የሞዴል ማጠቃለያ የጥያቄውን ክስተት ሉፕ በጭራሽ አያግደውም።
- ነው።** ሊደረደር የሚችል** (`stackPriority` 35)፡ በተደራረበ የቧንቧ መስመር ውስጥ የሚሠራው ከመዋቅር ሞተሮች በኋላ ነው (CCR፣ ክፍለ-ጊዜ-ድፕ፣ ዋና ክፍል፣ Caveman) ነገር ግን ከ `ultra` በፊት፣ የትርጉም መግረዝ አስቀድሞ መዋቅራዊ በሆነ የታመቀ ጽሑፍ — ለምሳሌ `rtk -> caveman -> llmlingua` በጣም ውጤታማ ነው።
- **ውድቀት - በማንኛውም ስህተት ላይ ይከፈታል** (የጠፋው አማራጭ ዴፕ፣ የሰራተኛ መራቢያ፣ የሞዴል ጭነት፣ ግምት ወይም የጊዜ ማብቂያ) → ዋናው ጽሁፍ ሳይለወጥ ተመልሷል፣ በጭራሽ ስህተት የለም።

የሞተር ቦታ `open-sse/services/compression/engines/llmlingua/`. የዳሽቦርዱ ገጽ `Dashboard -> Context & Cache -> LLMLingua` ነው።

**ለምን ተጠየቀ፡-** በ npm የታተመ ጥቅል፣ ራሱን የቻለ ጥቅል እና የ Docker ምስል መርከብ** ያለ** እነዚህ deps ቀጭን ለመቆየት. በማይኖሩበት ጊዜ የሰራተኛው ጥገኝነት በር (በ `worker.ts` ውስጥ `@atjsh/llmlingua-2` መፍታት ፍተሻ) ይወድቃል እና ሞተሩ** አልተሳካም - በፀጥታ ይከፈታል** — LLMLingua መምረጥ ምንም-op ይሆናል (ጽሑፍ ሳይለወጥ ተመልሷል፣ ምንም ስህተት አልተመዘገበም)። በተቆረጠ አካባቢ ውስጥ እሱን ለማግበር የአማራጭ ቁልል ይጫኑ፡-

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` ማስወገድ (2.0.4 +) ቀደም ሲል የበላይ የሆነውን ~ 800 MB አስተዋፅዖ አበርካችውን ያስወግዳል — ቀሪው አሻራ የ transformers.js + onnxruntime-node runtimes ነው፣ በተጨማሪም የ TinyBERT ሞዴል (~ 57 MB) በመጀመሪያ ጥቅም ላይ የዋለው (በ npm በኩል አይደለም)።

በየአካባቢው፡-

- **Dev/ `npm install`** `--omit=optional` (ወይም `--no-optional`) ካላለፉ በቀር — በራስ-ሰር ተጭኗል። ምንም እርምጃ አያስፈልግም።
- **ግሎባል npm (`npm i -g omniroute`) / ለብቻው** — ከላይ ያለውን የመጫኛ ትዕዛዙን በተጫነው የጥቅል ማውጫ ውስጥ ያሂዱ ወይም አማራጭ deps ሳያስቀሩ እንደገና ይጫኑ።
- **Docker** — በተገኘው የምስል ንብርብር ውስጥ የመጫኛ ትዕዛዙን ይጨምሩ; የታተመው ምስል በንድፍ ቀጭን ይላካል.
- **VPS (PM2)** — ወደ መተግበሪያው `node_modules` ጫን እና ሰራተኛው በሩን እንደገና እንዲፈትሽ ሂደቱን እንደገና አስጀምር።
- **ጥሬ ቀጣይ ራሱን የቻለ (`npm run build` → `.build/next/standalone/server.js`)** — ራሱን የቻለ መከታተያ መርከቦች NEITHER ሠራተኛውንም ሆነ አማራጭ ዴፕስ፣ ስለዚህ ሞተሩ በጸጥታ ወድቋል-ይከፈታል። `scripts/build/colocate-standalone.mjs` ሁለቱንም እንደገና ይተገበራል (ሰራተኛ esbuild + አማራጭ-ጥልቀት ወደ ገለልተኛ ዛፍ መዘጋት); ከእያንዳንዱ ግንባታ በኋላ በ `postbuild` npm መንጠቆ በኩል በራስ-ሰር ይሰራል። ዲፕስ በማይኖርበት ጊዜ የማይሳካ ፣ ለስላሳ-ለስላሳ።

**ንቁ መሆኑን ያረጋግጡ፡-** በ LLMLingua ተመርጧል፣ እውነተኛ ፕሮሴስ በትክክል ይቀንሳል (ሞተሩ መከፈት ያቆማል) እና የመጀመሪያው ጥያቄ ሞዴሉን ወደ `${DATA_DIR}/models/llmlingua` እንዲወርድ ያደርገዋል። በሩ ሆን ብሎ `@atjsh/llmlingua-2` — ብቻ ነው የሚመረምረው ሌሎቹ እኩዮች ኢኤስኤም ብቻ ናቸው እና `require.resolve` በእነርሱ ላይ ይጥላል — በተገኘበት ጊዜም እንኳ ሰራተኛው በ `import()` ሰአት እኩያ ከጠፋ ይከፈታል።

## የተደረደሩ የቧንቧ መስመሮች

የተቆለለ ሁነታ የቧንቧ መስመር ደረጃዎችን በቅደም ተከተል ያካሂዳል. ነባሪው፡-

```txt
rtk -> caveman
```

መጠየቂያው የትዕዛዝ ውፅዓትን ከሰው ወይም ከረዳት ፕሮሴ ጋር የሚያጣምርበት ለኮዲንግ-ወኪል ክፍለ ጊዜዎች ይህንን ይጠቀሙ። RTK በመጀመሪያ ጫጫታ ያላቸውን የመሳሪያ ምዝግብ ማስታወሻዎችን ይቀንሳል፣ ከዚያም Caveman የቀረውን የተፈጥሮ ቋንቋ ይጨመቃል።

የቧንቧ መስመር ደረጃዎች ከ `stackedPipeline` ጋር በመጨመቂያ መቼቶች ወይም በመጭመቂያ ጥንብሮች የተዋቀሩ ናቸው።

ሁለቱም ሞተሮች አንድ አይነት ብቁ የሆነ ክፍያ ሲቀንሱ፣ የቁጠባ ውህድ፡-

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP ተደራሽነት ዛፍ ማጣሪያ

MCP ተደራሽነት-ዛፍ ስማርት ማጣሪያ ከአፈፃፀም በኋላ በ MCP ላይ የሚሰራ የማመቅ ንብርብር ነው።** የመሳሪያ ውጤቶች** በጥያቄዎች ወይም አውድ ላይ አይደለም። እሱ የሚያነጣጥረው የቃል ተደራሽነት-ዛፍ እና የአሳሽ ቅጽበታዊ ፎቶ ጭነት እንደ Playwright፣ ኮምፒውተር አጠቃቀም እና አሳሽ-አውቶማቲክ MCP አገልጋዮች ባሉ መሳሪያዎች የተመለሱ ናቸው።

### ምን ያደርጋል

1. **ጩኸት መግፈፍ** — ባዶ generic/text ግቤቶችን ያስወግዳል (`- generic:`፣ `- text: ""`)
2. **የእህት ወይም የእህት መውደቅ** — መቼ ≥ `collapseThreshold` (ነባሪ 30) ተከታታይ መስመሮች መዋቅራዊ ድግግሞሾች ሲሆኑ ወደ መጀመሪያው `collapseKeepHead` (ነባሪ 10) መስመሮች ውስጥ ይወድቃሉ + አንድ ቆጠራ ማጠቃለያ + የመጨረሻው `collapseKeepTail` (ነባሪ 5) መስመሮች
3. **የማጣቀሻ ጥበቃ** በ Playwright/computer-use የሚፈለጉ — `[ref=eXX]` መልህቆች በጭራሽ አይነኩም
4. **ጠንካራ መቆራረጥ** — ከተደረመሰ በኋላ ያለው ጽሑፍ አሁንም `maxTextChars` (ነባሪ 50,000) የሚበልጥ ከሆነ፣ ወኪሉ መስራቱን እንዲቀጥል የአሰሳ ፍንጭ ያለው ቁርጥራጭ

### የሞተር ቦታ

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### ማዋቀር

በአለምአቀፍ መቼቶች (ሚግሬሽን 056) በ `compression.mcpAccessibility` ተቆጣጥሮታል። ነባሪ ውቅር፡

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

ማጣሪያው የሚተገበረው `type` `"text"` በሆነው እና ርዝመታቸው ከ `minLengthToProcess` በላይ በሆኑ የመሳሪያ ውጤቶች ላይ ብቻ ነው። ፈጣን መጨናነቅን አይጎዳውም ወይም ክፍያን አይጠይቅም።

### የሚጠበቁ ቁጠባዎች

በአሳሽ ቅጽበተ-ፎቶ መሳሪያ ውጤቶች ላይ ከ60–80%፣ በገጽ ውስብስብነት ላይ በመመስረት። የብልሽት ስልተ ቀመር O(n) በመስመር ቆጠራ ነው እና ግድየለሽ መዘግየትን ይጨምራል።

## መጭመቂያ Combos

የማመቂያ ጥንብሮች ወደ ማዞሪያ ኮምቦዎች ሊመደቡ የሚችሉ የመጭመቂያ መገለጫዎች ተሰይመዋል።

- `compression_combos`: ሁነታን፣ ቧንቧ መስመርን፣ RTK ውቅርን፣ የቋንቋ ውቅረትን እና ነባሪ ማርከርን ያከማቻል
- `compression_combo_assignments`: የመጭመቂያ ጥምር ወደ ማዞሪያ ጥምር ካርታ
- አጠቃላይ ጥምር ከመሻሩ በፊት የአሂድ ጊዜ ውህደት የተመደበውን የመጭመቂያ ጥምርን ይፈታል።
- ትንታኔዎች `compression_combo_id` እና `engine` ያካትታሉ

## ቅድመ-ሁኔታዎች/ኦፕሬተር መመሪያ (CCR እና ክፍለ-ጊዜ-የተቀነሰ)

CCR (`ccr`) እና `session-dedup` ጽሑፍን ይተኩ ወይም ይሽሩ እና ሀ** ምልክት ማድረጊያ** ከኋላ. ይህ ክፍል ደንበኛን ለማገናኘት፣ ሁለቱን ማርከሮች ለማንበብ እና የተሸሸገውን ይዘት ለማውጣት ወይም ለመመርመር የኦፕሬተር ማጣቀሻ ነው። የእያንዳንዱ ሞተር ሜካኒክስ ከላይ ተሸፍኗል; ይህ "እንዴት እንደማሄድ" ንብርብር ነው.

### መጓጓዣዎች እና የመጨረሻ ነጥቦች

የ CCR መሳሪያዎችን የሚያጋልጥ MCP አገልጋይ በሶስት መንገዶች ሊደረስበት ይችላል. ነባሪው መሠረት URL `http://localhost:20128` (`OMNIROUTE_BASE_URL`) ነው

| መጓጓዣ                          | URL / ትዕዛዝ                              | ማስታወሻዎች                                                                                                             |
| ----------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| ሊተላለፍ የሚችል HTTP (ደንበኛ፣ የሚመከር) | `http://localhost:20128/api/mcp/stream` | የመጨረሻው ነጥብ የአሁኑ MCP ደንበኞች ያናግሩታል።                                                                                   |
| Legacy SSE singleton          | `http://localhost:20128/api/mcp/sse`    | የቆየ ነጠላ መጓጓዣ። እሱ** ይዘጋል።** ሊተላለፉ የሚችሉ ክፍለ ጊዜዎች; `streamable-http` ደንበኞችን በ `/api/mcp/stream` ላይ ተጠቀም እንጂ ይህን አይደለም። |

### የማከማቻ ደረጃዎች (ከዳግም ማስጀመር የሚተርፈው)

CCR ሀ** ባለ ሁለት ደረጃ** ማከማቻ፣ በማህደረ ትውስታ-ብቻ አይደለም፡-

- **ትኩስ የማህደረ ትውስታ ደረጃ** — በብሎክ ካፕ 2 MiB፣ በርዕሰ መምህር 16 MiB፣ ዓለም አቀፍ 64 MiB። ግቤቶች ነባሪ የ24 h TTL (ቢበዛ 7 ቀናት)። ሙሉ MCP ከማስታወሻ ማግኘት በ 256 KiB ተሸፍኗል; ማንኛውም ትልቅ ነገር አሁንም በክልል / ግሬፕ ሁነታዎች ሊደረስበት ይችላል.
- **የሚበረክት SQLite ደረጃ** (`ccr_blocks`፣ `COMPRESSION_CCR_DURABLE_STORE`፣ በነባሪነት) — የውስጠ-ማህደረ ትውስታ ደረጃን ስለሚደግፍ ብሎክ LRU ማስወጣት፣ ዳግም ማስጀመር ወይም ሰርስሮ ማረፍን በሌላ አጋጣሚ ይተርፋል። ረድፉ የብሎኩን TTL ያቆያል፣ስለዚህ ከ TTL ያለፈ ብሎክ ከሁለቱም እርከኖች ጠፍቷል።

ሶስት ጠባቂዎች ዘላቂውን የደረጃ ወሰን — ጠብቀው የሚቆዩት የማስታወስ ችሎታ ሲኖር ብቻ ነው፡-

1. እገዳው አልቋል** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. የሩጫ ጊዜው የደመና ጊዜ ነው (አካባቢያዊ ዲስክ የለም);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

ስለዚህ "ብሎክው ጠፋ" ብርድ ልብስ ዳግም ማስጀመሪያ ታሪክ አይደለም sub-512 KB ብሎክ በአካባቢያዊ፣ ደመና ያልሆነ የሩጫ ጊዜ እንደገና ሲጀመር TTL እስኪያልቅ ድረስ በዘላቂው እርከን በኩል ይኖራል። ለተለዋዋጭ [የአካባቢ ማጣቀሻን](../reference/ENVIRONMENT.md) ይመልከቱ።

`[dedup:ref]` እይታ ወደ ኋላ ሆን ተብሎ የተደረገ የፕሮቶኮል ውሳኔ — ምንም ቅድመ-መላክ መልሶ ግንባታ የለም። እንደ "ይህ ትክክለኛ ጽሑፍ ቀደም ሲል በዚህ ክፍለ ጊዜ ሽቦ ላይ እንደነበረ" አድርገው ይያዙት።

### የደንበኛ ቅድመ ሁኔታዎች

- **ቁልፍ (ስቲዲዮ)** የ stdio ደዋይ በየጥያቄው ማንነት የለውም፣ ስለዚህ በ `OMNIROUTE_API_KEY` ያረጋግጣል (በ MCP አገልጋይ `env` ውስጥ ተቀምጧል)። ያለ እሱ ደዋዩ ስም-አልባ ነው እና ርእሰ መምህር የሚያስፈልጋቸው መሳሪያዎች ዝቅ ሊያደርጉ ይችላሉ።
- **`tools[]` የመርፌ ቅድመ ሁኔታ ነው።** የ CCR ሰርስሮ-ፕሮቶኮል መመሪያ (#8033) በመርፌ ገብቷል።** ብቻ** የጥያቄው ማስታወቂያ `tools[]` ደንበኛው በትክክል ወደ `omniroute_ccr_retrieve` መድረስ እንደሚችል ሲያረጋግጥ። ግጥሚያው በተከፋፋይ (`__` — `.` `mcp__gateway__omniroute_ccr_retrieve` `/`፣ `:`) የታሰረ ተከታይ-ክፍል ግጥሚያ ነው — የማይዛመድ ወይም የማይዛመድ `tools[]` ማለት መመሪያው በንድፍ _አልተወጋም_ ማለት ነው።
- **`codemode:false` (OpenCode ደንበኞች).** OpenCode ወደ ኮድ ሁነታ ነባሪ ያደርገዋል፣ ይህም ወደ ሞዴሉ እና ቤተኛ መሳሪያዎቹን ብቻ የሚያስተዋውቅ ነው።** አይደለም** MCP መሳሪያዎችን በቤተኛ `tools[]` ዝርዝር ላይ ያስቀምጡ። የ `omniroute_ccr_*` መሳሪያዎች እንዲተዋወቁ በ MCP አገልጋይ መግቢያ ላይ `codemode: false` ያዘጋጁ። ይህ ሀ** ደንበኛ** ቅንብር፣ አንድ OmniRoute አይደለም። የ CCR መመሪያን እስካሁን አልተወጋም OpenCode መሳሪያን `<server>_<tool>` ሰይሞታል፣ ስለዚህ `omniroute` የሚባል አገልጋይ `omniroute_omniroute_ccr_retrieve` ያጋልጣል፣ እና `_` ከተመሳሰሉት መለያያቶች ውስጥ አንዱ አይደለም።
- **ርዕሰ መምህራን.** ማከማቻ እና ሰርስሮ ማውጣት በእያንዳንዱ የተረጋገጠ ርእሰመምህር (በ API ቁልፍ) ተነጥለዋል። ቁልፍ የሚያየው የራሱን ብሎኮች ብቻ ነው።

### ወሰኖች በአንድ መሣሪያ

የወሰን ማስፈጸሚያ ሁልጊዜ ጠባብ ስፋት ላላቸው HTTP/SSE ጠሪዎች በርቷል። የ `omniroute_` CCR መሳሪያዎች ያስፈልጉታል፡-

| መሳሪያ                     | ወሰን                 |
| ------------------------ | ------------------- |
| `omniroute_ccr_store`    | `write:compression` |
| `omniroute_ccr_delete`   | `write:compression` |
| `omniroute_ccr_retrieve` | `read:compression`  |
| `omniroute_ccr_inspect`  | `read:compression`  |
| `omniroute_ccr_list`     | `read:compression`  |
| `omniroute_ccr_stats`    | `read:compression`  |

የጎደለው ወሰን ይመልሳል**MCP መሣሪያ ስህተት ውጤት** (`isError: true`፣ HTTP አይደለም 403 — `403 LOCAL_ONLY` የተለየ loopback route-guard auth ነው) `Error: Insufficient MCP scopes for <tool>. Missing: <scope>.` አነስተኛ የርቀት ቁልፍ `mcp:connect` ይይዛል (የ `/api/mcp/` አካባቢያዊ-ብቻ ቀረጻን ይፈቅዳል) እና የሚፈልገውን የተወሰነ read/write ወሰን።

### የመልሶ ማግኛ ገደቦች እና ገጽ ማውጣት

MCP መሣሪያ ጽሑፍ ውጤቶች በ `mcpAccessibility.maxTextChars` ዙሪያ ተቆርጠዋል (ነባሪ `50000`)። የአንድ ብሎክ የ `full` ሰርስሮ ማውጣት በ256 KiB — ተሸፍኗል** ያልተገደበ ሙሉ ሰርስሮ ማውጣት የለም።** . የብሎክ `chars=N` ትልቅ ሲሆን ሙሉውን ከመጎተት ይልቅ ገጹን ይለጥፉት፡-

- ዋና ደንብ፡-**`chars > 40000` → `mode` ይጠቀሙ** ፣ በጭራሽ ባዶ ሙሉ።
- `mode:"grep"` — regex `pattern` በመስመር የተጣጣመ መስመር፣ እስከ 1,000 የሚደርሱ ተዛማጅ መስመሮች (`unique: true` drops ተደጋጋሚ)፣ "እኔ የሚያስፈልገኝን አንድ መስመር ፈልግ" በጣም ርካሽ።
- `mode:"lines"` — ባለ 1 ጠቋሚ መስመር ክልል; ሁለቱንም `start` እና `end` ያስፈልገዋል።
- `mode:"head"` / `mode:"tail"` — first/last `n` መስመሮች.
- `mode:"stats"` — መስመር፣ ቁምፊ እና ባይት ያለ ሰውነት ይቆጠራሉ።

በአንድ ጊዜ ሁሉንም ነገር ከመጠየቅ ይልቅ በገጾች ውስጥ ረጅም ብሎክ ለመራመድ `mode:"lines"` በ `start`/`end` ይጠቀሙ።

### የመሳሪያ መሰየም

የማውጫ መሳሪያው በአሁኑ ጊዜ `omniroute_ccr_retrieve` ይባላል (የ `omniroute_` ቅድመ ቅጥያ የአገልጋይ ስም ግጭቶች ቀኑ ያለፈበት መፍትሄ ነው)። ይበልጥ ንጹህ የሆነ የታሰረ-ቅጥያ መሳሪያ ስም እና ለ MCP JSON ውጤቶች የተቆራረጡ መካከለኛ ሕብረቁምፊዎች እንደ ላይኛው ተከታታዮች ይከተላሉ; ይህ ገጽ አሁን ያለውን፣ የተላከውን ባህሪ ብቻ ይመዘግባል።

### የክፍለ ጊዜ የሕይወት ዑደት

ሊተላለፍ የሚችል-ኤችቲቲፒ ክፍለ ጊዜዎች ስራ ፈትተው አገልጋዩ ያጭዳቸዋል፤ የስራ ፈት መስኮቱ `MCP_SESSION_IDLE_MS` ቋሚ ነው (በስም የተጠቀሰው፣ ሃርድ ኮድ የተደረገ እሴት አይደለም፣ ስለዚህ ይህ ገጽ ሲቀየር አይንሸራተትም)። የስራ ፈት-የታጨደ ክፍለ ጊዜ ምልክቱ HTTP 404 ከ `Unknown Mcp-Session-Id` — ጋር መፍትሄው ክፍለ-ጊዜውን እንደገና ማገናኘት ወይም እንደገና ማስጀመር ነው።** አይደለም** ቁልፉን ለማሽከርከር፣ ወሰን ለመቀየር ወይም መሣሪያን እንደገና ለመሰየም።

## ወሰን እና ማግለያዎች

**መክተቻዎች በጭራሽ አልተጨመቁም።** `open-sse/handlers/embeddings.ts` ምንም አይነት የመጭመቂያ ሞተር — ብሎ አይጠራም የ request/response አካላት ሳይነኩ በቀጥታ ወደ ፈጻሚው ያልፋሉ። ይህ ዛሬ መዋቅራዊ ነው (መክተት እና የቻት ማጠናቀቂያዎች የጋራ ተቆጣጣሪዎች ናቸው)፣ የሩጫ ጊዜ ፍተሻ አይደለም፣ ነገር ግን በ #8034 ውስጥ ያለው የቬክተር-ማዛባት ስጋት በመክተቻው መንገድ ላይ ምንም የተጋላጭነት ወለል የለውም ማለት ነው።

**Per-model/endpoint ማግለል ማጣሪያ (#8034).** ለውይይት ማጠናቀቂያ ኦፕሬተር የሞዴል መታወቂያዎችን / `provider/model` ኢላማዎችን ሊሰየም ይችላል ይህም በፍፁም መታመም የሌለበት — መጭመቂያው ወደ መክተቻ-አጠገብ ዱካ ከተጠጋ እና በአጠቃላይ ለማንኛውም ሞዴል ትክክለኛ ባይት ለ ባይት አፋጣኝ (የመወሰኛ ኢቫልስ፣ መሸጎጫ ሚስጥራዊነት ቅድመ ቅጥያ፣ ወዘተ.) ከሆነ ጠቃሚ ነው።

- የቅንጅቶች መስክ፡- `exclusions?: string[]` በአለምአቀፍ የመጭመቂያ ውቅረት (`GET`/`PUT /api/settings/compression`)፣ ባለው `key_value` መጭመቂያ ስም ቦታ (`src/lib/db/compression.ts`) በኩል ቀጥሏል — ምንም አዲስ ሠንጠረዥ የለም።
- ዳሽቦርድ ትር፡** ዳሽቦርድ → መጭመቂያ → የማይካተቱ** (`/dashboard/compression/exclusions`)
- የስርዓተ-ጥለት አገባብ፡- `*` ብቸኛው የዱር ምልክት ነው። በስርዓተ-ጥለት ውስጥ ያሉት ሁሉም የሬጌክስ ሜታ ቁምፊዎች ከመዛመዳቸው በፊት ያመለጠ ነው፣ ስለዚህ `gpt-5.6` ከትክክለኛው ሕብረቁምፊው ጋር ብቻ ይዛመዳል፣ በጭራሽ `gpt-5x6` (ReDoS-Safe፣bounded፣ Nonsted Quantifiers)። ቅጦች ከሁለቱም በባዶ ሞዴል መታወቂያ እና በ `provider/model` ውህድ — `gpt-5-6`፣ `openai/gpt-5-6` እና `openai/*` ሁሉም ይሰራሉ፣ እና `*` ብቻውን እያንዳንዱን ሞዴል አያካትትም።
- ተዛማጅ `isCompressionExcluded()` / `normalizeCompressionExclusions()` በ `open-sse/services/compression/exclusions.ts` ውስጥ። `chatCore.ts` የማመቅ ቅንብሮችን ከፈታ በኋላ የተገለለውን ኢላማ ይፈትሻል፣** ማንኛውም ሞተር ከመሄዱ በፊት** ፣ እና ክብሪትን ልክ እንደ መጭመቅ በአለምአቀፍ ደረጃ እንደተሰናከለ አድርጎ ያስተናግዳል — የጥያቄው አካል ባይት ተመሳሳይ ነው። ለትንታኔ ታይነት መዝለሉ በ `writeCompressionSkip(..., "excluded")` በኩል ይመዘገባል።
- ነባሪ (empty/absent ዝርዝር)፡ ከቅድመ-#8034 ባህሪ ጋር ተመሳሳይ የሆነ — ምንም አልተካተተም።

## የታወቁ ገደቦች

- **LLMLingua-2 (SLM) በጋራ የሚገኙ የአማራጭ ዲፕስ ያስፈልገዋል።** ሰራተኛው በምርት ግንባታ ውስጥ ይሰራል `@atjsh/llmlingua-2` + እኩዮች ወደ `dist/node_modules` ሲገኙ ( `scripts/build/colocateOptionals.mjs`, #4286 ይመልከቱ)። ያለ እነርሱ ሞተሩ አይሳካም-ይከፈታል (የመጀመሪያውን ጽሑፍ ይመልሳል). የሰራተኛ አፈታት ከአሁን በኋላ በ `import.meta.url` ላይ የተመካ አይደለም (ብቻውን በጥቅል ውስጥ ይሞታል) — በሩጫ ጊዜ cwd / `argv[1]` ላይ ይመሰረታል።
- **የዋሻማን ቋንቋ ጥቅሎች `de` / `fr` / `ja` ከፊል ናቸው።** `context` + `filler` + `structural` ደንቦችን ይላካሉ ነገር ግን `dedup` / `ultra` ጥቅሎች የሉም፣ ስለዚህ `ultra` ጥንካሬ ለእነዚያ ቋንቋዎች ከ `full` አይበልጥም (የራሳቸውን ህግጋት ብቻ ይጠቀማሉ — ወደ እንግሊዘኛ `dedup`/`ultra` ደንቦች የጸጥታ መመለስ የለም፣ ይህም የውጪ ጽሁፍን ሊያስተካክል ይችላል)። `en` / `es` / `id` / `pt-BR` ተጠናቅቋል። ለከፊል ጥቅሎች የ `dedup.json` + `ultra.json` መዋጮ እንኳን ደህና መጡ።
- **የተቆለለ ቴሌሜትሪ የተጨመቁ ሞተሮችን ብቻ ይዘረዝራል።** የተቆለለ የቧንቧ መስመር ሞተሩ የሚሰራ ነገር ግን 0% ቁጠባ ያፈራው `stats:null` ይመልሳል እና በ `engineBreakdown` — ውስጥ ከተዘለለ ደረጃ የማይለይ አይታይም። "ሮጣ፣ 0 %" ከ"ተዘለለ" መለየት የብልሽት-ሞዴል ለውጥ ያስፈልገዋል እናም ዘግይቷል።
