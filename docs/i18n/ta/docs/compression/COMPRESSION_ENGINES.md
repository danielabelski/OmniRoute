OmniRoute சுருக்கமானது இயந்திர ஒப்பந்தங்களைச் சுற்றி கட்டமைக்கப்பட்டுள்ளது. ஒரு பயன்முறையானது ஒரு இன்ஜினை நேரடியாக இயக்கலாம் (`caveman` அல்லது `rtk`) அல்லது பல என்ஜின்களை வரிசையாக இயக்கும் நிலையான அடுக்கப்பட்ட பைப்லைன்.

## முறைகள்

| பயன்முறை     | எஞ்சின் பாதை                                                                                          | நோக்கம் உள்ளீடு                                         |
| ------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `off`        | எதுவும் இல்லை                                                                                         | சரியான உடனடி பாதுகாப்பு                                 |
| `lite`       | கேவ்மேன் லைட் உதவியாளர்கள்                                                                            | குறைந்த ஆபத்து எப்போதும் சுத்தப்படுத்துதல்              |
| `standard`   | குகைமனிதன்                                                                                            | இயற்கை மொழி உடனடி ஒடுக்கம்                              |
| `aggressive` | கேவ்மேன் + history/tool சுருக்கங்கள்                                                                  | நீண்ட அரட்டை அமர்வுகள்                                  |
| `ultra`      | கேவ்மேன் + கத்தரித்து உதவியாளர்கள்                                                                    | சூழல் வரம்பு மீட்பு                                     |
| `rtk`        | RTK                                                                                                   | டெர்மினல், ஷெல், உருவாக்க, சோதனை மற்றும் கிட் வெளியீடு  |
| `omniglyph`  | OmniGlyph                                                                                             | நேட்டிவ் புரோவைடர் வயரில் உள்ள படமாக சூழல்              |
| `stacked`    | குழாய். கோரிக்கை இயல்புநிலை `session-dedup -> lite` ஆகும். `rtk -> caveman` தேர்வு செய்யப்பட்டுள்ளது. | கலப்பு கருவி பதிவுகள் மற்றும் உரைநடை, அதிகபட்ச சேமிப்பு |

### OmniGlyph சுருக்க சுயவிவரங்கள்

`omniglyph` இன்ஜின் (தொகுப்பு `omniglyph`, 1.4.0 +) பெயரிடப்பட்ட சொற்பொருள் சுயவிவரத்தை ஏற்றுக்கொள்கிறது, இது உலகளவில் `omniglyph.profile` மூலம் சுருக்க அமைப்புகளில் அல்லது அடுக்கப்பட்ட பைப்லைன் படி கட்டமைப்பு மூலம் அமைக்கப்படுகிறது:

| சுயவிவரம்     | எல்லை                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `aggressive`  | இயல்புநிலை. வெளியிடப்பட்ட ரசீதுகளின் கொள்கையானது — பட அமைப்பு, கருவி ஆவணங்கள் மற்றும் அடர்த்தியான வரலாறு ஆகியவற்றை அளவிடுகிறது. |
| `balanced`    | நேரடி மாநில பூர்வீகமாக வைத்திருக்கிறது, கடைசி 8 திருப்பங்களைப் பாதுகாக்கிறது, பழைய மூடிய வரலாற்றைக் குறைக்கிறது                 |
| `coding-safe` | அதிகாரம், டூல் ஸ்கீமாக்கள் மற்றும் லைவ் டூல் அவுட்புட்டை சொந்தமாக வைத்திருக்கிறது, கடைசி 12 திருப்பங்களைப் பாதுகாக்கிறது        |
| `passthrough` | உருமாற்றம் இல்லாத பாதைகள்; இயந்திரம் தவிர்க்கப்பட்டது                                                                           |

சுயவிவரம் ஒரு** கூரை, ஒரு தளம் அல்ல** : தொகுப்பில் உள்ள `mergeCompressionProfileOptions` சுயவிவரத்தை மூடிய நஷ்டமான பாதையை மீண்டும் திறக்க அழைப்பாளரை அனுமதிக்க மறுக்கிறது, எனவே ஒரு படி `preserveSystemPrompt: false` `coding-safe` இன் கீழ் கணினி சுருக்கத்தை மீண்டும் இயக்க முடியாது.

இந்தக் குறியீட்டுத் தளத்தில் அளவிடப்படுகிறது: `coding-safe` மற்றும் `balanced` `minCompressChars` அதிகபட்சமாக உயர்த்தி, கணினி, கருவித் திட்டங்கள் மற்றும் கருவி முடிவுகளை பூர்வீகமாக வைத்திருக்கின்றன, எனவே வரலாற்றைக் குவிக்காத ஒரு அமர்வு இன்னும் `below_min_chars` இல் நிற்கிறது மற்றும் இயந்திரம் எதையும் மாற்றாது. அதனால்தான் இயல்புநிலையானது பாதுகாப்பான சுயவிவரத்தை விட `aggressive` ஆகும்.

தொகுப்பு அதன் சொந்த மாதிரி நோக்கம் மற்றும் சுயவிவரத்தை அதன் சூழல் உள்ளமைவிலிருந்து தீர்க்கிறது. OmniRoute ஒருபோதும் முடிவைப் பிரதிநிதித்துவப்படுத்துவதில்லை: அடாப்டர் மாடல் கேட்டை தொகுப்பின் மிகவும் கட்டுப்படுத்தப்பட்ட நோக்கத்திற்கு பொருத்துகிறது, எனவே ஹோஸ்ட் சூழல் அமைப்புகள் அனுமதிப்பட்டியலை மட்டுமே சுருக்கலாம், அதை OmniRoute இன் அளவிடப்பட்ட ரசீதுகளுக்கு அப்பால் விரிவுபடுத்த முடியாது.

## என்ஜின் ரெஜிஸ்ட்ரி

பதிவகம் `open-sse/services/compression/engines/registry.ts` இல் வாழ்கிறது. என்ஜின்கள் பகிரப்பட்ட ஒப்பந்தத்தை வெளிப்படுத்துகின்றன:

- `id`: `caveman` அல்லது `rtk` போன்ற நிலையான இயந்திர ஐடி
- `apply(text, config)`: அடுக்கப்பட்ட பைப்லைன்களால் பயன்படுத்தப்படும் மரபு செயல்படுத்தும் பாதை
- `compress(input, config)`: முதன்மை செயலாக்க பாதை திரும்பும் உரை + புள்ளிவிவரங்கள்
- `getConfigSchema()`: சரியான கட்டமைப்பின் JSON-Schema போன்ற வடிவத்தை வழங்குகிறது
- `validateConfig(config)`: `{ valid, errors[] }` வழங்குகிறது

பதிவு `registerCompressionEngine(engine)` (அல்லது மேம்பட்ட நிகழ்வுகளுக்கு `registerEngine` ) பயன்படுத்துகிறது, இது ஏற்கும் முன் `assertValidEngine()` மற்றும் `validateConfig(defaultConfig)` அழைக்கிறது. இயக்க நேரத்தில் ஒரு இயந்திரத்தை அகற்ற `unregisterCompressionEngine(id)` பயன்படுத்தவும்.

`strategySelector.ts` சுருக்க இயங்கும் முன் உள்ளமைக்கப்பட்ட இயந்திரங்களை பதிவு செய்கிறது. இது முன்னோட்டம், இயக்க நேர சுருக்கம், அடுக்கப்பட்ட பயன்முறை, சோதனைகள் மற்றும் எதிர்கால எஞ்சின்கள் அதே செயல்படுத்தும் பாதையைப் பயன்படுத்த அனுமதிக்கிறது.

### MCP விளக்கம் சுருக்கம் (தொடர்புடையது)

ஒரு தனி பதிவகம் MCP கருவி விளக்க மெட்டாடேட்டாவை பதிவு நிலை — இல் சுருக்குகிறது `open-sse/mcp-server/descriptionCompressor.ts` மற்றும் [MCP-SERVER.md](../frameworks/MCP-SERVER.md) பார்க்கவும். இது கேவ்மேன் விதிகளை மீண்டும் பயன்படுத்துகிறது ஆனால் கருவி மெட்டாடேட்டாவில் இயங்குகிறது, பேலோடுகளை கோரவில்லை.

### கூடுதல் உள்ளமைக்கப்பட்ட இயந்திரங்கள்

கேவ்மேன், RTK மற்றும் LLMLingua-2 க்கு அப்பால், பதிவகம் பல சிறப்பு இழப்பற்ற / கட்டமைப்பு இயந்திரங்களை அனுப்புகிறது (அடுக்கப்பட்ட பைப்லைன்கள், விளையாட்டு மைதானம் மற்றும் சோதனைகள் மூலம் பயன்படுத்தப்படுகிறது):

| இயந்திரம்     | ஐடி             | அது என்ன செய்கிறது                                                                                                                                                                                |
| ------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CCR           | `ccr`           | Content-Compress-Retrieve (H4): repeated/large தொகுதிகள் ஒருமுறை அனுப்பப்பட்டு அதன்பின் குறிப்பிடப்படும், பெரிய தொடர்ச்சியான உரைத் தொகுதிகளை உள்ளடக்க முகவரியிடப்பட்ட குறிப்புகளுடன் மாற்றுகிறது. |
| தலையறை        | `headroom`      | SmartCrusher (H3 + N5): ஒரே மாதிரியான JSON-வரிசை பேலோடுகளின் இழப்பற்ற அட்டவணைச் சுருக்கம் ஒரு நெடுவரிசை `[N rows]` வடிவத்தில்.                                                                    |
| அயனியாக்கி    | `ionizer`       | மிகப் பெரிய ஒரே மாதிரியான தொகுதிகளுக்கான Head/middle/tail வரிசை மாதிரி, ஒரு CCR உள்ளடக்கம்-முகவரியிடப்பட்ட குறிப்பு என எலிடெட் நடுப்பகுதியை சேமிக்கிறது.                                          |
| அமர்வு-தூய்மை | `session-dedup` | உள்ளடக்கம்-அட்ரஸ் செய்யப்பட்ட குறுக்கு-திரும்புக் குறைப்பு (டோக்கன்மைசர்-இன்ஸ்பைர்டு): இதே அமர்வின் முந்தைய திருப்பங்களில் ஏற்கனவே காணப்பட்ட elides உரை.                                          |

**CCR மீட்டெடுப்பு-நெறிமுறை அறிவுறுத்தல் (#8033):** முதல் முறையாக CCR ஒரு கோரிக்கையில் ≥ 1 ப்ளாக்கை மாற்றும் போது, இன்ஜின் ஒரு ஒற்றை, idempotent `system` செய்தியை முன்வைக்கிறது ( `[CCR protocol]` செண்டினலுடன் முன்னணியில் உள்ளது) அழைப்பாளருக்கு மார்க்கர் → கருவி ஒப்பந்தத்தை கற்பிக்கிறது: `[CCR retrieve hash=<24hex> chars=N]` மார்க்கர் என்றால் என்ன, ஹாஷ் வினைச்சொல்லாக நகலெடுக்கப்பட வேண்டும் (அனைத்தும் 24 hexi க்கு தவறான எழுத்துகள் இருக்கலாம். "தடுப்பு கிடைக்கவில்லை" தவறவிட்டது), `[dedup:ref sha=...]` — "வரலாற்றில் திரும்பிப் பார்" என்று பொருள்படும், "கருவியை அழைக்க" அல்ல. குறிப்பு ஊசி போடப்படுகிறது** அழைப்பவரின் விளம்பரப்படுத்தப்பட்ட `tools[]` நிரூபிக்கும் போது மட்டுமே அது உண்மையில் `omniroute_ccr_retrieve` அடைய முடியும்** ( `open-sse/services/compression/engines/ccr/protocolInstruction.ts` இல்`callerSupportsCcrRetrieve()` ) — ஒரு எளிய OpenAI-இணக்கமான அழைப்பாளர் அந்தக் கருவி இல்லாமல், அது அடைய முடியாத ஒன்றை அழைப்பதற்கான அறிவுறுத்தலைப் பெறுவதில்லை. உட்செலுத்துவதற்கு முன் சென்டினலுக்கான செய்தி வரலாற்றை ஸ்கேன் செய்வதன் மூலம் ஐடெம்போடென்சி செயல்படுத்தப்படுகிறது, எனவே பல முறை கோரிக்கைகள் (முந்தைய செய்திகளை மீண்டும் இயக்கும்) ஒவ்வொரு முறையும் குறிப்பை அடுக்கி வைக்காது.

## குகைமனிதன்

கேவ்மேன் பயன்முறை சாதாரண உரைநடையின் சொற்பொருள் ஒடுக்கத்தில் கவனம் செலுத்துகிறது:

- குறியீடு தொகுதிகள், URLs, JSON, பாதைகள் மற்றும் கட்டமைக்கப்பட்ட தரவு ஆகியவற்றைப் பாதுகாக்கிறது
- நிரப்பு, ஹெட்ஜிங், மீண்டும் மீண்டும் சூழல், மற்றும் verbose இணைப்பு சொற்றொடர்களை நீக்குகிறது
- `open-sse/services/compression/rules/` இல் மொழி-விழிப்புணர்வு கோப்பு விதி தொகுப்புகளை ஆதரிக்கிறது
- மரபுவழி `standard`, `aggressive`, மற்றும் `ultra` முறைகள் மூலம் கிடைக்கும்

டாஷ்போர்டு மேற்பரப்பு `Dashboard -> Context & Cache -> Caveman` ஆகும்.

கேவ்மேன் அப்ஸ்ட்ரீம் `~75%` குறைவான வெளியீட்டு டோக்கன்கள், `22-87%` வரம்பைக் கொண்ட வரையறைகளில் `65%` சராசரி வெளியீட்டு சேமிப்பு மற்றும் `~46%` உள்ளீடு-சுருக்கக் கருவி ஆகியவற்றைப் புகாரளிக்கிறது. OmniRoute அடுக்கப்பட்ட prompt/context சேமிப்புகளை ஆவணப்படுத்தும் போது கேவ்மேன் உள்ளீட்டு பக்க எண்ணைப் பயன்படுத்துகிறது; கேவ்மேன் வெளியீட்டு முறை ஒரு தனி பதில்-நடத்தை அம்சமாக உள்ளது.

## RTK

RTK பயன்முறை கட்டளை மற்றும் கருவி வெளியீட்டில் கவனம் செலுத்துகிறது:

- `git status`, `git branch`, `git diff`, Vitest/Jest/Pytest, Cargo/Go சோதனைகள், TypeScript/Vite/Webpack பில்ட்ஸ், ESLint, npm audit/installs, Docker பதிவுகள், ஷெல் `find`/`grep`, ஸ்டேக் ட்ரேஸ்கள் மற்றும் பொதுவான பதிவுகள் போன்ற வெளியீட்டு வகுப்புகளைக் கண்டறிகிறது
- `open-sse/services/compression/engines/rtk/filters/` இலிருந்து 49 JSON வடிப்பான்களைப் பயன்படுத்துகிறது
- RTK-பாணி அறிவிப்பு பைப்லைனை ஆதரிக்கிறது: ANSI அகற்றுதல், மாற்றுதல், மேட்ச்-அவுட்புட் ஷார்ட்-சர்க்யூட், strip/keep கோடுகள், ஒரு வரி துண்டித்தல், head/tail/max-line துண்டித்தல் மற்றும் ஆன்-காலி ஃபால்பேக்
- `.rtk/filters.json` இல் நம்பகமான திட்ட வடிப்பான்களையும் `DATA_DIR/rtk/filters.json` இல் உலகளாவிய வடிப்பான்களையும் ஆதரிக்கிறது
- கீற்றுகள் ANSI தொடர்கள், முன்னேற்ற சத்தம், மீண்டும் மீண்டும் கோடுகள், மற்றும் உதவாத கொதிகலன்
- செயல்படக்கூடிய தோல்விகள், எச்சரிக்கைகள், சுருக்கங்கள், மாற்றப்பட்ட கோப்புகள் மற்றும் வால் சூழல் ஆகியவற்றைப் பாதுகாக்கிறது
- அங்கீகரிக்கப்பட்ட மேலாண்மை வழிகள் மூலம் recovery/debugging க்கான திருத்தப்பட்ட மூல வெளியீட்டை விருப்பப்படி தக்கவைத்துக் கொள்ளலாம்

டாஷ்போர்டு மேற்பரப்பு `Dashboard -> Context & Cache -> RTK` ஆகும்.

தனிப்பயன் வடிப்பான்களுக்கான செயல்பாட்டு விவரங்கள், நம்பிக்கை, சரிபார்ப்பு மற்றும் மூல-வெளியீட்டு மீட்பு ஆகியவை [`RTK_COMPRESSION.md`](./RTK_COMPRESSION.md) இல் நேரலையில் உள்ளன.

RTK அப்ஸ்ட்ரீம் கட்டளை-வெளியீட்டு சுருக்கத்திற்கான `60-90%` சேமிப்பை தெரிவிக்கிறது. அதன் README உதாரணம், `~118,000` டோக்கன்களில் இருந்து `~23,900` க்கு செல்லும் 30 நிமிட Claude குறியீடு அமர்வு அல்லது `79.7%` சேமிக்கப்படுகிறது.

## LLMLingua-2 (சொற்பொருள் சீரமைப்பு)

LLMLingua-2 பயன்முறை செயல்படுகிறது** சொற்பொருள் டோக்கன் சீரமைப்பு** ஒரு சிறிய ONNX டோக்கன் வகைப்படுத்தியைப் பயன்படுத்தி உரைநடையில், விதி அடிப்படையிலான கேவ்மேன் மற்றும் RTK இன்ஜின்களை நிறைவு செய்கிறது:

- கணினி அல்லாத செய்திகளில் மட்டுமே உரைநடையை சுருக்குகிறது; வேலியிடப்பட்ட குறியீடு தொகுதிகள் மற்றும் பிற பாதுகாக்கப்பட்ட கட்டுமானங்கள் ஒருபோதும் மாற்றப்படாது
- `@atjsh/llmlingua-2` பின்தளத்தில் (ONNX வழியாக `@huggingface/transformers`) இயங்குகிறது, எனவே மாதிரி அனுமானம் கோரிக்கை நிகழ்வு வளையத்தைத் தடுக்காது
- உள்ளது** அடுக்கக்கூடிய** (`stackPriority` 35): அடுக்கப்பட்ட பைப்லைனில் இது கட்டமைப்பு இயந்திரங்களுக்குப் பிறகு இயங்குகிறது (CCR, அமர்வு-டெடப், ஹெட்ரூம், கேவ்மேன்) ஆனால் `ultra` க்கு முன், ஏனெனில் ஏற்கனவே-கட்டமைப்பு ரீதியாக-அமுக்கப்பட்ட உரை — இல் சொற்பொருள் சீரமைப்பு மிகவும் பயனுள்ளதாக இருக்கும் `rtk -> caveman -> llmlingua`
- **தோல்வி-எந்தப் பிழையிலும் திறக்கப்படும்** (விருப்பத்தேர்வு டெப்ஸ், தொழிலாளி ஸ்பான், மாடல் லோட், அனுமானம் அல்லது காலக்கெடுவைக் காணவில்லை) → அசல் உரை மாறாமல் திரும்பும், ஒருபோதும் பிழை இல்லை

எஞ்சின் இடம்: `open-sse/services/compression/engines/llmlingua/`. டாஷ்போர்டு மேற்பரப்பு `Dashboard -> Context & Cache -> LLMLingua` ஆகும்.

### மாதிரிகள்

இயல்புநிலை மாதிரி**TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~ 57 MB, வேகமாக). அதிக துல்லியம்** BERT-அடிப்படை** மாடல் (`Arcoldd/llmlingua4j-bert-base-onnx`, ~ 710 MB) இன்ஜின் config `model` புலம் வழியாக கிடைக்கிறது. `@huggingface/transformers` தேர்ந்தெடுக்கப்பட்ட மாதிரியை HuggingFace Hub இலிருந்து `${DATA_DIR}/models/llmlingua` க்கு முதல் அழைப்பிலேயே சோம்பேறித்தனமாக பதிவிறக்குகிறது (`modelStore.ts`); ஒரு `modelPath` config மேலெழுதுதல் அதை ஒரு உள்ளூர் நகலில் சுட்டிக்காட்டுகிறது (ஆஃப்லைன் / காற்று இடைவெளி நிறுவல்கள்).

| `js-tiktoken`        | `^1.0.20`      | டோக்கனைசர்                                              |

`@huggingface/transformers` ஆனது `^4.2.0` இல் பொருத்தப்பட்டுள்ளது (உள்ளூர் உட்பொதிவுகள் பாதையுடன் பகிரப்பட்டது மற்றும் தனித்த பண்டில் கண்டறியப்பட்டது); `@atjsh/llmlingua-2@2.0.5` `"^3.5.2 || ^4.0.0"` உடன் இணைகிறது, எனவே Transformers.js v3 மற்றும் v4 இரண்டும் ஆதரிக்கப்படுகின்றன. 2.0.4 முதல், `@atjsh/llmlingua-2` இனி `@tensorflow/tfjs` தேவையில்லை, இது SLM அடுக்கில் இருந்து மிகப்பெரிய ஒற்றை பங்களிப்பாளரை (TensorFlow.js) அகற்றியது. மேலே உள்ள இரண்டு தொகுப்புகள் மட்டுமே ப்ரூன் செய்யக்கூடிய SLM சகாக்கள். ஒரு நிலையான `npm install` (dev) விருப்ப சார்புகள் தவிர்க்கப்படும் வரை தானாகவே விருப்ப அடுக்கை நிறுவுகிறது.

**ஏன் தேவை:** npm-வெளியிடப்பட்ட தொகுப்பு, முழுமையான தொகுப்பு மற்றும் Docker படக் கப்பல்** இல்லாமல்** இந்த டெப்ஸ் மெலிதாக இருக்க. அவர்கள் இல்லாத போது, தொழிலாளியின் சார்பு வாயில் ( `worker.ts` இல் ஒரு `@atjsh/llmlingua-2` தீர்வு ஆய்வு) தோல்வியடைகிறது மற்றும் இயந்திரம்** தோல்வி - அமைதியாக திறக்கிறது** — ஐத் தேர்ந்தெடுப்பது LLMLingua ஆகாது (உரை மாறாமல் திரும்பியது, பிழை பதிவு செய்யப்படவில்லை). சீரமைக்கப்பட்ட சூழலில் அதைச் செயல்படுத்த, விருப்பமான அடுக்கை நிறுவவும்:

```bash
# pin to the versions declared in package.json optionalDependencies
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` அகற்றுதல் (2.0.4 +) முன்பு ஆதிக்கம் செலுத்திய ~ 800 MB பங்களிப்பாளர் — நீக்குகிறது, மீதமுள்ள தடம் transformers.js + onnxruntime-node இயக்க நேரங்கள், மேலும் TinyBERT மாதிரி (~ 57 முதல் MB இல் பதிவிறக்கம் செய்யப்படவில்லை).

ஒரு சூழலுக்கு:

- **தேவ் / `npm install`** நீங்கள் `--omit=optional` (அல்லது `--no-optional`) ஐ கடந்தால் தவிர — தானாக நிறுவப்படும். நடவடிக்கை தேவையில்லை.
- **குளோபல் npm (`npm i -g omniroute`) / தனி** — நிறுவப்பட்ட தொகுப்பு கோப்பகத்தில் மேலே உள்ள நிறுவல் கட்டளையை இயக்கவும் அல்லது விருப்பமான டெப்ஸைத் தவிர்க்காமல் மீண்டும் நிறுவவும்.
- **Docker** — நிறுவல் கட்டளையை பெறப்பட்ட பட அடுக்கில் சேர்க்கவும்; வெளியிடப்பட்ட படம் வடிவமைப்பால் மெலிதானது.
- **VPS (PM2)** பயன்பாட்டின் `node_modules` இல் — நிறுவவும், பின்னர் செயல்முறையை மறுதொடக்கம் செய்யவும், இதனால் பணியாளர் வாயிலை மீண்டும் ஆய்வு செய்கிறார்.
- **ரா நெக்ஸ்ட் ஸ்டாண்டலோன் (`npm run build` → `.build/next/standalone/server.js`)** — தனியான டிரேஸ் ஷிப்கள் NEITHER தொழிலாளி அல்லது விருப்ப டெப்ஸ், எனவே இயந்திரம் அமைதியாக தோல்வியடைகிறது-திறக்கப்படுகிறது. `scripts/build/colocate-standalone.mjs` இரண்டையும் மீண்டும் பயன்படுத்துகிறது (தொழிலாளர் + விருப்ப-ஆழ்ந்த மூடுதலை தனி மரத்தில் உருவாக்குகிறார்); ஒவ்வொரு கட்டத்திற்கும் பிறகு இது `postbuild` npm ஹூக் வழியாக தானாகவே இயங்கும். டெப்ஸ் இல்லாதபோது, செயலற்ற, ஃபெயில்-மென்ட்.

**செயலில் உள்ளதா என சரிபார்க்கவும்:** LLMLingua தேர்ந்தெடுக்கப்பட்டால், உண்மையான உரைநடை உண்மையில் சுருங்குகிறது (இயந்திரம் தோல்வி-திறப்பதை நிறுத்துகிறது), மற்றும் முதல் கோரிக்கை மாதிரி பதிவிறக்கத்தை `${DATA_DIR}/models/llmlingua` க்கு தூண்டுகிறது. கேட் வேண்டுமென்றே `@atjsh/llmlingua-2` — மட்டுமே ஆய்வு செய்கிறது, மற்ற சகாக்கள் ESM-மட்டுமே மற்றும் `require.resolve` தற்போது — இருக்கும்போது கூட அவர்கள் மீது வீசுகிறது, எனவே `import()` நேரத்தில் யாரேனும் ஒருவர் உண்மையாகக் காணவில்லை என்றால், தொழிலாளி தோல்வியடைகிறார்.

## அடுக்கப்பட்ட குழாய்கள்

அடுக்கப்பட்ட பயன்முறை பைப்லைன் படிகளை வரிசையாக இயக்குகிறது. இயல்புநிலை:

```txt
rtk -> caveman
```

குறியீட்டு முகவர் அமர்வுகளுக்கு இதைப் பயன்படுத்தவும், அங்கு கட்டளை வெளியீட்டை மனித அல்லது உதவி உரைநடையுடன் இணைக்கும். RTK முதலில் சத்தமில்லாத கருவி பதிவுகளை குறைக்கிறது, பின்னர் கேவ்மேன் மீதமுள்ள இயற்கை மொழியை சுருக்குகிறது.

பைப்லைன் படிகள் `stackedPipeline` உடன் சுருக்க அமைப்புகளில் அல்லது சுருக்க காம்போஸ் மூலம் கட்டமைக்கப்படுகின்றன.

இரண்டு என்ஜின்களும் ஒரே தகுதியான பேலோடை குறைக்கும் போது, சேமிப்பு கலவை:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP அணுகல் மர வடிகட்டி

MCP அணுகல்தன்மை-மரம் ஸ்மார்ட் ஃபில்டர் என்பது MCP இல் இயங்கும் ஒரு பிந்தைய செயலாக்க சுருக்க அடுக்கு ஆகும்.** கருவி முடிவுகள்** , அறிவுறுத்தல்கள் அல்லது சூழலில் அல்ல. இது Playwright, கணினி பயன்பாடு மற்றும் உலாவி-தானியங்கும் MCP சேவையகங்கள் போன்ற கருவிகளால் திரும்பப் பெறப்பட்ட verbose accessibility-tree மற்றும் உலாவி ஸ்னாப்ஷாட் பேலோடுகளை குறிவைக்கிறது.

### அது என்ன செய்கிறது

1. **சத்தம் அகற்றுதல்** — வெற்று generic/text உள்ளீடுகளை நீக்குகிறது (`- generic:`, `- text: ""`)
2. **உடன்பிறப்பு சரிவு** — போது ≥ `collapseThreshold` (இயல்புநிலை 30) தொடர்ச்சியான கோடுகள் கட்டமைப்பு மறுமுறைகளாக இருந்தால், அவற்றை முதல் `collapseKeepHead` (இயல்புநிலை 10) வரிகளாகச் சுருக்குகிறது + ஒரு எண்ணிக்கை சுருக்கம் + கடைசி `collapseKeepTail` (இயல்புநிலை 5) வரிகள்
3. **குறிப்பு பாதுகாப்பு** Playwright/computer-use க்கு தேவைப்படும் — `[ref=eXX]` ஆங்கர்கள் ஒருபோதும் தொடப்படாது
4. **கடினமான துண்டிப்பு** — சரிவுக்குப் பிறகு உரை `maxTextChars` விட அதிகமாக இருந்தால் (இயல்புநிலை 50,000), வழிசெலுத்தல் குறிப்புடன் துண்டிக்கப்படும், இதனால் முகவர் தொடர்ந்து வேலை செய்ய முடியும்

### எஞ்சின் இடம்

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### கட்டமைப்பு

உலகளாவிய அமைப்புகளில் `compression.mcpAccessibility` ஆல் கட்டுப்படுத்தப்படுகிறது (இடம்பெயர்வு 056). இயல்புநிலை கட்டமைப்பு:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

`type` `"text"` மற்றும் நீளம் `minLengthToProcess` விட அதிகமாக இருக்கும் கருவி-முடிவு பேலோடுகளுக்கு மட்டுமே வடிகட்டி பயன்படுத்தப்படும். இது உடனடி சுருக்க அல்லது கோரிக்கை பேலோடுகளை பாதிக்காது.

### எதிர்பார்த்த சேமிப்பு

பக்கத்தின் சிக்கலான தன்மையைப் பொறுத்து உலாவி ஸ்னாப்ஷாட் கருவி முடிவுகளில் 60-80%. சரிவு அல்காரிதம் வரி எண்ணிக்கையில் O(n) ஆக உள்ளது மற்றும் மிகக் குறைவான தாமதத்தை சேர்க்கிறது.

## சுருக்க கலவைகள்

சுருக்க காம்போக்கள் சுருக்க சுயவிவரங்கள் என்று அழைக்கப்படுகின்றன, அவை ரூட்டிங் காம்போக்களுக்கு ஒதுக்கப்படலாம்:

- `compression_combos`: ஸ்டோர்ஸ் முறை, பைப்லைன், RTK கட்டமைப்பு, மொழி கட்டமைப்பு மற்றும் இயல்புநிலை மார்க்கர்
- `compression_combo_assignments`: ஒரு சுருக்க சேர்க்கையை ஒரு ரூட்டிங் சேர்க்கைக்கு வரைபடமாக்குகிறது
- இயக்க நேர ஒருங்கிணைப்பு, பொதுவான சேர்க்கை மேலெழுதுவதற்கு முன் ஒதுக்கப்பட்ட சுருக்க சேர்க்கையை தீர்க்கிறது
- பகுப்பாய்வுகளில் `compression_combo_id` மற்றும் `engine` ஆகியவை அடங்கும்

டாஷ்போர்டு மேற்பரப்பு: `Dashboard -> Context & Cache -> Compression Combos`.

## முன்நிபந்தனைகள் / ஆபரேட்டர் வழிகாட்டி (CCR & அமர்வு-டெடப்)

CCR (`ccr`) மற்றும் `session-dedup` உரையை மாற்றவும் அல்லது எலிட் செய்யவும் மற்றும் a ஐ விட்டு விடுங்கள்** குறிப்பான்** பின்னால். இந்த பிரிவு கிளையண்டை வயரிங் செய்வதற்கும், இரண்டு குறிப்பான்களைப் படிப்பதற்கும், நீக்கப்பட்ட உள்ளடக்கத்தை மீட்டெடுப்பதற்கும் அல்லது கண்டறிவதற்கும் ஆபரேட்டர் குறிப்பு ஆகும். ஒவ்வொரு இயந்திரத்தின் இயக்கவியல் மேலே விவரிக்கப்பட்டுள்ளது; இது "எப்படி இயக்குவது" அடுக்கு.

### போக்குவரத்து மற்றும் இறுதிப் புள்ளிகள்

CCR கருவிகளை வெளிப்படுத்தும் MCP சேவையகத்தை மூன்று வழிகளில் அடையலாம். இயல்புநிலை அடிப்படை URL `http://localhost:20128` (`OMNIROUTE_BASE_URL`):

| போக்குவரத்து                                                   | URL / கட்டளை                            | குறிப்புகள்                                                                                                                                                           |
| -------------------------------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ஸ்ட்ரீம் செய்யக்கூடிய HTTP (கிளையண்ட், பரிந்துரைக்கப்படுகிறது) | `http://localhost:20128/api/mcp/stream` | தற்போதைய MCP வாடிக்கையாளர்கள் பேசும் இறுதிப்புள்ளி.                                                                                                                   |
| மரபு SSE சிங்கிள்டன்                                           | `http://localhost:20128/api/mcp/sse`    | பழைய சிங்கிள்டன் போக்குவரத்து. அது** மூடுகிறது** ஸ்ட்ரீம் செய்யக்கூடிய அமர்வுகள்; `/api/mcp/stream` எதிராக `streamable-http` கிளையண்டுகளைப் பயன்படுத்தவும், இது அல்ல. |

### சேமிப்பக அடுக்குகள் (மறுதொடக்கத்தில் உயிர்வாழ்வது)

CCR என்பது a** இரண்டு அடுக்கு** ஸ்டோர், நினைவகத்தில் மட்டும் அல்ல:

- **ஹாட் இன்-மெமரி டயர்** — per-block cap 2 MiB, per-principal 16 MiB, உலகளாவிய 64 MiB. உள்ளீடுகள் இயல்புநிலை 24 h TTL (அதிகபட்சம் 7 நாட்கள்). நினைவகத்திலிருந்து முழு MCP மீட்டெடுப்பு 256 KiB ஆக உள்ளது; பெரிய எதையும் இன்னும் ரேஞ்சட் / grep முறைகள் மூலம் அடைய முடியும்.
- **நீடித்த SQLite அடுக்கு** (`ccr_blocks`, `COMPRESSION_CCR_DURABLE_STORE`, முன்னிருப்பாக ஆன்) — நினைவகத்தில் உள்ள அடுக்குகளை ஆதரிக்கிறது, எனவே ஒரு தொகுதி LRU வெளியேற்றம், மறுதொடக்கம் அல்லது மற்றொரு நிகழ்வில் தரையிறங்கும் போது தப்பிக்கும். வரிசையானது பிளாக்கின் TTL வைத்திருக்கிறது, எனவே அதன் TTL கடந்த ஒரு தொகுதி இரண்டு அடுக்குகளிலிருந்தும் இல்லாமல் போய்விட்டது.

மூன்று பாதுகாவலர்கள் நீடித்த அடுக்கு — ஒரு தொகுதி நினைவகத்தில் வைத்திருக்கும் போது மட்டுமே:

1. தொகுதி முடிந்துவிட்டது** 512 KB** (`MAX_DURABLE_BLOCK_BYTES`);
2. இயக்க நேரம் ஒரு கிளவுட் இயக்க நேரம் (உள்ளூர் வட்டு இல்லை);
3. `COMPRESSION_CCR_DURABLE_STORE=false`.

எனவே "பிளாக் காணாமல் போனது" என்பது ஒரு போர்வை மறுதொடக்கம் கதை அல்ல: ஒரு உள்ளூர், கிளவுட் அல்லாத இயக்க நேரத்தின் sub-512 KB பிளாக் அதன் TTL இயங்கும் வரை நீடித்த அடுக்கு வழியாக மறுதொடக்கம் செய்யும். மாறிக்கான [சுற்றுச்சூழல் குறிப்பைப்](../reference/ENVIRONMENT.md) பார்க்கவும்.

### வாடிக்கையாளர் முன்நிபந்தனைகள்

- **விசை (stdio):** ஒரு stdio அழைப்பாளர் ஒவ்வொரு கோரிக்கை அடையாளத்தையும் கொண்டிருக்கவில்லை, எனவே இது `OMNIROUTE_API_KEY` உடன் அங்கீகரிக்கிறது ( MCP சேவையகத்தின் `env` இல் அமைக்கப்பட்டுள்ளது). இது இல்லாமல் அழைப்பவர் அநாமதேயமாக இருக்கிறார் மற்றும் ஒரு முதன்மை தேவைப்படும் கருவிகள் சிதைந்து போகலாம்.
- **`tools[]` என்பது ஊசி முன்நிபந்தனை.** CCR மீட்டெடுப்பு-நெறிமுறை அறிவுறுத்தல் (#8033) உட்செலுத்தப்பட்டது** மட்டுமே** கோரிக்கையின் விளம்பரப்படுத்தப்பட்ட `tools[]` வாடிக்கையாளர் உண்மையில் `omniroute_ccr_retrieve` அடைய முடியும் என்பதை நிரூபிக்கும் போது. இந்தப் போட்டியானது ஒரு பிரிப்பான் (`__`, `.`, `/`, `:`) மூலம் வரம்பிடப்பட்ட ஒரு பின்தங்கிய-பிரிவுப் பொருத்தம் — ஒருபோதும் வெற்று சப்ஸ்ட்ரிங் — இருக்காது, எனவே `mcp__gateway__omniroute_ccr_retrieve` போன்ற பெயரிடப்பட்ட பெயர் இன்னும் கணக்கிடப்படுகிறது. இல்லாத அல்லது பொருந்தாத `tools[]` என்றால், அறிவுறுத்தல் வடிவமைப்பின் மூலம் _இல்லை_ செலுத்தப்பட்டது.
- **`codemode:false` (OpenCode வாடிக்கையாளர்கள்).** OpenCode குறியீடு பயன்முறையில் இயல்புநிலையாக உள்ளது, இது மாதிரி மற்றும் அதன் சொந்த கருவிகளை மட்டுமே விளம்பரப்படுத்துகிறது** இல்லை** MCP கருவிகளை சொந்த `tools[]` பட்டியலில் வைக்கவும். MCP சேவையக உள்ளீட்டில் `codemode: false` அமைக்கவும், அதனால் `omniroute_ccr_*` கருவிகள் விளம்பரப்படுத்தப்படும். இது ஒரு** வாடிக்கையாளர்** அமைப்பு, OmniRoute ஒன்று அல்ல. இது இன்னும் CCR அறிவுறுத்தலைப் பெறவில்லை: OpenCode ஒரு கருவி `<server>_<tool>` என்று பெயரிடுகிறது, எனவே `omniroute` எனப்படும் சேவையகம் `omniroute_omniroute_ccr_retrieve` வெளிப்படுத்துகிறது, மேலும் `_` பொருந்திய பிரிப்பான்களில் ஒன்றல்ல.
- **அதிபர்கள்.** சேமிப்பகம் மற்றும் மீட்டெடுப்பு ஆகியவை அங்கீகரிக்கப்பட்ட முதன்மைக்கு ( API விசைக்கு) தனிமைப்படுத்தப்படும். ஒரு விசை அதன் சொந்த தொகுதிகளை மட்டுமே பார்க்கிறது.

### ஒரு கருவிக்கான நோக்கம்

குறுகிய நோக்கமுள்ள HTTP/SSE அழைப்பாளர்களுக்கு ஸ்கோப் அமலாக்கம் எப்போதும் இயக்கத்தில் இருக்கும். `omniroute_` CCR கருவிகள் தேவை:

| கருவி                    | நோக்கம்             |
| ------------------------ | ------------------- |
| `omniroute_ccr_store`    | `write:compression` |
| `omniroute_ccr_delete`   | `write:compression` |
| `omniroute_ccr_retrieve` | `read:compression`  |
| `omniroute_ccr_inspect`  | `read:compression`  |
| `omniroute_ccr_list`     | `read:compression`  |
| `omniroute_ccr_stats`    | `read:compression`  |

ஒரு விடுபட்ட நோக்கம் திரும்பும்**MCP கருவி பிழை முடிவு** (`isError: true`, HTTP 403 — அல்ல `403 LOCAL_ONLY` என்பது தனி லூப்பேக் ரூட்-கார்டு அங்கீகாரம்): `Error: Insufficient MCP scopes for <tool>. Missing: <scope>.` ஒரு குறைந்தபட்ச ரிமோட் கீயானது `mcp:connect` ( `/api/mcp/` லோக்கல்-ஒன்லி கார்வ்-அவுட்டை அங்கீகரிக்கிறது) மற்றும் அதற்குத் தேவையான குறிப்பிட்ட read/write ஸ்கோப்பை வைத்திருக்கும்.

### மீட்டெடுப்பு வரம்புகள் & பேஜினேஷன்

MCP கருவி உரை முடிவுகள் `mcpAccessibility.maxTextChars` (இயல்புநிலை `50000`) சுற்றி கிளிப் செய்யப்பட்டன. ஒரு தொகுதியின் ஒரு `full` மீட்டெடுப்பு 256 KiB — ஆக உள்ளது** வரம்பற்ற முழு மீட்டெடுப்பு இல்லை** . ஒரு பிளாக்கின் `chars=N` பெரியதாக இருக்கும் போது, முழு விஷயத்தையும் இழுப்பதற்குப் பதிலாக அதை பக்கமாக்குங்கள்:

- கட்டைவிரல் விதி:**`chars > 40000` → ஒரு `mode` ஐப் பயன்படுத்துகிறது** , ஒருபோதும் முழுமையடையாது.
- `mode:"grep"` — regex `pattern` பொருந்திய வரி வரி, 1,000 வரை பொருந்தும் வரிகள் (`unique: true` drops repets), "எனக்குத் தேவையான ஒரு வரியைக் கண்டுபிடி" என்பதற்காக மலிவானது.
- `mode:"lines"` — ஒரு 1-குறியிடப்பட்ட வரி வரம்பு; `start` மற்றும் `end` இரண்டும் தேவை.
- `mode:"head"` / `mode:"tail"` — first/last `n` கோடுகள்.
- `mode:"stats"` — கோடு, எழுத்து மற்றும் பைட் உடல் இல்லாமல் எண்ணிக்கை.

`start`/`end` உடன் `mode:"lines"` பயன்படுத்தி, முழுப் பொருளையும் ஒரே நேரத்தில் கோருவதை விட, பக்கங்களில் நீண்ட பிளாக் நடக்கவும்.

### கருவி பெயரிடுதல்

மீட்டெடுக்கும் கருவிக்கு தற்போது `omniroute_ccr_retrieve` என்று பெயரிடப்பட்டுள்ளது ( `omniroute_` முன்னொட்டு என்பது கிராஸ்-சர்வர் பெயர் மோதல்களுக்கான தேதியிட்ட தீர்வாகும்). ஒரு தூய்மையான வரம்பிற்குட்பட்ட பின்னொட்டு கருவியின் பெயர் மற்றும் MCP JSON முடிவுகளுக்கான திருத்தம் துண்டிக்கப்பட்ட மிட்-ஸ்ட்ரிங் அப்ஸ்ட்ரீம் ஃபாலோ-அப்களாக கண்காணிக்கப்படும்; இந்தப் பக்கம் தற்போதைய, அனுப்பப்பட்ட நடத்தையை மட்டுமே ஆவணப்படுத்துகிறது.

### அமர்வு வாழ்க்கை சுழற்சி

ஸ்ட்ரீமபிள்-HTTP அமர்வுகள் செயலிழந்து, சேவையகம் அவற்றை அறுவடை செய்கிறது; செயலற்ற சாளரம் `MCP_SESSION_IDLE_MS` மாறிலி ஆகும் (பெயரால் குறிப்பிடப்படுகிறது, ஹார்ட்கோட் செய்யப்பட்ட மதிப்பு அல்ல, எனவே இந்தப் பக்கம் மாறும் போது அது மாறாது). செயலற்ற முறையில் அறுவடை செய்யப்பட்ட அமர்வின் அறிகுறி, `Unknown Mcp-Session-Id` — உடன் HTTP 404 ஆகும், இது அமர்வை மீண்டும் இணைக்க அல்லது மறுதொடக்கம் செய்வதாகும்** இல்லை** ஒரு விசையைச் சுழற்ற, நோக்கத்தை மாற்ற அல்லது ஒரு கருவியின் மறுபெயரிட.

## நோக்கம் மற்றும் விலக்குகள்

**உட்பொதிப்புகள் ஒருபோதும் சுருக்கப்படுவதில்லை.** `open-sse/handlers/embeddings.ts` ஒருபோதும் எந்த சுருக்க இயந்திரத்தையும் — என்று அழைப்பதில்லை, request/response உடல்கள் தீண்டப்படாமல் நேரடியாக செயல்படுத்துபவருக்குச் செல்லும். இது இன்று கட்டமைப்பாக உள்ளது (உட்பொதித்தல்கள் மற்றும் அரட்டை நிறைவுகள் என்பது ஒரு ரன்டைம் சரிபார்ப்பு அல்ல, ஆனால் இதன் பொருள் #8034 இல் உள்ள வெக்டார்-டிஸ்டோர்ஷன் கவலை உட்பொதித்தல்கள் பாதையில் வெளிப்பாடு இல்லை.

**Per-model/endpoint exclusion filter (#8034).** For chat completions, an operator can name model ids / `provider/model` targets that must never be compressed — a guardrail useful if compression is ever wired closer to an embeddings-adjacent path later, and generally useful for any model whose exact byte-for-byte prompt matters (deterministic evals, cache-sensitive prefixes, etc.).

- அமைப்புகள் புலம்: உலகளாவிய சுருக்க கட்டமைப்பில் `exclusions?: string[]` (`GET`/`PUT /api/settings/compression`), தற்போதுள்ள `key_value` சுருக்க பெயர்வெளி (`src/lib/db/compression.ts`) — புதிய அட்டவணை இல்லை.
- டாஷ்போர்டு தாவல்:** டாஷ்போர்டு → சுருக்க → விலக்குகள்** (`/dashboard/compression/exclusions`)
- பேட்டர்ன் தொடரியல்: `*` மட்டுமே வைல்டு கார்டு. ஒரு மாதிரியில் உள்ள மற்ற எல்லா ரெஜெக்ஸ் மெட்டாக்ராக்டர்களும் பொருத்தப்படுவதற்கு முன்பு தப்பிக்கப்படுகின்றன, எனவே `gpt-5.6` எழுத்துச்சரத்துடன் மட்டுமே பொருந்துகிறது, ஒருபோதும் `gpt-5x6` அல்ல (ReDoS-பாதுகாப்பானது, வரம்புக்குட்பட்டது, உள்ளமைக்கப்பட்ட அளவுகோல்கள் இல்லை). பேட்டர்ன் மாடல் ஐடி மற்றும் `provider/model` கலவையான — `gpt-5-6`, `openai/gpt-5-6`, மற்றும் `openai/*` ஆகிய இரண்டுக்கும் எதிராக பேட்டர்ன்கள் கேஸ்-சென்சிட்டிவ் முறையில் பொருந்துகின்றன, மேலும் `*` மட்டும் ஒவ்வொரு மாதிரியையும் விலக்குகிறது.
- பொருத்தம்: `open-sse/services/compression/exclusions.ts` இல் `isCompressionExcluded()` / `normalizeCompressionExclusions()`. சுருக்க அமைப்புகளைத் தீர்த்தவுடன் `chatCore.ts` விலக்கப்பட்ட இலக்கைச் சரிபார்க்கிறது,** எந்த இயந்திரமும் இயங்கும் முன்** , மற்றும் ஒரு போட்டியை சுருக்கமானது உலகளாவிய ரீதியில் முடக்கப்பட்ட — போன்றே கருதுகிறது. பகுப்பாய்வுத் தெரிவுநிலைக்காக ஸ்கிப் `writeCompressionSkip(..., "excluded")` மூலம் பதிவு செய்யப்படுகிறது.
- இயல்புநிலை (empty/absent பட்டியல்): முன்-#8034 நடத்தை — போன்றது எதுவும் விலக்கப்படவில்லை.

## அறியப்பட்ட வரம்புகள்

- **LLMLingua-2 (SLM) க்கு இணை-இருந்த விருப்ப டெப்ஸ் தேவை.** `@atjsh/llmlingua-2` + சகாக்கள் `dist/node_modules` இல் இணைந்திருக்கும் போது மட்டுமே தொழிலாளி உற்பத்தி கட்டமைப்பில் இயங்குகிறார் (பார்க்க `scripts/build/colocateOptionals.mjs`, #4286). அவை இல்லாமல், இயந்திரம் தோல்வியடைகிறது (அசல் உரையை வழங்குகிறது). பணியாளரின் தெளிவுத்திறன் இனி `import.meta.url` ஐச் சார்ந்து இருக்காது (அது தனித்தனி மூட்டையில் இறக்கிறது) — இது இயக்க நேரத்தில் நங்கூரமிடும் cwd / `argv[1]`.
- **கேவ்மேன் மொழி தொகுப்புகள் `de` / `fr` / `ja` பகுதியளவு உள்ளன.** அவர்கள் `context` + `filler` + `structural` விதிகளை அனுப்புகிறார்கள், ஆனால் `dedup` / `ultra` தொகுப்புகள் இல்லை, எனவே `ultra` தீவிரம் அந்த மொழிகளுக்கு `full` விட வலுவாக இல்லை (அவர்கள் தங்கள் சொந்த விதிகளை மட்டுமே பயன்படுத்துகிறார்கள் — அங்கு ஆங்கில `dedup`/`ultra` விதிகளுக்கு அமைதியான வீழ்ச்சி இல்லை, இது வெளிநாட்டு உரையை மாற்றும்). `en` / `es` / `id` / `pt-BR` முடிந்தது. பகுதி தொகுப்புகளுக்கு `dedup.json` + `ultra.json` இன் பங்களிப்புகள் வரவேற்கப்படுகின்றன.
- **அடுக்கப்பட்ட டெலிமெட்ரி சுருக்கப்பட்ட இயந்திரங்களை மட்டுமே பட்டியலிடுகிறது.** ஒரு அடுக்கப்பட்ட-பைப்லைன் படி `engineBreakdown` அதன் இயந்திரம் இயங்கும் ஆனால் 0 % சேமிப்பை `stats:null` திரும்பப் பெறுகிறது — "ரன், 0 %" ஐ "தவிர்த்தது" என்பதிலிருந்து வேறுபடுத்துவதற்கு ஒரு முறிவு மாதிரி மாற்றம் தேவைப்படும் மற்றும் ஒத்திவைக்கப்படுகிறது.
